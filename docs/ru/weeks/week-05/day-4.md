## 1. Теория — фигура, оси и что на них размещается :id=1-learn--the-figure-the-axes-and-what-goes-on-them

У каждого понятия ниже одни и те же пять частей: что это, как пишется (блок, который можно запустить, — график появится под ним), когда применять, ловушка и небольшое задание. Запускайте блоки сверху вниз: первый блок читает данные, из которых рисуют все следующие графики.

### Фигура и оси — страница и график на ней :id=figure-and-axes--the-page-and-the-chart-on-it

**Что это.** **matplotlib** (*matplotlib library*) рисует графики в два слоя. **Фигура** (*figure*) — это страница: её размер, файл, который вы сохраняете. **Оси** (*axes*) — один график на этой странице: линии, столбцы, заголовок, две шкалы. `fig, ax = plt.subplots()` создаёт по одному и того и другого; всё, что вы рисуете, — это методы `ax`.

**Как пишется.** Первый блок читает два файла дня, затем рисует самый простой график:

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from pathlib import Path
# папка для PNG-файлов
Path("figures").mkdir(exist_ok=True)
# один серый для данных, один цвет для акцента
GREY, BLUE, RED = "#9ca3af", "#1d4ed8", "#dc2626"
# одна строка на кредит: dpd, корзина, остаток
status = pd.read_csv("../excel/loans_status.csv", parse_dates=["disbursed_at"])
# одна строка на месяц × продукт
md = pd.read_csv("../excel/monthly_disbursements.csv", parse_dates=["month"])
# убираем октябрь 2026: один день — не месяц
md = md[md["month"] < "2026-10-01"]
# одна строка на месяц
monthly = md.groupby("month", as_index=False)[["loans", "amount"]].sum()

# фигура (страница) с одними осями (область графика), 8 × 4 дюйма
fig, ax = plt.subplots(figsize=(8, 4))
# рисуем на осях: сначала x, потом y
ax.plot(monthly["month"], monthly["amount"])
ax.set_title("Disbursed per month")
```

Последние три строки `monthly` — фрейма, который рисует график:

| month | loans | amount |
|---|---|---|
| 2026-07-01 | 367 | 20 693 870 000 |
| 2026-08-01 | 358 | 22 290 210 000 |
| 2026-09-01 | 361 | 17 015 490 000 |

В `monthly` 33 строки, с января 2024 по сентябрь 2026; график — одна линия через них, которая заканчивается на 17,0 млрд в сентябре.

| | фигура `fig` | оси `ax` |
|---|---|---|
| это | страница | один график на странице |
| вы задаёте | размер (`figsize=`), общий заголовок (`fig.suptitle`), строку источника (`fig.text`) | данные (`ax.plot`, `ax.bar` …), `ax.set_title`, `ax.set_xlabel`, `ax.set_ylim` |
| вы сохраняете | `fig.savefig("figures/01.png")` | — |

`plt.plot(...)` без `fig, ax` тоже рисует — на «текущих осях». Для быстрого взгляда это нормально, а как только графиков два, начинается путаница. Пишите `fig, ax = plt.subplots()` каждый раз.

**Когда применять.**
- В начале каждого графика: одна пара `fig, ax`, дальше методы `ax`.
- Всегда, когда график пойдёт в файл или в презентацию, — сохраняется именно фигура.

> ⚠️ **Осторожно.** `ax.title("…")` падает с `TypeError: 'Text' object is not callable`. У осей сеттеры начинаются с `set_`: `ax.set_title`, `ax.set_xlabel`, `ax.set_ylim`.

### Bar и barh — как сравниваются категории :id=bar-and-barh--how-categories-compare

**Что это.** **Столбчатая диаграмма** (*bar chart*) рисует по столбцу на категорию; длина столбца — это число. `ax.bar` рисует вертикальные столбцы, `ax.barh` — горизонтальные (*линейчатая диаграмма*), они лучше для рейтингов и длинных подписей. Столбец читают по длине, поэтому **столбцы начинаются с нуля**.

### Диаграмма рассеяния — два числа на строку :id=scatter--two-numbers-per-row

### Подписи, заголовки и форматы чисел — график, который можно процитировать :id=labels-titles-and-number-formats--a-chart-people-can-quote

**Что это.** График готов, когда читатель может его процитировать, не спрашивая вас. Для этого нужны **заголовок, который формулирует вывод** (*finding title*), подписи осей с единицами, числа в читаемом виде (млрд, а не `2e10`) и файл, сохранённый в фиксированном размере. **Форматтер** (`FuncFormatter`) переписывает каждую подпись делений оси; `fig.savefig` записывает PNG.

**Как пишется.**

```python
from matplotlib.ticker import FuncFormatter
# каждое деление: 20000000000 → "20 bn"
bn = FuncFormatter(lambda x, _: f"{x / 1e9:,.0f} bn")
fig, ax = plt.subplots(figsize=(10, 4))
ax.plot(monthly["month"], monthly["ma3"], color=BLUE, lw=2)
ax.yaxis.set_major_formatter(bn)
# от нуля; верх — автоматически
ax.set_ylim(0, None)
last = monthly["ma3"].iloc[-1]
# вывод, посчитанный из данных
ax.set_title(f"The 3-month average reached {last / 1e9:.1f} bn a month", loc="left")
ax.set_ylabel("disbursed per month, 3-month average")
# меньше краски: без рамки с двух сторон
ax.spines[["top", "right"]].set_visible(False)
# строка источника
fig.text(0.01, 0.01, "monthly_disbursements.csv · Jan 2024 – Sep 2026", fontsize=9, color="#6b7280")
# освободить место для всех подписей
fig.tight_layout()
fig.savefig("figures/01_disbursements_ma3.png", dpi=150, facecolor="white")
```

Заголовок гласит «The 3-month average reached 20.0 bn a month», ось y идёт от 0 до 20 млрд, а график сохранён как PNG размером 1 500 × 600 пикселей в `figures/`.

### Малые множественные графики — по панели на группу :id=small-multiples--one-panel-per-group

**Что это.** **Малые множественные графики** (*small multiples*) — сетка маленьких однотипных графиков, по одному на группу. `plt.subplots(rows, cols)` возвращает одну фигуру и массив осей; на каждых осях вы рисуете одну группу. `sharey=True` даёт всем панелям одну шкалу y; `sharey=False` оставляет каждой панели свою.

**Как пишется.**

```python
# самый крупный продукт первым

# один ряд из пяти осей
fig, axes = plt.subplots(1, 5, figsize=(16, 3), sharey=False)
for ax, p in zip(axes, products):
    one = md[md["product"] == p]
    ax.plot(one["month"], one["amount"] / 1e9, color=BLUE)
    ax.set_title(p, loc="left", fontsize=10)
    ax.tick_params(axis="x", rotation=45)
fig.suptitle("Monthly disbursements by product, bn UZS — each panel on its own scale", x=0.01, ha="left")
fig.tight_layout()
md.groupby("product")["amount"].sum().div(1e9).round(1).sort_values(ascending=False)
```

### Какой график для какого вопроса :id=what-chart-for-what-question

**Что это.** Тип графика следует из **вопроса**, а не из данных. Таблица и правила недели 4 без изменений — каждая строка теперь метод matplotlib, который вы уже применили.

**Как пишется.**

| Вопрос | график | метод `ax.` | Заметки |
|---|---|---|---|
| Как это меняется во времени? | линия | `plot(x, y)` | x — настоящие даты; по линии на ряд |
| Как сравниваются категории? | bar / barh | `bar` / `barh` | **от нуля**; сортировка по значению, если нет естественного порядка |
| Как распределено одно число? | гистограмма | `hist(values, bins=…)` | интервалы вручную; логарифмическая ось для денег |
| Разброс по группам | ящик с усами | `boxplot([g1, g2, …])` | медиана, квартили, усы |
| Два числа на строку | рассеяние | `scatter(x, y, s=8, alpha=0.3)` | логарифмические оси для денег |
| Матрица: группа × группа | тепловая карта | `sns.heatmap(wide)` | когорта × MOB, матрица переходов |
| По ряду на группу | малые множественные | `plt.subplots(1, n)` | `sharey` решает, что сравнивается |

Правила, которые не дело вкуса: **никаких круговых** больше трёх долей, **никакого 3D**, **столбцы с нуля**, **сортировка по значению**, если порядок не естественный, **один цвет + один акцент**, **заголовок формулирует вывод** (*«SME — 60 % портфеля»*, а не *«Остаток по продуктам»*), **нет легенды для одного ряда**, **единица на оси или в заголовке**, **строка источника**, **никакой второй оси y** (две линии на двух шкалах пересекаются где угодно). Незаконченный период — однодневный октябрь 2026, 0,85 млрд, — убирают из любого временного ряда. Если один столбец подавляет остальные, как 7 429 текущих кредитов, он уходит в подпись оси, а не на логарифмическую шкалу.

**Когда применять.**
- До первой строки кода графика: назовите вопрос, затем выберите строку таблицы.

### seaborn — статистические графики по длинным данным :id=seaborn--statistical-charts-from-long-data

**Что это.** **seaborn** (*seaborn library*) работает поверх matplotlib и рисует целый статистический график одним вызовом из DataFrame. Его главный подарок — **`hue`**: третий столбец становится цветом, по линии или столбцу на значение. `hue` нужны **длинные** данные (*long format*: одна строка на месяц × продукт); `heatmap` нужны **широкие** (*wide format*: матрица, как `pivot` или `crosstab`).

**Как пишется.**

```python
import seaborn as sns
# один стиль для всех графиков после этой строки
sns.set_theme(style="whitegrid")
fig, ax = plt.subplots(figsize=(10, 4))
# ДЛИННЫЕ данные: hue = по линии на продукт
sns.lineplot(data=md, x="month", y="amount", hue="product", ax=ax)
fig, ax = plt.subplots(figsize=(6, 3))
# ИТОГ по продукту
sns.barplot(data=status, x="outstanding", y="product", estimator=sum, errorbar=None, color=GREY, ax=ax)
# ШИРОКИЕ данные: продукты × грейды
ct = pd.crosstab(status["product"], status["grade"])
fig, ax = plt.subplots(figsize=(6, 3))
# по окрашенной подписанной ячейке на пару
sns.heatmap(ct, annot=True, fmt="d", cmap="Reds", ax=ax)
ct
```

### sqlite3 и read_sql — мост :id=sqlite3-and-read_sql--the-bridge

**Что это.** `sqlite3.connect(path)` открывает файл базы данных. **`pd.read_sql(query, con)`** выполняет любой SQL в базе и возвращает результат как DataFrame со столбцами из `SELECT`. Любой запрос недель 1–3 — соединения, CTE, оконные функции — попадает в pandas без перепечатывания. Значения передаются через **`params=`**, по одному `?` на значение.

**Как пишется.**

```python
import sqlite3
# база данных — это файл: ни сервера, ни пароля
con = sqlite3.connect("../raw/nur.db")
q = """SELECT strftime('%Y-%m', disbursed_at) AS month, COUNT(*) AS loans, SUM(principal) AS disbursed
       FROM loans WHERE disbursed_at < ? GROUP BY 1 ORDER BY 1"""
# SQL выполняется в базе; обратно приходит DataFrame
by_month = pd.read_sql(q, con, params=("2026-10-01",))
fwd = pd.read_sql("SELECT COUNT(*) AS n FROM payments WHERE paid_at > ?", con, params=("2026-10-01",))
print(len(by_month), fwd["n"][0])
by_month.tail(3)
```

| вам нужно | вы пишете |
|---|---|
| открыть базу | `con = sqlite3.connect("../raw/nur.db")` |
| запрос → DataFrame | `pd.read_sql(sql, con)` |
| значение из Python в запросе | `?` в SQL + `params=(value,)` — запятая делает кортеж |
| даты как даты | `parse_dates=["disbursed_at"]` |
| DataFrame → таблица | `df.to_sql("name", con, if_exists="replace", index=False)` |
| SQL Server / PostgreSQL | `sqlalchemy.create_engine("mssql+pyodbc://…")`, затем тот же `read_sql` |

**Когда применять.**
- Любое число, которое — один `GROUP BY` или соединение по большим таблицам: пусть его считает база.
- Цепочка CTE недели 3 (винтажи, roll rate): вставьте её в `read_sql` без изменений.

> ⚠️ **Осторожно.** Значения идут в `params=`, никогда — в текст SQL. `f"… WHERE paid_at > '{as_of}'"` работает сегодня и ломается на первом значении с кавычкой — а на настоящем сервере именно так проходит инъекция.

### Когда SQL, когда pandas :id=when-sql-when-pandas

**Что это.** В одном ноутбуке живут оба инструмента. **SQL** агрегирует и соединяет внутри базы, на её зерне. **pandas** придаёт форму, режет, проверяет и рисует то, что вернулось. Разделение — решение, которое вы принимаете на каждом шаге.

        plt.close(fig)
    return sorted(p.name for p in out.glob("*.png"))

### Отчёт как скрипт — на входе дата, на выходе тот же отчёт :id=a-report-as-a-script-one-date-in-the-same-report-out

**Что это.** **Скрипт отчёта** (*report script*) строит весь отчёт из одного **параметра** — даты отчёта — и ничего не требует вводить руками. SQL выполняется через `read_sql` с датой в `params=`, pandas придаёт результату форму, и каждую неделю выполняются те же проверки. На следующей неделе меняется только дата.

**Как пишется.** Отчёт Бекзода: неделя перед понедельником и неделя перед ней.

```python
import sqlite3
import pandas as pd
con = sqlite3.connect("../raw/nur.db")
# кредиты, выданные в [start, stop), по продуктам
DISBURSED = """
SELECT p.name AS product, COUNT(*) AS loans, SUM(l.principal) AS disbursed
FROM loans l JOIN products p ON p.product_id = l.product_id
WHERE l.disbursed_at >= ? AND l.disbursed_at < ?
GROUP BY p.name ORDER BY disbursed DESC"""
# деньги, полученные в [start, stop), без дублей, как в неделе 3
COLLECTED = """
SELECT COUNT(*) AS payments, SUM(amount) AS collected
FROM (SELECT DISTINCT installment_id, paid_at, amount FROM payments)
WHERE paid_at >= ? AND paid_at < ?"""

def totals(con, start, stop):
    """Одна неделя: кредиты и выданные деньги, платежи и полученные деньги."""
    d = pd.read_sql(DISBURSED, con, params=(start, stop))
    c = pd.read_sql(COLLECTED, con, params=(start, stop))
    return {"from": start, "loans": d["loans"].sum(), "disbursed": d["disbursed"].sum(),
            "payments": c["payments"][0], "collected": c["collected"][0]}

def weekly_report(con, report_date):
    """Отчёт Бекзода на понедельник: неделя перед report_date и неделя перед ней."""
    end = pd.Timestamp(report_date)
    # неделя идёт с понедельника по воскресенье, поэтому дата отчёта — понедельник
    assert end.day_name() == "Monday", "report_date must be a Monday"
    mon = str((end - pd.Timedelta(days=7)).date())
    mon_before = str((end - pd.Timedelta(days=14)).date())
    summary = pd.DataFrame([totals(con, mon, report_date), totals(con, mon_before, mon)],
                           index=["this week", "last week"])
    by_product = pd.read_sql(DISBURSED, con, params=(mon, report_date))
    # две таблицы должны сойтись, прежде чем что-то записано
    assert by_product["loans"].sum() == summary.loc["this week", "loans"]
    return summary, by_product

REPORT_DATE = "2026-09-28"
summary, by_product = weekly_report(con, REPORT_DATE)
summary
```

| неделя | from | loans | collected |
|---|---|---|---|
| this week | 2026-09-21 | 81 | 3 683 149 376 |
| last week | 2026-09-14 | 87 | 3 930 504 321 |

Две строки. Неделя 21–27 сентября выдала 3 695 090 000 по 81 кредиту и собрала 3 683 149 376 с 760 платежей; неделя до неё выдала 3 554 960 000 по 87 кредитам и собрала 3 930 504 321 с 751. `by_product` раскладывает 81 кредит: малый бизнес — 8 кредитов на 1 964 920 000, затем авто, потребительские, микро и «Купи сейчас, плати потом». В следующий понедельник те же строки выполняются как `weekly_report(con, "2026-10-05")`; наши учебные данные заканчиваются 1 октября, поэтому на этой странице пробуйте более ранний понедельник.

**Когда применять.**

> ⚠️ **Осторожно.** Дата, вписанная прямо в SQL (`'2026-09-21'`), — второй параметр, который никто не вспомнит поменять. Каждая дата в скрипте берётся из `report_date`; перед тем как отдать файл, найдите в нём `2026`.

### Записываем результат — листы Excel, CSV и PNG :id=writing-it-out-excel-sheets-csv-and-a-png

**Что это.** Отчёт покидает скрипт в виде файлов. **`to_excel`** записывает DataFrame в книгу; **`pd.ExcelWriter`** складывает несколько таблиц в один файл, каждую на свой **лист**. **`to_csv`** пишет простую текстовую таблицу, которую прочитает любой инструмент, а **`savefig`** сохраняет график. В имени каждого файла стоит дата отчёта, поэтому одна неделя никогда не перезаписывает другую.

**Как пишется.** Сначала книга — на ноутбуке:

```python
# (только схема — не для запуска) на ноутбуке: одна книга, по листу на таблицу
with pd.ExcelWriter(out / f"weekly_{REPORT_DATE}.xlsx") as xw:
    summary.to_excel(xw, sheet_name="summary")
    by_product.to_excel(xw, sheet_name="by_product", index=False)
```

### Запуск каждую неделю — Планировщик заданий, cron, Power BI :id=running-it-every-week-task-scheduler-cron-power-bi

**Что это.** **Планировщик** (*scheduler*) запускает программу в заданное время без вас. В Windows это **Планировщик заданий** (*Task Scheduler*); в Linux и на большинстве серверов — **cron**. Скрипт тогда должен пройти от начала до конца, когда за клавиатурой никого нет: взять дату из командной строки (или из календаря), записать файлы и завершиться.

**Как пишется.** Копия на ноутбуке, `weekly_report.py`, заканчивается несколькими строками, которые выполняются, только когда файл запущен как программа:

```python
# (только схема — не для запуска) конец weekly_report.py на ноутбуке
import sys
from datetime import date, timedelta

if __name__ == "__main__":
    # дата из командной строки или понедельник текущей недели
    if len(sys.argv) > 1:
        report_date = sys.argv[1]
    else:
        today = date.today()
        report_date = str(today - timedelta(days=today.weekday()))
    # пути строятся от папки самого скрипта, а не от места запуска
    here = Path(__file__).parent
    con = sqlite3.connect(here.parent / "raw" / "nur.db")
    summary, by_product = weekly_report(con, report_date)
```

Запуск вручную или через cron на сервере:

```bash
# вручную, за один понедельник
python weekly_report.py 2026-09-28
# cron: каждый понедельник в 08:00
# (строку добавляют командой crontab -e)
0 8 * * 1 cd /home/you/report && python weekly_report.py
```

На компьютере с Windows то же делает Планировщик заданий через форму:

1. Пуск → **Планировщик заданий** → **Создать простую задачу** → имя, например *Еженедельный отчёт*.
2. Триггер: **Еженедельно**, понедельник, 08:00.
3. Действие: **Запустить программу**. Программа: полный путь к `python.exe` (в терминале его печатает `where python`). Аргументы: `weekly_report.py`. **Рабочая папка**: папка, где лежит скрипт.
4. Готово. Правый щелчок по задаче → **Выполнить** один раз, и найдите новый файл в `reports/`.

Если отчёт — опубликованная страница Power BI, а не файл, расписание живёт в Power BI Service: **обновление по расписанию** модели заново читает источники (до 8 раз в день на Pro), а базе внутри компании нужен локальный шлюз данных (on-premises data gateway). Шаги — в неделе 7, день 4.

**Когда применять.**
- Планировщик заданий: скрипт работает на вашем компьютере с Windows, и в этот час он должен быть включён.
- cron: сервер, который работает всегда, — обычное место для отчётов команды.
- Обновление по расписанию в Power BI: отчёт — опубликованная страница Power BI, а не файл.

> ⚠️ **Осторожно.** Планировщик запускает скрипт из другой папки, поэтому `"../raw/nur.db"` ведёт в никуда, и запуск падает в 08:00, когда никто не смотрит. Стройте каждый путь от папки самого скрипта (`Path(__file__).parent`) или заполните **Рабочую папку**, а затем один раз запустите задачу вручную.

**Что это.** **Git** (*version control*) хранит историю файлов папки. Папка становится **репозиторием** (*repository*). Ваши файлы живут в **рабочей папке**. `git add` кладёт изменение в **область подготовки** (*staging area*) — список того, что сохранит следующее сохранение. `git commit` сохраняет подготовленные файлы одним **коммитом** (*commit*): версией с id, автором, временем и сообщением. История — это цепочка коммитов.

```text
рабочая папка    ваши файлы на диске
     │ git add
     ▼
подготовка       следующий коммит
     │ git commit
     ▼
история          все сохранённые версии
```

**Как пишется.** В терминале, в папке отчёта:

```bash
# один раз на проект: сделать папку репозиторием
git init
# что изменилось с последнего коммита
git status
# подготовить два файла к следующему коммиту
git add weekly_report.py README.md
# сохранить подготовленные файлы одной версией
git commit -m "Add the weekly report script"
# история, по строке на коммит
git log --oneline
```

До `git add` команда `git status` показывает два файла как *untracked* (не отслеживаются); после — под *Changes to be committed*; после коммита она говорит *nothing to commit, working tree clean*, а `git log --oneline` показывает одну строку: короткий id и сообщение. GitHub Desktop ([Tools at work](tools-at-work.md)) делает то же кнопками: галочка у файла — это `git add`, **Commit to main** — `git commit`.

**Когда применять.**
- Любой файл, который вы ещё будете менять: SQL, ноутбуки, скрипты, словарь данных.
- Перед рискованным изменением: сначала коммит, чтобы было к чему вернуться.

> ⚠️ **Осторожно.** Коммит сохраняет только подготовленное. Измените файл и закоммитьте без `git add` — Git ответит *no changes added to commit*, а правка останется только в папке. Перед каждым коммитом запускайте `git status`, чтобы видеть, что в него войдёт.

### Ветки и слияние — пробуем изменение, не ломая main :id=branches-and-merge-try-a-change-without-breaking-main

**Что это.** **Ветка** (*branch*) — именованная линия коммитов. В `main` лежит версия, которая работает каждый понедельник. Новая ветка, например `fix-dates`, принимает ваши коммиты, не трогая `main`. **`git switch`** переключает между ветками, а **`git merge`** приносит коммиты ветки в ту, на которой вы стоите, — когда они работают.

**Как пишется.**

```bash
# новая ветка отсюда, и переход на неё
git switch -c fix-dates
# меняем скрипт и сохраняем его на ветке
git add weekly_report.py
git commit -m "Start the week on Monday"
# назад на main, и вливаем ветку
git switch main
git merge fix-dates
# слито: имя ветки больше не нужно
git branch -d fix-dates
```

```text
main       o───o───────────o слияние
                \         /
fix-dates        o───────o
```

`git switch -c fix-dates` — это `git branch fix-dates` и `git switch fix-dates` за один шаг. Если на `main` не было новых коммитов, пока вы работали, слияние будет **перемоткой** (*fast-forward*): `main` просто сдвигается к последнему коммиту ветки. Если двигались обе ветки, Git делает **коммит слияния** с двумя родителями, как на рисунке.

**Когда применять.**
- Изменение, в котором вы не уверены, пока `main` должен работать каждый понедельник.
- Двое работают одновременно: каждый на своей ветке, ветки сливают по очереди.

> ⚠️ **Осторожно.** Если обе ветки изменили одни и те же строки файла, слияние останавливается с **конфликтом**. Git помечает в файле обе версии (`<<<<<<<`, `=======`, `>>>>>>>`) и ждёт, пока вы оставите нужные строки, сделаете `git add` файла и `git commit`. Маленькие ветки, слитые вовремя, конфликтуют редко.

### GitHub, push и pull — и что туда никогда не попадает :id=github-push-and-pull-and-what-never-goes-in

**Что это.** **GitHub** хранит копию репозитория в интернете — её называют **удалённым репозиторием** (*remote*, `origin`). **`git push`** отправляет туда ваши новые коммиты; **`git pull`** приносит в вашу папку коммиты, которые отправили другие. Файл **`.gitignore`** перечисляет, что Git никогда не должен отслеживать: данные, результаты и пароли.

**Как пишется.**

```bash
# один раз: связать папку с пустым репозиторием на GitHub
git remote add origin https://github.com/you/report.git
git push -u origin main
# каждый день: сначала чужие коммиты, потом свои
git pull
git push
```

```text
# .gitignore: никогда в репозитории
*.db
*.xlsx
*.csv
reports/
.env
```

С таким `.gitignore` команда `git status` перестаёт показывать `nur.db` (9 МБ данных о клиентах) и еженедельные книги. В репозитории лежит код, который их делает, поэтому любой, у кого есть данные, может запустить его снова. Пароли лежат в `.env`: скрипт их читает, а Git не видит. Учебный репозиторий хранит свои данные в Git намеренно — Nur Finance выдумана; на работе данные остаются снаружи.

**Когда применять.**
- `git push`: в конце куска работы, чтобы она была в безопасности не только на ноутбуке и её видели другие.
- `git pull`: перед началом, чтобы работать с последней версией.
- `.gitignore`: в первый же день, до первого `git add`.

> ⚠️ **Осторожно.** Пароль, хоть раз попавший в коммит, остаётся в истории, даже если следующий коммит удалил файл: любой, у кого есть репозиторий, прочитает старую версию. Сразу смените пароль и с первого дня держите секреты в `.env`.
