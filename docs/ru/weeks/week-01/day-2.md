## 1. Теория — задаём таблице вопрос :id=1-learn-asking-a-table-a-question

### Устройство запроса :id=the-shape-of-a-query

**Что это.** **Запрос** (*query*) — вопрос к базе, записанный на SQL. У каждого запроса этой недели один и тот же скелет из **предложений** (*clauses*): `SELECT` называет столбцы, `FROM` — таблицу, `WHERE` — строки, `ORDER BY` — порядок, `LIMIT` — сколько строк. Обязательны только `SELECT` и `FROM`.

**Как пишется.**

```sql
-- только схема: замените имена, прежде чем выполнять
SELECT   column1, column2        -- какие столбцы (или * — все)
FROM     table_name              -- из какой таблицы
WHERE    condition               -- какие строки (необязательно)
ORDER BY column1 DESC            -- в каком порядке (необязательно)
LIMIT    5;                      -- не больше скольких строк (необязательно; SQL Server: SELECT TOP 5 …)
```

Настоящий запрос со всеми предложениями — пять самых крупных кредитов в дефолте:

```sql
SELECT loan_id, principal, status
FROM loans
WHERE status = 'default'
ORDER BY principal DESC
LIMIT 5;
```

5 строк, сначала крупные: сверху кредит 370 на 589 000 000. Читайте его как одно предложение: *«из `loans` оставь кредиты в дефолте, покажи три столбца, сначала самый большой основной долг, остановись после пяти»*.

**Когда применять.**
- Всегда: предложения идут именно в таком порядке, иначе база остановится с синтаксической ошибкой.
- База **выполняет** их в другом порядке: FROM → WHERE → SELECT → ORDER BY → LIMIT. Она берёт таблицу, оставляет строки, прошедшие фильтр, вырезает ваши столбцы, сортирует и останавливается. Поэтому в `WHERE` можно использовать столбец, которого нет в выводе.

### Псевдонимы — AS переименовывает столбец в результате :id=aliases-as-renames-a-column-in-the-result

**Что это.** **Псевдоним** (*alias*) — новое имя столбца в результате. Его пишут после столбца через `AS`. Сама таблица не меняется.

**Как пишется.**

```sql
SELECT loan_id      AS loan,          -- столбец AS новое_имя
```

> ⚠️ **Осторожно.** Псевдониму с пробелом нужны двойные кавычки: `AS "amount UZS"`. Проще писать `_` вместо пробела.

### DISTINCT — одна строка на каждое значение :id=distinct-one-row-per-different-value

**Что это.** **DISTINCT** убирает из результата повторяющиеся строки. Его пишут сразу после `SELECT`. Он оставляет одну строку на каждое различное сочетание выбранных столбцов.

**Как пишется.**

```sql
SELECT DISTINCT channel FROM applications;
```

**Когда применять.**
- Чтобы узнать, что лежит в столбце, прежде чем по нему фильтровать, — самый быстрый взгляд.
- Чтобы перечислить в отчёте различные значения: регионы, продукты, статусы.

### LIMIT и TOP — только первые N строк :id=limit-and-top-only-the-first-n-rows

**Что это.** **LIMIT** возвращает не больше N строк. Его пишут в самом конце запроса. SQL Server пишет то же самое как **TOP N** сразу после `SELECT`. Это единственное место на этой неделе, где две СУБД пишут запрос по-разному.

**Как пишется.**

```sql
-- SQL Server
SELECT TOP 3 application_id, requested_amount FROM applications ORDER BY requested_amount DESC;
-- SQLite / PostgreSQL / MySQL
SELECT application_id, requested_amount FROM applications ORDER BY requested_amount DESC LIMIT 3;
```

3 строки: заявка 5074 просила 599 060 000 — больше всех из 14 000. (Блок выполняет обе строки: `TOP` он сам превращает в `LIMIT` и показывает последний результат.)

**Когда применять.** «Пять самых крупных», «десять самых новых», «первая строка» — всегда вместе с `ORDER BY`.

> ⚠️ **Осторожно.** `LIMIT` без `ORDER BY` возвращает *какие-то* N строк, а не самые крупные и не самые новые. Сначала сортируйте, потом отрезайте.

### BETWEEN — диапазон, оба края включены :id=between-a-range-with-both-ends-included

**Что это.** **BETWEEN a AND b** оставляет значения от `a` до `b`, **оба края включены**. Это короткая запись `>= a AND <= b`.

**Как пишется.**

```sql
SELECT COUNT(*) FROM loans WHERE term_months BETWEEN 12 AND 24;   -- то же, что term_months >= 12 AND term_months <= 24
```

2 940 кредитов выданы на срок от 12 до 24 месяцев — включая кредиты ровно на 12 и ровно на 24 месяца.

**Когда применять.** Диапазоны чисел («от 1 до 5 миллионов») и простых дат («первая неделя сентября»).

> ⚠️ **Осторожно.** На столбце, где лежит дата **и время**, `BETWEEN '…-01' AND '…-31'` теряет всё, что было после полуночи последнего дня. См. подраздел *Текст, числа и даты* ниже.

### LIKE — текстовый шаблон :id=like-a-text-pattern

**Что это.** **LIKE** оставляет текстовые значения, которые подходят под **шаблон**. В шаблоне `%` означает любое число символов (в том числе ни одного), а `_` — ровно один символ.

**Как пишется.**

```sql
SELECT name FROM products WHERE name LIKE '%loan';   -- что угодно, а в конце «loan»
```

**Когда применять.** «Начинается с», «кончается на», «содержит»: `LIKE 'M%'`, `LIKE '%ova'`, `LIKE '%loan%'`.

### IS NULL — пустая ячейка :id=is-null-the-empty-cell

**Что это.** **NULL** (*пустое значение*) значит «здесь нет значения — неизвестно». Это не ноль и не пустой текст. `IS NULL` находит пустые ячейки, `IS NOT NULL` — заполненные.

**Как пишется.**

```sql
SELECT COUNT(*) FROM applications WHERE credit_score IS NULL;       -- 388
SELECT COUNT(*) FROM applications WHERE credit_score IS NOT NULL;   -- 13 612
```

### AND, OR, NOT — соединяем условия, со скобками :id=and-or-not-combining-conditions-with-brackets

**Что это.** **AND** оставляет строку, когда истинны **оба** условия. **OR** — когда истинно **хотя бы одно**. **NOT** переворачивает условие: `NOT IN`, `NOT LIKE`, `IS NOT NULL`, `NOT (…)`. **AND связывает сильнее, чем OR** — как умножение раньше сложения.

**Как пишется.** SME-заявки, которым мы сказали «да»:

```sql
SELECT COUNT(*) FROM applications
WHERE product_id = 5 AND (status = 'approved' OR status = 'approved_not_disbursed');
```

854 заявки. Теперь те же слова без скобок:

```sql
SELECT COUNT(*) FROM applications
WHERE product_id = 5 AND status = 'approved' OR status = 'approved_not_disbursed';
```

1 469. База прочитала это как `(product_id = 5 AND status = 'approved') OR status = 'approved_not_disbursed'`, и внутрь попали одобренные, но не выданные заявки **любого** продукта. Ошибки нет, число неверное.

```sql
SELECT COUNT(*) FROM loans WHERE status NOT IN ('closed', 'written_off');
```

3 396 кредитов не закрыты и не списаны: 3 352 активных + 44 в дефолте.

**Когда применять.** В каждом фильтре, где больше одного условия.

| Вы имеете в виду | Пишите |
|---|---|
| должны выполняться оба | `a AND b` |
| достаточно одного | `a OR b` |
| одно условие И выбор из двух | `a AND (b OR c)` — скобки, всегда |
| ни одно из списка | `col NOT IN (…)` |

> ⚠️ **Осторожно.** Когда в одном `WHERE` встречаются `AND` и `OR`, ставьте скобки. Неверная группировка — не ошибка, а другой вопрос, который прекрасно выполняется.

### Текст, числа и даты в условиях :id=text-numbers-and-dates-in-conditions

**Что это.** Значение в условии пишется по своему типу. У каждого типа одно правило и одна ловушка.

| Тип | Как писать значение | Ловушка |
|---|---|---|
| **текст** | в одинарных кавычках, точно как в базе: `'active'` | в SQLite `=` различает регистр: `status = 'Active'` находит 0 строк |
| **число** | без кавычек и без пробелов: `200000000` | `200 000 000` — синтаксическая ошибка |
| **дата** | текст `'YYYY-MM-DD'` в кавычках: `'2026-09-01'` | столбец, где есть ещё и **время** (`applied_at`), не равен простой дате |

**Как пишется.** В `applied_at` лежат дата и время, например `2025-06-02 10:35:00`:

```sql
SELECT COUNT(*) FROM applications WHERE applied_at = '2025-06-02';                               -- 0: ни одной строки ровно в полночь
SELECT COUNT(*) FROM applications WHERE applied_at >= '2025-06-02' AND applied_at < '2025-06-03'; -- весь день
```

2 июня 2025 года подано 14 заявок. Первая строка находит 0, потому что `'2025-06-02 10:35:00'` не равно `'2025-06-02'`.

**Когда применять.** Для периода пишите **полуоткрытый диапазон**: `>= первый день AND < первый день следующего периода`. Он работает на датах со временем и без, в любой СУБД. Для года: `applied_at >= '2025-01-01' AND applied_at < '2026-01-01'`.

> ⚠️ **Осторожно.** `= NULL`, `'Active'` вместо `'active'` и `BETWEEN` на столбце с датой и временем выполняются без ошибки и дают неверное число. Привыкайте к `IS NULL`, точному написанию и полуоткрытым диапазонам.

### Собираем вместе :id=putting-it-together

## 6. Уголок компании <span class="badge company">Доля одобрений</span> :id=6-company-corner-approval-rate

**Определение.** Доля одобрений (approval rate) — это доля кредитных заявок, на которые компания ответила *«да»*:

> **доля одобрений = одобренные заявки ÷ заявки, по которым принято решение**

Это первое число, на которое смотрит риск-менеджер после изменения правил скоринга, и первое число, на которое жалуется менеджер по продажам. Два запроса и деление вручную (на следующей неделе `GROUP BY` и `CASE` будут делить за вас):

```sql
SELECT COUNT(*) FROM applications;                                                    -- ожидайте 14000
SELECT COUNT(*) FROM applications WHERE status IN ('approved', 'approved_not_disbursed'); -- ожидайте 8595
```

8 595 / 14 000 = **61.4 %**. `approved_not_disbursed` считается одобренной: компания *сказала «да»*; клиент ушёл. Одобрение — это про наше решение, а не про решение клиента.

**Ловушка — отменённые заявки.** Выполните ещё один запрос:

```sql
SELECT COUNT(*) FROM applications WHERE status = 'cancelled';   -- ожидайте 1817
```
