## 2. Теория — данные в виде таблиц :id=2-learn-data-as-tables

### Зачем нужны таблицы? :id=why-tables

Компания не хранит «клиента Азиза». Она хранит факты в **таблицах**: таблица — это сетка, в которой каждая **строка** — это одна сущность (один клиент, один кредит, один платёж), а каждый **столбец** — один признак этой сущности (имя, сумма, дата). Такая база называется **реляционной**, а язык, на котором ей задают вопросы, — **SQL**.

Представьте Excel: лист — это таблица, но с тремя правилами, которые Excel не навязывает:

1. У каждого столбца **один тип** (в столбце с датами лежат только даты).
2. У каждой строки есть уникальный **идентификатор** — **первичный ключ** (PK).
3. Строки одной таблицы указывают на строки другой, храня их идентификатор, — это **внешний ключ** (FK).

> 💡 **Главное.** Одна таблица хранит один вид объектов, а одна строка — один такой объект. **Первичный ключ** называет ровно одну строку; **внешний ключ** — это столбец, который хранит первичный ключ другой таблицы: так таблицы указывают друг на друга.

### Как читать связь :id=reading-a-relationship

> «`loans.customer_id` — внешний ключ на `customers.customer_id`»

означает: в таблице `loans` столбец `customer_id` хранит число, и это число — идентификатор строки в `customers`. У одного клиента может быть много кредитов; один кредит принадлежит ровно одному клиенту. Это связь **«один ко многим»**. Записывается так: `customers 1 — ∞ loans`.

> 💡 **Главное.** Сторона «многие» хранит ключ стороны «один»: каждый кредит хранит свой `customer_id`, а клиент не хранит списка идентификаторов кредитов. Чтобы понять направление связи, спросите себя: «может ли у одного такого быть много тех?»

Теперь всю базу можно прочитать как предложения:

- **Клиент** подаёт много **заявок**; каждая заявка — на один **продукт**, обрабатывается в одном **филиале** одним **сотрудником** (staff).
- Одобренная заявка превращается не более чем в один **кредит**.
- У кредита много **плановых платежей** (его график) и приходит много **платежей**.
- По просроченному кредиту проводится много **действий по взысканию**.

## 3. Разобранный пример — читаем строку как аналитик :id=3-worked-example-reading-a-row-like-an-analyst

Мадина спрашивает: *«Кредит 1 — расскажите его историю одним предложением.»* Писать SQL пока не нужно: на каждом шаге ниже есть готовый запрос. Нажмите **▶ Выполнить**, прочитайте строку и идите по ключам от таблицы к таблице.

1. `loans`, строка с `loan_id = 1`: запишите `customer_id`, `product_id`, `principal`, `term_months`, `disbursed_at`, `status`.

```sql
SELECT * FROM loans WHERE loan_id = 1;
```

2. `customers`, строка с этим `customer_id` (3473 — число, которое вы только что прочитали): имя, регион, сегмент.

```sql
SELECT * FROM customers WHERE customer_id = 3473;
```

3. `products`, строка с этим `product_id`: название продукта.

```sql
SELECT * FROM products WHERE product_id = 2;
```

4. `installments`, строки с `loan_id = 1`: сколько их? Какая первая `due_date`?

```sql
SELECT * FROM installments WHERE loan_id = 1;
```

5. `payments`, строки с `loan_id = 1`: сколько их и был ли хоть один платёж позже срока?

```sql
SELECT * FROM payments WHERE loan_id = 1;
```

Шаблон предложения: *«[Имя] из [регион] взял(а) [продукт] на [сумма] на [срок] мес. [дата]; оплачено [n] из [срок] платежей по графику, кредит имеет статус [status].»* Настоящее предложение вы напишете в сегодняшнем домашнем задании.

Эта цепочка — таблица фактов → ключ → справочник → ключ → следующая таблица фактов — составляет 80 % того, что SQL делает за вас. Завтра вы будете писать такие запросы сами; на следующей неделе один запрос пройдёт всю цепочку целиком.

**Жизненный цикл кредита.** Любая кредитная компания, от банка до BNPL-приложения, проводит деньги через одни и те же семь шагов. Выучите их по порядку; каждому соответствует таблица.

| Шаг | Что происходит | Таблица | Метрика, о которой спрашивают |
|---|---|---|---|
| 1. Заявка | клиент просит деньги | `applications` | заявок в день, по каналам |
| 2. Решение | скоринг и правила говорят «да»/«нет» | `applications.status`, `credit_score` | **доля одобрений** |
| 3. Выдача | деньги уходят с нашего счёта | `loans.disbursed_at`, `principal` | **выдачи** (сумма за месяц) |

| 7. Списание / возврат | мы ставим на кредите крест или получаем часть денег обратно | `loans.status` | **NPL**, доля списаний, возвраты |
