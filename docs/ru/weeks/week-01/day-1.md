## 2. Теория — данные в виде таблиц :id=2-learn-data-as-tables

### Таблица, строка, столбец — три слова :id=table-row-column-the-three-words

**Что это.** **Таблица** (*table*) — это список однотипных объектов: все клиенты или все кредиты. **Строка** (*row*) — один объект из этого списка: один клиент. **Столбец** (*column*) — одно свойство, которое есть у каждой строки: дата рождения, регион. База из таких таблиц называется **реляционной**. **SQL** — язык, на котором ей задают вопросы.

**Как пишется.** Сегодня вы читаете таблицы; создавать их вы начнёте в День 3. Три строки и пять из одиннадцати столбцов `customers`:

### Типы данных — один вид значений в столбце :id=data-types-one-kind-of-value-per-column

**Что это.** У каждого столбца есть **тип данных** (*data type*): вид значений, которые в нём могут лежать. В числовом столбце — только числа. В столбце с датами — только даты. Для этого курса хватит четырёх типов.

| Тип | Что хранит | Столбцы Nur Finance |
|---|---|---|
| **целое число** — `INTEGER` (`INT`, `BIGINT` в SQL Server) | идентификаторы, количества, деньги в сумах | `loan_id`, `principal`, `term_months` |
| **дробное число** — `REAL` (`DECIMAL` в SQL Server) | ставки и доли | `annual_rate` (0.3 = 30 % годовых) |
| **текст** — `TEXT` (`NVARCHAR` в SQL Server) | имена, коды, статусы | `status`, `region`, `phone` |
| **дата** — здесь хранится как текст `'YYYY-MM-DD'` (`DATE` в SQL Server) | дни и моменты времени | `disbursed_at`, `applied_at` |

**Как пишется.** Панель **«База данных»** показывает тип каждого столбца справа от его имени. Можно спросить и саму базу:

```sql
SELECT loan_id, principal, annual_rate, disbursed_at,
       -- typeof() = «какого типа это значение?» в SQLite
       typeof(principal), typeof(annual_rate), typeof(disbursed_at)
FROM loans
LIMIT 3;
```

Кредит 1: основной долг 31 150 000 — `integer`, ставка 0.3 — `real`, дата `2025-03-28` — `text`. SQLite хранит даты как текст в порядке год-месяц-день. В таком порядке текст сортируется и сравнивается как дата.

**Когда применять.**
- Тип решает, что можно делать со столбцом: складывать числа, сравнивать даты, искать внутри текста.
- В День 3 вы выберете тип для каждого столбца таблицы, которую создадите сами.

> ⚠️ **Осторожно.** Номер телефона — это **текст**, а не число, хотя он состоит из цифр. Телефоны никогда не складывают, а `+` в начале должен сохраниться.

### «Один ко многим» — ключ хранит сторона «многие» :id=one-to-many-the-many-side-carries-the-key

**Что это.** Связь **«один ко многим»** (*one-to-many*) соединяет одну строку с одной стороны со многими строками с другой. У одного клиента может быть много кредитов; один кредит принадлежит ровно одному клиенту. Записывается так: `customers 1 — ∞ loans`. Внешний ключ всегда стоит на стороне **«многие»**: каждый кредит хранит свой `customer_id`, а клиент не хранит списка кредитов.


4 строки — у Гульбахор Собировой четыре кредита: один активный, два закрытых, один списанный. Все четыре указывают на одного и того же клиента.

**Когда применять.** Связи бывают трёх видов, и в Nur Finance есть все три.

| Вид | Запись | Пример в Nur Finance |
|---|---|---|
| **«один ко многим»** | `1 — ∞` | `customers 1 — ∞ loans`, `loans 1 — ∞ installments` |
| **«один к одному»** (здесь: «один к нулю или одному») | `1 — 0..1` | `applications 1 — 0..1 loans`: из заявки получается не больше одного кредита, из отклонённой — ни одного |
| **«многие ко многим»** | `∞ — ∞`, через третью таблицу | клиенты и продукты: клиент может взять много продуктов, у продукта много клиентов; каждая строка `loans` записывает одну такую пару |

Чтобы понять направление, спросите: **«может ли у одного такого быть много тех?»**

### Как читать связь предложением :id=reading-a-relationship-as-a-sentence

**Что это.** Каждый внешний ключ — это одно предложение о бизнесе. Ключ `дочерняя.fk → родительская.pk` читается так: **«каждая дочерняя строка принадлежит одной родительской; у родительской может быть много дочерних»**.

**Как пишется.**

| Внешний ключ | Читается как |
|---|---|
| `loans.customer_id → customers.customer_id` | Каждый кредит принадлежит одному клиенту; у клиента может быть много кредитов. |
| `installments.loan_id → loans.loan_id` | Каждый плановый платёж принадлежит одному кредиту; у кредита много плановых платежей (его график). |
| `payments.installment_id → installments.installment_id` | Каждый платёж внесён за один плановый платёж; за один плановый платёж может прийти несколько платежей (часть сейчас, остаток потом). |
| `applications.officer_id → staff.staff_id` | Каждую заявку ведёт один сотрудник; один сотрудник ведёт много заявок. |

Вся база, прочитанная предложениями:

- **Клиент** подаёт много **заявок**. Каждая заявка — на один **продукт**, в одном **филиале**, её ведёт один **сотрудник** (staff).
- Одобренная заявка превращается не более чем в один **кредит**.
- У кредита много **плановых платежей** (график), и по нему приходит много **платежей**.
- По просроченному кредиту проводится много **действий по взысканию**, каждое — одним взыскателем (staff).

**Когда применять.** Перед любым вопросом, который затрагивает две таблицы, произнесите предложение вслух. Если оно звучит неверно — неверен ключ.

### Одиннадцать таблиц — «кто/что» и «что произошло» :id=the-eleven-tables-whowhat-and-what-happened

**Что это.** Nur Finance хранит данные в одиннадцати таблицах двух видов:

- **Таблицы «кто/что»** описывают объекты: клиента, продукт, филиал, сотрудника, календарный день. Они короткие и меняются редко.

Почти в любой компании данные устроены так. В День 4 вы узнаете, как это называется в хранилище: *измерения и факты*.

### Жизненный цикл кредита в таблицах :id=the-loan-lifecycle-in-the-tables

**Что это.** **Жизненный цикл кредита** (*loan lifecycle*) — путь одного кредита от первой заявки до последнего платежа. Каждый шаг оставляет строки в таблице «что произошло».

**Как пишется.** Путь в виде схемы:

```text
customers           кто
   │
   ▼
applications        заявка
   │
   │ approved
   ▼
loans               выдан
   ├──▶ installments
   │      график: что положено платить
   ├──▶ payments
   │      что пришло
   └──▶ collections_actions
          если платёж просрочен
```

- `applications.status`: approved · approved_not_disbursed · rejected · cancelled
- `loans.status`: active · closed · default · written_off

Кредит 1 начался с заявки 2. Первый шаг его жизненного цикла:

```sql
SELECT application_id, customer_id, applied_at, status FROM applications WHERE application_id = 2;
```

1 строка: клиент 3473 подал заявку 2025-03-23 в 17:00, статус `approved`. Через пять дней, 2025-03-28, кредит 1 был выдан. Разобранный пример ниже проходит с ним следующие шаги.

**Когда применять.** Любой вопрос о кредитовании стоит на одном шаге пути:
- «Сколько человек подали заявку?» → `applications`.
- «Сколько мы выдали?» → `loans`.
- «Кто просрочил?» → `installments` и `payments`.

Уголок компании добавляет метрику, за которой следят на каждом шаге.

## 3. Разобранный пример — читаем строку как аналитик :id=3-worked-example-reading-a-row-like-an-analyst

Мадина спрашивает: *«Кредит 1 — расскажите его историю одним предложением.»* Писать SQL пока не нужно: на каждом шаге есть готовый запрос. Нажмите **▶ Выполнить**, прочитайте строку и идите по ключам от таблицы к таблице. Каждый шаг называет идею из теории, которую он использует.

**Шаг 1 — строка по первичному ключу.** В `loans` — строка с `loan_id = 1`. Запишите `customer_id`, `product_id`, `principal`, `term_months`, `disbursed_at`, `status`.

```sql
SELECT * FROM loans WHERE loan_id = 1;
```

**Шаг 2 — идём по внешнему ключу.** `customer_id` равен 3473. В `customers` строка 3473 даёт имя, регион и сегмент.

```sql
SELECT * FROM customers WHERE customer_id = 3473;
```

**Шаг 3 — второй внешний ключ.** `product_id` равен 2. В `products` строка 2 даёт название продукта.

```sql
SELECT * FROM products WHERE product_id = 2;
```

**Шаг 4 — «один ко многим»: график.** В `installments` — все строки с `loan_id = 1`. Сколько их? Какая первая `due_date`?

```sql
SELECT * FROM installments WHERE loan_id = 1;
```

**Шаг 5 — снова «один ко многим», на шаге жизненного цикла «погашение».** В `payments` — все строки с `loan_id = 1`. Сколько их? Был ли хоть один платёж позже срока?

```sql
SELECT * FROM payments WHERE loan_id = 1;
```

Шаблон предложения: *«[Имя] из [регион] взял(а) [продукт] на [сумма] на [срок] мес. [дата]; оплачено [n] из [срок] платежей по графику, кредит имеет статус [status].»* Настоящее предложение вы напишете в сегодняшнем домашнем задании.

Эта цепочка — строка «что произошло» → ключ → строка «кто/что» → по ключу обратно к следующей таблице «что произошло» — составляет 80 % того, что SQL делает за вас. Завтра вы будете писать такие запросы сами; на следующей неделе один запрос пройдёт всю цепочку целиком.

| Шаг | Что происходит | Таблица | Метрика, о которой спрашивают |
|---|---|---|---|
