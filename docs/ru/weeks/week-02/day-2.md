## 1. Теория — агрегация: много строк в одно число :id=1-learn-aggregation-many-rows-into-one-number

### COUNT — строки, значения и разные значения :id=count-rows-values-and-different-values

**Что это.** **Агрегатная функция** (*aggregate function*) берёт много строк и возвращает одно значение. **COUNT** считает — в трёх формах, которые отвечают на три разных вопроса:

- `COUNT(*)` считает **строки**.
- `COUNT(столбец)` считает строки, где этот столбец **не NULL**.
- `COUNT(DISTINCT столбец)` считает **разные** значения, кроме NULL.

**Как пишется.** На крошечной таблице из четырёх платежей:

| `pay` | loan_id | method |
|---|---|---|
| | 1 | card |
| | 1 | cash |
| | 2 | card |
| | 3 | NULL |

```sql
WITH pay(loan_id, method) AS (VALUES (1, 'card'), (1, 'cash'), (2, 'card'), (3, NULL))
SELECT COUNT(*)               AS rows_,         -- 4: каждая строка
       COUNT(method)          AS with_method,   -- 3: NULL пропущен
       COUNT(DISTINCT method) AS methods        -- 2: card и cash
FROM pay;
```

На настоящих данных:

```sql
SELECT COUNT(*)                    AS loans,            -- 7 828
       COUNT(closed_at)            AS with_close_date,  -- 4 227
       COUNT(DISTINCT customer_id) AS borrowers         -- 4 335
FROM loans;
```

7 828 кредитов; у 4 227 из них есть дата закрытия; они принадлежат 4 335 разным людям, значит, у многих клиентов больше одного кредита.

**Когда применять.**

| Вопрос | Пишем |
|---|---|
| Сколько кредитов? | `COUNT(*)` |
| У скольких кредитов есть дата закрытия? | `COUNT(closed_at)` |
| Сколько разных людей брали кредит? | `COUNT(DISTINCT customer_id)` |

> ⚠️ **Осторожно.** «Сколько клиентов?», посчитанное через `COUNT(*)` по `loans`, считает кредиты, а не людей: 7 828 вместо 4 335. Считайте столбец, который называет то, что вы имеете в виду.

### SUM — сложить столбец :id=sum-add-a-column-up

**Что это.** **SUM** складывает значения числового столбца по строкам, которые остались после `WHERE`. Значения NULL пропускаются.

**Как пишется.**

```sql
SELECT SUM(principal) AS disbursed            -- 404 783 280 000
FROM loans;

SELECT SUM(principal) AS active_disbursed     -- 296 980 040 000
FROM loans
WHERE status = 'active';                      -- сначала WHERE, потом сумма по оставшимся строкам
```

Всего выдано 404.8 млрд сумов; 297.0 млрд из них — по кредитам, которые ещё активны.

**Когда применять.** «Сколько денег»: выдано, получено, просрочено. Для «сколько штук» используйте `COUNT`.

> ⚠️ **Осторожно.** `SUM` по пустому набору строк возвращает NULL, а не 0: `SELECT SUM(principal) FROM loans WHERE status = 'frozen'` даёт NULL. `COALESCE` из Дня 4 превращает его в 0.

### AVG — среднее и ловушка целых чисел :id=avg-the-average-and-the-whole-number-trap

**Что это.** **AVG** — сумма значений, кроме NULL, делённая на их количество. Результат — одно число на все строки (или одно на группу — дальше).

**Как пишется.**

```sql
SELECT AVG(principal)                   AS avg_ticket,    -- 51 709 667.86
       SUM(principal) / COUNT(*)        AS int_division,  -- 51 709 667: целое ÷ целое
       1.0 * SUM(principal) / COUNT(*)  AS by_hand        -- 51 709 667.86
FROM loans;
-- SQL Server: AVG по целочисленному столбцу тоже даёт целое — пишите AVG(1.0 * principal)
```

Средний кредит — 51.7 млн сумов. При делении вручную два целых числа теряют .86: дробная часть отбрасывается, а не округляется.

**Когда применять.** Средний чек, средний срок, среднее число дней просрочки. Ставьте рядом со средним количество: среднее по 3 кредитам и по 3 000 выглядят на слайде одинаково.

> ⚠️ **Осторожно.** Целое ÷ целое = целое. `SUM(term_months) / COUNT(*)` возвращает 11; настоящий средний срок — 11.78 месяца. Ставьте `1.0 *` в начало или используйте `AVG`. К делению вернёмся в День 3.

### MIN и MAX — наименьшее и наибольшее :id=min-and-max-the-smallest-and-the-largest

**Что это.** **MIN** и **MAX** возвращают наименьшее и наибольшее значение столбца. Они работают с числами, датами и текстом.

**Как пишется.**

```sql
SELECT MIN(principal)    AS smallest,      -- 300 000
       MAX(principal)    AS largest,       -- 599 060 000
       MIN(disbursed_at) AS first_loan,    -- 2024-01-02
       MAX(disbursed_at) AS last_loan      -- 2026-10-01
FROM loans;
```

Кредиты — от 300 000 до 599 060 000 сумов. Первый выдан 2 января 2024 года, последний — в отчётную дату, 1 октября 2026 года.

**Когда применять.** Диапазон столбца — первая проверка любой новой таблицы. Первая и последняя дата периода. Самый старый неоплаченный платёж (DPD в среду использует `MIN(due_date)`). Даты, хранящиеся текстом `'YYYY-MM-DD'`, работают, потому что такой текст сортируется как дата.

> ⚠️ **Осторожно.** В тексте заглавные буквы идут раньше строчных. `MAX(last_name)` по `customers` — это `'yusupov'`: фамилия, набранная со строчной буквы, а не последняя по алфавиту.

### GROUP BY по одному столбцу — одна строка на группу :id=group-by-one-column-one-row-per-group

**Что это.** **GROUP BY** (*группировка*) делит строки на группы с одинаковым значением. Каждый агрегат затем считается один раз на группу, и в результате одна строка на группу.

```sql

FROM loans
GROUP BY risk_grade;              -- A 1 821 · B 3 404 · C 2 264 · D 339
```

Четыре строки, по одной на грейд. В сумме 7 828 — проверяйте эту сумму у каждого сгруппированного результата.

**Когда применять.** «На X», «по X», «для каждого X»: кредиты по грейдам, платежи по способам, действия по сотрудникам.

### GROUP BY по двум столбцам — одна строка на сочетание :id=group-by-two-columns-one-row-per-combination

**Что это.** Когда в `GROUP BY` два столбца, группа — это **сочетание** значений. В результате одна строка на каждое сочетание, которое встречается в данных.

**Как пишется.**

```sql
SELECT status, risk_grade, COUNT(*) AS loans
FROM loans
GROUP BY status, risk_grade
ORDER BY status, risk_grade;          -- 16 строк: 4 статуса × 4 грейда
```

| status | risk_grade | loans |
|---|---|---|
| active | A | 750 |
| active | B | 1 445 |
| … | | |
| written_off | C | 98 |
| written_off | D | 30 |

16 строк, потому что каждый статус встречается с каждым грейдом. Списанные кредиты: 13 в грейде A, 98 в грейде C — грейд предсказывает убыток.

Сочетание, которого нет в данных, **не получает строки** — а не строку с 0. Когда нужны нули, постройте полную сетку через `CROSS JOIN` из Дня 1.

Группой может быть и **выражение**. Месяц даты — тема среды; он нужен вам уже сегодня, так что скопируйте как есть:

```sql
-- SQL Server:  FORMAT(l.disbursed_at, 'yyyy-MM')      SQLite:  strftime('%Y-%m', l.disbursed_at)
SELECT strftime('%Y-%m', l.disbursed_at) AS month, p.name, COUNT(*) AS loans, SUM(l.principal) AS disbursed
FROM loans l JOIN products p ON p.product_id = l.product_id
WHERE l.disbursed_at >= '2026-01-01'
GROUP BY strftime('%Y-%m', l.disbursed_at), p.name
ORDER BY month, disbursed DESC;       -- 50 строк: 10 месяцев × 5 продуктов
```

`GROUP BY` повторяет выражение: SQL Server не принимает там псевдоним `month` (SQLite принимает оба варианта).

**Когда применять.** «По X и Y»: по месяцам и продуктам, по регионам и сегментам. Результат получается **длинным**: одна строка на ячейку таблицы, которую вы покажете.

### WHERE vs HAVING — фильтр строк или фильтр групп :id=where-vs-having-filter-rows-or-filter-groups

**Что это.** `WHERE` фильтрует **строки до** группировки. **HAVING** фильтрует **группы после** того, как агрегаты посчитаны. «Активные кредиты, филиалы, где их больше 300» требует обоих.

Зелёные группы остаются, зачёркнутые уходят.", "tables": [{"id": "grp", "name": "группы", "cols": ["branch_name", "active_loans"], "rows": [["Samarkand Central", 396], ["Fergana Central", 373], ["Andijan Central", 334], ["Namangan Central", 287], ["Bukhara Central", 270], ["Nukus Central", 213]], "keep": [0, 1, 2], "drop": [3, 4, 5], "more": "… и ещё 4: 3 выше, 1 ниже"}, {"id": "res", "name": "результат", "cols": ["branch_name", "active_loans"], "rows": [["Tashkent Central", 435], ["Tashkent North", 428], ["Tashkent South", 416], ["Samarkand Central", 396], ["Fergana Central", 373], ["Andijan Central", 334]], "via": "HAVING COUNT(*) > 300"}]}

**Как пишется.**

```sql
SELECT b.branch_name, COUNT(*) AS active_loans
FROM loans l JOIN branches b ON b.branch_id = l.branch_id
WHERE l.status = 'active'            -- оставить только активные кредиты (строки)
GROUP BY b.branch_name
HAVING COUNT(*) > 300                -- оставить только филиалы, где их больше 300 (группы)
ORDER BY active_loans DESC;          -- 6 филиалов: Tashkent Central 435 … Andijan Central 334
```

У шести филиалов из десяти больше 300 активных кредитов — от Tashkent Central с 435 до Andijan Central с 334.

**Когда применять.**

| | WHERE | HAVING |
|---|---|---|
| Фильтрует | строки | группы |
| Выполняется | до `GROUP BY` | после `GROUP BY` |
| Может использовать агрегат | нет | да |
| Пример | `l.status = 'active'` | `COUNT(*) > 300` |

> ⚠️ **Осторожно.** `WHERE COUNT(*) > 300` — ошибка: когда выполняется `WHERE`, никакого счёта ещё нет. Условие на обычный столбец ставьте в `WHERE`, даже если в запросе есть `HAVING`, — так дешевле, и это значит «до подсчёта».

### Агрегация после соединения — решите, что такое одна строка :id=aggregating-over-a-join-decide-what-one-row-is

**Что это.** Когда вы агрегируете после соединения, `COUNT` и `SUM` работают по строкам **результата соединения**. Одна строка такого результата — одна строка стороны «многие» (День 1). Поэтому сначала решите, что такое одна строка, а потом — что считать или складывать.

**Как пишется.** Соединение «многие к одному» сохраняет одну строку на кредит, поэтому счёт и суммы по кредитам остаются верными:

```sql
SELECT p.name, COUNT(*) AS loans, COUNT(DISTINCT l.customer_id) AS customers, SUM(l.principal) AS disbursed
FROM loans l
JOIN products p ON p.product_id = l.product_id     -- многие к одному: одна строка — по-прежнему один кредит
GROUP BY p.name
ORDER BY disbursed DESC;
```

| name | loans | customers | disbursed |
|---|---|---|---|
| Small business loan | 781 | 724 | 241 117 150 000 |
| Auto loan | 391 | 381 | 84 791 530 000 |
| Consumer loan | 2 418 | 2 000 | 65 109 280 000 |
| Micro loan | 2 669 | 2 133 | 7 221 210 000 |
| Buy now pay later | 1 569 | 1 364 | 6 544 110 000 |

Заёмщики микрокредитов возвращаются: 2 669 кредитов на 2 133 человека.

Соединение «один ко многим» повторяет каждый кредит, поэтому сумма столбца кредита по нему неверна:

```sql
SELECT p.name, SUM(l.principal)
FROM loans l JOIN installments i ON i.loan_id = l.loan_id    -- один ко многим: одна строка — платёж по графику
JOIN products p ON p.product_id = l.product_id
GROUP BY p.name;                     -- SME 5 862 295 560 000 — в 24 раза больше, и никто бы не заметил
```

Каждый основной долг посчитан по разу на каждый платёж по графику. Множитель — срок, а он у продуктов разный, поэтому меняется даже порядок: BNPL обгоняет Micro.

| Соединение | Одна строка — это | `COUNT(*)` считает | `SUM(l.principal)` |
|---|---|---|---|
| `loans → products` | кредит | кредиты | верно |
| `loans → installments` | платёж по графику | платежи по графику | неверно: каждый долг × его срок |

**Когда применять.** В каждом сгруппированном отчёте, где подписи лежат в другой таблице: названия продуктов, филиалов, регионы. Правило: **агрегируйте столбец на зерне его собственной таблицы.** Суммы кредитов — по `loans`; суммы платежей по графику — по `installments`. Если нужны обе в одном результате, агрегируйте каждую таблицу отдельно и соединяйте результаты — инструмент для этого дадим на Неделе 3.

### ORDER BY по агрегату или его псевдониму :id=order-by-an-aggregate-or-its-alias

**Что это.** После группировки `ORDER BY` может сортировать по агрегату (`ORDER BY COUNT(*) DESC`), по его псевдониму (`ORDER BY active_loans DESC`) или по номеру столбца (`ORDER BY 2 DESC`). Вместе с `LIMIT` это даёт **топ-N**.

**Как пишется.**

```sql
SELECT b.branch_name, COUNT(*) AS active_loans
FROM loans l JOIN branches b ON b.branch_id = l.branch_id
WHERE l.status = 'active'
GROUP BY b.branch_name
ORDER BY active_loans DESC           -- псевдоним; COUNT(*) DESC или 2 DESC дают тот же порядок
LIMIT 3;                             -- SQL Server: SELECT TOP 3 … (строку с LIMIT уберите)
```

Tashkent Central 435, Tashkent North 428, Tashkent South 416 — три ташкентских филиала держат больше всего активных кредитов.

**Когда применять.** Топ-N и анти-топ-N: крупнейшие продукты, самые слабые филиалы, самые занятые сотрудники взыскания. Предпочитайте псевдоним номеру: `ORDER BY 2` молча начнёт сортировать по другому столбцу, как только кто-то добавит столбец перед ним.

> ⚠️ **Осторожно.** Количество и сумма дают разные рейтинги. По числу активных кредитов Tashkent South третий; по сумме их основного долга — четвёртый, после Fergana Central. Сортируйте по мере, которую называет вопрос, и пишите её в заголовке.

### Порядок выполнения запроса :id=the-order-a-query-runs-in

**Что это.** База выполняет запрос не сверху вниз, как вы его пишете. Предложения выполняются в таком порядке:

```text
FROM / JOIN  →  WHERE          →  GROUP BY         →  HAVING          →  SELECT             →  ORDER BY     →  LIMIT
какие строки    оставить строки   собрать группы      оставить группы    посчитать столбцы     отсортировать   отрезать
```

**Как читать.** Каждое предложение видит только то, что сделали предложения до него:

| Потому что … | нельзя написать | пишите вместо этого |
|---|---|---|
| `WHERE` выполняется до `GROUP BY` | `WHERE COUNT(*) > 300` | `HAVING COUNT(*) > 300` |
| `WHERE` выполняется до `SELECT` | `WHERE active_loans > 300` (псевдонима ещё нет) | повторите выражение или используйте `HAVING` |
| `GROUP BY` выполняется до `SELECT` | `GROUP BY month` в SQL Server | повторите `strftime('%Y-%m', …)` в `GROUP BY` (SQLite принимает псевдоним) |
| `ORDER BY` выполняется после `SELECT` | — | `ORDER BY active_loans` работает везде |

**Когда применять.** Каждый раз, когда ошибка говорит, что столбца или псевдонима не существует или агрегат здесь запрещён: найдите предложение в строке выше и спросите, что уже выполнилось.

### Операции над множествами — результаты стопкой :id=set-operators-stacking-results

**Что это.** Соединения ставят таблицы рядом; **операции над множествами** (*set operators*) кладут результаты запросов **друг на друга**. Оба запроса должны возвращать одинаковое число столбцов совместимых типов.

```pic
{"id": "w02d2-pic3", "title": "UNION кладёт один результат на другой и убирает повторы", "caption": "Только клиенты 2, 5 и 17. `UNION` ставит второй список под первый и вычёркивает каждую строку, которая уже была: 5 и 17 есть в обоих списках. `UNION ALL` оставил бы все пять строк.", "tables": [{"id": "l", "name": "loans", "cols": ["customer_id"], "rows": [[5], [17]], "tone": ["a", "b"]}, {"id": "a", "name": "applications", "cols": ["customer_id"], "rows": [[5], [2], [17]], "tone": ["a", "c", "b"]}, {"id": "res", "name": "результат", "cols": ["customer_id"], "rows": [[5], [17], [5], [2], [17]], "tone": ["a", "b", "a", "c", "b"], "drop": [2, 4], "via": "UNION"}]}
```

**Как пишется.**

```sql
SELECT customer_id FROM loans
UNION                                        -- сложить стопкой и убрать повторяющиеся строки
SELECT customer_id FROM applications;        -- 5 453 строки
```

5 453 строки — каждый клиент, подававший заявку: каждый заёмщик тоже подавал заявку.

| Оператор | Оставляет | На наших данных |
|---|---|---|
| `UNION` | все строки обоих, **дубликаты убраны** | запрос выше → 5 453 строки |
| `UNION ALL` | все строки обоих, дубликаты сохранены (быстро) | то же с `UNION ALL` → 21 828 строк (7 828 + 14 000) |
| `EXCEPT` | строки первого запроса, которых нет во втором | `applications` `EXCEPT` `loans` → 1 118 человек подавали заявку, но не получили кредит |
| `INTERSECT` | строки, которые есть в обоих | заявители, которые также заёмщики → 4 335 |

**Когда применять.** `UNION ALL` складывает блоки «этот месяц» и «прошлый месяц» в одну таблицу для графика. `EXCEPT` — это анти-соединение, записанное через множества.

> 💡 **Главное.** По умолчанию используйте `UNION ALL`. `UNION` должен сортировать, чтобы убрать дубликаты, и молча сливает строки, которые законно одинаковы, — два месяца с одинаковым числом превращаются в одну строку.

### Собираем вместе :id=putting-it-together

Один запрос, все инструменты дня. *«Активные кредиты по филиалам: сколько, на какую сумму, средний чек — только филиалы, где активных кредитов больше 300, сначала с наибольшей суммой».*

```sql
SELECT b.branch_name,
       COUNT(*)                AS active_loans,       -- COUNT: одна строка группы = один кредит
       SUM(l.principal)        AS active_principal,   -- SUM по тем же строкам
       ROUND(AVG(l.principal)) AS avg_ticket          -- AVG; ROUND (среда) = целые сумы
FROM loans l
JOIN branches b ON b.branch_id = l.branch_id          -- многие к одному: одна строка — по-прежнему кредит
WHERE l.status = 'active'                             -- строки, до группировки
GROUP BY b.branch_name                                -- одна строка на филиал
HAVING COUNT(*) > 300                                 -- группы, после группировки
ORDER BY active_principal DESC;                       -- псевдоним, после SELECT
```

|---|---|---|---|
| Tashkent Central | 435 | 42 718 190 000 | 98 202 736 |
| Tashkent North | 428 | 38 262 090 000 | 89 397 407 |
| Fergana Central | 373 | 36 994 490 000 | 99 180 938 |
| Tashkent South | 416 | 36 954 370 000 | 88 832 620 |
| Samarkand Central | 396 | 35 511 850 000 | 89 676 389 |
| Andijan Central | 334 | 27 620 130 000 | 82 695 000 |

Прочитайте его в порядке выполнения: `FROM … JOIN` даёт одну строку на кредит с его филиалом; `WHERE` оставляет 3 352 активных; `GROUP BY` собирает десять групп-филиалов; `HAVING` оставляет шесть; `SELECT` считает три числа; `ORDER BY` сортирует по сумме. У Fergana Central активных кредитов меньше, чем у Tashkent South, но денег в них больше: её средний чек — самый высокий из шести.

## 2. Разобранный пример — таблица для совета :id=2-worked-example-the-board-pack-table

**Задача (Мадина):** *число кредитов и выданная сумма в 2026 году по месяцам и продуктам.*

Каждый шаг использует один подраздел раздела 1, в том порядке, в каком вы их изучили.

1. **COUNT и SUM.** «Число кредитов» — это `COUNT(*)`; «выданная сумма» — `SUM(principal)`. Оба читают `loans`, где одна строка — один кредит.
2. **GROUP BY по двум столбцам.** Одна строка ответа на (месяц, продукт). Месяц — выражение `strftime('%Y-%m', l.disbursed_at)`, повторённое в `GROUP BY`.
3. **WHERE vs HAVING.** Период — условие на строки, поэтому он идёт в `WHERE`: `disbursed_at >= '2026-01-01'` (и `< '2027-01-01'`, если бы данные могли идти дальше; наши заканчиваются 2026-10-01). Условия на группу нет, поэтому нет и `HAVING`.
4. **Агрегация после соединения.** Название продукта лежит в `products`. `loans → products` — «многие к одному», поэтому одна строка — по-прежнему один кредит, и суммы остаются верными. Платежи по графику не нужны.
5. **ORDER BY.** По месяцу, затем по псевдониму `disbursed`, сначала самые крупные.
6. Запрос: запрос «месяц × продукт» из раздела 1. Первые строки результата:

| month | product | loans | disbursed |
|---|---|---|---|
| 2026-01 | Small business loan | 34 | 10 042 990 000 |
| 2026-01 | Auto loan | 20 | 4 620 560 000 |
| 2026-01 | Consumer loan | 90 | 2 337 660 000 |
| 2026-01 | Micro loan | 99 | 262 110 000 |
| 2026-01 | Buy now pay later | 44 | 189 050 000 |
| 2026-02 | Small business loan | 21 | 6 035 880 000 |
| … | | | |

50 строк (10 месяцев × 5 продуктов; в октябре один день). Это **длинный формат** (*long format*) — одна строка на ячейку слайда Мадины. Её слайд — **широкий** формат (месяцы по горизонтали). Превращение длинного в широкий — это четверговый `SUM(CASE …)` или, на практике, сводная таблица в Excel/Power BI поверх именно этого результата. Отдавайте длинную таблицу; она правильная.

7. **Проверка по итогу без группировки.** `SELECT COUNT(*), SUM(principal) FROM loans WHERE disbursed_at >= '2026-01-01'` → 3 051 кредит, 162 333 060 000. 50 строк должны давать в сумме это. Так и есть.

**P2.** *(SUM)* Общий основной долг кредитов малому бизнесу (`product_id = 5`) и всех кредитов. Какая доля выданных денег приходится на SME? (Разделите вручную.)

**P3.** *(AVG)* Средний основной долг активных кредитов — один раз через `AVG`, один раз как `SUM(principal) / COUNT(*)`. Почему числа различаются?

<details><summary>Ответ</summary>

```sql
SELECT AVG(principal) AS avg_ticket, SUM(principal) / COUNT(*) AS by_hand, COUNT(*) AS loans
FROM loans WHERE status = 'active';                           -- 88 597 863.96 · 88 597 863 · 3352
```
Обе стороны `SUM(principal) / COUNT(*)` — целые числа, поэтому и деление целочисленное: .96 отбрасывается. `1.0 * SUM(principal) / COUNT(*)` даёт те же 88 597 863.96, что и `AVG`. (В SQL Server `AVG` по целочисленному столбцу тоже целый.)

</details>

**P4.** *(MIN и MAX)* Самый маленький и самый крупный микрокредит (`product_id = 1`), а также время первой и последней заявки в `applications`.


**P5.** *(GROUP BY по одному столбцу)* Число кредитов и общий основной долг по `status`, сначала с наибольшей суммой.

<details><summary>Ответ</summary>

active 3 352 / 296.98 млрд · closed 4 242 / 94.15 млрд · written_off 190 / 10.02 млрд · default 44 / 3.63 млрд. Закрытых кредитов больше, но они мельче — короткие кредиты Micro и BNPL закрываются быстро.

**P6.** *(GROUP BY по одному столбцу)* Кредиты, выданные за каждый год, с общей суммой и средним чеком, округлённым до целых сумов (`ROUND(x)` округляет до целого; подробно — в среду).

<details><summary>Ответ</summary>

```sql
FROM loans GROUP BY strftime('%Y', disbursed_at) ORDER BY yr;
```
2024: 1 736 кредитов, 86.52 млрд · 2025: 3 041, 155.93 млрд · 2026 (до 1 октября): 3 051, 162.33 млрд. Девять месяцев 2026 года уже превзошли весь 2025.

</details>

**P7.** *(GROUP BY по одному столбцу)* Поступления платежей в 2026 году: количество и сумма по месяцам. Есть ли что-то странное в конце списка?

<details><summary>Ответ</summary>

```sql
SELECT strftime('%Y-%m', paid_at) AS month, COUNT(*) AS payments, SUM(amount) AS received
FROM payments WHERE paid_at >= '2026-01-01' GROUP BY strftime('%Y-%m', paid_at) ORDER BY month;
```
В январе 2 466 / 11.76 млрд, к сентябрю рост до 3 159 / 16.34 млрд — а затем **2026-10: 52** и **2026-11: 8**. Данные на 1 октября; 60 платежей датированы 1 октября или позже, и **24** из них датированы *после* отчётной даты (последний — 2026-11-24). Либо выгрузка выполнена позже, чем указано в её подписи, либо это запланированные автосписания, записанные заранее. Отметьте это для Тимура; в пятницу об этом спросят.

</details>

**Уровень одобрения по каналам** (*approval rate by channel*). На первой неделе вы считали его двумя подсчётами для всей компании. По каналам способ «двумя запросами» — это по три группы в каждом:

```sql
SELECT channel, COUNT(*) AS applications FROM applications GROUP BY channel;                            -- app 5006 · branch 6223 · partner 2771
SELECT channel, COUNT(*) AS approved FROM applications WHERE status LIKE 'approved%' GROUP BY channel;  -- app 2915 · branch 3965 · partner 1715
```

```sql
-- SQLite
SELECT channel, COUNT(*) AS applications, ROUND(100.0 * AVG(status LIKE 'approved%'), 1) AS approval_pct
FROM applications GROUP BY channel;
-- SQL Server

FROM applications GROUP BY channel;
```

Те же три числа. Четверговый `SUM(CASE WHEN … THEN 1 ELSE 0 END)` — переносимая запись той же идеи; прочтите её там, а пользуйтесь той, что нравится вашей СУБД.
