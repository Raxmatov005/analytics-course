## 1. Теория — функции меняют значение на выходе :id=1-learn-functions-change-a-value-on-the-way-out

### Что делает функция — значение на входе, изменённое значение на выходе :id=what-a-function-does-a-value-in-a-changed-value-out

**Что это.** **Функция** (*function*) берёт значение из строки и возвращает изменённое значение. В таблице ничего не меняется; меняется только результат. Функции работают в `SELECT`, `WHERE`, `GROUP BY`, `HAVING` и `ORDER BY`. В этот день диалекты расходятся сильнее всего: каждый пример написан для SQLite, а вариант SQL Server — в комментарии в конце строки.

Написания одного цвета выходят одним чистым значением.", "tables": [{"name": "результат", "cols": ["method", "cleaned"], "rows": [["'Card'", "'card'"], ["'card'", "'card'"], ["'CASH '", "'cash'"], ["'cash'", "'cash'"], ["'PayMe'", "'payme'"], ["'payme'", "'payme'"]], "tone": ["a", "a", "b", "b", "c", "c"], "new": ["cleaned"], "more": "… всего 10 написаний и 6 чистых значений"}]}

**Как пишется.** `функция(значение, другие аргументы)` — везде, где мог бы стоять столбец:

```sql
SELECT DISTINCT method, LOWER(TRIM(method)) AS cleaned   -- две функции, одна внутри другой
FROM payments
ORDER BY cleaned;                                        -- 10 строк: 10 сырых написаний, 6 очищенных значений
```

Десять сырых написаний возвращаются рядом с очищенным значением: `Card` и `card` оба становятся `card`, `CASH ` и `cash` — `cash`. Внутренняя функция выполняется первой: сначала `TRIM`, потом `LOWER`.

**Когда применять.** Очистка подписей перед группировкой, вычисление числа из других чисел (доля, возраст в днях), вырезание части текста или даты.

> 💡 **Главное.** Функция меняет значение на выходе из запроса — `LOWER(method)` показывает `card` вместо `Card`, но в таблице по-прежнему лежит `Card`. По чему бы вы ни группировали или фильтровали — группируйте и фильтруйте по *одному и тому же* выражению.

### Конкатенация — склейка текстов через || :id=concatenation-joining-texts-with

**Что это.** **Конкатенация** (*concatenation*) склеивает тексты в один. SQLite пишет `||`; SQL Server — `+` или `CONCAT(…)`.

**Как пишется.**

```sql
SELECT first_name || ' ' || last_name AS full_name,      -- SQL Server: first_name + ' ' + last_name или CONCAT(first_name, ' ', last_name)
       'Loan ' || 42                  AS label           -- число превращается в текст: 'Loan 42'
FROM customers
WHERE customer_id = 1;                                   -- Eldor Olimov · Loan 42
```

Клиент 1 — *Eldor Olimov*. `' '` посередине — текст из одного пробела; без него получится `EldorOlimov`.

**Когда применять.** Один читаемый столбец из нескольких: полное имя, подпись вроде `'2026-Q3'`, ключ сравнения для поиска дубликатов.

> ⚠️ **Осторожно.** Что угодно `||` NULL — это NULL: `'Eldor' || ' ' || NULL` возвращает NULL, и всё имя пропадает. (`CONCAT` в SQL Server считает NULL пустым текстом; его `+` тоже возвращает NULL.) А `+` в SQLite только складывает числа: `'a' + 'b'` равно 0.

### UPPER и LOWER — один регистр для всех значений :id=upper-and-lower-one-case-for-every-value

**Что это.** **UPPER** делает каждую букву заглавной; **LOWER** — строчной. Остальные символы не меняются. Пишется одинаково на обоих движках.

**Как пишется.**

```sql
SELECT customer_id, first_name, last_name, UPPER(last_name) AS upper_last
FROM customers
WHERE last_name = LOWER(last_name);                      -- 40 строк: фамилии, набранные целиком строчными
```

У 40 клиентов фамилия набрана целиком строчными буквами, например `jalilova`. У всех 40 id 6001 или больше — это дубликаты прошлой недели.

**Когда применять.** Перед сравнением или группировкой текста, который набирали люди: `LOWER(a) = LOWER(b)`, `GROUP BY LOWER(method)`. И чтобы найти криво набранные строки: `WHERE x = LOWER(x)` или `WHERE x = UPPER(x)`.

### TRIM — убрать пробелы по краям :id=trim-remove-spaces-at-the-ends

**Что это.** **TRIM** убирает пробелы в начале и в конце текста. `LTRIM` убирает только левые, `RTRIM` — только правые. Пробелы внутри текста остаются.

**Как пишется.**

```sql
SELECT TRIM('CASH '),          -- 'CASH'
       TRIM('  bank transfer ')  -- 'bank transfer': внутренний пробел остаётся
;
SELECT COUNT(*) FROM customers WHERE first_name <> TRIM(first_name);   -- 18
```

У 18 имён есть пробел с краю, например `'Yulduz '`. Для базы `'Yulduz '` и `'Yulduz'` — разные значения.

**Когда применять.** На каждом текстовом столбце, который набирал человек или который скопирован из файла, — прежде чем сравнивать, группировать или соединять по нему.

### LENGTH — сколько символов :id=length-how-many-characters

**Что это.** **LENGTH** возвращает число символов в тексте. В SQL Server она называется `LEN`.

**Как пишется.**

```sql
SELECT LENGTH(phone) AS characters, COUNT(*) AS customers   -- SQL Server: LEN(phone)
FROM customers
GROUP BY LENGTH(phone);                                      -- одна строка: 13 · 6 040
```

Одна строка: у всех 6 040 номеров по 13 символов (`+998` и девять цифр). Проверка длины — самый быстрый тест формата для кодов, телефонов и идентификаторов.

**Когда применять.** Чтобы проверить формат (каждый телефон — 13 символов), найти скрытые пробелы (`LENGTH(x) <> LENGTH(TRIM(x))`), найти пустые тексты (`LENGTH(x) = 0`).

> ⚠️ **Осторожно.** `LEN` в SQL Server игнорирует пробелы в конце: `LEN('Bobur ')` равно 5, а `LENGTH('Bobur ')` в SQLite — 6. Проверка длины, которая находит «грязные» имена на одном движке, на другом не найдёт ничего — в SQL Server сравнивайте `DATALENGTH`.

### SUBSTR — часть текста :id=substr-a-piece-of-a-text

**Что это.** **SUBSTR**`(текст, начало, n)` возвращает `n` символов, начиная с позиции `начало`; первый символ — позиция 1. Без `n` возвращает всё до конца. Отрицательное начало считается от конца. SQL Server пишет `SUBSTRING(текст, начало, n)`, `LEFT(текст, n)` и `RIGHT(текст, n)`.

**Как пишется.** Дата со временем, хранящаяся текстом, — это строка с фиксированными позициями:

```text
2026-09-27 14:05:00
1234567890123456789      → SUBSTR(applied_at, 1, 10) = '2026-09-27'   SUBSTR(applied_at, 12, 2) = '14'
```

```sql
SELECT SUBSTR(applied_at, 12, 2) AS hour, COUNT(*) AS applications   -- SQL Server: DATEPART(hour, applied_at)
FROM applications
GROUP BY SUBSTR(applied_at, 12, 2)
ORDER BY applications DESC;                                           -- первым 15 → 1 089
```

Заявки приходят с 08:00 до 21:59; самый загруженный час — 15:00, 1 089 заявок. `SUBSTR(phone, -4)` даёт последние четыре цифры (`RIGHT(phone, 4)` в SQL Server).

**Когда применять.** Коды с фиксированными позициями: час в тексте даты со временем, код региона в номере счёта, последние цифры телефона.

### REPLACE — заменить один текст другим :id=replace-swap-one-text-for-another

**Что это.** **REPLACE**`(текст, 'старое', 'новое')` заменяет **каждое** вхождение `'старое'` внутри текста на `'новое'`. `'новое'` может быть пустым — тогда `'старое'` удаляется. Пишется одинаково на обоих движках.

**Как пишется.** Исправление вчерашних десяти способов оплаты:

```sql
SELECT REPLACE(LOWER(TRIM(method)), 'bank transfer', 'transfer') AS method, COUNT(*) AS payments
FROM payments
GROUP BY REPLACE(LOWER(TRIM(method)), 'bank transfer', 'transfer')
ORDER BY payments DESC;
-- card 17621 · payme 8900 · click 8790 · cash 8790 · transfer 8774
```

Пять строк — пять настоящих способов. `TRIM` и `LOWER` сливают `Card`, `CASH `, `PayMe` и `Click` с их группами; последнее отклонение, `bank transfer`, — другое *слово*, и слить его может только `REPLACE`: transfer вырастает с 8 747 до 8 774.

**Когда применять.** Известное неверное написание → верное; удаление символа (`REPLACE(phone, '-', '')`); местный формат (`REPLACE(phone, '+998', '8')`).

> ⚠️ **Осторожно.** REPLACE меняет каждое вхождение, в том числе внутри более длинных слов. `REPLACE(method, 'transfer', 'bank transfer')` превратит 27 строк, уже записанных как `bank transfer`, в `bank bank transfer`. Заменяйте более длинный и редкий текст на более короткий, как выше.

### INSTR — где начинается текст :id=instr-where-a-text-starts

**Что это.** **INSTR**`(текст, 'кусок')` возвращает позицию, где `'кусок'` впервые начинается внутри текста, или 0, если его нет. SQL Server пишет `CHARINDEX('кусок', текст)` — аргументы в обратном порядке.

**Как пишется.**

```sql
SELECT INSTR('bank transfer', ' '),      -- 5: пробел — 5-й символ      SQL Server: CHARINDEX(' ', 'bank transfer')
       INSTR('card', ' ');               -- 0: пробела нет
```

Её обычный напарник — `SUBSTR`: найти, где что-то начинается, и резать там. Мажорная версия мобильного приложения — это текст до первой точки:

```sql
SELECT SUBSTR(app_version, 1, INSTR(app_version, '.') - 1) AS major, COUNT(*) AS events
FROM app_events
GROUP BY major;                          -- 3 → 11 325 · 4 → 11 459
```

События приложения делятся почти поровну: 11 325 из версии 3.x и 11 459 из версии 4.x.

**Когда применять.** Разрезать по разделителю, позиция которого меняется от строки к строке: часть до `@` в email, до `.` в версии, до пробела в полном имени. И как проверка: `INSTR(x, ' ') > 0` значит «содержит пробел».

### LIKE — шаблоны с % и _ :id=like-patterns-with-and-_

**Что это.** **LIKE** сравнивает текст с **шаблоном**. `%` означает любое число символов (в том числе ни одного); `_` — ровно один символ. Вы встречали его на Неделе 1; здесь все его правила.

**Как пишется.**

```sql
SELECT COUNT(*) FROM applications WHERE status LIKE 'approved%';   -- 8 595: 'approved' и 'approved_not_disbursed'
SELECT COUNT(*) FROM customers    WHERE last_name LIKE '%ova';     -- 2 447 фамилий на 'ova'
SELECT COUNT(*) FROM customers    WHERE first_name LIKE '_____';   -- 1 862 имени ровно из 5 символов
```

8 595 заявок начинаются с `approved`: 7 917 `approved` и 678 `approved_not_disbursed`.

**Когда применять.** «Начинается с», «заканчивается на», «содержит»: `'approved%'`, `'%ova'`, `'%transfer%'`. Для точного значения используйте `=`.

> ⚠️ **Осторожно.** В SQLite `LIKE` не различает заглавные и строчные латинские буквы, а `=` различает: `'card' LIKE 'Card'` — истина, `'card' = 'Card'` — ложь. Поэтому `method LIKE 'card'` находит 17 621 строку, а `method = 'card'` — 17 564. В SQL Server оба следуют сортировке столбца (по умолчанию регистр не важен).

### ROUND — округлить до n знаков :id=round-round-to-n-decimals

**Что это.** **ROUND**`(x, n)` округляет `x` до `n` знаков после запятой; `ROUND(x)` — до целого. Пятёрка округляется от нуля: `ROUND(2.5)` равно 3.

**Как пишется.**

```sql
SELECT p.name, ROUND(AVG(l.principal) / 1000000.0, 1) AS avg_ticket_m      -- сначала делим, потом один раз округляем
FROM loans l JOIN products p ON p.product_id = l.product_id
GROUP BY p.name
ORDER BY avg_ticket_m DESC;               -- SME 308.7 · Auto 216.9 · Consumer 26.9 · BNPL 4.2 · Micro 2.7
```

Средний кредит SME — 308.7 млн сумов; средний микрокредит — 2.7 млн. Поделённые на миллион и округлённые до одного знака, числа готовы для слайда.

**Когда применять.** В самом конце, на числе, которое вы показываете. SQL Server умеет округлять и слева от запятой — `ROUND(x, -6)` означает «до миллиона»; SQLite не умеет, поэтому сначала делите, как выше.

> ⚠️ **Осторожно.** Округляйте один раз, в конце. Если округлить части, а потом сложить, сумма уплывает: пять округлённых долей редко дают ровно 100.0.

### Целочисленное и десятичное деление :id=integer-and-decimal-division

**Что это.** Оба движка делят два целых числа **как целые**: `7917 / 14000` — это **0**. Дробная часть отбрасывается молча. Если одна из сторон — десятичное число, результат будет десятичным.

**Как пишется.**

```sql
SELECT 7917 / 14000,                   -- 0
       7917 * 100 / 14000,             -- 56   (снова целое: отброшено, не округлено)
       7917 * 100.0 / 14000,           -- 56.55
       ROUND(7917 * 100.0 / 14000, 2); -- 56.55
-- Альтернатива в SQL Server: CAST(7917 AS FLOAT) / 14000
```

7 917 из 14 000 заявок одобрены: 56.55 %. Это говорят только варианты со `100.0`.

**Когда применять.** В каждой доле, проценте, «среднем вручную» и отношении.

> ⚠️ **Осторожно.** Целое ÷ целое = целое, и в SQL Server, и в SQLite. Ни ошибки, ни предупреждения — просто неверная доля. Ставьте `100.0 *` в **начало** каждого процента, чтобы уже первая операция давала десятичное число.

### CAST — изменить тип значения :id=cast-change-the-type-of-a-value

**Что это.** **CAST**`(x AS тип)` преобразует значение в другой тип: текст в число, число в текст, десятичное в целое. Типы SQLite — `INTEGER`, `REAL`, `TEXT`; у SQL Server среди прочих `INT`, `BIGINT`, `FLOAT`, `DECIMAL(18,2)`, `DATE`.

**Как пишется.**

```sql
SELECT CAST(AVG(principal) AS INTEGER),   -- 51 709 667: .86 отброшено, а не округлено      SQL Server: CAST(… AS BIGINT)
       ROUND(AVG(principal)),             -- 51 709 668: округлено
       CAST('2026' AS INTEGER) + 1,       -- 2027: текст в число
       CAST(7917 AS REAL) / 14000         -- 0.5655: одна сторона стала десятичной до деления
FROM loans;
```

`CAST … AS INTEGER` и `ROUND` здесь расходятся на единицу: CAST отбрасывает дробную часть, ROUND её округляет.

**Когда применять.** Целые дни из дробной разности `julianday` в SQLite (ниже); текстовый код, сравниваемый с числом; десятичное число перед делением.

> ⚠️ **Осторожно.** CAST готового результата — слишком поздно: `CAST(7917 / 14000 AS REAL)` равно 0.0, потому что целочисленное деление уже выбросило дробную часть. Преобразуйте вход, а не выход.

### ABS — величина числа без знака :id=abs-the-size-of-a-number-without-its-sign

**Что это.** **ABS**`(x)` возвращает `x` без минуса: `ABS(-45)` равно 45, `ABS(45)` — тоже 45. Одинаково на обоих движках.

**Как пишется.** Насколько каждый платёж отличается от суммы, которую требовал его платёж по графику, в любую сторону?

```sql
SELECT COUNT(*) AS different,
       SUM(p.amount > i.total_due) AS over_paid,          -- SQL Server: SUM(IIF(p.amount > i.total_due, 1, 0))

FROM payments p JOIN installments i ON i.installment_id = p.installment_id
WHERE ABS(p.amount - i.total_due) > 0;                    -- 427 · 0 · 427
```

### Проценты — часть от целого, умноженная на 100 :id=percentages-a-part-of-a-whole-times-100

**Что это.** **Процент** (*percentage*) — часть, делённая на целое, умноженная на 100. В SQL: `100.0 * часть / целое`, округлённое один раз в конце. Разница между двумя процентами измеряется в **процентных пунктах**.

**Как пишется.** В SQLite сравнение — это 1 или 0, поэтому `SUM(условие)` считает строки, где оно истинно:

```sql
SELECT channel,
       COUNT(*) AS applications,
       ROUND(100.0 * SUM(status LIKE 'approved%') / COUNT(*), 1) AS approval_pct   -- SQL Server: SUM(IIF(status LIKE 'approved%', 1, 0))
FROM applications
GROUP BY channel;                        -- app 58.2 · branch 63.7 · partner 61.9
```

Филиал одобряет 63.7 % своих заявок, приложение — 58.2 %: разрыв 5.5 процентного пункта (а не «5.5 %»).

**Когда применять.** Доля одобрений, доля опоздавших, доля продукта в портфеле, доля процентов в платеже. Четверговый `SUM(CASE …)` — переносимая запись подсчитанной части.

### Фильтр периода — полуоткрытый диапазон :id=filtering-a-period-the-half-open-range

**Что это.** **Полуоткрытый диапазон** включает начало периода и останавливается прямо перед началом следующего: `col >= начало AND col < начало_следующего`. Он верен для дат, для дат со временем, для месяцев от 28 до 31 дня и на переходе через год.

**Как пишется.**

```sql
SELECT COUNT(*) FROM applications
WHERE applied_at >= '2026-09-01' AND applied_at < '2026-10-01';     -- 621: весь сентябрь, в любое время суток
```

621 заявка в сентябре 2026 года. `BETWEEN '2026-09-01' AND '2026-09-30'` возвращает 598: он останавливается на 30 сентября **00:00:00**, и 23 заявки, поданные позже в тот день, теряются.

**Когда применять.** В каждом отчёте за период: месяц, квартал, год, «последние 30 дней». Не фильтруйте и через `strftime('%Y-%m', applied_at) = '2026-09'`: это вернёт те же 621 строку, но вычислит функцию на каждой строке и не даст базе использовать индекс (Неделя 3).

> ⚠️ **Осторожно.** `BETWEEN '2026-09-01' AND '2026-09-30'` читается как «весь сентябрь», но останавливается на 30 сентября 00:00:00 — каждая строка с более поздним временем в тот день пропадает (здесь 23).

```sql
GROUP BY REPLACE(LOWER(TRIM(p.method)), 'bank transfer', 'transfer')                     -- то же выражение, что в SELECT
ORDER BY payments DESC;
```

## 2. Разобранный пример — кредиты, выплаченные раньше, чем были запрошены (расследование, 30 мин) :id=2-worked-example-loans-paid-out-before-they-were-requested-detective-30-min

Подсказка Мадины: *некоторые кредиты были выданы раньше, чем клиент подал заявку.* Это сравнение дат в двух таблицах. Шаги 1 и 2 используют подразделы раздела 1 про даты; шаг 3 — вопрос Тимура, он возвращается к подразделам про строки и проценты.

**Шаг 1 — распределение (даты как текст, арифметика дат, CAST).** `date(a.applied_at)` берёт дату из даты со временем заявки; `julianday(…) - julianday(…)` даёт число дней между ними; `CAST(… AS INTEGER)` делает их целыми. Затем посчитайте кредиты для каждого числа дней:

```sql
-- SQL Server: DATEDIFF(day, CAST(a.applied_at AS DATE), l.disbursed_at)
SELECT CAST(julianday(l.disbursed_at) - julianday(date(a.applied_at)) AS INTEGER) AS days_to_disburse, COUNT(*)
FROM loans l JOIN applications a ON a.application_id = l.application_id
GROUP BY days_to_disburse ORDER BY days_to_disburse;
```

<details><summary>Что вы увидите</summary>

Значения от 0 до 7 включают 7 816 кредитов (0 дней: 925 — канал app выплачивает в тот же день; 3 дня — мода, 1 670). Отрицательная разность означает, что кредит выдан *раньше*, чем подана заявка.

</details>

**Шаг 2 — выведите их списком (сравнение дат в двух соединённых таблицах).** Отрицательная разность означает `l.disbursed_at < date(a.applied_at)`; это и есть фильтр.


## 6. Уголок компании <span class="badge company">DPD в расчёте</span> :id=6-company-corner-dpd-computed

В День 3 первой недели вы получили определение и числа 413 и 14 / 124 / 25 / 16 / 234, чтобы их *прочитать*. Сегодня вы их получаете сами.

**DPD (days past due, дни просрочки) кредита на дату** = число дней с момента срока его **самого старого не полностью оплаченного платежа**. Три шага, каждый — инструмент этой недели:

1. **Сколько оплачено по каждому платежу?** `installments LEFT JOIN payments`, группировка по платежу, суммирование платежей (LEFT, чтобы неоплаченные платежи остались, с 0). Оставьте только наступившие платежи (`due_date <= отчётная дата`) — и только те, где *оплачено < к оплате*. Это условие на агрегат → `HAVING`.
2. **По каждому кредиту — самый старый такой платёж:** `MIN(due_date)` с группировкой по кредиту.
3. **Дни:** отчётная дата минус эта дата.

Шаги 1 и 2 — это две группировки подряд, для их цепочки нужен CTE (`WITH … AS (…)`) с недели 3. **Это предпросмотр: выполните и прочитайте.** Читайте его как два именованных результата; на следующей неделе вы сами напишете такую форму.

```sql
WITH unpaid AS (                                   -- шаг 1: наступившие платежи, не оплаченные полностью
  SELECT i.installment_id, i.loan_id, i.due_date, i.total_due,
         COALESCE(SUM(p.amount), 0) AS paid        -- COALESCE: NULL (нет платежа) → 0; День 4
  FROM installments i
  LEFT JOIN payments p ON p.installment_id = i.installment_id
  WHERE i.due_date <= '2026-10-01'
  GROUP BY i.installment_id, i.loan_id, i.due_date, i.total_due
  HAVING COALESCE(SUM(p.amount), 0) < i.total_due
),
dpd AS (                                           -- шаги 2 + 3: самый старый неоплаченный по кредиту, в днях
  SELECT loan_id,
         MIN(due_date) AS oldest_unpaid_due,
         CAST(julianday('2026-10-01') - julianday(MIN(due_date)) AS INTEGER) AS dpd,   -- DATEDIFF(day, MIN(due_date), '2026-10-01')
         COUNT(*) AS unpaid_instalments,
         SUM(total_due - paid) AS overdue_amount
  FROM unpaid GROUP BY loan_id
)
SELECT * FROM dpd ORDER BY dpd DESC;
```

**413 строк** — кредиты хотя бы с одним наступившим не полностью оплаченным платежом. Сверху: кредит 2167, самый старый неоплаченный срок 2024-03-26, **919 DPD**, 6 неоплаченных платежей, списан. Кредитов, которых нет в результате, DPD равен 0 (просрочки нет) — кредит 1 один из них: его мартовский платёж с опозданием на 45 дней оплачен, поэтому просрочки по нему сегодня нет.

**Корзины** требуют `CASE` — *инструмент завтрашнего дня: прочитайте сегодня, напишете завтра.* Замените последнюю строку на:

```sql
SELECT CASE WHEN dpd = 0  THEN '0'
            WHEN dpd <= 30 THEN '1-30'
            WHEN dpd <= 60 THEN '31-60'
            WHEN dpd <= 90 THEN '61-90'
            ELSE '90+' END AS bucket,
       COUNT(*) AS loans, SUM(overdue_amount) AS overdue
FROM dpd GROUP BY bucket ORDER BY MIN(dpd);
```

|---|---|---|---|
| 0 | 14 | 53 018 776 | платежи со сроком *сегодня* (2026-10-01), не оплаченные на утро — ещё не просрочены. Корзина 0 = DPD 0: у остальных 7 415 кредитов с DPD 0 нет наступивших неоплаченных платежей, поэтому в этот список они не попадают (по всему портфелю корзина 0 — 7 429, Неделя 8) |
