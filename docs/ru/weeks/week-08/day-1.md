### Что такое метрика — числитель, знаменатель, фильтр, период :id=what-a-metric-is-numerator-denominator-filter-period

**Что это.** **Метрика** (*metric*) — число, определённое так точно, что два аналитика получают одно и то же значение. У метрики-доли четыре части: **числитель** (единицы, которые сделали действие), **знаменатель** (все единицы, которые могли его сделать), **фильтр** (какие единицы вообще учитываются) и **период** (когда).

**Как пишется.**

```sql
-- форма любой метрики-доли
-- единицы, которые сделали действие
SELECT SUM(CASE WHEN <сделал действие> THEN 1 ELSE 0 END) AS numerator,
       -- все единицы, которые могли
       COUNT(*)                                           AS denominator,
       ROUND(100.0 * SUM(CASE WHEN <сделал действие> THEN 1 ELSE 0 END) / COUNT(*), 1) AS rate_pct
FROM <одна строка на единицу>
-- какие единицы вообще учитываются
WHERE <фильтр>
  AND <дата> >= '<начало>' AND <дата> < '<конец>';
  -- период: начало включено, конец исключён
```

### Дерево метрик — от «Полярной звезды» к её драйверам :id=a-metric-tree-from-the-north-star-to-its-drivers

**Что это.** **Метрика «Полярная звезда»** (*North Star metric*) — одно число, которое лучше всего показывает ценность, которую создаёт компания. Для кредитора это обычно сумма выдач за месяц. **Дерево метрик** (*metric tree*) раскладывает это число на **драйверы** — множители, которые перемножаются обратно в него; каждый из них команда может сдвинуть.

**Как пишется.** Знаменатель каждого множителя — числитель предыдущего, поэтому произведение сокращается до итога:

```text
сумма выдач
  =  заявки
       (сколько просят)
  ×  одобрено ÷ заявки
       (доля одобрений)
  ×  кредиты ÷ одобрено
       (оформление)
  ×  сумма ÷ кредиты
       (средний чек)
```

По заявкам, поданным в сентябре 2026:

```sql
WITH m AS (
  SELECT COUNT(*)                                                                         AS applications,
         SUM(CASE WHEN a.status IN ('approved', 'approved_not_disbursed') THEN 1 ELSE 0 END) AS approved,
         COUNT(l.loan_id)                                                                  AS loans,
         SUM(l.principal)                                                                  AS amount
  FROM applications a
  -- кредит, если заявка им стала
  LEFT JOIN loans l ON l.application_id = a.application_id
  WHERE a.applied_at >= '2026-09-01' AND a.applied_at < '2026-10-01')
SELECT applications,
       ROUND(100.0 * approved / applications, 2) AS approval_pct,  -- драйвер 2
       ROUND(100.0 * loans / approved, 2)        AS take_up_pct,   -- драйвер 3
       -- драйвер 4
       ROUND(1.0 * amount / loans)                AS avg_ticket,
       ROUND(applications * (1.0 * approved / applications) * (1.0 * loans / approved) * (1.0 * amount / loans)) AS product,
       amount
FROM m;
```

621 заявка × 61.67 % одобрено × 87.21 % оформлено × 43 732 545 сум на кредит = 14 606 670 000 сум — произведение попадает точно в сумму.

**Когда применять.**
- Итог сдвинулся: спуститесь по дереву и найдите драйвер, который сдвинулся.
- Команда просит цель: дайте ей драйвер, который она может толкать, а не итог.

| | Входная метрика | Выходная метрика |
|---|---|---|
| Что это | драйвер, который команда двигает напрямую | результат, который читает совет директоров |
| Пример | заявки, доля одобрений, оформление | сумма выдач, прибыль |
| | **Опережающая метрика** (*leading metric*) — сдвигается первой | **Запаздывающая метрика** (*lagging metric*) — подтверждает позже |
| Пример | заявки на этой неделе, FPD30 | NPL90 через год, списания |

> ⚠️ **Осторожно.** Поставьте в середину цепочки долю одобрений из риск-отчёта (одобрено ÷ рассмотрено) — и произведение перестанет равняться итогу. Внутри дерева каждый знаменатель должен быть предыдущим числителем.

### Кредитная воронка — визит → заявка → одобрение → выдача → погашение :id=the-lending-funnel-visit-application-approval-disbursement-repayment

**Что это.** **Воронка** (*funnel*) — упорядоченный список шагов и число единиц, дошедших до каждого. Воронка кредитора заканчивается деньгами, которые вернулись: **визит → заявка → одобрение → выдача → погашение**. **Конверсия шага** (*step conversion*) = дошли до этого шага ÷ дошли до предыдущего. **Конверсия от верха** = дошли до этого шага ÷ дошли до шага 1.

**Как пишется.** Одна строка на единицу с флагом 0/1 на каждый шаг, затем одна сумма на шаг:

```sql
-- форма
WITH u AS (
  SELECT <id единицы>,
         -- 1, если единица дошла до шага 1
         MAX(CASE WHEN <шаг 1 случился> THEN 1 ELSE 0 END) AS step1,
         MAX(CASE WHEN <шаг 2 случился> THEN 1 ELSE 0 END) AS step2
  FROM <события> GROUP BY <id единицы>)
SELECT SUM(step1), SUM(step2) FROM u;
-- единицы, дошедшие до каждого шага
```

Единица здесь — **сессия в приложении** (`application_id` в `app_events`). Сессии, открытые в январе–июне 2026, прослеженные до первого платежа по графику:

```sql
-- одна строка на сессию в приложении
WITH s AS (
  SELECT application_id, MIN(event_time) AS opened_at,
         MAX(CASE WHEN event_name = 'app_open'           THEN 1 ELSE 0 END) AS visit,
         MAX(CASE WHEN event_name = 'submit_application' THEN 1 ELSE 0 END) AS application,
         MAX(CASE WHEN event_name = 'approved'           THEN 1 ELSE 0 END) AS approval
  FROM app_events GROUP BY application_id),
-- первый платёж по графику каждого кредита и когда его оплатили
first_inst AS (
  SELECT i.loan_id, i.due_date, MIN(p.paid_at) AS paid_at
  FROM installments i LEFT JOIN payments p ON p.installment_id = i.installment_id
  WHERE i.installment_no = 1
  GROUP BY i.loan_id, i.due_date)
SELECT SUM(s.visit)                                             AS visit,
       SUM(s.application)                                       AS application,
       SUM(s.approval)                                          AS approval,
       COUNT(l.loan_id)                                         AS disbursement,
       -- первый платёж оплачен вовремя
       SUM(CASE WHEN f.paid_at <= f.due_date THEN 1 ELSE 0 END) AS repayment
FROM s
LEFT JOIN loans l      ON l.application_id = s.application_id
LEFT JOIN first_inst f ON f.loan_id = l.loan_id
WHERE s.opened_at >= '2026-01-01' AND s.opened_at < '2026-07-01';
```

### Протекающие шаги — где искать :id=leaky-steps-where-to-look

**Что это.** **Протекающий шаг** (*leaky step*) — шаг, который теряет больше всего единиц: в штуках (**отвал**, *drop-off*) или в конверсии шага. Найти его — половина работы; вторая половина — проверить, что утечка настоящая, и назвать, кто может её устранить.

**Как пишется.** Разбейте крупные шаги на подшаги и поставьте рядом с каждым отвал. `LAG` читает число предыдущего шага:

```sql
-- каждая сессия в приложении, по одной строке
WITH s AS (
  SELECT application_id,
         MAX(CASE WHEN event_name = 'app_open'           THEN 1 ELSE 0 END) AS opened,
         MAX(CASE WHEN event_name = 'view_offer'         THEN 1 ELSE 0 END) AS viewed,
         MAX(CASE WHEN event_name = 'start_application'  THEN 1 ELSE 0 END) AS started,
         MAX(CASE WHEN event_name = 'submit_application' THEN 1 ELSE 0 END) AS submitted,
         MAX(CASE WHEN event_name = 'approved'           THEN 1 ELSE 0 END) AS approved,
         MAX(CASE WHEN event_name = 'contract_signed'    THEN 1 ELSE 0 END) AS signed
  FROM app_events GROUP BY application_id),
steps AS (
  SELECT 1 AS k, 'app_open' AS step, SUM(opened) AS n FROM s UNION ALL
  SELECT 2, 'view_offer',         SUM(viewed)    FROM s UNION ALL
  SELECT 3, 'start_application',  SUM(started)   FROM s UNION ALL
  SELECT 4, 'submit_application', SUM(submitted) FROM s UNION ALL
  SELECT 5, 'approved',           SUM(approved)  FROM s UNION ALL
  SELECT 6, 'contract_signed',    SUM(signed)    FROM s UNION ALL
  SELECT 7, 'disbursed', COUNT(*) FROM s JOIN loans l ON l.application_id = s.application_id)
SELECT k, step, n,
       -- отвал на этом шаге
       LAG(n) OVER (ORDER BY k) - n                    AS lost,
       -- конверсия шага
       ROUND(100.0 * n / LAG(n) OVER (ORDER BY k), 1)  AS step_pct
FROM steps ORDER BY k;
```

### Удержание — возвращение за новым кредитом :id=retention-coming-back-for-another-loan

**Что это.** **Удержание** (*retention*) — доля группы, которая возвращается через время N. Соцсеть считает людей, которые снова открыли её на 7-й день. Кредитор считает заёмщиков, которые взяли **ещё один кредит**: удержание на N месяцах = клиенты со вторым кредитом в течение N месяцев после первого ÷ клиенты в группе.

### Таблица удержания и кривая удержания :id=the-retention-table-and-the-retention-curve

**Что это.** **Таблица удержания** (*retention table*) ставит когорты в строки, а возраст N — в столбцы; каждая ячейка — удержание этой когорты в этом возрасте. Ячейка существует, только если у **каждого** клиента когорты прошло N месяцев; иначе она остаётся пустой. **Кривая удержания** (*retention curve*) рисует одну строку таблицы линией по N.

**Как пишется.** Запрос удержания из предыдущего раздела, сгруппированный по когорте, с правилом пустой ячейки вокруг каждой ячейки:

```sql
WITH ranked AS (
  SELECT customer_id, disbursed_at,
         ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY disbursed_at, loan_id) AS n
  FROM loans),
pairs AS (
  SELECT f.disbursed_at AS first_at, s.disbursed_at AS second_at,
         strftime('%Y', f.disbursed_at) || 'Q' || ((CAST(strftime('%m', f.disbursed_at) AS INTEGER) + 2) / 3) AS cohort
  FROM ranked f LEFT JOIN ranked s ON s.customer_id = f.customer_id AND s.n = 2
  WHERE f.n = 1)
SELECT cohort, COUNT(*) AS customers,
       -- пусто, если не у каждого клиента прошло 3 месяца
       CASE WHEN MAX(date(first_at, '+3 months')) <= '2026-10-01'
            THEN ROUND(100.0 * SUM(CASE WHEN second_at <= date(first_at, '+3 months') THEN 1 ELSE 0 END) / COUNT(*), 1) END AS m3,
       CASE WHEN MAX(date(first_at, '+6 months')) <= '2026-10-01'
            THEN ROUND(100.0 * SUM(CASE WHEN second_at <= date(first_at, '+6 months') THEN 1 ELSE 0 END) / COUNT(*), 1) END AS m6,
       CASE WHEN MAX(date(first_at, '+12 months')) <= '2026-10-01'
            THEN ROUND(100.0 * SUM(CASE WHEN second_at <= date(first_at, '+12 months') THEN 1 ELSE 0 END) / COUNT(*), 1) END AS m12
FROM pairs
WHERE first_at >= '2025-01-01' AND first_at < '2026-07-01'
GROUP BY cohort ORDER BY cohort;
```

### Отток — клиенты, которые уходят :id=churn-the-customers-who-leave

**Что это.** **Отток** (*churn*) — доля клиентов, которые перестают быть клиентами. Клиент кредитора может уйти только после погашения. Поэтому клиент **уходит в отток**, когда кредит закрыт, другого действующего кредита нет и новый кредит не следует в течение окна (здесь 6 месяцев). **Доля оттока** (*churn rate*) = ушедшие ÷ клиенты, которые могли уйти.

**Как пишется.** Клиенты, чей кредит закрылся в первом квартале 2026:

```sql
-- клиенты, погасившие кредит в I квартале 2026
WITH closers AS (
  SELECT customer_id, MAX(closed_at) AS closed_at
  FROM loans
  WHERE status = 'closed' AND closed_at >= '2026-01-01' AND closed_at < '2026-04-01'
  GROUP BY customer_id),
-- в тот день был другой действующий кредит: уйти в отток не может
still_borrowing AS (
  SELECT DISTINCT c.customer_id
  FROM closers c
  JOIN loans l ON l.customer_id = c.customer_id
              AND l.disbursed_at <= c.closed_at AND (l.closed_at IS NULL OR l.closed_at > c.closed_at)),
base AS (
  SELECT * FROM closers WHERE customer_id NOT IN (SELECT customer_id FROM still_borrowing)),
-- первый кредит после закрытия, если он есть
next_loan AS (
  SELECT b.customer_id, MIN(l.disbursed_at) AS next_at
  FROM base b JOIN loans l ON l.customer_id = b.customer_id AND l.disbursed_at > b.closed_at
  GROUP BY b.customer_id)
SELECT COUNT(*)                                                                               AS could_churn,
       SUM(CASE WHEN n.next_at <= date(b.closed_at, '+6 months') THEN 1 ELSE 0 END)           AS came_back,
       SUM(CASE WHEN n.next_at IS NULL OR n.next_at > date(b.closed_at, '+6 months') THEN 1 ELSE 0 END) AS churned,
       ROUND(100.0 * SUM(CASE WHEN n.next_at IS NULL OR n.next_at > date(b.closed_at, '+6 months') THEN 1 ELSE 0 END) / COUNT(*), 1) AS churn_pct
FROM base b LEFT JOIN next_loan n ON n.customer_id = b.customer_id;
```

### Тщеславные метрики и метрики для действий :id=vanity-metrics-vs-actionable-metrics

**Что это.** **Тщеславная метрика** (*vanity metric*) растёт, что бы вы ни делали, и из неё не следует никакого решения: всего зарегистрированных клиентов, все кредиты за всё время, установки приложения. **Метрика для действий** (*actionable metric*) может упасть, у неё есть владелец, и её изменение говорит кому-то, что делать.

**Как пишется.** Одни и те же новые клиенты, двумя способами:

```sql
WITH monthly AS (
  SELECT strftime('%Y-%m', registered_at) AS month, COUNT(*) AS new_customers
  FROM customers GROUP BY month),
-- тщеславная: нарастающий итог может только расти
running AS (
  SELECT month, new_customers, SUM(new_customers) OVER (ORDER BY month) AS all_customers
  FROM monthly),
first_loan AS (
  SELECT customer_id, MIN(disbursed_at) AS first_at FROM loans GROUP BY customer_id),
-- для действий: новые клиенты с первым кредитом в течение 60 дней
activated AS (
  SELECT strftime('%Y-%m', c.registered_at) AS month,
         ROUND(100.0 * SUM(CASE WHEN f.first_at >= date(c.registered_at)
                                 AND f.first_at <= date(c.registered_at, '+60 days') THEN 1 ELSE 0 END) / COUNT(*), 1) AS loan_in_60d_pct
  FROM customers c LEFT JOIN first_loan f ON f.customer_id = c.customer_id
  GROUP BY month)
SELECT r.month, r.new_customers, r.all_customers, a.loan_in_60d_pct
FROM running r JOIN activated a ON a.month = r.month
WHERE r.month >= '2026-01' AND r.month <= '2026-07'
ORDER BY r.month;
```

«Всего клиентов» растёт каждый месяц, с 5 183 до 5 820, — даже в июне, когда новых регистраций стало меньше: 104 вместо 119. Доля новых клиентов с первым кредитом в течение 60 дней сдвинулась с 52.0 % в январе до 78.2 % в июле: это число может упасть, и если оно упадёт, кто-то должен действовать.

### Собираем вместе :id=putting-it-together

Камола спрашивает: *«Становится ли приложение лучше в превращении визитов в постоянных клиентов?»* Четыре сегодняшних понятия отвечают на это одним запросом — сессии в приложении по кварталам 2025 года, прослеженные до денег:

```sql
-- единица воронки: сессия в приложении
WITH s AS (
  SELECT application_id, MIN(event_time) AS opened_at,
         MAX(CASE WHEN event_name = 'submit_application' THEN 1 ELSE 0 END) AS submitted
  FROM app_events GROUP BY application_id)
-- период
SELECT strftime('%Y', s.opened_at) || 'Q' || ((CAST(strftime('%m', s.opened_at) AS INTEGER) + 2) / 3) AS quarter,
       -- знаменатель
       COUNT(*)                                                    AS sessions,
       ROUND(100.0 * SUM(s.submitted) / COUNT(*), 1)               AS visit_to_application_pct,
       -- конец воронки
       ROUND(100.0 * COUNT(l.loan_id) / COUNT(*), 1)               AS visit_to_money_pct
FROM s LEFT JOIN loans l ON l.application_id = s.application_id
-- фильтр: закрытые кварталы
WHERE s.opened_at >= '2025-01-01' AND s.opened_at < '2026-01-01'
GROUP BY quarter ORDER BY quarter;
```

Сессий становится больше: с 373 до 526 за квартал; визит → деньги — 51.7 %, 54.0 %, 52.1 % и 56.7 %, лучший квартал — последний. Прочитайте это вопросами раздела. *Определение:* сессии — знаменатель, квартал — период. *Воронка:* две доли — это конверсия от верха до двух шагов. *Протекающие шаги:* если визит → заявка падает, а визит → деньги держится, протекает анкета, а не скоркарта. *Удержание:* воронка охватывает только первый кредит; таблица удержания говорит, возвращаются ли эти заёмщики (2025Q1: 44.5 % в течение года).

## 2. Разобранный пример — дерево метрик за август 2026 (15 мин) :id=2-worked-example-the-metric-tree-for-august-2026-15-min

**Задача:** Бекзод хочет, чтобы выдачи августа были объяснены цепочкой драйверов, у каждого из которых есть владелец.

**Шаг 1 — определения метрик.** До любого запроса напишите карточку определения для каждого множителя. **Период** — август 2026. **Когорта** — заявки, поданные в августе, прослеженные до выдачи (даже если деньги ушли в сентябре). **Активный клиент**: клиент, который в течение месяца подал заявку в любом канале, открыл приложение или имел непогашенный кредит.

**Шаг 2 — дерево метрик.** Пять драйверов, знаменатели которых сцеплены: активные клиенты × доля заявок × доля одобрений × оформление × средний чек. Один запрос возвращает все числители:

```sql
WITH act AS (
  SELECT customer_id FROM applications WHERE applied_at >= '2026-08-01' AND applied_at < '2026-09-01'
  UNION SELECT customer_id FROM app_events WHERE event_time >= '2026-08-01' AND event_time < '2026-09-01'
  UNION SELECT customer_id FROM loans
        WHERE disbursed_at < '2026-09-01' AND (closed_at IS NULL OR closed_at >= '2026-08-01')),
apps AS (
  SELECT a.application_id, a.status, l.principal
  FROM applications a LEFT JOIN loans l ON l.application_id = a.application_id
  WHERE a.applied_at >= '2026-08-01' AND a.applied_at < '2026-09-01')
-- 2 846
SELECT (SELECT COUNT(*) FROM act)                                            AS active_customers,
       -- 649
       COUNT(*)                                                              AS applications,
       -- 392
       SUM(CASE WHEN status IN ('approved', 'approved_not_disbursed') THEN 1 ELSE 0 END) AS approved,
       -- 363
       COUNT(principal)                                                      AS loans,
       -- 23 335 710 000
       SUM(principal)                                                        AS disbursed
FROM apps;
```

**Шаг 3 — проверьте, что дерево перемножается обратно.** Каждый множитель — это числитель ÷ предыдущий числитель, поэтому произведение должно равняться итогу:

| множитель | определение | август 2026 |
|---|---|---|
| активные клиенты | как выше | 2 846 |
| доля заявок | 649 ÷ 2 846 | 22.80 % |
| доля одобрений (дерево) | 392 ÷ 649 | 60.40 % |
| оформление | 363 ÷ 392 | 92.60 % |
| средний чек | 23 335 710 000 ÷ 363 | 64 285 702 |
| **произведение** | 2 846 × 0.2280 × 0.6040 × 0.9260 × 64 285 702 | **23 335 710 000** ✓ |

Произведение равно сумме, выданной по августовским заявкам, с точностью до сума.

**Шаг 4 — воронка внутри дерева.** Одобрение и оформление — два шага **кредитной воронки**. Риск-отчёт скажет: одобрение = 392 ÷ 566 рассмотренных = 69.3 %; дерево использует 60.4 %. Разница — 83 отменённые заявки: **протекающий шаг**, который в дереве сидит внутри «одобрения». Одно название, два знаменателя: пишите карточку определения под обоими числами.

**Шаг 5 — фраза.** *«Августовские заявки дали 363 кредита на 23.3 млрд сум: 2 846 активных клиентов, 22.8 % из которых подали заявку; 60.4 % заявок одобрены, а 92.6 % одобренных выданы, при среднем чеке 64.3 млн.»*

У 15 закрытых кредитов `closed_at` пуст (неделя 3), поэтому по этому определению их клиенты считаются «с остатком долга» навсегда; это не более 15 человек на базу в тысячи — отметьте это и не давайте этому себя остановить.

## 6. Уголок компании <span class="badge company">Дерево метрик кредитной компании</span> :id=6-company-corner-the-metric-tree-of-a-lending-company

Выдачи — «Полярная звезда» продуктовой команды; у **совета директоров** — чистая прибыль. Её дерево, с владельцем каждой ветви (см. [Кто чем занимается](company/roles.md)):

- **ЧИСТАЯ ПРИБЫЛЬ (до налогов)** — *CFO / Финансы (FP&A)*
  - **+ процентный доход** = средний портфель × доходность — *Финансы*
    - средний портфель ← выдачи − погашения − списания — *Портфельный менеджер (Бекзод)*
      - выдачи = активные клиенты × доля заявок × одобрение × оформление × чек
        - активные клиенты, доля заявок, оформление — *Продукт (Камола), маркетинг, управляющие филиалов*
        - доля одобрений — *Риск (Нилуфар): скоркарта и порог отсечения*
        - средний чек — *Портфельный менеджер: лимиты продуктов, структура*
    - доходность ← годовая ставка, структура сроков, досрочные погашения, комиссии — *Продукт + Финансы (ценообразование)*
  - **− стоимость фондирования** = средний портфель × ставка фондирования — *Казначейство / Финансы*
  - **− стоимость риска** = резервы (ожидаемые потери) + списания − возвраты — *Риск + Взыскание*
    - PD ← политика одобрения, структура грейдов, FPD (опережающий сигнал), roll rates — *Риск (Нилуфар)*
    - LGD ← cure rate, возвраты, реструктуризация — *Взыскание (Севара)*
    - EAD ← чек, срок, амортизация — *Портфельный менеджер*
  - **− операционные расходы** ← стоимость привлечения кредита (по каналам), обслуживание, сотрудники взыскания, IT — *Финансы, Операции*

Для чего нужно дерево: **каждый запрос, который вы получаете, — это узел на нём.** Воронка Камолы — левый край выдач; FPD Нилуфар — опережающий край PD; cure rate Севары — это LGD; дашборд Тимура — это дерево, нарисованное страницами. Когда число наверху сдвигается, вы спускаетесь вниз, пока один из дочерних узлов не объяснит изменение, — это в точности лог-разложение из P2, по одному уровню за раз.

### Рост — к предыдущему месяцу и к прошлому году :id=growth-month-on-month-and-year-on-year

**Что это.** **Рост к предыдущему месяцу** (*month-on-month*, MoM) сравнивает месяц с месяцем до него. **Рост к прошлому году** (*year-on-year*, YoY) сравнивает его с тем же месяцем годом раньше. YoY — честное сравнение, когда месяцы различаются: у того же месяца столько же дней, те же праздники и тот же сезон.

**Как пишется.**

```text
MoM = этот месяц ÷ предыдущий − 1
YoY = этот месяц ÷ тот же месяц
      годом раньше − 1
```

`LAG(x)` читает предыдущий месяц, а `LAG(x, 12)` — месяц на 12 строк выше (W3D2). Последние шесть закрытых месяцев:

```sql
-- только закрытые месяцы: в октябре 2026 пока один день
WITH m AS (
  SELECT strftime('%Y-%m', disbursed_at) AS month,
         SUM(principal)                  AS disbursed
  FROM loans
  WHERE disbursed_at < '2026-10-01'
  GROUP BY 1),
g AS (
  SELECT month, ROUND(disbursed / 1e9, 2) AS bn,
         -- к предыдущему месяцу: строка выше
         ROUND(100.0 * (disbursed - LAG(disbursed) OVER (ORDER BY month))
               / LAG(disbursed) OVER (ORDER BY month), 1) AS mom_pct,
         -- к прошлому году: на 12 строк выше
         ROUND(100.0 * (disbursed - LAG(disbursed, 12) OVER (ORDER BY month))
               / LAG(disbursed, 12) OVER (ORDER BY month), 1) AS yoy_pct
  FROM m)
-- фильтр показа снаружи, чтобы LAG ещё видел 2025 год
SELECT * FROM g WHERE month >= '2026-04' ORDER BY month;
```

Шесть строк. Рост к предыдущему месяцу четыре раза меняет знак: от −23.7 % (сентябрь) до +28.9 % (июль). Рост к прошлому году положителен в каждой строке: от +16.2 % до +114.4 %. Эти +114.4 % в мае говорят о слабом мае 2025 года не меньше, чем о мае 2026.

То же в pandas: `pct_change()` — для строки выше, `shift(12)` — для строки на 12 выше (W5D4).

```python
import sqlite3
import pandas as pd

con = sqlite3.connect("data/raw/nur.db")
m = pd.read_sql("""
    SELECT strftime('%Y-%m', disbursed_at) AS month,
           SUM(principal) AS disbursed, COUNT(*) AS loans
    FROM loans WHERE disbursed_at < '2026-10-01'
    GROUP BY 1 ORDER BY 1""", con, index_col="month")
# к предыдущему месяцу: строка выше
m["mom_pct"] = (m["disbursed"].pct_change() * 100).round(1)
# к прошлому году: строка на 12 выше
m["yoy_pct"] = ((m["disbursed"] / m["disbursed"].shift(12) - 1) * 100).round(1)
```

### Сезонность — одни и те же месяцы высоко или низко каждый год :id=seasonality-the-same-months-high-or-low-every-year

**Что это.** **Сезонность** (*seasonality*) — узор, который повторяется вместе с календарём: одни и те же месяцы каждый год высоко или низко. **Сезонный индекс** (*seasonal index*) выражает её числом: среднее этого месяца ÷ среднее всех месяцев. Индекс 1.10 значит «обычно на 10 % выше типичного месяца», 0.90 — на 10 % ниже.

**Как пишется.**

```text
сезонный индекс (март)
  = среднее всех мартов
  ÷ среднее всех месяцев
```

Nur растёт примерно на 47 % в год, поэтому сначала уберите рост. Сравните каждый месяц с **12 месяцами вокруг него**: шесть до, сам месяц, пять после. Каждый календарный месяц входит в это окно один раз, поэтому его среднее несёт уровень, а не сезон. Затем усредните отношения по каждому календарному месяцу:

```sql
WITH m AS (
  SELECT strftime('%Y-%m', disbursed_at) AS month,
         SUM(principal)                  AS disbursed
  FROM loans
  WHERE disbursed_at < '2026-10-01'
  GROUP BY 1),
w AS (
  SELECT month, disbursed,
         -- уровень: 12 месяцев вокруг этого
         AVG(disbursed) OVER (ORDER BY month ROWS BETWEEN 6 PRECEDING AND 5 FOLLOWING) AS level,
         COUNT(*)       OVER (ORDER BY month ROWS BETWEEN 6 PRECEDING AND 5 FOLLOWING) AS months_in
  FROM m)
-- одна строка на календарный месяц
SELECT substr(month, 6, 2)              AS mo,
       COUNT(*)                         AS years,
       ROUND(MIN(disbursed / level), 2) AS lowest,
       ROUND(MAX(disbursed / level), 2) AS highest,
       ROUND(AVG(disbursed / level), 2) AS seasonal_index
FROM w
-- только полные окна
WHERE months_in = 12
GROUP BY mo ORDER BY mo;
```

### Скользящее среднее — глаже, но на месяц позже :id=moving-average-smoother-and-a-month-late

**Что это.** **Скользящее среднее** (*moving average*, W3D1) заменяет каждый месяц средним его и месяцев прямо перед ним. Трёхмесячное среднее сглаживает бо́льшую часть шума отдельных месяцев. Оно смотрит только назад, поэтому **запаздывает**: поворачивает примерно на месяц позже настоящей линии.

**Как пишется.**

```text
3-месячное среднее (сентябрь)
  = (июль + август + сентябрь) ÷ 3
```

```sql
WITH m AS (
  SELECT strftime('%Y-%m', disbursed_at) AS month,
         SUM(principal)                  AS disbursed
  FROM loans
  WHERE disbursed_at < '2026-10-01'
  GROUP BY 1),
a AS (
  SELECT month, ROUND(disbursed / 1e9, 2) AS bn,
         -- этот месяц и два до него
         ROUND(AVG(disbursed) OVER (ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) / 1e9, 2) AS ma3_bn
  FROM m)
SELECT * FROM a WHERE month BETWEEN '2025-07' AND '2025-12' ORDER BY month;
```

В pandas это `m["disbursed"].rolling(3).mean()` (W5D4).

**Что это.** **Прогноз** (*forecast*) угадывает будущие месяцы по прошлым. Четыре простых метода: **наивный** (каждый месяц вперёд = последний известный месяц), **сезонный наивный** (каждый месяц = тот же месяц годом раньше), **среднее за последние 3 месяца** и **линейный тренд** (прямая, которая проходит ближе всего к прошлым месяцам, продолженная вперёд). **Проверка на отложенных данных** (*holdout test*) прячет последние месяцы, прогнозирует их по месяцам до этого и измеряет промах: **MAE** — средний промах в сумах, **MAPE** — средний промах в % от факта.

**Как пишется.**

```text
промах = прогноз − факт
MAE    = среднее |промаха|
MAPE   = среднее |промаха| ÷ факт
```

Спрячьте апрель–сентябрь 2026 и дайте четырём методам спрогнозировать их по 27 месяцам до этого:

```python
import sqlite3
import numpy as np
import pandas as pd

con = sqlite3.connect("data/raw/nur.db")
m = pd.read_sql("""
    SELECT strftime('%Y-%m', disbursed_at) AS month,
           SUM(principal) AS disbursed
    FROM loans WHERE disbursed_at < '2026-10-01'
    GROUP BY 1 ORDER BY 1""", con)
y = m["disbursed"].to_numpy() / 1e9
# спрятать последние H месяцев: это проверка
H = 6
train, test = y[:-H], y[-H:]
n = len(train)
# прямая через месяцы обучения
slope, start = np.polyfit(np.arange(n), train, 1)
forecasts = {
    "naive": np.repeat(train[-1], H),
    "seasonal naive": y[n - 12:n - 12 + H],
    "average of last 3": np.repeat(train[-3:].mean(), H),
    "straight line": start + slope * np.arange(n, n + H),
}
mape = {}
for name, f in forecasts.items():
    mae = np.mean(np.abs(f - test))
    mape[name] = np.mean(np.abs(f - test) / test) * 100
    print(f"{name:18} MAE {mae:.2f} bn   MAPE {mape[name]:.1f} %")
```

```sql
FROM q
ORDER BY quarter;
```
