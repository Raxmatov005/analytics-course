### Ответ по STAR — ситуация, задача, действие, результат :id=the-star-answer-situation-task-action-result

**Что это.** **STAR** — форма рассказа о вашей работе: **S**ituation — ситуация (кому что было нужно и зачем), **T**ask — задача (что именно вы должны были сдать), **A**ction — действие (что вы сделали — метод, а не только инструмент), **R**esult — результат (число и то, что из-за него изменилось). По этой форме интервьюеры оценивают ответы на «расскажите о случае, когда…» и разбор резюме.

**Как пишется.** Одно предложение на букву; в результате — число, которое вы можете доказать:

| Буква | Предложение |
|---|---|
| S | Остаток долга у Бекзода не совпадал с книгой Финансов. |
| T | Найти разницу до отправки отчётного пакета за месяц. |
| A | Сверил платежи с платежами по графику; нашёл строки с одинаковыми платежом по графику, датой и суммой; построил очищенное представление. |
| R | 25 строк-дублей, 58 397 800 сумов посчитаны дважды; все отчёты с тех пор используют очищенные платежи. |

Строка R берётся из запроса, а не из памяти:

```sql
SELECT COUNT(*) AS duplicate_rows, SUM(amount) AS counted_twice
FROM (SELECT amount,
             ROW_NUMBER() OVER (PARTITION BY installment_id, paid_at, amount ORDER BY payment_id) AS rn
      FROM payments)
WHERE rn > 1;  -- каждая копия после первой
```

### Привычки на живом SQL — думайте вслух, проверяйте, называйте ловушку :id=live-sql-habits-think-aloud-check-name-the-trap

**Что это.** На живой задаче по SQL интервьюер оценивает **процесс** не меньше, чем запрос. Пять привычек: **повторите** задачу и задайте один уточняющий вопрос; **назовите таблицы и гранулярность**; **пишите маленькими шагами** и запускайте каждый; **сверьте** результат с числом, которое вы уже знаете; **назовите ловушку**, которую вы обошли.

**Как пишется.** Добавьте проверку прямо в запрос, чтобы она была на экране, когда вы о ней говорите:

```sql
-- задача: кредиты и сумма выдач в сентябре 2026 по каналам
-- гранулярность: один кредит, таблицы: loans → applications (ради канала)
SELECT a.channel, COUNT(*) AS loans, SUM(l.principal) AS disbursed
FROM loans l JOIN applications a ON a.application_id = l.application_id
-- полуоткрытый интервал: без BETWEEN по датам
WHERE l.disbursed_at >= '2026-09-01' AND l.disbursed_at < '2026-10-01'
GROUP BY a.channel
UNION ALL
-- проверка: известный итог сентября
SELECT 'TOTAL', COUNT(*), SUM(principal)
FROM loans
WHERE disbursed_at >= '2026-09-01' AND disbursed_at < '2026-10-01';
```

branch — 172 кредита, app — 123, partner — 66; строка итога показывает 361 кредит и 17 015 490 000 сумов — это контрольное число 6, значит, соединение ничего не потеряло.

| Привычка | Что вы говорите |

| повторить | «Итак: одна строка на канал, сентябрь 2026, количество и сумма — кредиты, а не заявки?» |

### Метод кейса — реально ли это, насколько велико, где, почему, что делать :id=the-case-method-is-it-real-how-big-where-why-what-now

**Что это.** **Кейс** — открытый бизнес-вопрос («FPD вырос вдвое — что вы делаете?»). **Метод кейса** отвечает на него за пять шагов, в таком порядке: **реально ли это?** (то же определение, тот же период, достаточно кредитов), **насколько велико?** (штуки, а не только доли), **где?** (разбиение MECE: продукт, канал, грейд, версия, регион, сотрудник), **почему?** (событие: смена политики, сбой, кампания, мошенничество), **что делать?** (рекомендация и мониторинг).

**Как пишется.** Первые два шага — это запрос. FPD30 в приложении по месяцу, в котором наступил срок первого платежа:

```sql
-- очищенные платежи
WITH pay AS (
  SELECT installment_id, paid_at, amount FROM (
    SELECT installment_id, paid_at, amount,
           ROW_NUMBER() OVER (PARTITION BY installment_id, paid_at, amount ORDER BY payment_id) AS rn
    FROM payments) WHERE rn = 1),
-- первые платежи по графику, достаточно зрелые для оценки
first_inst AS (
  SELECT i.loan_id, i.due_date, i.total_due, COALESCE(SUM(p.amount), 0) AS paid_in_30
  FROM installments i
  LEFT JOIN pay p ON p.installment_id = i.installment_id
                 AND p.paid_at <= date(i.due_date, '+30 days') AND p.paid_at <= '2026-10-01'
  WHERE i.installment_no = 1 AND i.due_date <= '2026-09-01'
  GROUP BY i.loan_id, i.due_date, i.total_due)
SELECT strftime('%Y-%m', f.due_date) AS due_month,
       COUNT(*)                                                         AS loans,
       SUM(CASE WHEN f.paid_in_30 < f.total_due THEN 1 ELSE 0 END)      AS fpd30,
       ROUND(100.0 * SUM(CASE WHEN f.paid_in_30 < f.total_due THEN 1 ELSE 0 END) / COUNT(*), 2) AS fpd30_pct
FROM first_inst f
JOIN loans l    ON l.loan_id = f.loan_id
JOIN products p ON p.product_id = l.product_id
WHERE p.channel = 'app' AND f.due_date >= '2026-03-01'
GROUP BY due_month ORDER BY due_month;
```

FPD30 «вырос вдвое» с июля на август: с 0.74 % до 1.64 %. В штуках это 1 кредит из 136 против 2 из 122. Один лишний дефолт на сотню кредитов — не кризис, а повод наблюдать дальше, с интервалом.

**Когда применять.**
- B3 и любой вопрос вида «X вырос/упал — что вы делаете?».
- На работе: половина «кризисов» недели у кредитора — это один лишний дефолт, смена определения или сбой платежей.

> ⚠️ **Осторожно.** Перескочить к «почему» («новая версия приложения с багом») раньше, чем к «реально ли» и «насколько велико», — самый частый способ провалить кейс. Сначала проверьте штуки, вслух.

### Как продолжать учиться (бесплатно) :id=how-to-keep-learning-free

- **Практика SQL:** SQLBolt (интерактивные основы), **Mode SQL Tutorial** (mode.com/sql-tutorial — аналитический SQL с оконными функциями), задачи «Database» на HackerRank и LeetCode (в стиле собеседований), StrataScratch (бесплатные вопросы с настоящих собеседований в компаниях); и полный курс Data with Baraa (опорный курс SQL) для повторения.
- **Python:** Kaggle Learn (kaggle.com/learn — Pandas, Data Visualization, Intro to Machine Learning), затем по одному публичному датасету Kaggle в месяц, разобранному от начала до конца как ноутбук.
- **Статистика:** **StatQuest** с Джошем Стармером (YouTube) — p-значения, доверительные интервалы, мощность, логистическая регрессия в наглядном объяснении.
- **Power BI:** учебный путь **Power BI Data Analyst** от Microsoft Learn (learn.microsoft.com — бесплатный путь к сертификату PL-300) и его модули по DAX.
