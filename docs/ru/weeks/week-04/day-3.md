## 1. Изучение — очистка — это конвейер, даже когда это формула :id=1-learn-cleaning-is-a-pipeline-even-when-it-is-a-formula

### Как выглядят грязные данные — чек-лист :id=what-dirty-data-looks-like-a-checklist

**Что это.** **Грязные данные** (dirty data) — это значения, которые означают одно и то же, но записаны по-разному, или невозможные значения. Восемь видов покрывают почти любую выгрузку:

| Вид | Пример выше | Сколько в понедельничных файлах |
|---|---|---|
| **Лишние пробелы** | `Yulduz␣`, `CASH␣` | 18 имён; 30 платежей `CASH ` |
| **Регистр** | `MALIKA`, `jalilova`, `PayMe` | 22 имени заглавными, 40 фамилий строчными; 123 платежа с `Card` / `Click` / `PayMe` |
| **Синонимы** | `bank transfer` = `transfer` | 27 платежей |
| **Дубликаты** | 4516 = 6001; платёж 7172 = 52859 | 40 человек; 25 платежей |
| **Невозможные значения** | рождён 2031-04-12, рождён 1900-01-01, зарегистрирован 2027-01-09 | 7 дат рождения; 5 дат регистрации после даты отсчёта |
| **Числа, хранящиеся как текст** | телефон `+998…`, прочитанный как число, теряет `+` | каждый телефон, если тип неверный |
| **Даты, хранящиеся как текст** | `2024-04-03`, которая не сортируется и не сравнивается как дата | каждый столбец дат в CSV, пока ему не задан тип |
| **Пропуски** | пустой `monthly_income` | 356 клиентов; 388 заявок без `credit_score` |

**Как пишется.** По одной формуле на вид, на сыром листе, до того как вы что-либо меняете:

```excel
=SUMPRODUCT(--(LEN(B2:B6041)<>LEN(TRIM(B2:B6041))))     лишние пробелы → 18
=SUMPRODUCT(--EXACT(C2:C6041, LOWER(C2:C6041)))         написано целиком строчными → 40
=ROWS(UNIQUE(F2:F52876))                                различные сырые способы оплаты (Payments)
=COUNTBLANK(I2:I6041)                                   пропуски в monthly_income → 356
=SUMPRODUCT(--ISTEXT(E2:E6041))                         даты, хранящиеся как текст → должно быть 0
```

**Когда применять.**
- Первым делом с любым новым файлом: посчитайте каждый вид и запишите числа. Они станут вашим журналом изменений.
- После очистки: те же формулы на чистой таблице должны дать 0.

### Найти и заменить — Ctrl+H :id=find-replace-ctrlh

**Что это.** **Найти и заменить** (Find & Replace) меняет каждое вхождение одного текста на другой — в выделении, на листе или во всей книге. Это разовая правка: ничего не записывается, и следующий файл её не получит.

**Как пишется.**

```text
Ctrl+H
  Найти:           bank transfer
  Заменить на:     transfer
  Параметры ▸  Учитывать регистр        выкл.: card находит и Card, и CARD
               Ячейка целиком           вкл.: card не находит discard
               Искать: на листе / в книге
  Заменить все  →  «Произведено замен: 27»   ← запишите это число
```

Картинка — `method` до и после:

| до | после («Ячейка целиком» включено) |
|---|---|
| bank transfer | transfer |
| transfer | transfer |
| card | card |

На копии `Payments` прогон сообщает **27** замен: 27 строк `bank transfer`. В поле «Найти» работают подстановочные знаки: `*` — любой текст, `?` — один символ, `~*` — настоящая звёздочка.

**Когда применять.**
- Быстрый взгляд на **копии**: сколько строк с таким написанием?
- Разовый файл, который вы больше никогда не получите.

> ⚠️ **Осторожно.** Замена `" "` (пробела) на пустоту — это не `TRIM`: она удаляет и пробел *между* словами. `Malika Jalilova` превращается в `MalikaJalilova`.

### Текст по столбцам — один столбец на несколько :id=text-to-columns-split-one-column-into-several

**Что это.** **Текст по столбцам** (Text to Columns) делит каждую ячейку одного столбца на несколько столбцов — по **разделителю** (пробел, запятая, `|`) или по фиксированной ширине. Данные → Текст по столбцам. Это разовая правка на листе.

**Как пишется.**

```text

  Шаг 3  столбец 1 → Дата: ГМД (YMD)    столбец 2 → Общий
         Поместить в: ПУСТОЙ столбец    (разбиение перезаписывает столбцы справа)
```

| applied_at (до) | → дата | → время |
|---|---|---|
| 2025-06-02 10:35:00 | 2025-06-02 | 10:35:00 |
| 2026-09-30 21:36:00 | 2026-09-30 | 21:36:00 |

### Мгновенное заполнение — Excel угадывает образец :id=flash-fill-excel-guesses-the-pattern

**Что это.** **Мгновенное заполнение** (Flash Fill, Ctrl+E) заполняет столбец по одному-двум примерам, которые вы ввели. Excel выводит образец и пишет **значения**, а не формулы.

**Как пишется.**

```text
B: first_name   H (новый столбец)
MALIKA          Malika        ← вы вводите один пример
Yulduz␣         Yulduz        ← Ctrl+E заполняет остальное
Nodir           Nodir
```

На `Customers` ввод `Malika` рядом со строкой 6001 и Ctrl+E заполняют все 6 040 строк именем с заглавной буквы. Никакой формулы не остаётся.

**Когда применять.**
- Разовый взгляд: инициалы, код, вырезанный из длинного текста, переставленное имя.
- Никогда для файла, который возвращается каждый понедельник: следующий файл ничего не получит.

| | Мгновенное заполнение | Формула (`=PROPER(TRIM(B2))`) |
|---|---|---|
| оставляет | значения | правило |
| строки следующего понедельника | пустые | заполняются протягиванием, в таблице — автоматически |
| можно проверить? | только сравнением | да, прочитав формулу |

> ⚠️ **Осторожно.** Мгновенное заполнение может угадать *другое* правило, чем вы имели в виду, и всё равно выглядеть верно на первом экране. Сравните его столбец с формулой и посчитайте расхождения, прежде чем доверять.

### TRIM, CLEAN, SUBSTITUTE — починка текста формулами :id=trim-clean-substitute-repairing-text-with-formulas

**Что это.** Починка текста формулой на чистой вкладке, чтобы она запускалась заново. **TRIM** (*СЖПРОБЕЛЫ*) убирает пробелы по краям и двойные пробелы внутри. **CLEAN** (*ПЕЧСИМВ*) убирает непечатаемые символы — переносы строк и табуляции из копирования. **SUBSTITUTE** (*ПОДСТАВИТЬ*) заменяет один текст другим внутри ячейки. **LOWER**, **UPPER** и **PROPER** исправляют регистр (День 1).

**Как пишется.**

```excel
=TRIM(B2)                                        "Yulduz "  → "Yulduz"
=CLEAN(B2)                                       убирает переносы строк и табуляции
=SUBSTITUTE(text, old, new)                      каждое "old" внутри text становится "new"
=LOWER(TRIM(F2))                                 "CASH "  → "cash";  "PayMe" → "payme"
=SUBSTITUTE(LOWER(TRIM(F2)), "bank transfer", "transfer")              один синоним
=SUBSTITUTE(SUBSTITUTE(LOWER(TRIM(F2)), "bank transfer", "transfer"), "pay me", "payme")
                                                 вложенная: результат внутренней идёт во внешнюю
=TRIM(CLEAN(SUBSTITUTE(B2, CHAR(160), " ")))     неразрывные пробелы (CHAR 160) переживают TRIM
```

Картинка — `method` шаг за шагом:

| сырое | `LOWER(TRIM())` | `SUBSTITUTE(…, "bank transfer", "transfer")` |
|---|---|---|
| `CASH␣` | cash | cash |
| PayMe | payme | payme |
| bank transfer | bank transfer | transfer |
| card | card | card |

На `Payments`: 10 различных сырых способов оплаты. После полной формулы `=ROWS(UNIQUE(…))` → **5**: card, cash, transfer, payme, click.

**Когда применять.**
- Любой текст, который вы будете сравнивать, считать или сопоставлять: способы оплаты, имена, регионы.
- Вложенный `SUBSTITUTE` — для короткого списка синонимов; для длинного — таблица соответствий и поиск (День 2).

> ⚠️ **Осторожно.** `PROPER` делает заглавной букву после любого не-буквенного символа: `"payme"` → `"Payme"`, `"o'neil"` → `"O'Neil"`. Применяйте его к именам людей, а не к кодам.

### Даты, хранящиеся как текст — ISNUMBER, DATEVALUE, локаль :id=dates-stored-as-text-isnumber-datevalue-locale

**Что это.** Настоящая дата — это число (День 1). **Дата, хранящаяся как текст** (date stored as text), только похожа на дату: прижата влево, сортируется как текст и пропускается любым условием по дате. **DATEVALUE** (*ДАТАЗНАЧ*) превращает текст-дату в настоящую дату. **ISNUMBER** / **ISTEXT** показывают, что именно лежит в ячейке.

**Как пишется.**

```excel
=ISNUMBER(E2)                    TRUE = настоящая дата, FALSE = текст
=DATEVALUE(E2)                   "1981-08-15" → 29813 (формат ячейки «дата» → 1981-08-15)
=VALUE(E2)                       то же самое
=SUMPRODUCT(--ISTEXT(E2:E6041))  текстовые даты во всём столбце — должно быть 0
```

Как Excel читает введённый текст, зависит от **локали** (региональной настройки Windows):

| введено | локаль США (сначала месяц) | локаль «сначала день» (Россия, Великобритания) |
|---|---|---|
| `2026-03-14` | 14 марта 2026 | 14 марта 2026 |
| `03/04/2026` | 4 марта 2026 | 3 апреля 2026 |
| `14/03/2026` | **текст** — 14-го месяца нет | 14 марта 2026 |
| `14.03.2026` | **текст** | 14 марта 2026 |

Только ISO `yyyy-mm-dd` читается везде одинаково. Наши CSV используют его.

**Невозможные даты** — это настоящие даты, которые не могут быть правдой. В `customers_dirty.csv` невозможны **7** дат рождения: четыре в будущем (`2031-04-12`, `2027-02-28`) и три — `1900-01-01`, заглушка «даты нет». **5** клиентов зарегистрированы после даты отсчёта 2026-10-01.

**Когда применять.**
- Каждый столбец дат импортированного файла: `ISNUMBER` по всему столбцу до любой формулы с датами.
- Невозможные даты: очистите их и добавьте столбец-флаг. Никогда не придумывайте правдоподобную дату.

> ⚠️ **Осторожно.** Худший случай — столбец, преобразованный **наполовину**: в локали США `03/04/2026` становится датой, а `14/03/2026` остаётся текстом. Итоги занижены ровно на текстовые строки, а лист выглядит нормально.

### Ключ сопоставления — один текст, который значит «тот же человек» :id=a-matching-key-one-text-that-means-the-same-person

**Что это.** **Ключ сопоставления** (matching key) — это один текст, собранный из столбцов, которые определяют строку, и очищенный так, чтобы одинаковое давало одинаковый ключ: обрезанный, в одном регистре, с **разделителем** между частями.

**Как пишется.**

```excel
=LOWER(TRIM(B2)) & "|" & LOWER(TRIM(C2)) & "|" & TEXT(E2, "yyyy-mm-dd")
 first_name         разд.  last_name         разд.  birth_date как текст
```

| customer_id | ключ |
|---|---|
| 4516 | `malika|jalilova|1981-08-15` |
| 6001 | `malika|jalilova|1981-08-15` |
| 44 | `yulduz|karimova|1988-07-12` |
| 6005 | `yulduz|karimova|1988-07-12` |

У 4516 и 6001 теперь один ключ; у 44 и 6005 тоже. Второй ключ по `phone|birth_date` использует идентифицирующие поля: `=D2&"|"&TEXT(E2,"yyyy-mm-dd")`.

**Когда применять.**
- Перед подсчётом или удалением дубликатов: ключ *и есть* ваше определение «того же самого».
- Платежи: `installment_id|paid_at|amount` — тот же платёж по графику, оплаченный в тот же день, на ту же сумму.

> ⚠️ **Осторожно.** Без разделителя разные части могут склеиться в один ключ: `"Ali"&"Nazarov"` = `"Alin"&"azarov"` = `AliNazarov`. Всегда ставьте `"|"` между частями.

### COUNTIFS по ключу — найдите дубликаты, прежде чем удалять :id=countifs-on-the-key-find-duplicates-before-you-remove-them

**Что это.** Два столбца `COUNTIFS` по ключу показывают каждый дубликат **до того**, как что-либо удалено. **n** — сколько строк имеют этот ключ. **rank** — какая это копия: 1 для первой, 2 для повтора — `ROW_NUMBER() OVER (PARTITION BY key)` в Excel.

### Удалить дубликаты — и почему оно врёт :id=remove-duplicates-and-why-it-lies

**Что это.** **Удалить дубликаты** (Remove Duplicates, Данные → Удалить дубликаты) удаляет строки, равные по отмеченным столбцам. Оставляет **первую** строку каждой группы и сообщает только, *сколько* удалено. Сравнивает **без учёта регистра**, но **с учётом пробелов**.

**Как пишется.**

```text
выделите таблицу → Данные → Удалить дубликаты
  ☑ installment_id   ☑ paid_at   ☑ amount     ← столбцы, которые определяют «то же самое»
  ☐ payment_id ☐ method …                      ← не отмечайте то, что всегда различается
  OK → «Найдено и удалено повторяющихся значений: 25; осталось уникальных значений: 52 850»
```

| payment_id | installment_id | paid_at | amount | остаётся? |
|---|---|---|---|---|
| 7172 | 12040 | 2024-12-26 | 253 400 | да — первая |
| 52859 | 12040 | 2024-12-26 | 253 400 | удалена |

Почему оно врёт — на `Customers`:

| Отмеченные столбцы | Что происходит |
|---|---|
| first_name, last_name, birth_date (сырые) | регистр игнорируется, пробелы нет: `Yulduz␣` выживает — удалено слишком мало |
| то же после `TRIM` | уходят все настоящие дубликаты — **и** две пары разных людей с одинаковыми именем и датой рождения |
| phone, birth_date | ровно 40 настоящих дубликатов |
| все столбцы | удалено 0 — `customer_id` всегда различается |

**Когда применять.**
- На **копии**, чтобы проверить число, которое вы уже посчитали через `COUNTIFS`.
- Окончательное удаление — это записанный шаг Power Query (ниже).

> ⚠️ **Осторожно.** Инструмент никогда не говорит, *какие* строки ушли, и вернуть их можно только Ctrl+Z. Сначала посчитайте строки с `rank = 2`; если число инструмента другое, не сохраняйте.

### Power Query — загрузка, шаги, выгрузка :id=power-query-load-steps-load-back

**Что это.** **Power Query** (*Получить и преобразовать*, Get & Transform) импортирует файл и очищает его **записанными шагами**. Каждый щелчок становится шагом в панели **Примененные шаги** (Applied Steps). **Обновить** (Refresh) перечитывает файл и повторяет все шаги. Это версия SQL-представления в Excel.

**Как пишется.**

```text
Данные → Получить данные → Из файла → Из текстового/CSV-файла → payments_dirty.csv → Преобразовать данные
                                                                        │
   Редактор Power Query ───────────────────────────────────────────────┘
     предпросмотр строк             Примененные шаги (панель справа)
                                      Source
                                      Promoted Headers
                                      Changed Type
                                      … по шагу на каждый щелчок …
   Главная → Закрыть и загрузить  →  таблица на новом листе
```

Каждый шаг — одна строка на **M**, языке запросов, она видна в строке формул — это схема, вводить её не нужно:

```text
= Table.SelectRows(#"Changed Type", each [paid_at] <= #date(2026, 10, 1))
  функция           предыдущий шаг       условие
```

Писать на M не нужно. Нужно читать его настолько, чтобы видеть, что делает шаг. Правый щелчок по шагу → *Переименовать*, чтобы панель читалась как журнал изменений: `Trim method`, `bank transfer → transfer`, `Drop 25 duplicates`.

**Когда применять.**
- Любой файл, который придёт снова: понедельничная выгрузка, ежемесячный файл банка.
- Power Query нужен Excel для Windows или Microsoft 365. В **Sheets** его нет: там конвейер — это чистая вкладка формул (`ARRAYFORMULA`, `UNIQUE`, `QUERY`), которая пересчитывается, когда новый CSV импортируется поверх сырой вкладки.

> ⚠️ **Осторожно.** Шаги выполняются по порядку, сверху вниз. Вставьте шаг в середину — и каждый следующий шаг работает с его результатом; после любого изменения проверьте число строк на последнем шаге.

### Изменение типа — первый шаг после заголовков :id=change-type-the-first-step-after-the-headers

**Что это.** **Изменение типа** (Change Type) задаёт тип каждого столбца: целое число, десятичное число, дата, текст. Это `CAST` из SQL. Power Query угадывает типы при импорте; вы проверяете каждую догадку.

**Как пишется.**

```text
щёлкните значок типа в заголовке столбца (ABC / 123 / календарь) → выберите
M: = Table.TransformColumnTypes(#"Promoted Headers", {{"paid_at", type date}, {"amount", Int64.Type}, {"phone", type text}})
```

| столбец | неверная догадка | верный тип | почему |
|---|---|---|---|
| `paid_at` | Текст | Дата | фильтрам по дате и группировке по месяцам нужна дата |
| `amount` | Текст | Целое число | суммы |
| `phone` | Целое число | **Текст** | `+998902031105` как число теряет `+`; телефон — идентификатор, а не количество |
| `installment_id` | Целое число | Целое число | ключ, который соединяется с `installments` |

**Когда применять.**
- Сразу после *Promoted Headers*, до любого другого шага. Текстовым шагам нужны текстовые столбцы, фильтрам по дате — столбцы дат.

> ⚠️ **Осторожно.** Шаг `Trim` на столбце с числовым типом ничего не делает и не показывает ошибки. Фильтр по дате на текстовом столбце не работает. Сначала типы.

### Удалить дубликаты — записанный шаг :id=remove-duplicates-the-recorded-step

**Что это.** То же удаление, что и кнопка, но в виде шага. Выделите столбцы ключа, затем Главная → Удалить строки → Удалить дубликаты. Оставляет первую строку каждой группы, как `ROW_NUMBER() … WHERE rn = 1`.

**Как пишется.**

```text
Ctrl+щелчок по installment_id, paid_at, amount → Главная → Удалить строки → Удалить дубликаты
```

### Группировка — GROUP BY в Power Query :id=group-by-group-by-in-power-query

**Что это.** **Группировать по** (Group By, Преобразование → Группировать по) сворачивает строки в одну строку на ключ, с агрегатами: сумма, число строк, минимум, максимум, среднее. Это `GROUP BY` из SQL.

**Как пишется.**

```text
Преобразование → Группировать по → Подробнее
  группировать по:  method
  новый столбец: payments = Количество строк
  новый столбец: amount   = Сумма по amount
M: = Table.Group(#"Removed Duplicates", {"method"}, {{"payments", each Table.RowCount(_)}, {"amount", each List.Sum([amount])}})
```

|---|---|---|---|---|

| cash · 50 | | cash | 1 | 50 |

### Отмена свёртывания — широкие столбцы в строки :id=unpivot-wide-columns-into-rows

**Что это.** **Отменить свёртывание столбцов** (*отменить свёртывание*, Unpivot) превращает много столбцов значений в два столбца — **Атрибут** (бывший заголовок) и **Значение** — по строке на каждую бывшую ячейку. Так отчёт снова становится правильной таблицей (День 1).

### Закрыть и загрузить, Обновить :id=close-load-and-refresh

**Что это.** **Закрыть и загрузить** (Close & Load) записывает результат запроса в книгу. **Обновить** (Данные → Обновить все, Ctrl+Alt+F5) перечитывает исходный файл и повторяет все шаги.

### Ошибки, которые стоят балла на этой неделе :id=mistakes-that-cost-a-point-this-week

- Очистка сырого листа на месте с сохранением — свидетельство потеряно; сырое остаётся сырым.
- «Удалить дубликаты» по всем столбцам («для надёжности») — удалено 0, потому что идентификаторы различаются.
- «Удалить дубликаты» по нестрогому ключу без предварительного подсчёта — удалены настоящие люди (P8).
- `TRIM` не применён до сопоставления — дубликаты с пробелом в конце выживают.
- Текстовые преобразования над столбцом, всё ещё имеющим в Power Query тип «число», — ничего не происходит, ошибки нет.
- Телефон с числовым типом — `+` пропал, и ключ больше не совпадает с другим файлом.
- Merge с Left Outer по умолчанию, когда вы имели в виду Inner (или наоборот), — считайте строки после каждого слияния.
- Замена недостоверной даты правдоподобной — пропуск + флаг, никогда не догадка.
- Журнал изменений, перечисляющий инструменты («использовал Power Query») вместо изменений («удалил 25 дублирующихся платежей по installment_id + paid_at + amount, Σ 58 397 800»).

## 6. Уголок компании <span class="badge company">Уровень сбора по месяцам</span> :id=6-company-corner-collection-rate-by-month

**Уровень сбора** = сумма **собранного** ÷ сумма **к получению** за период. Третья неделя дала 94.1 % за сентябрь 2026 по `v_payments_clean` + `installments`; сегодня вы воспроизводите это по очищенным файлам, в Power Query (или сводной таблицей по объединённой таблице) и пишете определение под ним.

**Определение (наше):** для платежей по графику, **наступающих в месяце** (`due_date` в месяце, полуоткрыто), собрано = оплаты по этим платежам по графику с `paid_at <= 2026-10-01` из `payments_clean` (дубликаты удалены, строки с датой в будущем исключены фильтром даты отсчёта); ставка = Σ собрано ÷ Σ `total_due`.

```
Query  paid_by_installment   payments_clean → Filter paid_at <= 2026-10-01 → Group By installment_id: paid = Sum(amount)
Query  installments_paid     installments.csv → Merge paid_by_installment (Left Outer, installment_id) → expand paid → Replace null → 0
                             → Add Column → Date → Month → Start of Month (from due_date) as due_month
Query  collection_by_month   installments_paid → Group By due_month: due = Sum(total_due), paid = Sum(paid), instalments = Count Rows
                             → Add Column → Custom: rate = [paid] / [due]      → Close & Load
```
