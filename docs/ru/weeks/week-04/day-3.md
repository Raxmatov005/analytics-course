## 1. Изучение — очистка — это конвейер, даже когда это формула :id=1-learn-cleaning-is-a-pipeline-even-when-it-is-a-formula

### Правило очистки с первой недели, ещё раз :id=the-cleaning-rule-from-week-1-again

Никогда не чистите единственную копию. В SQL вы чистили *по пути наружу* (представление); в Excel эквивалент — **чистый лист, построенный из сырого листа** формулами или запросом: сырой лист остаётся как свидетельство, а очистка повторяема. Всё, что вы делаете с сырыми данными мышью («Найти и заменить», «Удалить дубликаты», «Текст по столбцам», «Мгновенное заполнение»), — разовая правка: годится, чтобы посмотреть, и не годится для файла на каждый понедельник. Структура сегодняшнего дня: ручные инструменты — чтобы *разведать*, Power Query — чтобы *поставлять*.

### Починка текста — TRIM, CLEAN, PROPER, SUBSTITUTE :id=text-repair-trim-clean-proper-substitute

```
=TRIM(B2)                          "Bobur "  → "Bobur"        (also collapses doubled inner spaces)
=CLEAN(B2)                         removes non-printing characters (line breaks, tabs from a copy-paste)
=PROPER(TRIM(C2))                  "jalilova" → "Jalilova";  "MALIKA" → "Malika"
=LOWER(TRIM(F2))                   "CASH "  → "cash";  "PayMe" → "payme"
=SUBSTITUTE(LOWER(TRIM(F2)), "bank transfer", "transfer")      week 2's expression, Excel spelling
=TRIM(CLEAN(SUBSTITUTE(x, CHAR(160), " ")))                     the full armour: non-breaking spaces (CHAR 160) survive TRIM
```

`PROPER` делает заглавной букву после каждого небуквенного символа — `"o'neil"` → `"O'Neil"`, но также `"payme"` → `"Payme"` и `"bnpl"` → `"Bnpl"` — поэтому она для *имён*, а не для кодов. **Нормализованный ключ** для сопоставления людей — это нижний регистр, обрезанные пробелы, склейка через разделитель: `=LOWER(TRIM(B2))&"|"&LOWER(TRIM(C2))&"|"&TEXT(E2,"yyyy-mm-dd")`. Разделитель важен: без него `"Ali"&"Nazarov"` и `"Alin"&"azarov"` совпадут.

### Найти и заменить (*найти и заменить*) — Ctrl+H :id=find-replace-найти-и-заменить-ctrlh

Ctrl+H, *Найти* `bank transfer`, *Заменить на* `transfer`, **Параметры**: *Учитывать регистр*, *Ячейка целиком*, область *Лист* или *Книга*. «Заменить все» сообщает, сколько замен сделано, — запишите число. Три предостережения: оно правит и формулы, содержащие этот текст; без *Ячейка целиком* поиск `card` правит `discard`; и это нигде не записывается — число нужно вручную вписать в журнал изменений. Подстановочные знаки: `*` — любой текст, `?` — один символ, `~*` — буквальная звёздочка. «Найти и заменить» для `" "` (пробела) на пустое значение — это **не** TRIM: оно удаляет и пробелы внутри имён.

### Текст по столбцам (*текст по столбцам*) и Мгновенное заполнение :id=text-to-columns-текст-по-столбцам-and-flash-fill

Данные → Текст по столбцам: разбить один столбец по разделителю (пробел, запятая, `|`) или по фиксированной ширине. `applied_at` = `2026-09-30 21:36:00` → дата и время в двух столбцах, каждый с типом, который вы выбираете на шаге 3 (задайте для столбца с датой **ГМД (YMD)**, иначе Excel в некоторых локалях неправильно прочитает `2026-09-30`). **Мгновенное заполнение** (Ctrl+E): введите нужный результат в первой ячейке (`Jalilova` рядом с `jalilova`), нажмите Ctrl+E, и Excel выведет шаблон для всего столбца — удобно, чтобы посмотреть, но невоспроизводимо (формулы не остаётся; следующий файл её не получит). Sheets: Данные → Разделить текст на столбцы; Мгновенного заполнения нет (используйте `SPLIT()`).

### Даты, хранящиеся как текст (*даты в текстовом формате*) :id=dates-stored-as-text-даты-в-текстовом-формате

Дата, которая является текстом, выровнена влево, не сортируется как дата, и `">="&DATE(…)` её никогда не находит. В наших CSV `2026-09-30` хранится как текст; Excel преобразует его при открытии в большинстве локалей, Sheets обычно тоже, Power Query всегда спрашивает. Если столбец — текст: `=DATEVALUE(E2)` превращает `"1981-08-15"` в число-дату 29 812 (отформатируйте ячейку как дату, чтобы увидеть её); `=VALUE(E2)` делает то же; «Текст по столбцам» с типом *Дата ГМД* преобразует целый столбец на месте. Проверка: `=ISTEXT(E2)` / `=ISNUMBER(E2)`. Ловушка в обратную сторону: `14/03/2026` в американской локали становится текстом (14-го месяца нет), а `03/04/2026` становится 4 марта — половина столбца преобразуется, половина нет. ISO `yyyy-mm-dd` — единственный безопасный формат обмена; настаивайте на нём у того, кто делает выгрузку.

### Поиск дубликатов перед удалением — COUNTIFS по ключу :id=finding-duplicates-before-removing-them-countifs-on-a-key

```
L2  key      =LOWER(TRIM(B2))&"|"&LOWER(TRIM(C2))&"|"&TEXT(E2,"yyyy-mm-dd")
M2  n        =COUNTIFS($L$2:$L$6041, L2)                 how many rows share this key
N2  rank     =COUNTIFS($L$2:L2, L2)                       1 for the first occurrence, 2 for the repeat  — ROW_NUMBER()
```

Отфильтруйте `n > 1`, чтобы увидеть группы, и `rank = 2` — «лишние» строки, затем сравните число с 40 дубликатами первой недели — если они различаются, прочитайте лишние пары, прежде чем что-либо решать (шаг 2 «Детектива»). Постройте второй ключ по `phone|birth_date` и третий по одному `phone` и сравните три числа. У каждого ключа бывают ложные срабатывания; столбец `rank` — это Excel-версия `ROW_NUMBER() OVER (PARTITION BY key ORDER BY row)`, и он позволяет *посмотреть* до удаления. Растущий диапазон `$L$2:L2` медленный на 50 000 строк — Power Query ниже делает то же за секунду.

### Удалить дубликаты (*удалить дубликаты*) — и почему оно врёт :id=remove-duplicates-удалить-дубликаты-and-why-it-lies

Данные → Удалить дубликаты, отметьте столбцы, определяющие совпадение, OK; Excel сообщит *удалено n повторяющихся значений*. Он сравнивает отмеченные столбцы **ровно так, как они отображены**, **без** учёта регистра, **с** учётом пробелов, и оставляет **первую** строку. Три прогона по `Customers` показывают проблему:

| Отмеченные столбцы | Что может произойти |
|---|---|
| first_name, last_name, birth_date (сырые) | регистр игнорируется, пробелы — нет: дубликат, имя которого заканчивается пробелом, выживает |
| те же после TRIM | уходят все настоящие дубликаты — **и любая пара разных людей**, у которых совпали имя и дата рождения |
| phone, birth_date | идентифицирующий ключ, который никто не отмечает первым, — сравните его число с числом первой недели |

Итак, на сырых текстах он удаляет слишком мало, на нестрогом ключе — слишком много, ничего не говорит о том, *какие* строки ушли, и не оставляет формулы. На `Payments`: отметьте `installment_id`, `paid_at`, `amount` и сравните число с дубликатами платежей третьей недели; отметьте все столбцы — и ничего не уйдёт (`payment_id` различается). Используйте его, чтобы *проверить число* на копии; результат поставляйте через Power Query, где шаг записан и выполняется заново.

### Power Query (*Получить и преобразовать*) — записанный конвейер :id=power-query-get-amp-transform-the-recorded-pipeline

Данные → **Получить данные** → Из файла → Из текста/CSV (в Sheets Power Query нет; см. ниже). Открывается редактор: предварительный просмотр и панель **Applied Steps (Применённые шаги)** справа — каждый щелчок становится шагом, по порядку, и выполняется заново при обновлении. Шаги, которые вы будете использовать:

| Шаг | Где | Эквивалент |
|---|---|---|
| **Source** / **Promoted Headers** | автоматически; иначе Главная → Использовать первую строку в качестве заголовков | чтение CSV |
| **Changed Type** | щёлкните значок в каждом заголовке: Целое число, Десятичное число, Дата, Текст | `CAST`; задайте `paid_at` тип «Дата», суммы — «Целое число», идентификаторы — «Целое число», phone — **Текст** |
| **Trim / Clean / lowercase / Capitalize Each Word** | Преобразование → Формат | `TRIM`, `CLEAN`, `LOWER`, `PROPER` |
| **Replace Values** | Преобразование → Заменить значения (`bank transfer` → `transfer`; отметьте *Сопоставлять всё содержимое ячейки*) | `REPLACE`, `SUBSTITUTE` |
| **Remove Duplicates** | выделите ключевые столбцы → Главная → Удалить строки → Удалить дубликаты | `ROW_NUMBER … WHERE rn = 1` (оставляет первую) |
| **Filter Rows** | стрелка в заголовке → Фильтры по дате → До… | `WHERE paid_at <= '2026-10-01'` |
| **Add Column → Custom / Conditional / Date → Month → Start of Month** | | вычисляемый столбец, `CASE`, `date(d, 'start of month')` |
| **Group By** | Преобразование → Группировать по; один или несколько ключей, агрегаты Sum / Count / Min / Max | `GROUP BY` |
| **Merge Queries** | Главная → Объединить запросы; выберите две таблицы, щёлкните ключевые столбцы, выберите **вид соединения (Join Kind)** | `JOIN`: Left Outer / Right Outer / Full Outer / Inner / Left Anti / Right Anti — вся глава второй недели в выпадающем списке |
| **Append Queries** | Главная → Добавить запросы | `UNION ALL` |
| **Close & Load To…** | Таблица на новом листе / Только создать подключение / Добавить в модель данных | `CREATE VIEW` (только подключение) или `CREATE TABLE AS` (загружено) |

У каждого шага в строке формул есть строка на **M** (языке запросов) — `= Table.Distinct(#"Lowercased Text", {"installment_id", "paid_at", "amount"})`. Писать на M не нужно; нужно уметь прочитать её настолько, чтобы увидеть, что делает шаг. Щёлкните шаг правой кнопкой → *Rename (Переименовать)*, чтобы панель читалась как журнал изменений: `Trim method`, `Lowercase method`, `bank transfer → transfer`, `Drop 25 duplicates`. **Обновить все** (Данные → Обновить все, Ctrl+Alt+F5) заново читает CSV по пути из *Source* и заново выполняет каждый шаг — меняйте путь один раз (Параметры источника данных), когда файл переезжает.

Две привычки. **Считайте на каждом шаге**: строка состояния показывает число строк предварительного просмотра; для настоящего числа — шаг Group By с *Count Rows* на дубликате запроса или загрузка и `=ROWS(tbl)`. **Типы раньше текстовых преобразований**: `Trim` по столбцу с типом «число» ничего не делает, фильтр по дате по текстовому столбцу не работает.

### Google Sheets: формулы, инструмент «Удалить дубликаты» и QUERY :id=google-sheets-formulas-the-remove-duplicates-tool-and-query

В Sheets нет Power Query. Воспроизводимый путь — **чистая вкладка, построенная формулами** из сырой вкладки: `=ARRAYFORMULA(TRIM(Raw!B2:B))`, `PROPER`, `SUBSTITUTE` и `UNIQUE` по ключевым столбцам для удаления дубликатов. Данные → Очистка данных → **Удалить дубликаты** и **Удалить пробелы** — разовые инструменты, с теми же оговорками, что и в Excel. Затем **`QUERY`** — SQL, на котором вы уже говорите, в виде функции:

```
=QUERY(Payments!A1:H, "select F, count(A), sum(E) group by F order by count(A) desc", 1)
=QUERY(Clean!A1:H, "select G, sum(E) where D >= date '2026-09-01' and D < date '2026-10-01' group by G", 1)
```

Буквы столбцов вместо имён, `label` для переименования, `pivot` для перекрёстной таблицы (`select G, sum(E) group by G pivot H`). Импорт CSV через Файл → Импорт с параметром *Заменить данные в выбранной ячейке* заново читает понедельничный файл; формулы пересчитываются — это версия «Обновить» в Sheets.

### Excel ↔ Google Sheets, сегодняшние инструменты :id=excel-google-sheets-todays-tools

| Excel | Sheets | Примечание |

## 6. Уголок компании <span class="badge company">Уровень сбора по месяцам</span> :id=6-company-corner-collection-rate-by-month

**Уровень сбора** = сумма **собранного** ÷ сумма **к получению** за период. Третья неделя дала 94.1 % за сентябрь 2026 по `v_payments_clean` + `installments`; сегодня вы воспроизводите это по очищенным файлам, в Power Query (или сводной таблицей по объединённой таблице) и пишете определение под ним.

**Определение (наше):** для платежей по графику, **наступающих в месяце** (`due_date` в месяце, полуоткрыто), собрано = оплаты по этим платежам по графику с `paid_at <= 2026-10-01` из `payments_clean` (дубликаты удалены, строки с датой в будущем исключены фильтром даты отсчёта); ставка = Σ собрано ÷ Σ `total_due`.

```
Query  paid_by_installment   payments_clean → Filter paid_at <= 2026-10-01 → Group By installment_id: paid = Sum(amount)
Query  installments_paid     installments.csv → Merge paid_by_installment (Left Outer, installment_id) → expand paid → Replace null → 0
                             → Add Column → Date → Month → Start of Month (from due_date) as due_month
Query  collection_by_month   installments_paid → Group By due_month: due = Sum(total_due), paid = Sum(paid), instalments = Count Rows
                             → Add Column → Custom: rate = [paid] / [due]      → Close & Load
```

| 2026-08 | 3 219 | 16 296 197 919 | 15 728 683 187 | 96.5 % |
| **2026-09** | **3 305** | **16 987 977 718** | **15 982 118 926** | **94.1 %** |

**Моё число: 94.1 %** за сентябрь 2026 — совпадает с SQL третьей недели, как и должно быть: те же строки, то же правило, другой инструмент. Три альтернативы дают другие числа, и каждая — допустимое *другое* определение, а не ошибка, — если оно записано:

- Использовать **грязные** платежи (с дубликатами): 15 982 758 126 → всё равно 94.1 % (один продублированный сентябрьский платёж, 639 200). В этом месяце безвредно; 58 млн по всей книге.
- **Получено в месяце ÷ к получению в месяце** (кассовый метод — все сентябрьские платежи, к какому бы платежу по графику они ни относились): 16 338 823 207 / 16 987 977 718 = **96.2 %**. Выше, потому что в сентябре поступили досрочные платежи по октябрьским платежам по графику и просроченные по августовским. Финансы часто имеют в виду именно это.
- Собрано **на сегодня**, а не на дату отсчёта: 24 строки с датой в будущем поднимают август до 96.8 % и оставляют июнь, июль и сентябрь без изменений до одного знака после запятой — здесь немного, но отчёт «на дату» не должен содержать платежей с более поздней датой.

Какое из них идёт правлению? Первое, с датой отсчёта, потому что оно отвечает на вопрос «из того, что подлежало оплате, сколько поступило» — приток в корзину 1–30 у Севары составляют те 5.9 %, которые не поступили. Кассовое отвечает на вопрос «сколько денег пришло» — вопрос Финансов о денежном потоке. Поместите определение в сноску плитки: *собрано на 2026-10-01 по платежам по графику, наступающим в месяце ÷ общая сумма к получению; платежи очищены от дубликатов.* Одно предложение — и Финансы с Взысканием перестают спорить о 2.1 пункта.

Версия для Sheets: вкладка `Clean` для платежей, вкладка `Inst` с `=SUMIFS(Clean!E:E, Clean!C:C, A2, Clean!D:D, "<="&DATE(2026,10,1))` для каждого платежа по графику (медленно на 92 193 строках — сделайте один раз, вставьте значения, отметьте в журнале), затем `=QUERY(Inst!A1:I, "select H, sum(G), sum(I) group by H", 1)` по столбцу `due_month`.

> Вопрос на собеседовании: *«Что такое уровень сбора и как вы вычислите его по платежам и графику?»* — Σ оплачено ÷ Σ к получению по платежам по графику, наступающим в периоде; оплаченное берётся из платежей без дубликатов, соединённых по идентификатору платежа по графику, с отсечкой по дате отсчёта; скажите, основан ли он на платежах по графику или кассовый; ожидайте, что последний месяц выглядит низко, пока не «созреет»; сверьте соединение по числу строк (каждый платёж по графику сохранён), прежде чем делить.
