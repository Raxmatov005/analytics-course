## 1. Изучение — поиск — это соединение с одной строкой :id=1-learn-a-lookup-is-a-join-with-one-row

Поиск приносит в вашу строку значение из другой таблицы: ставку продукта рядом с каждым кредитом, клиента рядом с номером кредита. Затем динамические массивы возвращают целые списки одной формулой, а два инструмента листа — выпадающие списки и условное форматирование — превращают результат в отчёт, которым управляет читатель.

**Маленькие таблицы этой страницы.** Большинство подразделов сначала показывают формулу на них, а затем на настоящей книге. Для `Car lease` в `rates` строки нет — на этой строке видно, что делает «не найдено».

| строка | A `loan_id` | B `product` | C `outstanding` |
|---|---|---|---|
| 2 | 101 | Micro loan | 4 |
| 3 | 102 | Auto loan | 200 |
| 4 | 103 | Car lease | 90 |
| 5 | 104 | Micro loan | 2 |

| строка | E `product` | F `rate` |
|---|---|---|

### Задача поиска — LEFT JOIN, который приносит один столбец :id=the-lookup-problem-a-left-join-that-brings-one-column

**Что это.** **Поиск значения** (lookup) берёт **ключ** из вашей строки (здесь `product`), находит такой же ключ в другой таблице и возвращает одно значение из той строки (здесь `rate`). Это `LEFT JOIN` второй недели, который приносит **один** столбец: каждая строка вашей таблицы остаётся, а строка, ключа которой нет, получает ошибку вместо NULL.

**Как пишется.** У каждой функции поиска одни и те же три части:

```text
what      the key in this row                 B2  ("Micro loan")
where     the column to search for the key    E2:E4
return    the column to bring back            F2:F4
```

Картинка — таблица кредитов с добавленной найденной ставкой:

| `loan_id` | `product` | `outstanding` | `rate` (найдено) |
|---|---|---|---|
| 101 | Micro loan | 4 | 0.42 |
| 102 | Auto loan | 200 | 0.24 |
| 103 | Car lease | 90 | `#N/A` |
| 104 | Micro loan | 2 | 0.42 |

Четыре строки на входе, четыре на выходе. `Car lease` не находит пары и получает `#N/A`. `Consumer loan` нет ни в одном кредите, поэтому его ничто не приносит — как правую строку в LEFT JOIN.

В настоящей книге столбец `rate` в `tblLoans` сохраняет все **7 828** строк: у каждого кредита ровно один продукт, а у каждого продукта ровно одна строка на `Lookup`.

**Когда применять.**
- «Каждый X с одним фактом о нём из другой таблицы»: каждый кредит со ставкой его продукта, каждый платёж по графику со статусом его кредита.
- Ключ на стороне поиска должен быть уникальным — одна строка на продукт, одна строка на кредит.

| SQL | Excel |
|---|---|
| `LEFT JOIN products p ON p.name = l.product` + `SELECT p.rate` | одна формула поиска в столбце `rate` таблицы `tblLoans` |
| NULL для строки без пары | `#N/A` (или ваш собственный текст «не найдено») |
| несколько совпадений → несколько строк | несколько совпадений → **только первое** |

> ⚠️ **Осторожно.** Поиск возвращает только **первое** совпадение. Если ключ на стороне поиска повторяется — *имя* клиента вместо идентификатора, — вы молча получите одну случайную строку. Ищите по идентификаторам.

### VLOOKUP и его четыре ловушки :id=vlookup-and-its-four-traps

**Что это.** **VLOOKUP** (*ВПР*) находит `what` в **первом столбце** диапазона и возвращает значение из n-го столбца той же строки. Это самый старый и самый используемый поиск в финансах — и в нём легче всего ошибиться.

**Как пишется.**

```excel
=VLOOKUP(what, where, column_number, FALSE)
=VLOOKUP(B2, $E$2:$F$4, 2, FALSE)          what = this row's product · where = the whole rates table
                                            2 = its 2nd column · FALSE = exact match
```

На маленькой таблице она возвращает 0.42, 0.24, `#N/A`, 0.42. На настоящей книге:

```excel
=VLOOKUP([@product], Lookup!$A$3:$F$7, 3, FALSE)     → 0.30 for a Consumer loan
```

Четыре ловушки, каждая из которых где-то уже дала неверное число правлению:

| # | Ловушка | Что идёт не так | Исправление |
|---|---|---|---|
| 1 | 4-й аргумент по умолчанию TRUE = **приближённый** поиск | на несортированном столбце ключей возвращает значение соседа, без ошибки | всегда пишите `FALSE` (или `0`) |
| 2 | Столбец — это **номер**, а не имя | вставьте столбец в `Lookup`, и `3` теперь указывает на `code` | `INDEX/MATCH` или `XLOOKUP` |
| 3 | Смотрит только **вправо** | ключ должен быть первым столбцом; вернуть `product` по `code` нельзя | `INDEX/MATCH` или `XLOOKUP` |
| 4 | Относительный диапазон **ползёт** | `A3:F7`, скопированный вниз, становится `A4:F8`, и последний продукт перестаёт находиться | `$A$3:$F$7` или имя таблицы |

`HLOOKUP` — то же самое, но вбок (ключи в первой *строке*). Вы встретите его в старых файлах.

**Когда применять.**
- В файлах, которые должны открываться в очень старом Excel, и когда вы читаете чужую работу.
- Для новой работы лучше `XLOOKUP` (ниже) или `INDEX/MATCH`.

> ⚠️ **Осторожно.** Пропустите `FALSE` — и ключ из несортированного списка вернётся значением *соседа*: неверная ставка, никакого `#N/A`, ничего красного.

### INDEX / MATCH — найти позицию, затем взять значение :id=index-match-find-the-position-then-take-the-value

**Что это.** **MATCH** (*ПОИСКПОЗ*) возвращает **позицию** значения в одном столбце. **INDEX** (*ИНДЕКС*) возвращает значение на этой позиции в другом столбце. Вместе это поиск, который может вернуть любой столбец — левее или правее ключа — и не ломается при вставке столбцов.

**Как пишется.**

```excel
=MATCH(what, one_column, 0)                    0 = exact match → a position (1, 2, 3 …)
=INDEX(one_column, position)                   the value at that position
=INDEX(return_column, MATCH(what, key_column, 0))
```

На маленькой таблице: `=MATCH("Auto loan", E2:E4, 0)` → **2**; `=INDEX(F2:F4, 2)` → **0.24**. Вместе: `=INDEX($F$2:$F$4, MATCH(B3, $E$2:$E$4, 0))` → 0.24.

На настоящей книге:

```excel
=INDEX(Lookup!$C$3:$C$7, MATCH([@product], Lookup!$A$3:$A$7, 0))     → the rate
=INDEX(Lookup!$A$3:$A$7, MATCH("SME", Lookup!$B$3:$B$7, 0))           → "Small business loan" (looking left)
```

`SME` стоит на позиции 5 в столбце `code`, поэтому `INDEX` берёт позицию 5 столбца `product`, который находится **левее** `code`.

**Третий аргумент MATCH — тип сопоставления.**

| Тип | Находит | Столбец должен быть |
|---|---|---|
| `0` | ровно `what` | в любом порядке |
| `1` | наибольшее значение ≤ `what` | отсортирован по возрастанию — случай диапазонов |
| `-1` | наименьшее значение ≥ `what` | отсортирован по убыванию |

`=MATCH(45, Lookup!$A$11:$A$15, 1)` → **3**: наибольшая нижняя граница ≤ 45 — это 31, третья граница. `=INDEX(Lookup!$B$11:$B$15, 3)` → `31-60`.

**Двумерный поиск.** Два `MATCH` выбирают одну ячейку из матрицы — один для строки, другой для столбца:

```excel
=INDEX(matrix, MATCH(row_key, row_labels, 0), MATCH(col_key, col_labels, 0))
```

На вчерашней матрице остатка долга регион × продукт ячейка Fergana × Small business loan возвращает **14 734 245 108**.

**Когда применять.**
- В любой версии Excel: `INDEX/MATCH` работает в Excel 2010 и новее, где `XLOOKUP` нет.
- Значение левее ключа; одна ячейка из двумерной таблицы.

> ⚠️ **Осторожно.** `MATCH` без третьего аргумента означает `1` — приближённый поиск по отсортированному столбцу. Для ключей пишите `0`, каждый раз.

### XLOOKUP — точное совпадение и «не найдено» :id=xlookup-exact-match-and-not-found

**Что это.** **XLOOKUP** (*ПРОСМОТРX*) — современный поиск (Excel 2021 / Microsoft 365, Google Sheets). Он принимает столбец ключей и столбец результата по отдельности, по умолчанию ищет точно и имеет собственный аргумент для «не найдено».

**Как пишется.**

```excel
=XLOOKUP(what, lookup_column, return_column, [if_not_found], [match_mode], [search_mode])
=XLOOKUP(B2, $E$2:$E$4, $F$2:$F$4, "not found")
```

На маленькой таблице она возвращает 0.42, 0.24, `not found`, 0.42 — строка 103 показывает `not found` вместо `#N/A`.

На настоящей книге:

```excel
=XLOOKUP([@product], Lookup!$A$3:$A$7, Lookup!$C$3:$C$7)              exact by default; #N/A if missing
=XLOOKUP($B$1, tblLoans[loan_id], tblLoans[customer], "not found")
```

Если в `B1` стоит 2167, вторая формула возвращает **Dilnoza Abdullaeva**; если 99999 — `not found`.

| Ловушка VLOOKUP | XLOOKUP |
|---|---|
| 1 — приближённый по умолчанию | точный по умолчанию |
| 2 — номер столбца | сам столбец результата |
| 3 — только вправо | столбец результата может быть где угодно |
| 4 — диапазон ползёт | по-прежнему закрепляйте `$` или используйте столбцы таблицы |

**Когда применять.**
- Каждый новый поиск «ключ → значение», когда у читателей файла Excel 2021 / 365 или Sheets.
- В Excel 2016/2019 она показывает `#NAME?` — там пишите `INDEX/MATCH` и укажите это в заголовке.

### XLOOKUP для диапазонов — приближённое совпадение и подстановочные знаки :id=xlookup-for-bands-approximate-and-wildcard-match

**Что это.** 5-й аргумент, **match_mode**, меняет способ сравнения. `-1` находит точное значение **или ближайшее меньшее** — правило для **таблицы диапазонов** (band table), в столбце ключей которой стоят нижние границы. `2` разрешает в ключе подстановочные знаки `*` и `?`.

**Как пишется.**

```excel
match_mode   0 exact (default) · -1 exact or next smaller · 1 exact or next larger · 2 wildcard
=XLOOKUP([@dpd], Lookup!$A$11:$A$15, Lookup!$B$11:$B$15, , -1)       the empty 4th argument: no not-found text
```

Таблица диапазонов на `Lookup` и что получают три значения dpd:

| `dpd_from` (A11:A15) | `bucket` (B11:B15) |
|---|---|
| 0 | 0 |
| 1 | 1-30 |
| 31 | 31-60 |
| 61 | 61-90 |
| 91 | 90+ |

| dpd | наибольший `dpd_from` ≤ dpd | корзина |
|---|---|---|
| 0 | 0 | 0 |
| 45 | 31 | 31-60 |
| 919 | 91 | 90+ |

dpd принимает 258 разных значений, от 0 до 919; пять строк границ покрывают их все. На `tblLoans` эта формула в точности воспроизводит поставляемый столбец `bucket`. То же правило в старых написаниях: `=VLOOKUP([@dpd], Lookup!$A$11:$B$15, 2, TRUE)` или `=INDEX(Lookup!$B$11:$B$15, MATCH([@dpd], Lookup!$A$11:$A$15, 1))`.

Подстановочный знак: `=XLOOKUP("Small*", Lookup!$A$3:$A$7, Lookup!$C$3:$C$7, , 2)` → **0.26**.

**Когда применять.**
- Любой диапазон: dpd → корзина, доход → группа, балл → класс, сумма → тариф.
- Смена границы становится одной ячейкой на `Lookup`, а не правкой каждой формулы.

| В столбце ключей | Используйте |
|---|---|
| нижние границы (0, 1, 31, 61, 91) | match_mode `-1` (`VLOOKUP … TRUE`, `MATCH … 1`) |
| верхние границы (0, 30, 60, 90, 9999) | match_mode `1` |

> ⚠️ **Осторожно.** Нижние границы с `1` или верхние с `-1` сдвигают каждое граничное значение в чужую корзину — dpd 31 попадает в `1-30` — без всякой ошибки. А `VLOOKUP … TRUE` и `MATCH … 1` требуют границ, отсортированных по возрастанию.

### XLOOKUP с конца — последнее совпадение :id=xlookup-from-the-end-the-last-match

**Что это.** 6-й аргумент, **search_mode**, задаёт направление. `1` (по умолчанию) ищет сверху и возвращает **первое** совпадение. `-1` ищет снизу и возвращает **последнее**.

**Как пишется.**

```excel
search_mode   1 first to last (default) · -1 last to first
=XLOOKUP(4567, tblPayments[loan_id], tblPayments[paid_at], , 0, -1)      the bottom row of loan 4567
```

У кредита 4567 три строки платежей: 2026-04-07, 2026-05-06, 2026-06-09. Сверху формула вернула бы 2026-04-07; снизу она возвращает **2026-06-09** (формат ячейки `yyyy-mm-dd`).

**Когда применять.**
- «Последний X каждого Y», когда таблица идёт в порядке дат: последний платёж по кредиту, последний статус заявки.
- С `MAXIFS` для проверки: `=MAXIFS(tblPayments[paid_at], tblPayments[loan_id], 4567)` возвращает самую позднюю дату при любом порядке строк.

> ⚠️ **Осторожно.** `-1` даёт последнюю **строку**, а не самую позднюю **дату**. В `tblPayments` у 80 из 7 436 кредитов с платежами нижняя строка — не самая поздняя дата (дубликаты и поздние записи стоят в конце). Для «самого позднего» используйте `MAXIFS` по дате.

### Поиск по двум ключам :id=two-key-lookups

**Что это.** **Поиск по двум ключам** находит строку, где совпадают сразу **два** столбца, — соединение по двум столбцам. Обычный способ: склеить два ключа в один через `&` и искать его.

**Как пишется.** Три способа, лучший первым:

```excel
1. helper key column    [@loan_id]&"|"&[@installment_no]   in the lookup table, then an exact lookup on it
2. glue inside          =XLOOKUP(k1&"|"&k2, col1&"|"&col2, return_column)
3. classic array        =INDEX(return_column, MATCH(1, (col1=k1)*(col2=k2), 0))    old Excel: Ctrl+Shift+Enter

```

`"|"` разделяет `1`&`12` и `11`&`2`: `1|12` и `11|2` — разные ключи, а `112` и `112` — нет. На маленькой таблице платежей по графику:

| `loan_id` | `installment_no` | `due_date` | ключ = `loan_id&"\|"&installment_no` |
|---|---|---|---|
| 1 | 1 | 2025-04-28 | 1\|1 |
| 1 | 2 | 2025-05-28 | 1\|2 |
| 1 | 3 | 2025-06-28 | 1\|3 |

`=XLOOKUP("1|3", key_column, due_date_column)` → 2025-06-28.

На настоящей книге: `=XLOOKUP(1&"|"&3, tblInstallments[loan_id]&"|"&tblInstallments[installment_no], tblInstallments[due_date])` → **2025-06-28**, третий платёж по графику кредита 1. Формула склеивает 92 193 пары при каждом пересчёте, поэтому на таблице такого размера вспомогательный столбец быстрее.

**Когда применять.**
- Строка определяется двумя столбцами: кредит + номер платежа, месяц + продукт, регион + продукт.
- Когда два ключа задают **группу**, а нужен **итог**, это не поиск: `SUMIFS` с двумя парами (вчера).

| Два ключа → | Используйте |
|---|---|
| значение одной строки | поиск по двум ключам |
| сумма по многим строкам | `SUMIFS` с двумя парами |

### IFERROR — замена ожидаемой ошибки :id=iferror-a-replacement-for-an-expected-error

**Что это.** **IFERROR** (*ЕСЛИОШИБКА*) возвращает результат формулы или второе значение, если формула вернула любую ошибку. Так `VLOOKUP` и `INDEX/MATCH` показывают «не найдено» вместо `#N/A`.

**Как пишется.**

```excel
=IFERROR(formula, value_if_error)
=IFERROR(INDEX($F$2:$F$4, MATCH(B4, $E$2:$E$4, 0)), "not found")      → "not found" for Car lease
```

На настоящей книге: `=IFERROR(INDEX(tblLoans[customer], MATCH($B$1, tblLoans[loan_id], 0)), "not found")` возвращает то же, что поиск кредита через XLOOKUP выше, — `not found` для 99999.

**Когда применять.**
- Промах **ожидаем**, а замена что-то **значит**: `"not found"`, `""`, иногда `0`.
- Вместе с контрольной ячейкой, которая считает промахи: `=COUNTIF(rate_column, "not found")` должна быть 0, когда каждый продукт есть на `Lookup`.

| `IFERROR(x, …)` | `XLOOKUP(…, "not found")` |
|---|---|
| ловит **любую** ошибку: `#N/A`, `#REF!`, `#VALUE!`, `#DIV/0!` | заменяет только «нет совпадения» |
| прячет сломанную формулу | сломанная формула по-прежнему показывает свою ошибку |

> ⚠️ **Осторожно.** `IFERROR(…, 0)` вокруг поиска с `SUM` над столбцом превращает каждый промах в ноль — итог выглядит полным, а он меньше. Никогда не оборачивайте формулу, которую не понимаете: `IFERROR` вокруг `#REF!` — это пустая ячейка на слайде для правления.

### UNIQUE — различные значения :id=unique-the-distinct-values

**Что это.** **UNIQUE** (*УНИК*) возвращает каждое различное значение диапазона один раз. Это `SELECT DISTINCT` в ячейке.

**Как пишется.**

```excel
=UNIQUE(range)
=UNIQUE(tblLoans[region])          → 8 rows, one per region
=ROWS(UNIQUE(tblLoans[branch]))    → 10   a count of distinct values
```

- Источник выпадающего списка.
- Подсчёт различных: `ROWS(UNIQUE(…))` = `COUNT(DISTINCT …)`.

### FILTER — строки, которые подходят под условие :id=filter-the-rows-that-meet-a-condition

**Что это.** **FILTER** (*ФИЛЬТР*) возвращает строки диапазона, для которых условие TRUE. Это `SELECT … WHERE …` в ячейке.

**Как пишется.**

```excel
=FILTER(range, condition, [if_empty])
=FILTER(tblLoans, (tblLoans[branch]=$B$1)*(tblLoans[dpd]>0), "no late loans")
         rows      AND = multiply: (a)*(b)                       text when nothing matches
```

Условия — это столбцы из TRUE/FALSE. **Перемножайте** их для AND, **складывайте** для OR: `(a)+(b)`.

На маленькой таблице кредитов: `=FILTER(A2:C5, B2:B5="Micro loan")` → строки 101 и 104.

На настоящей книге: `=FILTER(tblLoans[loan_id], (tblLoans[branch]="Termez Central")*(tblLoans[dpd]>0))` → **22** номера кредитов — просроченные кредиты Termez Central. `=SUM(FILTER(tblLoans[outstanding], (tblLoans[branch]="Termez Central")*(tblLoans[dpd]>0)))` → 159 281 532 просроченных денег.

**Когда применять.**
- Список, который читает человек: просроченные кредиты одного филиала для Севары, заявки одного сотрудника.
- С ячейкой в условии (`$B$1`), чтобы список менялся вместе с ячейкой.

| | `FILTER` | Кнопка фильтра в таблице |
|---|---|---|
| Результат | новый список, формулой | те же строки, часть скрыта |
| Меняется вместе с ячейкой | да | нет — кто-то должен щёлкнуть |
| Можно сложить формулой | да, `SUM(FILTER(…))` | только через `SUBTOTAL` |

> ⚠️ **Осторожно.** `AND(a, b)` внутри `FILTER` не работает — он возвращает одно TRUE/FALSE на весь столбец. Пишите `(a)*(b)`.

### SORT и SORTBY — упорядочить список :id=sort-and-sortby-order-a-list

**Что это.** **SORT** (*СОРТ*) возвращает диапазон, отсортированный по одному из его собственных столбцов. **SORTBY** сортирует диапазон по **другому** диапазону той же длины. Это `ORDER BY` в ячейке.

**Как пишется.**

```excel
=SORT(range, [column_number], [order])        order: 1 ascending (default), -1 descending
=SORTBY(range, by_range, [order])
=SORT(FILTER(tblLoans, …), 12, -1)            by the 12th column of tblLoans (dpd), worst first
=SORTBY(tblLoans[loan_id], tblLoans[outstanding], -1)
```

На маленькой таблице кредитов: `=SORTBY(A2:A5, C2:C5, -1)` → 102, 103, 101, 104 (по остатку 200, 90, 4, 2).

На настоящей книге: `=SORTBY(tblLoans[loan_id], tblLoans[outstanding], -1)` начинается с **4597** — наибольший остаток, 586 068 714, — затем 6478 и 2936. `=SORT(UNIQUE(tblLoans[region]))` перечисляет регионы от Andijan до Termez.

**Когда применять.**
- Рейтинг: худшие кредиты первыми, крупнейшие филиалы первыми.
- `SORT`, когда столбец сортировки внутри диапазона; `SORTBY`, когда нет, или когда вы сортируете один разлив по другому (`=SORTBY(A3#, B3#, -1)`).
- Первые n: `=TAKE(SORT(…), 5)` в Excel 365.

> ⚠️ **Осторожно.** Номер столбца в `SORT` считается от первого столбца диапазона, а не от столбца A листа. В `tblLoans` столбец `dpd` — 12-й.

### Условное форматирование — ячейки, которые красят себя сами :id=conditional-formatting-cells-that-colour-themselves

### Какой поиск и когда :id=which-lookup-when

**Что это.** Таблица выбора для инструментов этой страницы. Начинайте с вопроса: одно значение, диапазон, итог группы или список.

**Как пишется.**

| Ситуация | Использовать | Не использовать |
|---|---|---|
| Ключ → одно значение, Excel 365 / 2021 / Sheets | `XLOOKUP` | `VLOOKUP` (ловушки 1–3) |
| Ключ → одно значение, Excel 2016 / 2019 или файл, который другие откроют в старом Excel | `INDEX/MATCH` | `XLOOKUP` (там покажет `#NAME?`) |
| Диапазон (dpd → корзина, доход → группа, скоринговый балл → класс) | `XLOOKUP … -1` / `VLOOKUP … TRUE` / `MATCH … 1` по **отсортированной таблице нижних границ** | вложенные `IFS` с набранными вручную границами |
| Два ключа → одно значение | столбец-вспомогательный ключ + точный поиск | `VLOOKUP` по склейке, набранной в каждой ячейке |
| Два ключа → **сумма** | `SUMIFS` (это группа, а не строка) | поиск — он вернёт только первое совпадение |
| Одна ячейка из двумерной матрицы | `INDEX(matrix, MATCH(row), MATCH(col))` | копирование матрицы |
| Список подходящих строк | `FILTER` (+ `SORT`) | 7 828 `IF` |
| Различные значения столбца | `UNIQUE` | Удалить дубликаты на копии (среда: оно врёт) |
| Последнее вхождение (последний платёж по кредиту) | `XLOOKUP … , , , -1` по таблице в порядке дат или `MAXIFS` по дате | `VLOOKUP` (только первое совпадение) |

### Excel ↔ Google Sheets — сегодняшние функции :id=excel-google-sheets-todays-functions

**Что это.** В Sheets есть каждая функция этой страницы, с небольшими отличиями в написании. Ещё в Sheets есть **ARRAYFORMULA**, которая заставляет обычную формулу заполнить весь столбец, — замена вычисляемому столбцу таблицы.

**Как пишется.**

| Excel | Sheets | Примечание |
|---|---|---|
| `XLOOKUP(what, keys, values, "n/a", -1)` | то же | аргументы те же |
| `tblLoans[dpd]` | `Loans!L2:L` | столбец без нижней границы; отфильтруйте пустой хвост (`Loans!A2:A<>""`) |
| `[@dpd]` в вычисляемом столбце | `=ARRAYFORMULA(IFS(L2:L=0, "0", …))` в строке 2 | одна формула заполняет столбец |
| `FILTER(range, (a)*(b))` | `FILTER(range, a, b)` | условия отдельными аргументами; `(a)+(b)` для ИЛИ работает в обоих |
| `SORT(range, 12, -1)` | `SORT(range, 12, FALSE)` | FALSE = по убыванию |
| `SORTBY(range, by, -1)` | `SORT(range, by, FALSE)` | `SORT` в Sheets принимает диапазон для сортировки напрямую |
| `TAKE(SORT(…), 5)` | `SORTN(range, 5, 0, by, FALSE)` | топ-n одной функцией |
| Проверка данных → Список | Проверка данных → Раскрывающийся список (из диапазона) | та же идея |
| Условное форматирование → правило с формулой | Формат → Условное форматирование → Ваша формула | та же форма `=$M2="90+"` |

**Когда применять.** Когда файл живёт в Google Drive или формула коллеги пришла из Sheets.

Вопрос Севары одним блоком: *«просроченные кредиты выбранного мной филиала, худшие первыми, у каждого — ставка его продукта»*.

## 2. Разбор примера — лист Севары (15 мин) :id=_2-worked-example-sevara39s-sheet-15-min

**Запрос:** выбрать филиал и увидеть его просроченные кредиты, худшие первыми, с количеством, суммой и ставкой каждого кредита, раскрашенные по корзине. Лист `Collections`. Зерно основного блока: одна строка на **просроченный кредит выбранного филиала**.

1. **UNIQUE + SORT на вспомогательном листе.** `Helper!A2` = `=SORT(UNIQUE(tblLoans[branch]))` разливает десять названий филиалов от A до Z.
2. **Проверка данных — выпадающий список.** Выделите `Collections!B1`, Данные → Проверка данных → Список, источник `=Helper!$A$2#`. Каждая формула ниже читает `$B$1`.
3. **Разлив заголовка.** `A5` = `=tblLoans[#Headers]` разливает 13 названий столбцов.
4. **FILTER + SORT — список.**

```excel
A6:  =SORT(FILTER(tblLoans, (tblLoans[branch]=$B$1)*(tblLoans[dpd]>0), "no late loans"), 12, -1)
```

   Два условия перемножены (AND); столбец 12 = `dpd`; `-1` = худшие первыми.
5. **Формулы над разливом (`A6#`).**

```excel
A2  "Late loans"   B2  =IF(A6="no late loans", 0, COUNTA(INDEX(A6#, , 1)))     count of filtered rows
C2  "Outstanding"  D2  =SUM(INDEX(A6#, , 11))                                   11th column = outstanding
```

   Выберите **Tashkent South**: B2 → **59** просроченных кредитов, D2 → **1 566 587 839** — остаток долга *только просроченных кредитов*. ### Ошибки, которые стоят балла на этой неделе :id=mistakes-that-cost-a-point-this-week

- `VLOOKUP` без `FALSE` — неверная ставка без ошибки (P3).
- Поиск по `customer` (имени), чтобы достать что-либо, — 747 имён на 4 335 человек; ключи — это идентификаторы.
- Таблица корзин с верхней границей в качестве ключа (30, 60, 90) и режимом совпадения −1 — каждый dpd 31 попадает в `1-30`. Нижние границы с −1 или верхние с 1.
- `IFERROR(…, 0)` вокруг поиска и `SUM` над ним — промахи превращаются в нули, и итог выглядит полным.

## 6. Уголок компании <span class="badge company">Корзины DPD в Excel</span> :id=6-company-corner-dpd-buckets-in-excel

На второй неделе DPD и корзины считались в SQL; на третьей они оказались в представлении; сегодня **таблица** корзин переезжает в `Lookup!A10:C15`, а **правило** корзин становится одним приближённым поиском — то же разделение определения и данных, но в Excel.

```

                    B8, C8     =SUM(B3:B7), =SUM(C3:C7)             → 7 828 · 208 723 504 430
```

Почему таблица, а не `IFS`: когда Риск перейдёт на корзины 1–7 / 8–30 (глоссарий: **[varies]**), вы добавите строку в `Lookup`, и каждая формула, цвет и счёт последуют за ней. Версия на `IFS` — это та же проблема вставленной логики DPD, что была у Тимура в прошлый четверг, только по одному листу за раз. А почему приближённое совпадение, а не точное: dpd принимает 258 разных значений, от 0 до 919; корзина — это *диапазон*, и `match_mode −1` по нижним границам — это Excel-написание `CASE WHEN dpd <= 30`.

Ещё одну проверку попросит Севара: корзина **0** содержит 53 млн «просрочки» в SQL (14 платежей по графику, наступивших утром даты отсчёта), но здесь показывает dpd 0, как и должна, — DPD считает *дни*, а платёж, срок которого сегодня, просрочен на 0 дней. Поставьте дату отсчёта (`Lookup!B17`) на итоговый лист; без неё каждое число по корзинам неверно.

> 🎯 **Версия для собеседования.** *«Как бы вы разбили DPD по корзинам в Excel?»* — Отсортированная таблица диапазонов (нижняя граница, название) на листе поиска; `XLOOKUP` с режимом совпадения −1 (или `VLOOKUP … TRUE`, `MATCH … 1`) для каждого кредита; `COUNTIFS`/`SUMIFS` по корзинам с итогом, который сходится с числом кредитов и книгой; условное форматирование по тому же столбцу; дата отсчёта на листе. Границу менять в одной ячейке, никогда — в формуле.
