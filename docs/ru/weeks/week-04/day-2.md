## Сегодня в 3 строках :id=today-in-3-lines

- **Поиск** — это соединение: `VLOOKUP` (и его четыре ловушки), `INDEX/MATCH` и `XLOOKUP` — точное совпадение для ключей, **приближённое совпадение** для корзин и диапазонов, текст «не найдено» вместо `#N/A`.
- **Динамические массивы** — `FILTER`, `UNIQUE`, `SORT`, `SORTBY`, `SEQUENCE` — возвращают много ячеек из одной формулы (*разлив*); вместе с **выпадающим списком проверки данных** они дают отчёт, которым управляет читатель.
- **Условное форматирование** превращает столбец корзин в цвет; вы построили лист Севары и воспроизвели количества по корзинам 7 429 / 124 / 25 / 16 / 234 приближённым поиском по таблице `Lookup`.

## 1. Изучение — поиск — это соединение с одной строкой :id=1-learn-a-lookup-is-a-join-with-one-row

### VLOOKUP (*ВПР*) и его четыре ловушки :id=vlookup-впр-and-its-four-traps

`VLOOKUP(what, where, column_number, [approximate])` ищет `what` в **первом столбце** `where` и возвращает значение из n-го столбца той же строки. На нашем листе `Lookup` продукты лежат в `A3:F7` (product, code, annual_rate, min, max, channel):

```
=VLOOKUP([@product], Lookup!$A$3:$F$7, 3, FALSE)        → 0.30 for a Consumer loan
```

Это самая используемая и самая неправильно используемая функция в финансах. Четыре ловушки, каждая из которых где-то давала неверную цифру для правления:

1. **Четвёртый аргумент по умолчанию — TRUE = приближённое совпадение.** `=VLOOKUP("Micro loan", Lookup!A3:F7, 3)` не вернёт 0.42 — при приближённом совпадении Excel считает, что первый столбец *отсортирован*, и возвращает последнюю строку, которая по алфавиту ≤ значения; на нашем несортированном списке продуктов это неверная ставка без всякой ошибки. **Для ключей всегда пишите `FALSE`** (или `0`).
2. **Номер столбца — это счёт, а не имя.** Вставьте столбец в `Lookup`, и каждая `3` теперь указывает на `code`. У `INDEX/MATCH` и `XLOOKUP` этой проблемы нет.
3. **Она смотрит только вправо.** Ключ должен быть в первом столбце `where`; вернуть `product` по `code` нельзя, если таблица не устроена именно так.
4. **Относительный диапазон «ползёт».** `Lookup!A3:F7`, скопированный вниз, становится `A4:F8`, и последняя строка перестаёт находиться — вчерашний `$`. Используйте `$A$3:$F$7` или, лучше, имя таблицы.

`HLOOKUP` — то же самое, но вбок (ключи в первой *строке*); вы встретите его в старых файлах и никогда не будете писать сами.

### INDEX / MATCH (*ИНДЕКС / ПОИСКПОЗ*) — две функции, без ловушек 2–3 :id=index-match-индекс-поискпоз-two-functions-no-traps-23

`MATCH(what, one_column, 0)` возвращает **позицию** значения в столбце (0 = точное совпадение). `INDEX(one_column, position)` возвращает значение в этой позиции. Вместе они образуют поиск, который может смотреть влево, вправо или куда угодно:

```
=INDEX(Lookup!$C$3:$C$7, MATCH([@product], Lookup!$A$3:$A$7, 0))      → the rate
=INDEX(Lookup!$A$3:$A$7, MATCH("SME", Lookup!$B$3:$B$7, 0))            → "Small business loan" (looking left)
```

Третий аргумент `MATCH` — **тип совпадения**: `0` — точное (в любом порядке); `1` — наибольшее значение ≤ `what` (столбец отсортирован **по возрастанию**) — случай корзин; `−1` — наименьшее значение ≥ `what` (отсортирован по убыванию). Двумерный поиск — это `INDEX(matrix, MATCH(row_key, row_labels, 0), MATCH(col_key, col_labels, 0))` — выбор одной ячейки из вчерашней таблицы регион × корзина.

### XLOOKUP (*ПРОСМОТРX*) — то, чем стоит пользоваться, если оно есть :id=xlookup-просмотрx-the-one-to-use-when-you-have-it

Excel 2021 / Microsoft 365 и Google Sheets: `XLOOKUP(what, lookup_column, return_column, [if_not_found], [match_mode], [search_mode])`.

```
=XLOOKUP([@product], Lookup!$A$3:$A$7, Lookup!$C$3:$C$7)                     exact by default; #N/A if missing
=XLOOKUP(B1, tblLoans[loan_id], tblLoans[customer], "not found")               loan 2167 → Dilnoza Abdullaeva; 99999 → not found
=XLOOKUP([@dpd], Lookup!$A$11:$A$15, Lookup!$B$11:$B$15, , -1)                 approximate: next smaller → the bucket
```

Точное совпадение — **по умолчанию** (ловушки 1 больше нет); столбцы называются, а не считаются (ловушки 2 больше нет); столбец результата может быть где угодно (ловушки 3 больше нет); `if_not_found` заменяет обёртку `IFERROR`. **match_mode** `0` — точное · `−1` — точное или следующее *меньшее* · `1` — точное или следующее *большее* · `2` — подстановочные знаки. Для таблицы корзин с *нижней* границей в столбце ключа (`dpd_from` = 0, 1, 31, 61, 91) правило — `−1`: dpd 45 → наибольший `dpd_from` ≤ 45 равен 31 → `31-60`. **search_mode** `−1` ищет с конца — «последний платёж по этому кредиту» одной формулой. В Excel 2016/2019 XLOOKUP нет; пишите `INDEX/MATCH` и укажите это в заголовке.

### Поиск по двум ключам :id=two-key-lookups

Соединение по двум столбцам. Три способа, лучшие первыми: (1) **вспомогательный ключ** — столбец `key` = `[@region]&"|"&[@product]` в обеих таблицах и точный поиск по нему; (2) `XLOOKUP(key1&"|"&key2, col1&"|"&col2, return)` — склейка внутри формулы (это операция над массивом; для 7 828 строк нормально, для 92 193 медленно); (3) `INDEX(return, MATCH(1, (col1=key1)*(col2=key2), 0))` — классика, которой в старом Excel нужен ввод как формулы массива (Ctrl+Shift+Enter). Когда два ключа задают *группу* и вам нужна *сумма*, это вообще не поиск — это `SUMIFS` с двумя парами (вчера).

### IFERROR (*ЕСЛИОШИБКА*) :id=iferror-еслиошибка

`=IFERROR(VLOOKUP(…), "not found")` возвращает второе значение, когда первое даёт ошибку. Используйте её, чтобы заменить `#N/A` при законной промашке, — и **никогда** не используйте, чтобы скрыть `#REF!` или `#VALUE!`, которые вы не понимаете: `IFERROR` вокруг сломанной формулы — это пустая ячейка, которая прекрасно выглядит на слайде для правления. Правило: `IFERROR` — только там, где промах *ожидаем* и замена *осмысленна* (`0`, `"not found"`, `""`), и считайте промахи в контрольной ячейке.

### Динамические массивы (*динамические массивы*) — формулы, возвращающие таблицу :id=dynamic-arrays-динамические-массивы-formulas-that-return-a-table

Excel 365 / 2021 и Sheets: формула может вернуть много значений; они **разливаются** в ячейки ниже и правее, обведённые синей рамкой. На весь разлив ссылаются через `#`: если `A3` разливается, то `A3#` — это весь разлив. `#SPILL!` означает, что что-то мешает, — очистите ячейки.

| Функция | Возвращает | Пример |
|---|---|---|
| `UNIQUE(column)` | различные значения (`DISTINCT` в Excel) | `=UNIQUE(tblLoans[branch])` → 10 строк |
| `FILTER(table, condition, [if_empty])` | строки, где условие TRUE (`WHERE`) | `=FILTER(tblLoans, (tblLoans[branch]=$B$1)*(tblLoans[dpd]>0), "none")` |
| `SORT(range, [col], [−1])` | диапазон, отсортированный по n-му столбцу, −1 = по убыванию | `=SORT(FILTER(…), 12, -1)` — по dpd (12-й столбец `tblLoans`) |
| `SORTBY(range, by_range, −1)` | отсортированный по *другому* столбцу | `=SORTBY(A3#, B3#, -1)` — филиалы по их остатку долга |
| `SEQUENCE(n)` | 1, 2, … n вниз по столбцу | `=DATE(2026, SEQUENCE(10), 1)` → десять дат первого числа месяца 2026 года |
| `COUNTA(spill#)`, `SUM(INDEX(spill#, , 11))` | агрегат по разливу | количество и сумма отфильтрованного списка |

Условия внутри `FILTER` перемножаются для И — `(a)*(b)` — и складываются для ИЛИ — `(a)+(b)`; каждое — это столбец TRUE/FALSE, превращённый в 1/0. `UNIQUE` по `tblLoans[customer]` возвращает **747**, а не 4 335: имена — это не идентификаторы: поиск или подсчёт различных значений по столбцу с *именами* занижает число людей с распространёнными именами (и завышает число людей, записанных двумя способами, — среда).

В старом Excel ничего из этого нет; те же результаты дают сводная таблица (четверг) или расширенный фильтр. В **Sheets** `FILTER`, `UNIQUE`, `SORT`, `SORTN`, `SEQUENCE` есть изначально и разливаются так же; дополнительный инструмент — **`ARRAYFORMULA(…)`**, который заставляет любую обычную формулу заполнять столбец (`=ARRAYFORMULA(IF(L2:L="", "", IFS(L2:L=0,"0", …)))`) — замена вычисляемого столбца таблицы в Sheets.

### Проверка данных (*проверка данных*) — выпадающий список :id=data-validation-проверка-данных-the-dropdown

Выделите ячейку (`B1`), Данные → Проверка данных → Тип данных: **Список**, Источник: диапазон. Источником должен быть диапазон, а не имя столбца таблицы — укажите разлитый `UNIQUE` на вспомогательном листе (`=Helper!$A$2#`) или набранный вручную список филиалов. Sheets: Данные → Проверка данных → *Раскрывающийся список (из диапазона)*. Каждая формула на листе читает `$B$1`; читатель меняет одну ячейку — и отчёт меняется. Это Excel-версия параметра.

### Условное форматирование (*условное форматирование*) — данные, которые красят себя сами :id=conditional-formatting-условное-форматирование-data-that-colours-itself

Главная → Условное форматирование (Sheets: Формат → Условное форматирование). Четыре вида, которыми вы будете пользоваться:

- **Правила выделения ячеек** — `больше 90` по столбцу `dpd` → красная заливка. Подходит для одного порога.
- **Цветовые шкалы** — градиент от минимума к максимуму по `outstanding`: глаз находит крупные кредиты. Двухцветная шкала, белый → синий; никогда красно-зелёная для количества (дальтоники, да и красный в кредитном файле означает *плохо*).
- **Гистограммы** — полоска в ячейке, пропорциональная значению, диаграмма, которую вы получаете в таблице бесплатно.
- **Использовать формулу для определения форматируемых ячеек** — правило, которое вы будете писать чаще всего: выделите `A2:M7829`, формула `=$M2="90+"`, красная заливка. Весь трюк в том, что `$` стоит на столбце, а не на строке: каждая ячейка строки смотрит на корзину *своей* строки. Добавьте правила для `"61-90"` (оранжевый), `"31-60"` (жёлтый), `"1-30"` (светло-жёлтый); упорядочьте их и отметьте *Остановить, если истинно*.

Правила применяются к диапазону, который вы выделили при их создании, — таблица распространяет их на новые строки, обычный диапазон — нет. Диспетчер правил → *Этот лист* показывает все правила; лист с сорока пересекающимися правилами медленный и нечитаемый, так что одно правило — один смысл.

### Какой поиск и когда :id=which-lookup-when

| Ситуация | Использовать | Не использовать |
|---|---|---|
| Ключ → одно значение, Excel 365 / 2021 / Sheets | `XLOOKUP` | `VLOOKUP` (ловушки 1–3) |
| Ключ → одно значение, Excel 2016 / 2019 или файл, который другие откроют в старом Excel | `INDEX/MATCH` | `XLOOKUP` (там покажет `#NAME?`) |
| Диапазон (dpd → корзина, доход → группа, скоринговый балл → класс) | `XLOOKUP … -1` / `VLOOKUP … TRUE` / `MATCH … 1` по **отсортированной таблице нижних границ** | вложенные `IFS` с набранными вручную границами |
| Два ключа → одно значение | столбец-вспомогательный ключ + точный поиск | `VLOOKUP` по склейке, набранной в каждой ячейке |
| Два ключа → **сумма** | `SUMIFS` (это группа, а не строка) | поиск — он вернёт только первое совпадение |
| Одна ячейка из двумерной матрицы | `INDEX(matrix, MATCH(row), MATCH(col))` | копирование матрицы |
| Список подходящих строк | `FILTER` (+ `SORT`) | 7 828 `IF` |
| Различные значения столбца | `UNIQUE` | Удалить дубликаты на копии (среда: оно врёт) |
| Последнее вхождение (последний платёж по кредиту) | `XLOOKUP … , , , -1` (поиск с конца) или `MAXIFS` по дате | `VLOOKUP` (только первое совпадение) |

### Как читать ошибки :id=reading-the-errors

| Ошибка | Означает | Что проверить сначала |
|---|---|---|
| `#N/A` | поиск ничего не нашёл | пробел или разница в регистре в ключе (`"Micro loan "`), число, хранящееся как текст (`"2167"` против 2167 — `VALUE()` для одной из сторон) |
| `#REF!` | ссылка указывает на удалённые ячейки или номер столбца в `VLOOKUP` больше ширины диапазона | ширина диапазона; что было удалено |
| `#VALUE!` | неверный тип аргумента (текст там, где нужно число; диапазоны разного размера) | диапазоны `SUMIFS` равной длины; даты как текст |
| `#NAME?` | Excel не знает функцию (XLOOKUP в Excel 2016) или имя написано с ошибкой | версия Excel; кавычки вокруг текста |
| `#SPILL!` | динамическому массиву не хватает места | очистите ячейки ниже / правее формулы |
| `#DIV/0!` | доля с пустым знаменателем | пустая группа; `IF(den=0, "", num/den)` |

`IFERROR` скрывает все эти ошибки одинаково; вот почему он — только для *ожидаемых* промахов.

### Excel ↔ Google Sheets, сегодняшние функции :id=excel-google-sheets-todays-functions

| Excel | Sheets | Примечание |
|---|---|---|
| `XLOOKUP(what, keys, values, "n/a", -1)` | то же | Sheets добавил XLOOKUP в 2022 году, аргументы те же |
| `tblLoans[dpd]` | `Loans!L2:L` | столбец без нижней границы; `FILTER` игнорирует пустой хвост, только если его отфильтровать (`Loans!A2:A<>""`) |
| `[@dpd]` в вычисляемом столбце | `ARRAYFORMULA(IFS(L2:L=0, "0", …))` в строке 2 | одна формула заполняет столбец |
| `FILTER(range, (a)*(b))` | `FILTER(range, a, b)` | условия отдельными аргументами; `(a)+(b)` для ИЛИ работает в обоих |
| `SORT(range, 12, -1)` | `SORT(range, 12, FALSE)` | FALSE = по убыванию |
| `SORTBY(range, by, -1)` | `SORT(range, by, FALSE)` | `SORT` в Sheets принимает диапазон для сортировки напрямую |
| `TAKE(range, 5)` | `SORTN(range, 5, 0, by, FALSE)` | топ-n одной функцией в Sheets |
| Проверка данных → Список | Проверка данных → Раскрывающийся список (из диапазона) | та же идея; Sheets раскрашивает «чипы» |
| Условное форматирование → правило с формулой | Формат → Условное форматирование → Ваша формула | та же форма `$M2="90+"` |

## 2. Разбор примера — лист Севары (15 мин) :id=_2-worked-example-sevara39s-sheet-15-min

Лист `Collections`. Зерно основного блока: одна строка на **просроченный кредит выбранного филиала**.

```
A1  "Branch:"      B1  dropdown — Data Validation, List, source = Helper!$A$2#  where Helper!A2 = SORT(UNIQUE(tblLoans[branch]))
```

## 6. Уголок компании <span class="badge company">Корзины DPD в Excel</span> :id=6-company-corner-dpd-buckets-in-excel

На второй неделе DPD и корзины считались в SQL; на третьей они оказались в представлении; сегодня **таблица** корзин переезжает в `Lookup!A10:C15`, а **правило** корзин становится одним приближённым поиском — то же разделение определения и данных, но в Excel.

```
Loans, new column   lk_bucket  =XLOOKUP([@dpd], Lookup!$A$11:$A$15, Lookup!$B$11:$B$15, , -1)
Summary sheet       A3:A7      0 · 1-30 · 31-60 · 61-90 · 90+  (text — '0)
                    B3         =COUNTIFS(tblLoans[lk_bucket], A3)
                    C3         =SUMIFS(tblLoans[outstanding], tblLoans[lk_bucket], A3)
                    D3         =C3/SUM($C$3:$C$7)                    → 0.00%
                    B8, C8     =SUM(B3:B7), =SUM(C3:C7)             → 7 828 · 208 723 504 430
```

| bucket | loans | outstanding | share of outstanding |
|---|---|---|---|
| 0 | **7 429** | 197 486 207 578 | 94.62 % |
| 1-30 | **124** | 4 729 769 899 | 2.27 % |
| 31-60 | **25** | 748 610 049 | 0.36 % |
| 61-90 | **16** | 439 441 377 | 0.21 % |
| 90+ | **234** | 5 319 475 527 | **2.55 %** |

Затем две плитки под ней: **PAR30** `=SUMIFS(tblLoans[outstanding], tblLoans[dpd], ">30")/C8` → **3.12 %** и **NPL90** `=C7/C8` → **2.55 %** — те же 6 507 526 953 и 5 319 475 527, что в представлении третьей недели. Условное форматирование на `Loans`: `=$O2="90+"` (новый столбец `lk_bucket` — O, если `rate` из P1 стоит в N; используйте букву вашего столбца) красным — загорятся **234** строки, и это в точности 44 кредита `default` + 190 `written_off` (`=COUNTIFS(tblLoans[lk_bucket], "90+", tblLoans[status], "active")` → 0, проверка статуса со второй недели в одной ячейке).

Почему таблица, а не `IFS`: когда Риск перейдёт на корзины 1–7 / 8–30 (глоссарий: **[varies]**), вы добавите строку в `Lookup`, и каждая формула, цвет и счёт последуют за ней. Версия на `IFS` — это та же проблема вставленной логики DPD, что была у Тимура в прошлый четверг, только по одному листу за раз. А почему приближённое совпадение, а не точное: dpd принимает 900 разных значений; корзина — это *диапазон*, и `match_mode −1` по нижним границам — это Excel-написание `CASE WHEN dpd <= 30`.

Ещё одну проверку попросит Севара: корзина **0** содержит 53 млн «просрочки» в SQL (14 платежей по графику, наступивших утром даты отсчёта), но здесь показывает dpd 0, как и должна, — DPD считает *дни*, а платёж, срок которого сегодня, просрочен на 0 дней. Поставьте дату отсчёта (`Lookup!B17`) на итоговый лист; без неё каждое число по корзинам неверно.

> Вопрос на собеседовании: *«Как бы вы разбили DPD по корзинам в Excel?»* — Отсортированная таблица диапазонов (нижняя граница, название) на листе поиска; `XLOOKUP` с режимом совпадения −1 (или `VLOOKUP … TRUE`, `MATCH … 1`) для каждого кредита; `COUNTIFS`/`SUMIFS` по корзинам с итогом, который сходится с числом кредитов и книгой; условное форматирование по тому же столбцу; дата отсчёта на листе. Границу менять в одной ячейке, никогда — в формуле.
