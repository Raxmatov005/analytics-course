### Что такое сводная таблица — GROUP BY на листе :id=what-a-pivot-is-group-by-in-a-sheet

**Что это.** **Сводная таблица** читает таблицу, группирует её строки по одному или нескольким полям и агрегирует остальные. Это `SELECT product, SUM(outstanding) FROM loans GROUP BY product`, собранный перетаскиванием имён полей. Результат — новая маленькая таблица на своём листе; исходные строки не меняются.

**Как пишется.** Щёлкните внутри таблицы → Вставка → **Сводная таблица** (PivotTable) → На новый лист → OK. Справа открывается **список полей**:

```text
PivotTable Fields
  [x] product  [x] outstanding
  [ ] region   [ ] status …
    столбцы исходной таблицы
  Filters: (пусто)
  Columns: (пусто)
  Rows:    product
  Values:  Sum of outstanding
```

### Строки и значения — группа и агрегат :id=rows-and-values-the-group-and-the-aggregate

**Что это.** Поле в **«Строках»** (Rows) — это ключ `GROUP BY`: каждое различное значение становится одной строкой. Поле в **«Значениях»** (Values) агрегируется по каждой строке. Числовое поле становится *Sum of …*, текстовое — *Count of …*.

**Как пишется.**

| Область | Поле | SQL |
|---|---|---|
| Rows | product | `GROUP BY product` |
| Values | outstanding (Sum) | `SUM(outstanding)` |
|   | loan_id (Count) | `COUNT(*)` — перетащите поле в Values дважды, чтобы видеть его дважды |

На маленькой таблице, `product` в Rows и оба значения:

| product | Sum of outstanding | Count of loan_id |
|---|---|---|
| Consumer | 40 | 1 |
| Micro | 10 | 3 |
| SME | 450 | 2 |
| **Grand Total** | **500** | **6** |

Два поля в Rows дают иерархию: `region`, затем `product` перечисляет продукты **внутри** каждого региона, с промежуточным итогом по региону.

На `tblLoans`, Rows `product`, Values Sum от `outstanding` и Count от `loan_id`: Small business loan — **125 892 942 411** на **781** кредит; Micro loan — 956 106 370 на 2 669 кредитов. Строка Grand Total говорит 208 723 504 430 и 7 828.

**Когда применять.**
- Одно измерение, один или несколько показателей: остаток и число кредитов по продуктам.
- Два поля в Rows для детализации: регион → филиал.

> ⚠️ **Осторожно.** Числовой столбец с одной текстовой или пустой ячейкой сводится как **Count**, а не Sum. Если появилось *Count of outstanding*, проверьте исходный столбец, прежде чем чему-то верить.

### Операция в поле значений — Sum, Count, Average, Max, Min :id=summarize-values-by-sum-count-average-max-min

**Что это.** **Summarize Values By** (*Операция*) задаёт агрегат поля в Values: **Sum**, **Count**, **Average**, **Max**, **Min**, *Count Numbers*, *StdDev*. Это выбор между `SUM`, `COUNT`, `AVG`, `MAX` и `MIN`.

### Дополнительные вычисления — % от общего итога, столбца, строки, родителя :id=show-values-as-of-grand-total-of-column-of-row-of-parent

**Что это.** **Show Values As** (*Дополнительные вычисления*) превращает число в **долю** от итога без формулы. % of Grand Total делит на всю таблицу; % of Column Total — на свой столбец; % of Row Total — на свою строку; **% of Parent Row Total** — на группу уровнем выше (регион для филиала).

**Как пишется.** Параметры поля значений → вторая вкладка **Дополнительные вычисления** (Show Values As) → выбрать → OK (Sheets: *Show as*). Перетащите поле в Values дважды, чтобы видеть сумму и её долю рядом.

На маленькой таблице (продукт × регион, Sum of outstanding = 500):

| | Fergana | Tashkent | Итого | → % of Grand Total | → % of Column Total (Tashkent) | → % of Row Total (SME) |
|---|---|---|---|---|---|---|
| Consumer | | 40 | 40 | 8.0 % | 11.6 % | |
| Micro | 5 | 5 | 10 | 2.0 % | 1.4 % | |
| SME | 150 | 300 | 450 | 90.0 % | 87.0 % | Fergana 33.3 % · Tashkent 66.7 % |

- **% of Grand Total**: SME = 450 ÷ 500 = 90.0 %.
- **% of Column Total**: внутри 345 Tashkent, SME = 300 ÷ 345 = 87.0 %.
- **% of Row Total**: внутри 450 SME, Tashkent = 300 ÷ 450 = 66.7 %.

На `tblLoans`: сводная по продуктам с % of Grand Total даёт SME **60.3 %** книги. Перекрёстная продукт × корзина с **% of Column Total** говорит, что Consumer — **32.9 %** из 234 кредитов в 90+; с **% of Row Total** — что **3.7 %** из 781 кредита SME находятся в 90+.

**Когда применять.**

| Вопрос | Show Values As |
|---|---|
| Какая доля от целого? | % of Grand Total |
| Внутри этого столбца (корзины) — какая строка (продукт)? | % of Column Total |
| Внутри этой строки (продукта) — как она распределена? | % of Row Total |
| Внутри родительской группы (регион → филиал)? | % of Parent Row Total |

> ⚠️ **Осторожно.** Итог из долей имеет смысл только там, где доли складываются в 100 %. Для столбцов с % of Column Total отключите Grand Total по строкам, иначе читатель увидит «100 %» под каждым столбцом и начнёт их складывать.

### Дополнительные вычисления — отличие, нарастающий итог, ранг :id=show-values-as-difference-from-running-total-rank

**Что это.** Вторая половина Show Values As сравнивает элемент с **другим элементом** того же поля. **Difference From** (*Отличие*) показывает изменение относительно базового элемента (обычно *(previous)* — предыдущего); **% Difference From** — то же в процентах; **Running Total In** (*С нарастающим итогом в поле*) накапливает вниз по полю; **Rank Largest to Smallest** нумерует элементы. Это оконные функции третьей недели в виде выпадающего списка.

**Как пишется.** Параметры поля значений → Дополнительные вычисления → **Difference From** → базовое поле `disbursed_at` (или `Months`) → базовый элемент **(previous)**.

На маленькой таблице, Rows `disbursed_at`, сгруппированное по месяцам (следующий подраздел), Values Sum от `outstanding`:

| месяц | Sum | Difference From (previous) | % Difference From | Running Total In |
|---|---|---|---|---|
| Aug | 305 | | | 305 |
| Sep | 195 | −110 | −36.1 % | 500 |

На `tblLoans`, Rows `disbursed_at`, сгруппированное по годам, Values Sum от `principal`: 2024 — **86 522 990 000**, 2025 — **155 927 230 000**, 2026 — **162 333 060 000**. % Difference From (previous) для 2026: **+4.1 %** — за девять месяцев 2026 года выдано больше, чем за весь 2025-й. Running Total In заканчивается на 404 783 280 000 — всё, что когда-либо выдано.

**Когда применять.**
- Месяц к месяцу и год к году: Difference From, % Difference From.
- С начала года: Running Total In по полю даты.
- Столбец рейтинга рядом с суммой: Rank Largest to Smallest.

### Вычисляемое поле — отношение сумм :id=a-calculated-field-a-ratio-of-sums

**Что это.** **Вычисляемое поле** (Calculated Field) — новое поле значений, вычисляемое из **сумм** других полей: `= outstanding / principal` — это `SUM(outstanding) / SUM(principal)` для каждой строки сводной. Это **отношение сумм** — правильный способ показать ставку по группе.

**Как пишется.**

```text

  → Поля, элементы и наборы
  → Вычисляемое поле

  Формула:  = outstanding / principal
    имена полей; каждое значит
    «СУММА этого поля в этой строке»
  → Добавить → OK, затем формат 0.0%
    в параметрах поля значений
```

|---|---|---|---|---|
| Micro | 10 | 24 | **41.7 %** | 37.5 % (50 %, 62.5 %, 0 %) |
| SME | 450 | 600 | **75.0 %** | 75.0 % |
| Consumer | 40 | 50 | **80.0 %** | 80.0 % |

### Ловушка сводной: двойной счёт — знайте зерно :id=pivot-trap-double-counting-know-the-grain

**Что это.** Сводная таблица суммирует **каждую строку**, которую ей дали. Если в источнике одна строка на **платёж по графику** и в каждой стоит `principal` кредита, *Sum of principal* сложит каждый кредит по разу на каждый платёж. Это соединение «один-ко-многим» со второй недели, только внутри сводной.

**Как пишется.** Картинка — кредит 1, соединённый со своими тремя платежами:

| loan_id | installment_no | principal (скопирован с кредита) |
|---|---|---|
| 1 | 1 | 400 |
| 1 | 2 | 400 |
| 1 | 3 | 400 |

Сводная по этой таблице: *Sum of principal* для кредита 1 = **1 200**. Выдано было 400.

На реальных данных: `installments`, соединённая с `loans`, — 92 193 строки. Sum от `principal` по ней — **9 981 530 850 000**, в 24.7 раза больше реально выданных **404 783 280 000**.

**Когда применять.**
- Перед каждой сводной назовите зерно: *одна строка источника = один …*.
- Суммы на уровне кредита — из `tblLoans`; суммы на уровне платежа (`total_due`, `paid`) — из таблицы платежей по графику.

> ⚠️ **Осторожно.** Признак — Grand Total, слишком большой в «круглое» число раз. Сверяйте каждый Grand Total с известным числом: 7 828 кредитов, 208 723 504 430 остатка, 404 783 280 000 выдано.

### Обновление, кэш сводной и форматы, которые его переживают :id=refresh-the-pivot-cache-and-formats-that-survive-it

**Что это.** Сводная таблица читает снимок источника — **кэш сводной таблицы**, сделанный при её создании. Новые строки, изменённые значения и обновление Power Query **не** появятся, пока вы не **обновите** (Refresh) сводную. Форматы, заданные ячейкам сводной, теряются при обновлении; форматы из параметров поля значений сохраняются.

**Как пишется.**

| Действие | Что делает |
|---|---|
| Правый щелчок по сводной → Обновить | одна сводная |
| Данные → Обновить все (Ctrl+Alt+F5) | все запросы, потом все сводные |
| Анализ сводной таблицы → Изменить источник данных → tblLoans | стройте на таблице, никогда на A1:M7829 |
| Параметры поля значений → Числовой формат → `#,##0` | формат, который переживает обновление |

Картинка: пятничное обновление добавляет в `tblLoans` 120 кредитов.

|---|---|
| `Loans!$A$1:$M$7829` (фиксированный диапазон) | по-прежнему 7 828 кредитов — новые строки вне диапазона |
| `tblLoans` (таблица) | 7 948 кредитов — таблица выросла, сводная следует за ней |

Макет для читателя задаётся один раз: Конструктор → Макет отчёта → **В табличной форме** (Tabular Form) и *Повторять все подписи элементов*; **Промежуточные итоги** выключены; значения **переименованы** на месте (*Sum of outstanding* → *Остаток, UZS*); сортировка по главному значению; Параметры сводной таблицы → снять *Автоматически изменять ширину столбцов при обновлении*. **Sheets:** сводные сами следуют за диапазоном источника — расширьте его до целых столбцов.

**Когда применять.**

### GETPIVOTDATA — читаем сводную формулой :id=getpivotdata-reading-a-pivot-from-a-formula

**Что это.** **GETPIVOTDATA** (*ПОЛУЧИТЬ.ДАННЫЕ.СВОДНОЙ.ТАБЛИЦЫ*) возвращает одно значение сводной таблицы по **именам полей и элементов**, а не по адресу ячейки. Она продолжает возвращать правильное число после сортировки, фильтрации или перемещения сводной.

**Как пишется.**

| Формула | Даёт |
|---|---|
| `=GETPIVOTDATA("outstanding", $A$20)` | поле данных, любая ячейка сводной → Grand Total |
| `=GETPIVOTDATA("outstanding", $A$20, "product", "Small business loan")` | + поле и элемент → одна ячейка |

Введите `=` и щёлкните ячейку значения сводной: Excel напишет формулу сам. На сводной по продуктам маленькой таблицы `=GETPIVOTDATA("outstanding", $A$3, "product", "SME")` → **450**.

**Когда применять.**
- Плитки над страницей, которые должны показывать то же, что сводная.
- Проверочная ячейка: `=GETPIVOTDATA("outstanding", $A$20) = SUM(tblLoans[outstanding])` должна давать TRUE.

### Какая диаграмма для какого вопроса :id=which-chart-for-which-question

**Что это.** Тип диаграммы определяется **вопросом**, а не вкусом. Большинство неверных диаграмм — это неверный тип для верного числа.

**Как пишется.** Выделите сводную (**сводная диаграмма**, PivotChart, остаётся связанной и подчиняется срезам) или итоговый диапазон → Вставка → **Рекомендуемые диаграммы** → выбрать. Выбор:

| Вопрос | Диаграмма | Не |
|---|---|---|
| Как сравниваются категории? (остаток по продуктам) | **линейчатая** (длинные подписи, отсортирована) или **гистограмма** (мало коротких подписей) | круговая — глаз не сравнивает секторы |
| Как что-то меняется во времени? (выдачи по месяцам) | **график** (много периодов) или гистограмма (≤ 12) | столбцы с несортированными месяцами |
| Из чего состоит итог по категориям? (корзины по продуктам) | **гистограмма с накоплением**; **нормированная (100 %)**, когда важнее состав, чем размер | пять круговых |
| Часть целого, 2–3 части | круговая или кольцевая *допустимы* | круговая на 5+ секторов, объёмная круговая |

### Ловушка диаграммы: две оси :id=chart-trap-the-dual-axis

**Что это.** Диаграмма с **двумя осями** (комбинированная) рисует два показателя в двух разных масштабах — один по левой оси, другой по правой. ### Честная диаграмма — заголовок, подписи, спарклайны :id=building-an-honest-chart-title-labels-sparklines

**Что это.** **Честную диаграмму** нельзя прочитать неверно. Её заголовок формулирует вывод, ось (у столбцов) начинается с нуля, единицы написаны, и на ней нет ничего декоративного. **Спарклайн** (sparkline) — крошечная диаграмма внутри одной ячейки: тренд в строке таблицы.

**Как пишется.**

```text
Конструктор диаграмм
  → Добавить элемент диаграммы
  → Подписи данных / Названия осей
Формат оси → Число → #,##0,,,
  (миллиарды)
Формат оси → Границы → Минимум 0
Щелчок по легенде → Delete
  (одному ряду легенда не нужна)
Вставка → Спарклайны → График
  → диапазон B5:K5
  → место L5
  → отметить Максимальная
    и Минимальная точки
Спарклайн → Ось
  → Одинаковые для всех спарклайнов
  (иначе у каждой строки свой
  масштаб)

Sheets:
=SPARKLINE(B5:K5,{"charttype","column"})
```

Чек-лист, десять строк:

1. **Заголовок = вывод**, с числом: *SME — это 60 % книги на 10 % кредитов.*
2. **Подзаголовок = определение и дата среза**: *остаток основного долга, млрд UZS, на 1 окт 2026.*
3. **Ось от нуля** для столбцов и полос.
4. **Единицы** на оси или в подзаголовке; подписи данных отформатированы (`125.9`, а не `125892942411`).
5. **Сортировка** по значению, если нет естественного порядка (месяцы, корзины, грейды).
6. **Один цвет** для ряда, **один акцент** для точки, о которой заголовок; красный — только для *плохого*.
7. **Без легенды** для одного ряда.
8. **Без 3D**, теней и лишних линий сетки.
9. **Неполные периоды** (октябрь 2026, один день) убраны или помечены.
10. **Строка источника**: *tblLoans · 7 828 кредитов · Nur Finance.*

**Когда применять.** Каждая диаграмма, которая уходит с вашего стола. Спарклайны — когда в таблице строка на продукт и читателю нужен тренд рядом с числом.

### SQL → сводная таблица, таблица соответствий :id=sql-pivot-the-translation-table

**Что это.** Каждая настройка сводной таблицы — это предложение SQL со второй–третьей недели. Держите таблицу открытой, пока щелчки не запомнятся.

| SQL (недели 2–3) | Сводная таблица |
|---|---|
| `GROUP BY product` | `product` в **Rows** |
| `GROUP BY product, bucket` как перекрёстная таблица | `product` в Rows, `bucket` в **Columns** |
| `SUM(outstanding)`, `COUNT(*)`, `AVG(principal)`, `MAX(dpd)` | поле в **Values** с операцией Sum / Count / Average / Max |
| `WHERE status = 'active'` (фиксированно) | `status` в **Filters** или срез |
| `WHERE disbursed_at >= … AND < …` | **временная шкала** по `disbursed_at` или фильтр по дате в поле строк |
| `100.0 * SUM(x) / SUM(SUM(x)) OVER ()` | Show Values As → **% of Grand Total** |
| `SUM(x) / SUM(SUM(x)) OVER (PARTITION BY region)` | **% of Parent Row Total** |
| `SUM(SUM(x)) OVER (ORDER BY month)` | **Running Total In** month |
| `SUM(x) - LAG(SUM(x)) OVER (ORDER BY month)` | **Difference From** (previous) |
| `RANK() OVER (ORDER BY SUM(x) DESC)` | **Rank Largest to Smallest** |
| `ORDER BY SUM(x) DESC LIMIT 5` | сортировка + фильтр по значению → **Первые 10** → 5 |
| `strftime('%Y-%m', d)` в `GROUP BY` | правый щелчок по полю даты → **Группировать** → Месяцы, Годы |
| `SUM(a) / SUM(b)` | **вычисляемое поле** `= a / b` |
| `HAVING COUNT(*) > 100` | фильтр по значению → Больше на количестве |
| `COUNT(DISTINCT customer_id)` | при создании отметить *Добавить эти данные в модель данных* → **Число различных элементов** (Distinct Count) |

Чего сводная таблица не умеет: `JOIN` (сначала слияние в Power Query или столбец-поиск в данных) и окно по *строкам*, а не по группам (`ROW_NUMBER` на кредит). В **Sheets** для форм, которые сводная не делает, есть `QUERY`: `=QUERY(Loans!A1:M, "select D, sum(K), count(A) group by D order by sum(K) desc", 1)`.

**Когда применять.** Каждый раз, когда вы знаете запрос и нужны щелчки.

### Ошибки, которые стоят балла на этой неделе :id=mistakes-that-cost-a-point-this-week

- Сводная таблица на фиксированном диапазоне — новые строки никогда не приходят; стройте на таблице или запросе (P10).
- Забыли **Refresh** после обновления Power Query — сводная таблица показывает кэш прошлой недели.
- Сводная на таблице уровня платежа, суммирующая столбец уровня кредита, — каждый основной долг посчитан по разу на платёж (P8).
- *Average* в Values, когда в предложении говорится «ставка» или «доля», — отношение сумм требует вычисляемого поля или двух сумм и формулы.
- Круговая с пятью продуктами (два сектора по 0.5 % невидимы) или 3D-гистограмма.
- Ось столбцов, начинающаяся со 150 млрд.
- Заголовок диаграммы, называющий диаграмму (*Остаток долга по продуктам*), а не вывод.
- Однодневный столбец октября в месячном ряду без пометки.
- Два несвязанных показателя на двойной оси, из-за чего линии драматично пересекаются, — пересечение ничего не значит.
- Страница, оставленная отфильтрованной срезом, без видимой сверки с итогом таблицы.
