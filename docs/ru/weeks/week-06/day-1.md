### Вероятность — доля в долгом ряду испытаний :id=probability--a-long-run-share

**Что это.** **Вероятность** (*probability*) события A, **P(A)**, — число от 0 до 1: доля случаев, в которых A происходит, если одна и та же ситуация повторяется очень много раз. В кредитовании её никогда не знают точно. Её оценивают по истории: 91 дефолт по первому платежу (FPD) на 7 099 первых платежей даёт **P(FPD) ≈ 91 / 7 099 = 1.28 %**. Доля по нескольким случаям скачет; доля по многим случаям устанавливается (**закон больших чисел** — завтра измерим, как быстро).

**Как пишется.** P(A) ≈ (сколько раз произошло A) / (сколько раз смотрели). Блок разыгрывает новые партии кредитов с истинной долей FPD 1.28 % и выводит долю в каждой партии.

```python
# одни и те же «случайные» розыгрыши при каждом запуске
random.seed(2026)
p_true = 91 / 7099                # доля в долгом ряду
# каждый раз новая партия из n кредитов
for n in (10, 100, 1_000, 10_000, 100_000):
    # True = этот кредит — FPD
    k = sum(random.random() < p_true for _ in range(n))
    print(n, k, round(k / n, 4))  # кредитов, FPD, доля
```

| 10 | 0 | 0.0000 |
| 100 | 0 | 0.0000 |
| 1 000 | 13 | 0.0130 |
| 10 000 | 127 | 0.0127 |
| 100 000 | 1 282 | 0.0128 |

Партии из 10 и 100 кредитов показывают 0 % — истинные 1.28 % при таком размере не видны; 100 000 кредитов показывают 1.28 %.

**Когда применять.**
- Каждая доля в отчёте — доля FPD, доля одобрений, доля дефолтов — это оценка вероятности.
- Прежде чем доверять доле, посмотрите на знаменатель: 2 из 20 — намёк; 91 из 7 099 — свидетельство.

### События — противоположное, «и», «или» :id=events--complement-and-or

**Что это.** **Случайное событие** (*event*) — то, что для одного случая происходит или не происходит: D = «первый платёж по кредиту просрочен на 30+ дней» (FPD), A = «кредит пришёл через приложение». Из событий строят новые:

| Событие | Словами | Запись | Вероятность |
|---|---|---|---|
| **противоположное событие** (*complement*) | не D | D̄ | 1 − P(D) |
| **произведение событий** (*intersection*) | A и D | A ∩ D | посчитать случаи, где верно и то, и другое |
| **сумма событий** (*union*) | A или D, или оба | A ∪ D | P(A) + P(D) − P(A ∩ D) |

**Как пишется.** 7 099 кредитов в выборке FPD: 2 411 кредитов приложения, 91 FPD, 41 кредит — и то, и другое.

```text
              FPD     без FPD    итого
app            41      2 370     2 411
не app         50      4 638     4 688
итого          91      7 008     7 099
```

```python
n, app, fpd, both = 7099, 2411, 91, 41
print(round(1 - fpd / n, 4))  # не D:   0.9872
print(round(both / n, 4))     # A и D:  0.0058
# A или D: 0.3467 — 41 кредит вычитается один раз
print(round((app + fpd - both) / n, 4))
```

Сумма событий — это 2 461 кредит: 2 411 кредитов приложения плюс 91 FPD минус 41, посчитанный дважды, — значит P(A ∪ D) = 34.67 %.

События, которые не могут произойти вместе, — «приложение» и «филиал» для одного кредита, — называются **несовместными** (*mutually exclusive*). Их произведение пусто, а вероятности просто складываются.

**Когда применять.**
- «Какая доля *не* …» → противоположное событие. «… *и* …» → произведение. «… *или* …» → сумма.

> ⚠️ **Осторожно.** P(A или D) = P(A) + P(D) только тогда, когда A и D не пересекаются. 33.96 % + 1.28 % считает 41 FPD из приложения дважды; вычтите P(A ∩ D).

### Условная вероятность — «среди тех, кто…» :id=conditional-probability-quotamong-those-whoquot

**Что это.** **Условная вероятность** (*conditional probability*) **P(D | A)** — шанс D **среди случаев, где произошло A**. Черту читают как «при условии». Условие сужает знаменатель: со всех 7 099 кредитов до 2 411 кредитов приложения.

**Как пишется.** P(D | A) = P(A ∩ D) / P(A) = (число случаев «оба») / (число случаев A).

```python
# P(FPD | app) = 41 / 2 411 = 0.0170 — насколько рискован кредит из приложения?
print(round(both / app, 4))
# P(app | FPD) = 41 / 91    = 0.4505 — откуда берутся наши FPD?
print(round(both / fpd, 4))
```

Те же 41 кредит, два знаменателя: у 1.70 % кредитов приложения есть FPD, а 45.1 % всех FPD пришли через приложение.

**Когда применять.**

| | P(FPD при условии app) | P(app при условии FPD) |
|---|---|---|
| Знаменатель | 2 411 кредитов приложения | 91 FPD |
| Значение | 1.70 % | 45.1 % |
| Отвечает на вопрос | насколько рискован кредит из приложения? | откуда берутся наши дефолты? |
| В SQL | `WHERE channel = 'app'`, затем доля FPD | `WHERE fpd30 = 1`, затем доля app |

> ⚠️ **Осторожно.** У P(D | A) и P(A | D) общий только числитель (41 кредит). Прежде чем произнести процент вслух, назовите его знаменатель: «из кредитов приложения…» (2 411) или «из FPD…» (91).

### Независимость :id=independence

**Что это.** Два события **независимы** (*independent events*), если знание одного не меняет шанс другого: **P(D | A) = P(D)**. То же самое иначе: **P(A ∩ D) = P(A) · P(D)**.

**Как пишется.** Сравните условную долю с общей или наблюдаемую долю «оба» с произведением.

```python
p_app, p_fpd = app / n, fpd / n
# P(D | A) = 0.0170   против  P(D) = 0.0128
print(round(both / app, 4), round(p_fpd, 4))
# P(A ∩ D) = 0.00578 против  P(A)·P(D) = 0.00435
print(round(both / n, 5), round(p_app * p_fpd, 5))
```

Если бы канал не имел значения, FPD из приложения составляли бы 0.435 % от 7 099 кредитов — около 31; их 41. В этой выборке канал и FPD **не** независимы.

**Когда применять.**
- Перемножать вероятности («оба заёмщика уйдут в дефолт = p × p») можно только для независимых событий.
- Биномиальная модель ниже это предполагает: дефолт одного заёмщика не меняет шанс другого.

> ⚠️ **Осторожно.** «Не независимы в выборке» — ещё не «не независимы в реальности»: 10 лишних кредитов могут быть случайностью, и тест в среду это измерит. Кроме того, независимые — не то же, что несовместные. Несовместные события сильно зависимы: если произошло одно, другое произойти не может.

### Формула полной вероятности — доля как взвешенное среднее :id=the-law-of-total-probability--a-rate-as-a-weighted-average

**Что это.** **Формула полной вероятности** (*law of total probability*) собирает общую долю из групп, которые покрывают каждый случай ровно один раз: **P(D) = Σ P(D | группа) · P(группа)**. Доля по портфелю — **взвешенное среднее** долей по группам; вес каждой группы — её доля в портфеле.

**Как пишется.**

```python
# P(FPD | канал)
rate  = {"app": 41 / 2411,   "branch": 34 / 3263,   "partner": 16 / 1425}
# P(канал)
share = {"app": 2411 / 7099, "branch": 3263 / 7099, "partner": 1425 / 7099}
# 0.0128 — доля по портфелю
print(round(sum(rate[c] * share[c] for c in rate), 4))
```

| канал | доля P(канал) | доля FPD | доля × доля FPD |
|---|---|---|---|
| app | 0.3396 | 1.70 % | 0.58 % |
| branch | 0.4596 | 1.04 % | 0.48 % |
| partner | 0.2007 | 1.12 % | 0.23 % |
| **портфель** | 1 | | **1.28 %** |

1.28 % по портфелю — это три куска, по одному на канал: 0.58 + 0.48 + 0.23 п.п.

**Когда применять.**
- Новая структура: доля следующего месяца = Σ (новая доля канала × доля FPD канала).
- Знаменатель формулы Байеса (следующий подраздел) — это и есть формула полной вероятности.

> ⚠️ **Осторожно.** Группы не должны пересекаться и должны покрывать всех. Каналы так и устроены; «app» и «грейд C» — нет: кредит грейда C из приложения будет посчитан дважды.

**Что это.** **Формула Байеса** (*Bayes' rule*) «переворачивает» условную вероятность: от P(flag | fraud) — как часто мошенник получает пометку — к **P(fraud | flag)** — как часто пометка указывает на мошенника. Ответ сильно зависит от **базовой частоты** (*base rate*): насколько мошенничество распространено ещё до всякой пометки.

```pic

```

**Как пишется.** Словами: помеченные мошенники, делённые на всех помеченных.

```text
P(fraud | flag) =
  P(flag | fraud) · P(fraud)
  / [ P(flag | fraud) · P(fraud)
    + P(flag | honest) · P(honest) ]
```

Проще всего — **натуральные частоты**: представьте 10 000 заявителей. Правило вендора находит 90 % мошенников (**чувствительность**, *sensitivity*) и помечает 5 % честных заявителей (**доля ложных срабатываний**, *false-positive rate*). Наша базовая частота мошенничества с первым платежом — кредит, по которому не заплачено ни одного сума первого платежа, — 44 из 7 099 = 0.62 %.

```python
N, prior, sens, fpr = 10_000, 44 / 7099, 0.90, 0.05
fraud  = N * prior            # мошенники среди 10 000 заявителей
honest = N - fraud            # честные заявители
tp = sens * fraud             # помеченные мошенники
fp = fpr * honest             # помеченные честные заявители
print(round(fraud), round(tp), round(honest), round(fp))   # 62 56 9938 497
# 0.101 = P(fraud | flag)
print(round(tp / (tp + fp), 3))
```

### Случайные величины, математическое ожидание и дисперсия :id=random-variables-expected-value-and-variance

**Что это.** **Случайная величина** (*random variable*) — число, зависящее от случая: убыток по одному кредиту, число FPD в следующем месяце. **Дискретная** (*discrete*) принимает значения из списка, у каждого своя вероятность; **непрерывная** (*continuous*) принимает любое значение из промежутка. Её описывают три числа:
- **математическое ожидание** (*expected value*) E[X] = Σ x · P(X = x) — среднее в долгом ряду;
- **дисперсия** (*variance*) Var(X) = Σ (x − E[X])² · P(X = x) — средний квадрат расстояния до E[X];
- **стандартное отклонение** (*standard deviation*) sd = √Var — разброс в единицах самой величины.

**Как пишется.** Один потребительский кредит: выдано 27 млн сумов, PD = 77 / 2 418 = 3.18 % (потребительские кредиты сейчас в 90+), при дефолте теряется 60 % суммы.

| убыток L | P(L) |
|---|---|
| 0 | 0.9682 |
| 16.2 млн сумов (0.6 × 27 млн) | 0.0318 |

```python
# возможные убытки, сумы
values = [0, 0.6 * 27_000_000]
# их вероятности (в сумме 1)
probs  = [1 - 77 / 2418, 77 / 2418]
# математическое ожидание
E   = sum(x * q for x, q in zip(values, probs))
Var = sum((x - E) ** 2 * q for x, q in zip(values, probs))  # дисперсия
print(round(E), round(math.sqrt(Var)))                      # 515881 2844492
```

Ожидаемый убыток — 0.52 млн сумов, sd — 2.84 млн: разброс в пять раз больше среднего, так что один кредит — лотерейный билет.

Четыре правила на всю неделю: E[aX + b] = a·E[X] + b; Var(aX + b) = a²·Var(X); математические ожидания суммы складываются всегда; дисперсии складываются, когда величины независимы. Для 400 независимых потребительских кредитов: E = 400 × 0.52 млн = 206.4 млн, sd = √400 × 2.84 млн = 56.9 млн.

**Когда применять.**
- Ожидаемый убыток, ожидаемая выручка, ожидаемое число дефолтов: E.
- Насколько результат может отклониться от E: sd.

> 💡 **Главная мысль.** Математические ожидания складываются всегда; дисперсии — когда кредиты независимы. Поэтому итог растёт как n, а его разброс — как √n: это арифметика «многих мелких кредитов» и каждой завтрашней стандартной ошибки.

### Пуассон — заявки в час :id=poisson--applications-per-hour

**Что это.** **Распределение Пуассона** (*Poisson*) считает события в фиксированном окне — час, день, — когда они приходят независимо с постоянной средней интенсивностью **λ**. Параметр один, и **среднее = дисперсия = λ**. Фиксированного n нет: в часе может быть 0, 1, 2 … заявок.

**Как пишется.** P(X = k) = e^(−λ) · λ^k / k!. Заявки Nur за 2026 год (1 янв – 30 сен, календарные часы 08:00–20:59, пустые часы учтены): 5 102 заявки за 3 549 часов.

```python
lam, hours = 5102 / 3549, 3549  # λ = 1.44 заявки в час
def pois(k, lam):               # P(X = k) для X ~ Poisson(lam)
    return math.exp(-lam) * lam**k / math.factorial(k)
# сколько часов с 0, 1, … 6 заявками ожидает модель
print([round(hours * pois(k, lam), 1) for k in range(7)])
# 0.2375: пустой час   Excel: =POISSON.DIST(0, 1.4376, FALSE)
print(round(pois(0, lam), 4))
# 0.0158: 5 и более    Excel: =1 - POISSON.DIST(4, 1.4376, TRUE)
print(round(1 - sum(pois(k, lam) for k in range(5)), 4))
```

### Показательное — минуты между заявками :id=exponential--minutes-between-applications

**Что это.** Если приходы заявок подчиняются Пуассону, то **промежутки** между ними имеют **показательное (экспоненциальное) распределение** (*exponential*). Оно непрерывное — промежуток может длиться 12.4 минуты — и имеет один параметр: средний промежуток. Его странное свойство — **отсутствие последействия** (*memorylessness*): после 30 тихих минут ожидание следующей заявки по-прежнему в среднем 39 минут.

**Как пишется.** P(промежуток > t) = e^(−t / средний промежуток).

```python
# EXPON.DIST(60, 1/39.34, TRUE)

# 0.4665: P(промежуток > 30 мин); наблюдалось 0.4587
print(round(math.exp(-30 / mean_gap), 4))
```

По модели 21.8 % промежутков длятся больше часа; по данным — 21.7 %.

**Когда применять.**

> ⚠️ **Осторожно.** Отсутствие последействия подходит для приходов от многих независимых людей. Оно не подходит для того, что идёт по графику: платежи скапливаются у даты платежа, поэтому время до следующего платежа не показательное.

### Нормальное — кредитные скоры :id=normal--credit-scores

### Дисперсия и стандартное отклонение данных :id=variance-and-standard-deviation-of-data

**Что это.** **Дисперсия** (*variance*) столбца данных — средний квадрат расстояния до среднего. **Стандартное отклонение** (*standard deviation*) — корень из неё, снова в единицах столбца. Для **выборки** делят на n − 1, а не на n — это **выборочная дисперсия** (*sample variance*). pandas `.std()` и Excel `STDEV.S` делают так по умолчанию.

**Как пишется.** Пять кредитов 2, 4, 5, 6, 33 (среднее 10):

| x | x − среднее | (x − среднее)² |
|---|---|---|
| 2 | −8 | 64 |
| 4 | −6 | 36 |
| 5 | −5 | 25 |
| 6 | −4 | 16 |
| 33 | 23 | 529 |
| **сумма** | 0 | **670** |

Дисперсия = 670 / (5 − 1) = 167.5; sd = √167.5 = 12.94.

```python
# 167.5 12.94   Excel: =VAR.S(…), =STDEV.S(…)
print(st.variance(x), round(st.stdev(x), 2))
# 59.5 пункта (скоры), 112.6 млн сумов (основной долг)
print(round(s.std(), 1), round(prin.std() / 1e6, 1))
```

Скоры колеблются примерно на 59.5 пункта вокруг 659.6; основной долг — на 112.6 млн вокруг 51.7 млн, больше чем вдвое против среднего.

**Когда применять.**
- Насколько разбросан столбец, в его собственных единицах.
- Сравнение разброса двух групп; завтрашняя стандартная ошибка — это sd / √n.

> ⚠️ **Осторожно.** `np.std(x)` в NumPy делит на n; `.std()` в pandas — на n − 1. На 7 828 кредитах разницы не видно; на пяти значениях выше это 11.58 против 12.94. Пишите `ddof=1` в NumPy, когда имеете в виду выборку.

### Перцентили и квартили — где стоит значение :id=percentiles-and-quartiles--where-a-value-stands

**Что это.** **p-й перцентиль** (*percentile*; иначе — *квантиль* уровня p/100) — значение, ниже которого лежат p % данных. 50-й перцентиль — медиана. 25-й и 75-й — **квартили** (*quartiles*) Q1 и Q3. Q3 − Q1 — **межквартильный размах**, IQR (*interquartile range*), ширина центральной половины.

**Как пишется.** `col.quantile(q)`, где q от 0 до 1.

```python
# 15.8: скор 600 — это 16-й перцентиль
print(round(100 * (s < 600).mean(), 1))
```

Четверть кредитов меньше 2.88 млн; центральная половина — от 2.88 до 34.71 млн (IQR 31.8 млн); каждый десятый кредит больше 187 млн.

### Асимметрия — когда среднее и медиана расходятся :id=skew--when-the-mean-and-the-median-disagree

**Что это.** **Асимметрия** (*skewness*) измеряет, насколько распределение перекошено. **Правосторонняя** (положительная) асимметрия: длинный хвост больших значений, среднее выше медианы — деньги, доходы, дни просрочки. **Левосторонняя** (отрицательная): длинный хвост малых значений, среднее ниже медианы. Асимметрия около 0 — симметрия, среднее ≈ медиана.

**Как пишется.** `.skew()` в pandas. Больше примерно +1 или меньше −1 — сильная асимметрия.

```python
print(round(prin.skew(), 2), round(s.skew(), 2))  # 2.93 -0.04
# 8.9: средний основной долг почти в девять раз больше медианы
print(round(prin.mean() / prin.median(), 1))
```

### Симуляция — когда формулы кончаются :id=simulation--when-the-formula-runs-out

**Что это.** **Симуляция** (*simulation*, имитационное моделирование) много раз разыгрывает случайный мир на компьютере и считает, что произошло. Она отвечает на вопросы, которых не покрывает ни одна формула: месяц со смесью продуктов с разными PD, дефолты, которые движутся вместе, убыток со случайным LGD.

**Как пишется.** Разыграть, посчитать, сверить с формулой там, где она есть.

```python
# с seed: одни и те же «случайные» числа при каждом запуске
rng = np.random.default_rng(2026)
# 100 000 разыгранных месяцев по 400 кредитов
months = rng.binomial(400, 91 / 7099, size=100_000)
# 5.115, 0.0355 — по формуле 5.127, 0.0357
print(months.mean(), np.mean(months >= 10))
# [1, 10]: центральные 95 % месяцев
print(np.quantile(months, [0.025, 0.975]))
```

100 000 разыгранных месяцев дают в среднем 5.115 FPD и 10 или больше в 3.55 % случаев — это 5.127 и 3.57 % формулы в пределах шума симуляции.

**Когда применять.**
- Когда в модели есть части, которых не покрывает ни одно учебное распределение.
- Чтобы проверить формулу, в которой вы не уверены.

> 💡 **Главная мысль.** Симуляция — это формула, которую можно написать всегда: разыграйте мир много раз и посчитайте. Задайте seed, чтобы другие получили ваши числа, и проверьте её там, где формула есть, прежде чем доверять там, где её нет.

### Собираем вместе :id=putting-it-together

Один запрос — почти все инструменты дня: *«400 потребительских кредитов в следующем месяце — сколько будет дефолтов и сколько денег мы можем потерять?»*

```python
# вероятность: PD потребительского кредита, доля в долгом ряду
n, p_c = 400, 77 / 2418
# случайная величина: 16.2 млн сумов теряется при дефолте одного кредита
loss_if_default = 0.6 * 27_000_000
# биномиальное: ожидаемое число дефолтов
mean_d = n * p_c
# и его sd (предполагаем независимость)
sd_d = math.sqrt(n * p_c * (1 - p_c))
# перцентили биномиального:
lo = min(k for k in range(n + 1) if cdf(k, n, p_c) >= 0.025)
# центральные 95 % месяцев
hi = min(k for k in range(n + 1) if cdf(k, n, p_c) >= 0.975)
print(round(mean_d, 1), round(sd_d, 2), lo, hi)  # 12.7 3.51 6 20
# 206.4: ожидаемый убыток, млн сумов (мат. ожидания складываются)
print(round(mean_d * loss_if_default / 1e6, 1))
# 5.9 19.6: нормальное упрощение, ±1.96 sd
print(round(mean_d - 1.96 * sd_d, 1), round(mean_d + 1.96 * sd_d, 1))
```

|---|---|---|
| PD = 77 / 2 418 | 3.18 % | вероятность как доля в долгом ряду; условная — P(90+ при условии «потребительский») |
| убыток по одному кредиту | 0 или 16.2 млн | случайная величина, Бернулли |
| дефолты среди 400 | ожидаем 12.7, sd 3.51 | биномиальное, независимость |
| обычный месяц | от 6 до 20 дефолтов | перцентили биномиального |
| ожидаемый убыток | 206.4 млн сумов | математическое ожидание — ожидания складываются |
| быстрая проверка | от 5.9 до 19.6 | нормальное, 68-95-99.7 (±1.96 sd) |

## 2. Разбор примера — число Нилуфар для стены (15 мин) :id=_2-worked-example-nilufar39s-wall-number-15-min

**Шаг 1 — вероятность как доля в долгом ряду, затем биномиальная модель.** p = 91 / 7 099 = 1.282 % — доля FPD по портфелю в долгом ряду. Каждый из 400 кредитов следующего месяца — испытание Бернулли с этим p; предполагаем **независимость**; X = число FPD ~ Bin(400, 0.01282).

**Шаг 2 — математическое ожидание и sd биномиального.** E[X] = n·p = 400 × 0.01282 = **5.13**; sd = √(n·p·(1 − p)) = √(400 × 0.01282 × 0.98718) = **2.25**.

**Шаг 3 — перцентили: как выглядит обычный месяц.** Центральные 95 %: `X.ppf([0.025, 0.975])` → **от 1 до 10** (поскольку значения целые, P(1 ≤ X ≤ 10) равно 97.9 %, а не ровно 95). Нулевое число FPD само по себе необычно: P(X = 0) = 0.57 %.

**Шаг 4 — хвост биномиального, P(X ≥ k).** P(X ≥ k) для k = 8 … 13: 14.6 %, 7.5 %, **3.6 %**, 1.6 %, **0.6 %**, 0.2 %. Наименьшее k, при котором P(X ≥ k) ≤ 5 %, — **10**; при ≤ 1 % — **12**. Excel: `=BINOM.INV(400, 91/7099, 0.95) + 1` → 10, `=BINOM.INV(400, 91/7099, 0.99) + 1` → 12.

**Шаг 5 — симуляция для проверки формулы.** 100 000 месяцев с seed: среднее 5.115, P(X ≥ 10) = 3.55 %, центральные 95 % [1, 10] — формула, дважды.

**Шаг 6 — ответ, с формулой полной вероятности в качестве оговорки.** *«Ожидайте около 5 FPD на 400 кредитов; всё от 1 до 10 — обычный шум. Десять и больше случается менее чем в 4 месяцах из 100, если ничего не изменилось, — посмотрите на это; двенадцать и больше случается реже, чем раз в 100 месяцев, — звоните мне. Граница предполагает, что структура этого месяца такая же, как у портфеля; если 400 кредитов в основном из приложения (1.70 %), ожидаемое число равно 6.8, и 10 уже не редкость (14.8 %)».* Доля p по портфелю — взвешенное среднее долей по каналам, поэтому новая структура означает новое p.

**Шаг 7 — снова хвост биномиального, для прошлого октября.** 7 FPD на 288 кредитов; P(X ≥ 7 | n = 288, p = 1.28 %) = **8.0 %**. Необычно, но не тревожно — а за год из двенадцати поколений вы *должны ожидать* одно такого уровня. День 4 назовёт это проблемой множественных сравнений; сегодня это причина не созывать совещание при первой же семёрке.

- `sf(10)` для «10 и более» — это P(X > 10) = P(X ≥ 11). P(X ≥ k) = `sf(k − 1)` = `1 − BINOM.DIST(k − 1, …, TRUE)`.

## 6. Уголок компании <span class="badge company">Ожидаемые потери</span> :id=6-company-corner-expected-loss

У каждого кредитора есть число, отвечающее на вопрос «сколько этот портфель потеряет в среднем»: **ожидаемые потери** (*expected loss*).

- **PD — вероятность дефолта** (*probability of default*): шанс того, что кредит уйдёт в дефолт за горизонт (обычно 12 месяцев). Дефолт = 90+ DPD или «маловероятно, что заплатит».
- **LGD — уровень потерь при дефолте** (*loss given default*): доля задолженности, потерянная **при** дефолте, после возвратов (залог, взыскание, продажа долга). Необеспеченные потребительские кредиты: часто 50–80 %.
- **EAD — сумма под риском на момент дефолта** (*exposure at default*): что должны на момент дефолта — для амортизируемого кредита это остаток основного долга.

**EL = PD × LGD × EAD.** Это математическое ожидание случайной величины из раздела 1, просуммированное по кредитам (математические ожидания складываются — независимость или нет).

Грубая версия для Nur по грейдам на 2026-10-01: PD = доля кредитов грейда, сейчас находящихся в 90+; EAD = остаток основного долга по performing-кредитам (ещё не в 90+); **LGD = 60 %, принято допущением**.

```python
# (shape only — not meant to run)
# dpd_per_loan с 5-й недели + остаток долга (основной долг к оплате после даты
# отчёта)
L = loans_with_dpd_and_outstanding
L["d90"] = (L["dpd"] > 90).astype(int)
el = L.groupby("risk_grade").agg(loans=("loan_id", "size"), d90=("d90", "sum"))
el["PD"] = el["d90"] / el["loans"]
el["EAD"] = L[(L.d90 == 0) & (L.outstanding > 0)].groupby("risk_grade")["outstanding"].sum()
el["EL"] = el["PD"] * 0.60 * el["EAD"]
```

Грейд C — это 26.6 % экспозиции и **46.3 %** ожидаемых потерь; грейд D — 4.7 % экспозиции и 17.5 % потерь. Вот фраза для пакета по рискам: *потери живут в C и D, а не там, где деньги.*

**Это учебное упрощение, и мы говорим об этом прямо.** «PD» здесь — доля за всё время на сегодня, смешивающая кредиты любого возраста (кредит, выданный в прошлом месяце, не успел дойти до 90+; закрытый кредит не дойдёт никогда), поэтому это ни 12-месячная, ни пожизненная PD. LGD — догадка, одинаковая для всех грейдов. Настоящие банки оценивают **PD** по скоринговым картам и моделям поколений и переходов между корзинами просрочки (roll-rate) (неделя 3), откалиброванным на фиксированном горизонте, **LGD** — по фактически собранным возвратам по прошлым дефолтам за период работы с проблемной задолженностью, с дисконтированием, а **EAD** — по графику амортизации на ожидаемую дату дефолта.
