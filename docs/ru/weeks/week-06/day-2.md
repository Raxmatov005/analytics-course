### Генеральная совокупность и выборка — процесс за таблицей :id=population-and-sample--the-process-behind-the-table

**Что это.** **Генеральная совокупность** (*population*) — это всё, о чём вы хотите говорить. **Выборка** (*sample*) — та часть, которую вы наблюдали. **Параметр** (*parameter*) — истинное значение в совокупности: μ для среднего, p для доли; он неизвестен. **Оценка** (*estimate*), или статистика, — та же величина, посчитанная по выборке: x̄, p̂. Одно число — это **точечная оценка** (*point estimate*).

Даже «все 2 411 кредитов из приложения» — это выборка, когда вопрос о **процессе**: *будут* ли кредиты из приложения чаще уходить в дефолт? Кредитов из приложения следующего года в таблице нет.

| | Совокупность (неизвестна) | Выборка (то, что вы считаете) |
|---|---|---|
| среднее | μ | x̄ |
| стандартное отклонение | σ | s |
| доля | p | p̂ |
| объём | N | n |

### Хорошая оценка — несмещённая и состоятельная :id=a-good-estimate--unbiased-and-consistent

**Что это.** Хорошая оценка **несмещённая** (*unbiased*): верна в среднем по многим выборкам. Ещё она **состоятельная** (*consistent*): приближается к истине с ростом n. Выборочная дисперсия делится на **n − 1**, а не на n, чтобы быть несмещённой.

**Как пишется.** Выборочная дисперсия = сумма квадратов расстояний до выборочного среднего ÷ (n − 1). numpy: `x.var(ddof=1)`; pandas: `.var()`; Excel: `VAR.S`, `STDEV.S`. Проверьте экспериментом — 20 000 выборок по пять скоров, обе формулы, усреднение:

```python
# 20 000 выборок, n = 5 в каждой
samples = np.array([rng.choice(s, 5, replace=False) for _ in range(20_000)])
# 3543: дисперсия совокупности 13 612 скоров
print(round(s.var()))
# ≈ 2 862 (занижено), ≈ 3 578 (верно в среднем)
print(samples.var(axis=1, ddof=0).mean(), samples.var(axis=1, ddof=1).mean())
```

Деление на n даёт около 2 860 вместо 3 543 — на 20 % меньше при n = 5. Деление на n − 1 попадает около 3 543. Причина: собственное среднее выборки ближе к её пяти точкам, чем истинное среднее, поэтому квадраты расстояний выходят меньше в (n − 1)/n раза. (Стандартное отклонение, √ дисперсии, всё равно в среднем чуть занижено — 56.2 против 59.5 здесь, — и никто не против.)

**Когда применять.**
- Любое выборочное sd или дисперсия: `ddof=1`. При n = 5 (пилот, неделя филиала) разница 20 %; при n = 2 411 она незаметна.

> ⚠️ **Осторожно.** `np.std(x)` и `np.var(x)` по умолчанию берут ddof = 0 — формулу для совокупности; `.std()` в pandas берёт ddof = 1. В каждом выборочном расчёте передавайте numpy `ddof=1`.

### Ошибка выборки — каждая выборка немного промахивается :id=sampling-error--every-sample-misses-a-little

**Что это.** **Ошибка выборки** (*sampling error*) — разрыв между оценкой и параметром: x̄ − μ. Она возникает из-за того, *какие* единицы случайно попали в выборку. Это не ошибка в работе. Она есть у каждой выборки, и у другой выборки она другая.

### Стандартная ошибка — насколько сдвигается оценка :id=standard-error--how-much-an-estimate-moves

**Что это.** Берите выборку за выборкой — и оценка сдвигается. Её распределение по повторным выборкам называется **выборочным распределением** (*sampling distribution*). Стандартное отклонение этого распределения — **стандартная ошибка** (*standard error*, SE): типичный размер ошибки выборки.

**Как пишется.**

```text
SE of a mean
  = s / √n
  (sd данных ÷ квадратный корень
   из объёма выборки)
SE of a proportion
  = √( p̂ (1 − p̂) / n )
```

```python
# 5.69: SE среднего основного долга по 392 кредитам, млн сумов
print(round(pop.std() / math.sqrt(392) / 1e6, 2))
p = 41 / 2411
# 0.263: SE ставки FPD приложения, в пунктах
print(round(100 * math.sqrt(p * (1 - p) / 2411), 3))
```

Средний основной долг по 392 кредитам сдвигается от выборки к выборке примерно на 5.7 млн — это размер ошибок в таблице выше (от −3.4 до +8.5 млн). 1.70 % приложения сдвигается примерно на 0.26 пункта.

**Когда применять.**
- Внутри каждого интервала и каждого теста этой недели: оценка ± критическое значение × SE.
- Для планирования: вчетверо больше кредитов — вдвое меньше SE.

| | Стандартное отклонение (sd) | Стандартная ошибка (SE) |
|---|---|---|
| описывает | кредиты: насколько они различаются | оценку: насколько она сдвинулась бы |
| с ростом числа кредитов | почти не меняется | уменьшается как 1 / √n |
| основной долг, n = 400 | 112.6 млн | 112.6 / √400 = 5.63 млн |

> ⚠️ **Осторожно.** Интервал, построенный по sd вместо SE, шириной с сами данные — в √n раз шире, чем нужно. sd — про кредиты; SE — про ваше число.

### Закон больших чисел — среднее успокаивается :id=the-law-of-large-numbers--the-average-settles

**Что это.** **Закон больших чисел** (*law of large numbers*, ЗБЧ): с ростом n выборочное среднее приближается к среднему совокупности и остаётся рядом. Ему нужно конечное среднее — задача со звёздочкой показывает распределение, у которого его нет.

**Как пишется.** Скользящее среднее после n наблюдений = сумма первых n значений ÷ n.

```python
# 7 828 основных долгов в случайном порядке
order = np.random.default_rng(2026).permutation(pop)
# среднее после 1, 2, 3, … кредитов
running = np.cumsum(order) / np.arange(1, len(order) + 1)
for n in (10, 100, 1000, 7828):
    # сначала скачет; ровно 51.71 млн на 7 828
    print(n, round(running[n - 1] / 1e6, 2))
```

Одно перемешивание дало **106.38 млн** после 10 кредитов, **35.06 млн** после 100, **52.06 млн** после 1 000 и **51.71 млн** после всех 7 828. Ранние средние скачут, потому что один кредит МСБ (до 599 млн) перевешивает десять микрокредитов. Колебания затухают как 1 / √n.

**Когда применять.**
- Причина, по которой ставка по 2 411 кредитам стоит больше, чем ставка по 50.
- Причина не судить о новом филиале по первой неделе: скользящее среднее при n = 10 может быть вдвое больше истины.

### Доверительный интервал для среднего — t, а не z :id=confidence-interval-for-a-mean--t-not-z

**Что это.** **Доверительный интервал** (*confidence interval*, CI) — диапазон правдоподобных значений параметра: **оценка ± критическое значение × SE**. Для среднего критическое значение берётся из **распределения Стьюдента** (*Student's t*) с n − 1 **степенями свободы** (*degrees of freedom*), потому что вместо неизвестной σ стоит s. Значение z, 1.96, — предел t при росте n.

**Как пишется.** Среднее ± t(0.975, n − 1) × s / √n.

| df | 4 | 9 | 29 | 49 | 99 | 999 | ∞ (z) |
|---|---|---|---|---|---|---|---|
| t₀.₉₇₅ | 2.776 | 2.262 | 2.045 | 2.010 | 1.984 | 1.962 | 1.960 |


**Когда применять.**
- Среднее с его точностью: средний чек потребительского кредита, средний скор одобренных кредитов.

| ширина относительно другого | уже | на 15 % шире при n = 10, на 2.5 % при n = 50 |
| когда брать | практически никогда | всегда, для среднего |

### Доверительный интервал для доли — интервал Вальда :id=confidence-interval-for-a-proportion--the-wald-interval

**Что это.** **Интервал Вальда** (*Wald interval*) — учебниковый интервал для доли: p̂ ± 1.96 × √(p̂ (1 − p̂) / n). Он предполагает, что выборочное распределение доли — симметричный колокол. Около 0 % это не так: доля не может уйти ниже нуля, а вверх может уйти далеко.

**Как пишется.**

```python
def wald(k, n, z=1.96):  # k событий в n испытаниях
    p = k / n            # оценка p̂
    # критическое значение × стандартная ошибка
    half = z * math.sqrt(p * (1 - p) / n)
    return p - half, p + half
```

### Интервал Уилсона — правильный выбор по умолчанию для доли :id=the-wilson-interval--the-right-default-for-a-rate

**Что это.** **Интервал Уилсона** (*Wilson interval*) строится обращением критерия счёта (score test), а не колоколом вокруг p̂. Он никогда не отрицателен, никогда не имеет нулевой ширины, асимметричен в нужную сторону около 0 % и покрывает близко к 95 %. Интервал **Клоппера–Пирсона** («точный», *exact*) строится из самого биномиального распределения; он гарантирует *не менее* 95 % и потому слегка широк.

**Как пишется.**

```text
centre
  = (p̂ + z²/2n) / (1 + z²/n)
half-width
  = z √( p̂(1 − p̂)/n + z²/4n² )
    / (1 + z²/n)
```

```python
def wilson(k, n, z=1.96):
    p = k / n
    # чуть сдвинут к 50 %
    centre = (p + z**2 / (2 * n)) / (1 + z**2 / n)
    half = z * math.sqrt(p * (1 - p) / n + z**2 / (4 * n**2)) / (1 + z**2 / n)
    return centre - half, centre + half
# биномиальная P(X = k), из Дня 1 (нужна в практике)
def pmf(k, n, p):
    return math.comb(n, k) * p**k * (1 - p)**(n - k)
# 95 % CI для разности p1 − p2
def newcombe(k1, n1, k2, n2):
    p1, p2 = k1 / n1, k2 / n2
    l1, u1 = wilson(k1, n1); l2, u2 = wilson(k2, n2)
    d = p1 - p2
    return d, d - math.sqrt((p1 - l1)**2 + (u2 - p2)**2), d + math.sqrt((u1 - p1)**2 + (p2 - l2)**2)

for name, k, n in [("app", 41, 2411), ("branch", 34, 3263), ("partner", 16, 1425), ("2 in 150", 2, 150), ("0 in 120", 0, 120)]:
    print(name, "Wilson", [round(100 * v, 2) for v in wilson(k, n)], "Wald", [round(100 * v, 2) for v in wald(k, n)])
# [0.66, 0.05, 1.33]
print("app − branch", [round(100 * v, 2) for v in newcombe(41, 2411, 34, 3263)])
```

Приложение **1.26–2.30 %**, филиалы **0.75–1.45 %**, партнёры **0.69–1.82 %**; 2 из 150 → 0.37–4.73 %; 0 из 120 → 0–3.10 %. Интервал приложения уходит на 0.44 пункта ниже 1.70 и на 0.60 выше: правильная форма для ставки около нуля. В Excel нет функции Уилсона — при k в B1, n в B2, z в B3 (`=NORM.S.INV(0.975)`):

| Граница | Excel |
|---|---|
| Уилсон, нижняя | `=(B1/B2 + B3^2/(2*B2) - B3*SQRT(B1/B2*(1-B1/B2)/B2 + B3^2/(4*B2^2))) / (1 + B3^2/B2)` |
| Уилсон, верхняя | то же с `+` перед `B3*SQRT` |
| Клоппер–Пирсон, нижняя | `=BETA.INV(0.025, B1, B2-B1+1)` |
| Клоппер–Пирсон, верхняя | `=BETA.INV(0.975, B1+1, B2-B1)` |

**Когда применять.** Любая доля при любом n — FPD, доля одобрения, PAR30. Клоппер–Пирсон — когда аудитор или регулятор требует гарантированные 95 %. ### Объём выборки для заданной точности :id=sample-size-for-a-given-margin

**Что это.** **Предельная ошибка** (*margin of error*) E — полуширина интервала. Нужный **объём выборки** (*sample size*) — такое n, при котором предельная ошибка не больше E. Решите E = z × SE относительно n.

**Как пишется.**

```text
для доли:
  n = z² · p(1 − p) / E²
  p = ваша лучшая догадка; 0.5,
  если догадки нет (худший случай)
для среднего:
  n = (z · σ / E)²
  σ = из истории или пилота
округляйте всегда вверх
```

```python
z = 1.96
# кредитов нужно, чтобы оценить долю около p с точностью ± E
def n_for_rate(p, E):
    return math.ceil(z**2 * p * (1 - p) / E**2)
# наблюдений нужно, чтобы оценить среднее с точностью ± E
def n_for_mean(sigma, E):
    return math.ceil((z * sigma / E) ** 2)

print(n_for_rate(91 / 7099, 0.005), n_for_rate(0.5, 0.03))  # 1945 1068
print(n_for_mean(112.6e6, 5e6))                             # 1949
```

Ставка около 1.28 % с точностью ±0.5 пункта требует 1 945 кредитов. Доля, о которой вы ничего не знаете, с точностью ±3 пункта требует 1 068 — та самая «примерно тысяча» опросов общественного мнения. Средний основной долг с точностью ±5 млн сумов требует 1 949 кредитов.

| точность для ставки около 1.28 % | ±1 пункт | ±0.5 пункта | ±0.25 пункта |
|---|---|---|---|
| нужно кредитов | 487 | 1 945 | 7 779 |

Вдвое меньшая погрешность — вчетверо больше кредитов.

**Когда применять.**
- Перед пилотом, аудиторской выборкой или опросом: сколько случаев нам нужно?
- Чтобы сказать, какой точности сегмент вообще может достичь: филиал с 400 кредитами в год не определит FPD с точностью ±0.25 пункта.

> ⚠️ **Осторожно.** E в тех же единицах, что и p: ±0.5 пункта — это E = 0.005, а не 0.5. И формула использует арифметику Вальда — для ставки около 0 % при малом n проверьте результат интервалом Уилсона.

### Бутстреп — интервал без формулы :id=the-bootstrap--an-interval-without-a-formula

**Что это.** **Бутстреп** (*bootstrap*) считает выборку совокупностью. Он много раз пересэмплирует выборку **с возвращением**, каждый раз считает статистику и берёт 2.5-й и 97.5-й процентили: **процентильный бутстреп**.

**Как пишется.**

```python
def bootstrap_ci(values, stat=np.mean, B=10_000, seed=2026):
    # собственный генератор с зерном
    g = np.random.default_rng(seed)
    # B пересэмплов, статистика каждого
    boot = [stat(g.choice(values, len(values), replace=True)) for _ in range(B)]
    # средние 95 %
    return np.quantile(boot, [0.025, 0.975])
# ≈ 1.20 % … 2.24 %   (Уилсон 1.26 … 2.30)
print(bootstrap_ci(f.loc[f.channel == "app", "fpd30"].to_numpy()))
```

FPD приложения: бутстреп ≈ 1.20–2.24 %, близко к 1.26–2.30 % Уилсона. Его сила — статистика без формулы SE: **медиана** основного долга в выборке из 200 кредитов — 5.69 млн, бутстреп 95 % CI **4.54–8.27 млн** (истинная медиана 5.79 млн).

**Когда применять.**
- Медиана, процентиль, отношение сумм (доля взыскания = Σ оплачено / Σ к оплате), разность медиан.
- Среднее очень асимметричных денег при малом n, где t-интервал недопокрывает.

> ⚠️ **Осторожно.** При очень малом числе событий бутстреп слишком узок: он может лишь перетасовывать то, что видел. 7 FPD на 314 кредитов грейда D: бутстреп 0.64–3.82 % против 1.08–4.53 % у Уилсона. Для ставок около нуля — Уилсон; для медиан и отношений — бутстреп.

## 2. Разбор примера — каналы Бекзода (15 мин) :id=_2-worked-example-bekzod39s-channels-15-min

**1. Выборка — данные** (таблица FPD30 `f` с 5-й недели): приложение 41 / 2 411, филиалы 34 / 3 263, партнёры 16 / 1 425. Кредиты каждого канала — выборка из процесса этого канала, поэтому каждая ставка — оценка.

**2. Метод — интервал Уилсона.** Ставки около 1 % при n в тысячах: Уилсон, а не Вальд. `wilson(k, n)` из раздела 1 или `proportion_confint(k, n, alpha=0.05, method="wilson")`.

**3. Таблица — каждая оценка со своим интервалом.**

| канал | FPD / n | ставка | Уилсон 95 % | Вальд 95 % (для сравнения) |
|---|---|---|---|---|
| app | 41 / 2 411 | 1.70 % | **1.26–2.30 %** | 1.18–2.22 % |
| branch | 34 / 3 263 | 1.04 % | **0.75–1.45 %** | 0.69–1.39 % |
| partner | 16 / 1 425 | 1.12 % | **0.69–1.82 %** | 0.58–1.67 % |

**4. Прочитайте её — стандартная ошибка и что означает 95 %.** Интервал приложения лежит выше, но пересекается с интервалом филиалов между 1.26 и 1.45 %. Каждый интервал — примерно ±0.5 пункта, две стандартные ошибки, то есть столько же, сколько разрыв, о котором спрашивает Бекзод. Пересечение — не проверка: интервал для разности (Ньюкомб, приложение − филиалы) — от 0.05 до 1.33 пункта, то есть что угодно от почти нулевого разрыва до 1.3 пункта. При таких размерах выборок разница в 0.66 пункта находится у границы того, что данные способны различить.

**5. Что дадут дополнительные данные — объём выборки.** Чтобы знать ставку приложения с точностью ±0.25 пункта, понадобилось бы `n_for_rate(41 / 2411, 0.0025)` = 10 275 кредитов из приложения — более чем в четыре раза больше всей истории канала. Точность не придёт, если просто подождать месяц.

**6. Предложение для Бекзода (сегодняшняя половина).** *«FPD по приложению — 1.70 %, и мы на 95 % уверены, что истинная ставка канала лежит между 1.26 и 2.30 %; по филиалам — 1.04 % (0.75–1.45 %). Интервалы немного пересекаются, поэтому разрыв может быть реальным или отчасти шумом — завтрашний тест ответит на это напрямую».* Не «приложение хуже», не «разницы нет»: честное состояние знания во вторник.

### Типичные ошибки :id=mistakes-people-make

- «У 95-процентного CI есть 95-процентный шанс содержать истинное значение» — такой шанс есть у процедуры; а этот интервал либо содержит его, либо нет.
- sd кредитов, использованное там, где нужна SE оценки (интервал для среднего шириной во все данные).
- `STDEV.P` / `np.std()` (ddof 0) в выборочном интервале — по умолчанию numpy использует формулу для генеральной совокупности; передайте `ddof=1` (`.std()` в pandas уже так делает).
- Интервал Вальда для ставки 1 % при нескольких сотнях кредитов: покрытие 88 %, отрицательные границы, интервалы нулевой ширины при 0 событий.
- «Интервалы пересекаются, значит, разницы нет» — проверка разницы — это инструмент завтрашнего дня, а не глаз.
- Ставка на дашборде без n: 2.4 % по 586 кредитам и 2.4 % по 58 кредитам — разные утверждения.
- Бутстреп на 5 событиях: он может лишь пересэмплировать то, что видел, — слишком узко.
- Случайная выборка через `random.sample` без seed: никто не воспроизведёт ваш интервал.

## 6. Уголок компании <span class="badge company">Честная отчётность по ставке</span> :id=6-company-corner-reporting-a-rate-honestly

Каждая ставка на дашборде — это оценка по n кредитам. В честной плитке **три числа**: ставка, n и интервал — `FPD30 1.70 % · n = 2 411 · 95 % CI 1.26–2.30 %`. Без n и интервала читатель не отличит сигнал от малого знаменателя, и самое частое решение в кредитной компании — **ранжирование филиалов** — превращается в ранжирование удачи.

FPD30 по филиалам (филиал, в котором оформлен кредит), Уилсон 95 %, отсортировано по ставке, с **границами воронки**: диапазон, который показывал бы филиал такого размера в 95 % случаев, если бы его истинная ставка равнялась ставке портфеля 1.28 % (`stats.binom.ppf([0.025, 0.975], n, 91/7099) / n`):

```python
# использует scipy и statsmodels: они загружаются при первом ▶ Run (в ноутбуке
# они тоже есть)
p0 = 91 / 7099
b = f.groupby("branch_name")["fpd30"].agg(fpd="sum", n="size")
b[["lo", "hi"]] = [proportion_confint(k, n, method="wilson") for k, n in zip(b.fpd, b.n)]
b["funnel_lo"] = stats.binom.ppf(0.025, b.n, p0) / b.n
b["funnel_hi"] = stats.binom.ppf(0.975, b.n, p0) / b.n
# how surprising this many FPDs is at the book rate
b["p_ge"] = stats.binom.sf(b.fpd - 1, b.n, p0)
```

**Ловушка ранжирования.** «Худший» филиал (Bukhara, 1.43–3.97 %) и «лучший» (Nukus, 0.23–1.99 %) **пересекаются между 1.43 и 1.99 %**: данные не способны даже надёжно упорядочить верх и низ турнирной таблицы. Смоделируйте портфель, в котором все десять филиалов имеют ровно 1.28 % (`default_rng(2026)`, 10 000 портфелей, те же n): лучший по таблице филиал в среднем показывает **2.00 %**, превышает 2.39 % Bukhara в **10.5 %** портфелей, а нижний филиал оказывается ниже 0.68 % Nukus в **50 %** портфелей. Кто-то всегда первый и последний; таблица рейтинга ставок гарантирует «худший филиал», даже когда его нет.

Что Bukhara всё-таки говорит: это единственный филиал выше своей воронки (14 FPD там, где 13 — 97.5-процентная граница, P(≥ 14) = 0.02). Один филиал из десяти за 95-процентной границей — примерно то, что даёт случай: день множественных сравнений в четверг проверяет именно это. Правильное действие — **наблюдать** за Bukhara (поколения следующего квартала, состав кредитных специалистов), а не наказывать его.

Правила для пакета по рискам, начиная с сегодняшнего дня:
