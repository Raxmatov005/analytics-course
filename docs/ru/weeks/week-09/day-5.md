<details><summary>Образец ответа (открыть после сдачи)</summary>

```python
# (только схема — не для запуска)
# единица: один кредит с баллом (7 615 кредитов, 223 плохих)
def auc(t, col="credit_score"):
    good = t.loc[t["bad"] == 0, col]
    bad = t.loc[t["bad"] == 1, col]
    return stats.mannwhitneyu(good, bad).statistic / (len(good) * len(bad))


def ks(t, col="credit_score"):
    g = t.groupby(col)["bad"].agg(bads="sum", n="size")
    g["goods"] = g["n"] - g["bads"]
    # накопленные доли, от самого низкого балла вверх
    gap = (g["bads"].cumsum() / g["bads"].sum()
           - g["goods"].cumsum() / g["goods"].sum())
    return gap.max(), gap.idxmax()


a = auc(sc)
# AUC 0.689 · Джини 0.377 · KS 0.339 при 658.0
print(round(a, 3), round(2 * a - 1, 3), ks(sc))
# при 658 баллах и ниже: 147 из 223 плохих (65.9 %) и 2 363 из 7 392
# хороших (32.0 %)
```

*Интерпретация.* На 7 615 кредитах с 223 плохими Джини балла — 0.377 (AUC 0.689): случайный хороший кредит получает балл выше случайного плохого в 69 % случаев, а KS равен 0.34 при балле 658 — на этом балле и ниже лежат две трети плохих, но только треть хороших. Балл ранжирует, но слабо — чуть ниже обычных для скоринга заявок 0.4–0.6, — поэтому он годится, чтобы провести порог и задать грейды, а перестройку с бо́льшим объёмом информации (доход, продукт, собственная история клиента) стоит поставить в план как модель-претендента, а не как срочную меру.

</details>

*Частые ошибки:* AUC перевёрнут — `roc_auc_score(bad, score)` даёт единицу минус AUC, потому что высокий балл означает *более безопасный* кредит (берите `1 - bad` или `-score`); Джини выдан за AUC; KS прочитан как балл («KS = 658»); в предложении нет n и числа плохих.

-- единица: один кредит с баллом (7 615 кредитов, 223 плохих)
WITH s AS (
  SELECT a.credit_score AS score,
         CASE WHEN l.status IN ('default', 'written_off')
              THEN 1 ELSE 0 END AS bad
  FROM loans l
  JOIN applications a ON a.application_id = l.application_id
  WHERE a.credit_score IS NOT NULL),
c(cut) AS (VALUES (560), (600), (620), (640), (660))
SELECT c.cut,
       ROUND(100.0 * SUM(s.score >= c.cut) / COUNT(*), 1) AS kept_pct,
       ROUND(100.0 * SUM(CASE WHEN s.score >= c.cut THEN s.bad END)
             / SUM(s.score >= c.cut), 2) AS bad_rate_pct,

FROM c CROSS JOIN s
GROUP BY c.cut
ORDER BY c.cut;
