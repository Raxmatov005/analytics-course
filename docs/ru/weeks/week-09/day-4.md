### Порог отсечения — одна черта, два числа, которые движутся вместе :id=the-cut-off--one-line-two-numbers-that-move-together

**Что это.** **Порог отсечения** (*cut-off*) — наименьший скор, который Nur одобряет. Если его поднять, отказов станет больше: **уровень одобрения** (*approval rate*) падает, а вместе с ним и **доля плохих** среди всё ещё одобренных кредитов. Выбрать порог — значит выбрать точку на этом компромиссе.

**Как пишется.**

```python
def at(c):
    keep = s >= c
    return keep.mean(), y[keep].mean(), keep.sum(), y[keep].sum()

for c in (560, 600, 620, 640, 660):
    share, br, n, b = at(c)
    print(c, round(100 * share, 1), round(100 * br, 2), n, b)
```

### Избежанные плохие и отказы хорошим :id=bads-avoided-and-goods-turned-away

**Что это.** Если поднимать черту от «одобрять всех», отказ получают люди двух видов. **Избежанные плохие** — кредиты, которые стали бы плохими. **Отказы хорошим** — потерянные хорошие клиенты, доход, который так и не придёт. Их соотношение — хороших на одного избежанного плохого — цена более строгой черты.

**Как пишется.**

```python
for c in (560, 600, 640, 660):
    keep = s >= c
    avoided = y[~keep].sum()
    lost = (~keep & (y == 0)).sum()
    print(c, avoided, lost, round(lost / avoided, 1))
```

### Порог максимальной прибыли и безубыточная доля плохих :id=the-profit-maximising-cut-off-and-the-break-even-bad-rate

**Что это.** Подняв черту на один балл, мы отказываем кредитам с этим скором. Это добавляет денег, если эти кредиты потеряли бы деньги — если их доля плохих выше **безубыточной доли плохих** (*break-even bad rate*): хороший ÷ (хороший + плохой) = 1 454 907 ÷ 18 674 050 = **7.79 %**, безубыточная PD потребительского кредита из W8D2. **Порог максимальной прибыли** (*profit-maximising cut-off*) стоит там, где кредиты сразу под ним становятся плохими чаще, а кредиты над ним — реже.

**Как пишется.** Перебираем все пороги и оставляем лучший.

```python
cs = np.arange(424, 852)
pr = np.array([profit(c) for c in cs])
best = cs[pr.argmax()]
# 594 7.14 0.0779
print(best, round(pr.max() / 1e9, 2), round(good / (good + bad), 4))
plt.plot(cs, pr / 1e9)
plt.axvline(best, ls="--")
plt.xlabel("approve from score"); plt.ylabel("profit, bn soum")
```

### Swap-in и swap-out — что меняет новая черта :id=swap-in-and-swap-out--what-a-new-line-changes

**Что это.** Новая политика меняет решения в обе стороны по сравнению с сегодняшними. **Swap-out** — заявители, которых одобряют сегодня и которым откажет новое правило: Nur знает, как прошли их кредиты. **Swap-in** — заявители, которым отказывают сегодня и которых одобрит новое правило: этого не знает никто, потому что Nur никогда не давала им кредит. Оценка того, как они вели бы себя, называется **оценкой отклонённых заявок** (*reject inference*).

**Как пишется.** Чистое правило «одобрять от 600 и выше» против сегодняшних решений:

```sql
SELECT CASE WHEN status = 'rejected' AND credit_score >= 600
            THEN 'swap-in'
            WHEN status IN ('approved', 'approved_not_disbursed')
                 AND credit_score < 600
            THEN 'swap-out'
            ELSE 'same' END AS change,
       COUNT(*) AS applications
FROM applications
WHERE credit_score IS NOT NULL
GROUP BY change;
```

Правило дало бы swap-out для 363 одобренных заявок (331 из них стали кредитами, и 37 из них оказались плохими — это известно) и swap-in для 2 295 отклонённых заявителей, чью долю плохих не знает никто.

**Когда применять.**
- Любое изменение политики: покажите оба набора, что известно и что предполагается.
- Смягчение порога — опасное направление: оно держится на swap-in.

> ⚠️ **Осторожно.** Swap-in отклонили не просто так — часто по стоп-фактору, а не по скору. Предположение, что они ведут себя как одобренные заявители с тем же скором, обычно недооценивает их риск.

### Стоп-факторы и другие правила, кроме скора :id=policy-rules-besides-the-score

**Что это.** Кредитное решение — это скор **и** **стоп-факторы** (*policy rules*): жёсткие правила, которые отказывают, что бы ни говорил скор, — возраст, доход, доля дохода, уходящая на платежи, недавние просрочки в бюро, признаки мошенничества, чёрный список, — а также **ручные решения** (*overrides*), когда кредитный специалист идёт против скора. Так Nur и отказала заявителям с 720 и выдала кредиты ниже 560.

**Как пишется.** Доля отказов по полосам грейдов:

```sql
SELECT CASE WHEN credit_score < 600 THEN '1: below 600'
            WHEN credit_score < 660 THEN '2: 600-659'
            WHEN credit_score < 720 THEN '3: 660-719'
            ELSE '4: 720+' END AS band,
       COUNT(*) AS applications,
       ROUND(100.0 * SUM(status = 'rejected') / COUNT(*), 1)
         AS rejected_pct
FROM applications
WHERE credit_score IS NOT NULL
GROUP BY band ORDER BY band;
```

Ниже 600 отказывают 55.0 % заявителей; при 600–659 — 31.6 %; при 660–719 — 15.2 %; при 720 и выше — 5.9 %. Доля отказов падает со скором, но никогда не доходит до нуля: решают и другие правила.

**Когда применять.**
- Исследование порога должно держать стоп-факторы неизменными — иначе оно обещает swap-in, которых правила всё равно отклонят.
- Мониторинг: **доля ручных решений** (против скора) показывает, доверяют ли люди скоринговой карте.

### Чемпион / претендент — проверяем новую черту :id=champion--challenger--testing-a-new-line

**Что это.** **Чемпион / претендент** (*champion / challenger*) — это A/B-тест из W7 для кредитных решений. Текущая политика, чемпион, решает большинство заявок; случайная доля проходит через новую, претендента. Когда кредиты созреют, доли плохих и прибыль двух групп сравнивают.

**Как пишется.** Сколько кредитов нужно в каждой группе, чтобы увидеть меньшую долю плохих? Расчёт мощности из W7:

```python
from statsmodels.stats.proportion import proportion_effectsize
from statsmodels.stats.power import NormalIndPower

for p2 in (0.0255, 0.0200):
    h = proportion_effectsize(0.0293, p2)
    n = NormalIndPower().solve_power(h, alpha=0.05, power=0.8)
    print(p2, round(n))
```

Чтобы увидеть падение с 2.93 % до 2.55 % (черта на 600), в каждой группе нужно около 28 936 кредитов — больше, чем Nur выдала за всю свою жизнь (7 828). Падение до 2.00 % требует около 4 325.

**Когда применять.**
- Большое изменение с большим ожидаемым эффектом: новая скоринговая карта, новое правило продукта.
- Не для мелких сдвигов порога: их оценивают по наборам swap и по кривой прибыли, а вместо итоговой доли плохих смотрят на ранний индикатор (FPD30, W5).

> ⚠️ **Осторожно.** Плохие кредиты проявляются месяцами. Зафиксируйте длительность теста и выборку до старта и не останавливайтесь на первом удачном месяце (подглядывание из W7).

**Что это.** **Индекс стабильности популяции**, **PSI** (*population stability index*), сравнивает, как заявители этого периода распределены по полосам скора, с тем, как были распределены заявители эталонного периода — здесь 2024 года, первого года скоринговой карты. Для каждой полосы: (фактическая доля − ожидаемая доля) × ln(фактическая доля ÷ ожидаемая доля); затем полосы складываются. Обычное прочтение: **меньше 0.1 — стабильно, 0.1–0.25 — наблюдать, больше 0.25 — действовать**.

**Как пишется.**

```python
A = pd.read_sql("""SELECT applied_at, credit_score FROM applications
                   WHERE credit_score IS NOT NULL""", con)
edges = [560, 600, 640, 680, 720]
def shares(x):
    band = np.searchsorted(edges, x, side="right")
    return np.bincount(band, minlength=6) / len(x)
def psi(e, a):
    return np.sum((a - e) * np.log(a / e))

yr = A["applied_at"].str[:4]
e = shares(A.loc[yr == "2024", "credit_score"].to_numpy())
a = shares(A.loc[yr == "2026", "credit_score"].to_numpy())
# 0.0037
print(round(psi(e, a), 4))
```

PSI = 0.0037: заявители 2026 года распределены по полосам почти так же, как в 2024 году. Популяция стабильна.

**Когда применять.**
- Каждый месяц, для каждой используемой скоринговой карты.
- Прежде чем применять прошлогодний порог к заявителям этого года.

### CSI — какая характеристика сдвинулась :id=csi--which-characteristic-moved

**Что это.** **Индекс стабильности характеристики**, **CSI** (*characteristic stability index*), — та же формула для одного входа вместо скора: канала, продукта, запрошенной суммы, срока. Когда PSI растёт, значения CSI показывают, какой вход сдвинулся.

**Как пишется.** Полосы запрошенной суммы по квинтилям 2024 года, затем та же `psi`:

```python
B = pd.read_sql("SELECT applied_at, requested_amount FROM applications", con)
by = B["applied_at"].str[:4]
r24 = B.loc[by == "2024", "requested_amount"].to_numpy()
r26 = B.loc[by == "2026", "requested_amount"].to_numpy()
q = np.quantile(r24, [0.2, 0.4, 0.6, 0.8])
def share_q(x):
    return np.bincount(np.searchsorted(q, x, side="right"), minlength=5) / len(x)
# 0.0033
print(round(psi(share_q(r24), share_q(r26)), 4))
```

|---|---|

| продукт | 0.0005 |

| запрошенная сумма | 0.0033 |

- Перед запуском продукта или нового партнёра: ждите скачка CSI канала.

### Углублённо (по желанию) :id=depth-optional

- **Книги.** Naeem Siddiqi, *Intelligent Credit Scoring* (Wiley, 2-е изд., 2017): главы о выборе порогов, наборах swap, стоп-факторах и отчётах мониторинга (стабильность популяции, анализ характеристик). Lyn Thomas, Jonathan Crook, David Edelman, *Credit Scoring and Its Applications* (SIAM, 2-е изд., 2017): пороги по прибыли и оценка отклонённых заявок.
- **Откуда берётся PSI.** PSI — симметричная дивергенция Кульбака–Лейблера (дивергенция Джеффриса) между двумя распределениями по полосам: сумма KL(факт ‖ ожидание) и KL(ожидание ‖ факт). Поэтому он никогда не бывает отрицательным, а если поменять годы местами, число не изменится.
- **Пороги на практике.** Кредиторы часто задают черту по продукту и каналу, добавляют вокруг неё зону ручного рассмотрения («refer») и ведут таблицу стратегий: порог, ожидаемое одобрение, доля плохих и прибыль, подписанные комитетом по рискам.
- *Английские термины:* cut-off = порог отсечения, approval rate = уровень одобрения, break-even bad rate = безубыточная доля плохих, risk appetite = риск-аппетит, reject inference = оценка отклонённых заявок, hard policy rules = стоп-факторы, override = ручное решение, champion / challenger = чемпион / претендент, PSI = индекс стабильности популяции, CSI = индекс стабильности характеристики, model monitoring = мониторинг модели, recalibration = перекалибровка.

```sql
  WHERE a.credit_score IS NOT NULL)
SELECT c,
       ROUND(100.0 * SUM(score >= c) / COUNT(*), 1) AS approved_pct,

GROUP BY c ORDER BY c;
```

- Сравнивать уровни одобрения **без стоп-факторов**: отказывает не только скор.

- Реагировать на PSI одного **маленького месяца** и не замечать медленного падения среднего скора, которое остаётся под 0.1.

## 6. Уголок компании <span class="badge company">Кредитная политика и комитет по рискам</span> :id=6-company-corner-the-credit-policy-and-the-risk-committee

Порог отсечения живёт не в ноутбуке. Он живёт в **кредитной политике** (*credit policy*), документе, который говорит, кому Nur даёт кредиты, и меняется только тогда, когда за это проголосует **комитет по рискам** (*risk committee*). Типичная кредитная политика содержит:

- **Пороги скора** по продуктам и каналам, часто с **зоной ручного рассмотрения** вокруг каждой черты, где решает специалист.
- **Стоп-факторы** — правила, которые отказывают, что бы ни говорил скор: возраст, подтверждение дохода, лимиты доли платежей в доходе, просрочки в бюро, мошенничество и чёрные списки.
- **Лимиты** — наибольший кредит по грейду и продукту и сколько специалист может одобрить сам (**делегированные полномочия**).
- **Ручные решения** — когда специалист может пойти против скора, кто подписывает и при какой доле ручных решений начинается пересмотр.
- **Триггеры мониторинга** — уровни PSI, Джини и доли плохих, при которых политика должна вернуться в комитет.

Часть аналитика — бумага, за которую голосует комитет: **таблица стратегий** (каждая черта-кандидат с одобрением, долей плохих и прибылью — HW 9.4), наборы swap, страница мониторинга и рекомендация, написанная ответом вперёд. Комитет взвешивает её против того, чего в таблице нет: плана продаж, плана фондирования, позиции регулятора, репутации кредитора, который отказывает большой доле заявителей.
