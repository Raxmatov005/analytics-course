**Что это.** **Коэффициент корреляции Пирсона** *r* (*Pearson's correlation coefficient*) — число от −1 до +1. Его **знак** — направление: + когда y растёт вместе с x, − когда падает. Его **величина** — насколько близко точки лежат к прямой: ±1 — идеальная прямая, 0 — никакого прямолинейного рисунка. У r нет единиц, и ему всё равно, какой столбец назван x.

**Как пишется.** r — сумма произведений двух отклонений, поделённая так, чтобы остаться между −1 и +1:

```text
r = Σ (x − x̄)(y − ȳ)
    / √[ Σ (x − x̄)² · Σ (y − ȳ)² ]
```

```python
x, y = auto["pm"], auto["pay_k"]
dx, dy = x - x.mean(), y - y.mean()
r = (dx * dy).sum() / np.sqrt((dx**2).sum() * (dy**2).sum())
print(round(r, 4))
# 0.8926
# то же самое в numpy, в pandas и на всём портфеле
print(round(np.corrcoef(x, y)[0, 1], 4), round(x.corr(y), 4))
print(round(loans["pm"].corr(loans["pay_k"]), 3))
# 0.8926 0.8926
# 0.904
```

```excel

=PEARSON(B2:B392, C2:C392)
```

r = 0.893 для 391 автокредита: сильный растущий рисунок, точки близко к прямой. На всех 7 828 кредитах — 0.904.

**Когда применять.** Грубая шкала для |r| (привычка, а не закон):

| \|r\| | словами |
|---|---|
| меньше 0.1 | прямолинейной связи нет |
| 0.1 – 0.3 | слабая |
| 0.3 – 0.7 | умеренная |
| больше 0.7 | сильная |

- «Движутся ли эти два числа вместе, и в какую сторону?»
- Быстрый отбор характеристик, которые могут иметь значение, до любой модели.

### Корреляция — не причинность: третья переменная :id=correlation-is-not-causation-the-third-variable

**Что это.** Корреляция говорит, что два числа движутся вместе. Она не говорит, что одно двигает другое. Обе может двигать **третья переменная** (**вмешивающаяся переменная**, *confounder*). Она даже может сделать так, что корреляция по всем группам вместе направлена противоположно корреляции внутри каждой группы, — **парадокс Симпсона** (*Simpson's paradox*).

**Как пишется.** По всему портфелю: платят ли длинные кредиты больше? Потом посмотрите внутри каждого продукта.

```python
print(round(loans["term_months"].corr(loans["pay_k"]), 3))
# 0.335
for p, g in loans.groupby("product_id"):
    print(p, round(g["term_months"].corr(g["pay_k"]), 3))
# 1 -0.51
# 2 -0.621
# 3 -0.62
# 4 -0.389
# 5 -0.537
```

| продукт | кредитов | r(срок, платёж) |
|---|---|---|
| все кредиты | 7 828 | **+0.335** |
| Micro | 2 669 | −0.510 |
| Consumer | 2 418 | −0.621 |
| BNPL | 1 569 | −0.620 |
| Auto | 391 | −0.389 |
| SME | 781 | −0.537 |

По всему портфелю длинные кредиты платят больше в месяц (+0.335). Внутри каждого продукта — меньше. Вмешивающаяся переменная — продукт: автокредиты и SME одновременно и длинные, и крупные, и они тянут корреляцию портфеля вверх.

**Когда применять.**
- Прежде чем написать «X определяет Y»: назовите третьи переменные, которые могут двигать оба, и посмотрите внутри групп.
- Когда кто-то действует по корреляции («удлиним сроки — и платежи вырастут»): здесь действие дало бы обратный результат.

> ⚠️ **Осторожно.** Направление может быть и обратным: по кредитам с большим числом звонков взыскания чаще бывают дефолты, но звонки не вызывают дефолты — просрочка вызывает звонки.

### r = 0 — нет прямой линии, но это не «нет связи» :id=r-0-no-straight-line-not-no-link

**Что это.** r около 0 говорит, что **прямолинейного рисунка нет**. Он не доказывает, что числа не связаны: у буквы U или арки r может быть 0. И r пропускает строки, где хотя бы одно значение пусто, — говорите, сколько строк он использовал.

**Как пишется.** Продажи говорят, что богатые клиенты просят кредиты побольше. У каждой заявки есть запрошенная сумма; у каждого клиента — ежемесячный доход (838 заявок принадлежат клиентам без дохода в базе).

```python
a = apps.merge(cust[["customer_id", "monthly_income"]], on="customer_id")
a = a.dropna(subset=["monthly_income"])
print(len(a), round(a["monthly_income"].corr(a["requested_amount"]), 3))
# 13162 0.002
# и идеальная кривая может дать r = 0
u = np.arange(-3, 4)
print(np.corrcoef(u, u**2)[0, 1])
# 0.0
```

r = 0.002 на 13 162 заявках: запрошенная сумма совсем не растёт с доходом. Второй вывод — предупреждение: y = x² — идеальная зависимость, а её r равен 0.0, потому что левая половина падает, а правая растёт.

**Когда применять.**
- Чтобы проверить историю («богатые просят больше»): на наших данных — нет.
- Всегда рядом с диаграммой рассеяния — картинка покажет кривую, которую r пропускает.

> ⚠️ **Осторожно.** «r = 0, значит, доход не важен» — слишком сильно. Это говорит лишь, что сумма не растёт с доходом по прямой. Доход ещё может влиять на то, вернут ли кредит, — это другой вопрос.

### Ранговая корреляция Спирмена — для скошенных данных и выбросов :id=spearmans-rank-correlation-for-skewed-data-and-outliers

**Что это.** **Корреляция Спирмена** ρ (*Spearman's rank correlation*) — это r Пирсона, посчитанный на **рангах** (1-й, 2-й, 3-й…), а не на значениях. Она измеряет, продолжает ли y расти (или продолжает падать) с ростом x, — **монотонный** рисунок, прямой или кривой. Одно огромное значение — просто «самый большой ранг», поэтому доминировать не может.

**Как пишется.** `x.corr(y, method="spearman")` или `stats.spearmanr(x, y)`. Сумма кредита сильно скошена (коэффициент асимметрии 2.9: много мелких кредитов, немного огромных).

```python
x, y = loans["term_months"], loans["principal"]
print(round(x.corr(y), 3), round(x.corr(y, method="spearman"), 3))
# 0.581 0.713
# пять кредитов на прямой и одна опечатка
t = pd.Series([1, 2, 3, 4, 5, 6])
v = pd.Series([1.2, 1.9, 3.1, 3.9, 5.2, 60.0])
print(round(t.corr(v), 3), t.corr(v, method="spearman"))
# 0.699 1.0
```

Срок и сумма: Пирсон 0.581, Спирмен 0.713 — ранги видят «длиннее — значит крупнее» чище, чем скошенные значения. В игрушечном примере одна опечатка (60.0) тянет Пирсона вниз до 0.699; Спирмен остаётся 1.0, потому что порядок всё ещё идеальный.

**Когда применять.**

| | r Пирсона | ρ Спирмена |
|---|---|---|
| измеряет | прямую | рост без разворотов |
| берёт | значения | ранги |
| один выброс | сильно сдвигает | лишь один ранг |
| для | ровных чисел | денег, баллов |

> ⚠️ **Осторожно.** Спирмен не даёт наклона: он говорит, *что* y растёт, но не на сколько сумов. В Excel нет функции SPEARMAN: проранжируйте оба столбца через `RANK.AVG`, затем `CORREL` по рангам.

### Линия наименьших квадратов — наклон и свободный член :id=the-least-squares-line-slope-and-intercept

**Что это.** **Линия регрессии** (*regression line*) ŷ = a + b·x превращает рисунок в правило. **Наклон** b (*slope*) — насколько меняется y, когда x растёт на одну единицу. **Свободный член** a (*intercept*) — ŷ при x = 0. **Метод наименьших квадратов** (*least squares*) выбирает такие a и b, при которых сумма квадратов вертикальных отклонений Σ (y − ŷ)² минимальна.

**Как пишется.** Две строки арифметики: b = r · s_y / s_x и a = ȳ − b·x̄ (s — стандартное отклонение).

```python
x, y = auto["pm"], auto["pay_k"]
b = x.corr(y) * y.std() / x.std()
a = y.mean() - b * x.mean()
print(round(b, 2), round(a, 1))
# 41.49 -12.1
# платёж автокредита на 200 млн по линии
print(round(a + b * 200))
# 8286
```

b = 41.49: каждый лишний 1 млн сумов суммы добавляет 41 490 сумов к ежемесячному платежу. a = −12.1 тыс. сумов — это «платёж автокредита на 0 сумов»: такого кредита нет (автокредиты начинаются с 50 млн), поэтому свободный член только ставит линию на место. Автокредит на 200 млн — около 8.29 млн сумов в месяц.

**Когда применять.**
- «Насколько сдвигается y, когда x сдвигается на единицу?» — наклон, с единицами.
- Быстрое правило по истории: платёж ≈ a + b × сумма.

> ⚠️ **Осторожно.** Всегда называйте единицы наклона. Здесь: тысячи сумов платежа на 1 млн сумов суммы. Та же линия в простых сумах имеет b = 0.0415 — число меняется, линия нет.

### R² — доля разброса, которую объясняет линия :id=r-the-share-of-the-spread-the-line-explains

**Что это.** **R²** (**коэффициент детерминации**, *coefficient of determination*) — доля изменчивости y, которую учитывает линия: R² = 1 − SS_res / SS_tot, где SS_res = Σ (y − ŷ)² — то, что осталось после линии, а SS_tot = Σ (y − ȳ)² — изменчивость вокруг простого среднего. От 0 (линия не лучше среднего) до 1 (все точки на линии). При одном x R² = r².

**Как пишется.**

```python
yhat = a + b * auto["pm"]
ss_res = ((auto["pay_k"] - yhat) ** 2).sum()
ss_tot = ((auto["pay_k"] - auto["pay_k"].mean()) ** 2).sum()
print(round(1 - ss_res / ss_tot, 4), round(fit.rvalue ** 2, 4))
# 0.7967 0.7967
```

R² = 0.797: одна сумма кредита объясняет 79.7 % разброса платежей по автокредитам. Остальные 20.3 % — это в основном срок; следующие подразделы его находят.

**Когда применять.**
- Сравнивать модели **одного и того же** y на **одних и тех же** строках: «добавление срока поднимает R² с 0.797 до 0.961».
- Сказать, какую часть истории рассказывает одно число.

> ⚠️ **Осторожно.** Высокий R² не значит, что у линии правильная форма (это скажет график остатков), и не значит, что x вызывает y. Добавление любого столбца никогда не снижает R², даже столбца шума, — сравнивайте модели по **скорректированному R²** (`m.rsquared_adj` в statsmodels), который «штрафует» за каждый лишний столбец.

**Как пишется.** Рычаг каждого автокредита, потом опечатка в кредите с наибольшей суммой.

### Несколько предикторов — платёж ~ сумма + срок :id=several-predictors-payment-principal-term

**Что это.** **Множественная регрессия** (*multiple regression*) подбирает ŷ = a + b₁·x₁ + b₂·x₂ + … методом наименьших квадратов. Каждый коэффициент — изменение y на одну единицу его x **при фиксированных остальных x**. Именно этого не может одна корреляция: она отделяет эффект суммы от эффекта срока.

**Как пишется.** Таблица X со столбцом единиц (свободный член) и по столбцу на каждый предиктор; `np.linalg.lstsq` решает её.

```python
X = np.column_stack([np.ones(len(auto)), auto["pm"], auto["term_months"]])
coef, *_ = np.linalg.lstsq(X, auto["pay_k"], rcond=None)
print(coef.round(2))
# [6581.94   41.83 -184.3 ]
yhat2 = X @ coef
print(round(1 - ((auto["pay_k"] - yhat2) ** 2).sum() / ss_tot, 3))
# 0.961
```

Та же модель в statsmodels (при первом запуске она загружает ещё один пакет) печатает полную таблицу — коэффициенты, стандартные ошибки, p-value, R² и скорректированный R²:

```python
import statsmodels.formula.api as smf
m = smf.ols("pay_k ~ pm + term_months", data=auto).fit()
print(round(m.rsquared, 3), round(m.rsquared_adj, 3))
# 0.961 0.961
```

платёж ≈ 6 582 + 41.83 × сумма − 184.3 × срок (тыс. сумов, сумма в млн, срок в месяцах). При фиксированном сроке лишний 1 млн суммы добавляет 41 830 сумов. При фиксированной сумме лишний месяц срока снижает платёж на 184 300 сумов. R² растёт с 0.797 до 0.961.

**Когда применять.**
- Когда два предиктора связаны между собой (здесь смесь продуктов связывает срок и сумму по портфелю), а нужен собственный эффект каждого.
- Чтобы честно поднять R²: добавить предиктор, о котором просил график остатков.

### Фиктивная переменная продукта — столбец «да/нет» в модели :id=a-product-dummy-a-yesno-column-in-the-model

**Что это.** **Фиктивная переменная** (*dummy variable*) — столбец 0/1: 1 для «этой группы», 0 для остальных. Её коэффициент — сдвиг y между группой и **базовой** группой (той, что закодирована 0) при фиксированных остальных предикторах. Для столбца с k группами нужны k − 1 фиктивных переменных.

**Как пишется.** Кредиты Micro (42 % годовых) против BNPL (0 %), на 3- и 6-месячных кредитах, которые есть у обоих продуктов.

```python
mb = loans[loans["product_id"].isin([1, 3]) & loans["term_months"].isin([3, 6])].copy()
mb["micro"] = (mb["product_id"] == 1).astype(int)
X = np.column_stack([np.ones(len(mb)), mb["pm"], mb["term_months"], mb["micro"]])
coef, *_ = np.linalg.lstsq(X, mb["pay_k"], rcond=None)
print(len(mb), coef.round(1))
# 3719 [ 738.9  263.7 -174.2   67.2]
```

На 3 719 кредитах: кредит Micro платит в месяц на 67 200 сумов больше, чем кредит BNPL той же суммы и срока, — это цена его процентов. BNPL — базовая группа (micro = 0).

**Когда применять.**
- Продукт, канал, регион, класс риска: любая категория в регрессии.
- `pd.get_dummies(df["channel"], drop_first=True)` сразу делает k − 1 фиктивных столбцов.

> ⚠️ **Осторожно.** k фиктивных переменных для k групп плюс свободный член — **ловушка фиктивных переменных**: они в сумме дают столбец единиц, и модель нельзя решить однозначно. Одну группу оставьте без столбца — она станет базовой. И фиктивная переменная сдвигает линию на фиксированную величину; здесь настоящий разрыв растёт с суммой (проценты — это доля), для этого нужно взаимодействие (Углублённо).

### Прогноз против объяснения и ловушка экстраполяции :id=prediction-against-explanation-and-the-extrapolation-trap

**Что это.** У модели может быть две работы. **Прогноз** (*prediction*): хорошее ŷ для нового случая, похожего на те, по которым её подбирали. **Объяснение** (*explanation*): что каждый коэффициент говорит об устройстве мира. Модель может хорошо прогнозировать и плохо объяснять (прямая через кривой аннуитет), или наоборот. **Экстраполяция** (*extrapolation*) — прогноз вне диапазона x, который модель видела, — место, где ломается и то, и другое.

**Как пишется.** Линию Micro спрашивают о кредите на 300 млн:

```python
micro = loans[loans["product_id"] == 1]
b1, a1 = np.polyfit(micro["pm"], micro["pay_k"], 1)
print(micro["pm"].min(), micro["pm"].max())
# 0.5 4.99
print(round(a1 + b1 * 300))
# 81475
sme300 = loans[(loans["product_id"] == 5) & loans["pm"].between(280, 320)]
print(round(sme300["pay_k"].median()))
# 16012
```

Линию Micro подбирали по кредитам от 0.5 до 5 млн сумов. О 300 млн она говорит: 81.5 млн сумов в месяц; настоящие кредиты SME около 300 млн платят в медиане 16.0 млн. Вне своего диапазона линия — не правило, а догадка.

**Когда применять.**
- Перед каждым прогнозом: попадает ли новый случай в диапазон данных — по каждому предиктору и по их сочетанию (кредита на 10 млн на 48 месяцев нет ни в одном продукте)?
- Когда руководитель читает коэффициент как рычаг («поднимем x на 1, и y вырастет на b»): это безопасно, только если данные получены изменением x, а в наблюдательных данных так бывает редко.

### Углублённо (по желанию) :id=depth-optional

- **Откуда веера?** Формула аннуитета: платёж = сумма × r / (1 − (1 + r)^−n), где r — месячная ставка, n — срок. Для одного продукта и одного срока множитель постоянный, поэтому платёж — точная прямая через 0. По разным срокам множитель меняется, так что эффект суммы *умножается* на срок. Модель, которая их складывает, может лишь приблизить это.
- **Взаимодействия.** `smf.ols("pay_k ~ pm * C(term_months)", data=auto)` даёт каждому сроку свой наклон (`pm:C(term_months)[T.36]` — изменение наклона относительно 24 месяцев). На данных Micro–BNPL `pay_k ~ pm + pm:micro` при одном фиксированном сроке точно восстанавливает проценты: R² = 1.000.
- **Логарифмы.** `np.log(pay) ~ np.log(principal) + np.log(term)` превращает произведение в сумму; коэффициент суммы выходит близким к 1 (платёж пропорционален сумме).
- **Интервал для наклона.** `fit.slope ± t₀.₉₇₅ · fit.stderr` (t-интервал из 6-й недели) — а **интервал прогноза** для одного нового кредита намного шире интервала для самой линии, потому что отдельный кредит разбросан вокруг линии.
- *English terms:* scatter plot = диаграмма рассеяния, Pearson's r = коэффициент корреляции Пирсона, Spearman's rank correlation = ранговая корреляция Спирмена, spurious correlation = ложная корреляция, confounder = вмешивающаяся (скрытая) переменная, Simpson's paradox = парадокс Симпсона, linear regression = линейная регрессия, least squares = метод наименьших квадратов (МНК), slope / intercept = наклон / свободный член, R² = коэффициент детерминации, residuals = остатки, outlier = выброс, high-leverage point = точка с большим рычагом, multicollinearity = мультиколлинеарность, dummy variable = фиктивная переменная, extrapolation = экстраполяция.

## 2. Разбор примера — правило платежа для SME (15 мин) :id=2-worked-example-the-sme-payment-rule-15-min

*«Отделу SME нужна быстрая оценка ежемесячного платежа по сумме и сроку, до того как запустится система ценообразования»*. 781 кредит SME: 20–600 млн сумов, 12, 24 или 36 месяцев, все под 26 %.

**Шаг 1 — диаграмма рассеяния.** Платёж против суммы: растущее облако, разделённое на три веера, сверху кредиты на 12 месяцев.

**Шаг 2 — r и Спирмен.** r = 0.778, Спирмен 0.843. Сильная связь, и ранги согласны больше, чем значения (сумма скошена).

**Шаг 3 — третья переменная?** Очевидная — срок: внутри SME срок не зависит от суммы (r между ними −0.002), поэтому наклон он не исказит, но добавляет разброс.

**Шаг 4 — линия наименьших квадратов.** `stats.linregress(sme.pm, sme.pay_k)`: наклон **62.08** тыс. сумов на 1 млн, свободный член 238.3 тыс. Кредит на 300 млн: 238.3 + 62.08 × 300 = 18 861 тыс., 18.9 млн в месяц.

**Шаг 5 — R².** 0.778² = **0.605**: одна сумма объясняет 60 % разброса.

**Шаг 6 — график остатков.** Средний остаток по сроку: 12 месяцев **+10 192**, 24 месяца **−2 725**, 36 месяцев **−7 011** тыс. сумов. Линия сильно мимо для каждого срока, и разрывы расходятся веером с суммой.

**Шаг 7 — рычаг.** Наибольший рычаг — 0.0052 среди 781 кредита: ни один кредит не управляет линией.

**Шаг 8 — несколько предикторов.** `pay_k ~ pm + term_months`: 17 588 + 62.00 × сумма − 712.3 × срок, R² **0.891**. Для кредита на 300 млн на 24 месяца: 19 092 тыс. 22 настоящих кредита SME на 280–320 млн на 24 месяца платят от 15 167 до 17 029 тыс. (медиана 15 874). Модель с двумя предикторами всё ещё завышает примерно на 3 млн сумов: веер (Шаг 6) говорит, что срок умножает, а не прибавляет.

**Шаг 9 — линия внутри одного срока.** Только 246 кредитов на 24 месяца: наклон **53.87** тыс. на 1 млн, свободный член 0.0, **R² = 1.000**. Внутри одного продукта и одного срока платёж — точная прямая через 0: регрессия нашла множитель аннуитета (26 % годовых, 24 месяца → 53.87 тыс. сумов на 1 млн сумов). 300 млн на 24 месяца → **16 162** тыс. сумов.

**Шаг 10 — прогноз, а не экстраполяция.** *«Для кредитов SME на 20–600 млн: платёж ≈ сумма × 95.53 тыс. на 1 млн на 12 месяцев, 53.87 на 24, 40.29 на 36. Кредит на 300 млн на 24 месяца платит 16.2 млн сумов в месяц. Вне 20–600 млн или для другого срока спрашивайте ценообразование — правило таких кредитов не видело»*.

Чему научили шаги: корреляция (0.778) и даже R² 0.891 выглядели хорошо, но к правильной модели нас привёл график остатков.

### Типичные ошибки :id=mistakes-people-make

- Корреляцию читают как причину: «длинные сроки поднимают платежи» (r = +0.335 по продуктам; внутри каждого продукта знак отрицательный).
- r = 0 читают как «связи нет» — у кривой r может быть 0; говорите «нет прямолинейной связи».
- Пирсон на скошенном денежном столбце без взгляда на Спирмена или на диаграмму.
- `np.polyfit(y, x, 1)` или `SLOPE(x, y)` — аргументы перепутаны, другая линия.
- Наклон без единиц («41.49» чего?) или свободный член, прочитанный как настоящий платёж.
- R² сравнивают для разных y или разных строк, или поднимают, добавляя столбцы шума (берите скорректированный R²).
- Нет графика остатков: R² 0.891 выглядел хорошо для SME, а каждый срок был мимо на миллионы.
- Выброс удалён, потому что он мешал, а не потому что он неверен.
- Две копии одного числа в модели (запрошенная и выданная сумма) или k фиктивных переменных для k групп.
- Правило применяют вне диапазона, по которому его подбирали.

## 6. Уголок компании <span class="badge company">Платёжеспособность: платёж к доходу</span> :id=6-company-corner-affordability-payment-to-income

Прежде чем одобрить кредит, кредитор спрашивает, потянет ли клиент платёж. Обычное соотношение — **платёж к доходу** (**PTI**, *payment-to-income*): новый ежемесячный платёж, делённый на ежемесячный доход клиента. Его более широкий родственник — **долг к доходу** (**DTI**, *debt-to-income*) — ставит в числитель все ежемесячные платежи по долгам (наши и других кредиторов, из кредитного бюро). Многие регуляторы его ограничивают; в Узбекистане Центральный банк устанавливает предел **показателя долговой нагрузки** заёмщика (*debt burden ratio*) для потребительских кредитов — проверьте действующее правило, прежде чем называть число.

Сегодняшняя регрессия — первый инструмент команды по платёжеспособности: она оценивает платёж по запрошенному кредиту до запуска ценообразования, а PTI следует из него.

```python
li = loans.merge(cust[["customer_id", "monthly_income"]], on="customer_id")
li = li.dropna(subset=["monthly_income"])
li["pti"] = li["monthly_payment"] / li["monthly_income"]
```
