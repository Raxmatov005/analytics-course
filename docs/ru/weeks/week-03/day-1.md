## Сегодня в 3 строках :id=today-in-3-lines

- **Оконная функция** считает агрегат *рядом с* каждой строкой, а не схлопывает строки: `SUM(x) OVER ()` — общий итог на каждой строке, `SUM(x) OVER (PARTITION BY product)` — итог по продукту.
- `ORDER BY` внутри `OVER` превращает агрегат в **накопительный итог**; `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` даёт **скользящее среднее**.

## 1. Теория — тот же агрегат, но без потери строк :id=1-learn-the-same-aggregate-without-losing-the-rows

### Что такое окно — агрегат, который сохраняет каждую строку :id=what-a-window-is-an-aggregate-that-keeps-every-row

**Что это.** **Оконная функция** (*window function*) считает агрегат — сумму, среднее, количество — по набору строк и записывает ответ **в каждую строку**. `GROUP BY` сворачивает строки в одну на группу; окно сохраняет их все. Набор строк, по которому она считает, и есть **окно**.

**Маленькая таблица для этой страницы.** Каждое окно ниже сначала показано на этих пяти платежах, чтобы каждое число можно было проверить вручную.

| `pay` | loan | month | amount |
|---|---|---|---|
| | A | 1 | 100 |
| | A | 2 | 200 |
| | A | 3 | 300 |
| | B | 1 | 50 |
| | B | 2 | 50 |

**Как пишется.** Один и тот же `SUM` — один раз как обычный агрегат, один раз как окно:

```sql
WITH pay(loan, month, amount) AS (VALUES ('A', 1, 100), ('A', 2, 200), ('A', 3, 300), ('B', 1, 50), ('B', 2, 50))
SELECT SUM(amount) AS total FROM pay;                                   -- 1 строка: 700
```

```sql
WITH pay(loan, month, amount) AS (VALUES ('A', 1, 100), ('A', 2, 200), ('A', 3, 300), ('B', 1, 50), ('B', 2, 50))
SELECT loan, month, amount,
       SUM(amount) OVER () AS total                                     -- слово OVER делает SUM окном
FROM pay;                                                               -- 5 строк, в каждой 700
```

| loan | month | amount | total |
|---|---|---|---|
| A | 1 | 100 | 700 |
| A | 2 | 200 | 700 |
| A | 3 | 300 | 700 |
| B | 1 | 50 | 700 |
| B | 2 | 50 | 700 |

Первый запрос возвращает одну строку: 700. Второй возвращает все пять платежей, и рядом с каждым — 700. Ничего не свернулось; итог добавился столбцом.

**Когда применять.**
- Детали строки и число группы в одной строке: каждый кредит с итогом по компании, каждый платёж с итогом по своему кредиту.
- Всё, что сравнивает строку с её группой: доля от итога, отклонение от среднего, ранг, накопительный итог.

### OVER () — одно окно на все строки :id=over-one-window-over-all-the-rows

**Что это.** `OVER ()` с **пустыми скобками** создаёт одно окно, в которое входит каждая строка результата. Агрегат считается один раз по всем строкам и записывается в каждую.

**Как пишется.**

```sql
SELECT loan_id, principal,
       SUM(principal)        OVER () AS company_total,    -- агрегат(столбец) OVER ()
       ROUND(AVG(principal) OVER ()) AS company_avg,
       COUNT(*)              OVER () AS loans
FROM loans
ORDER BY loan_id
LIMIT 3;
```

| loan_id | principal | company_total | company_avg | loans |
|---|---|---|---|---|
| 1 | 31 150 000 | 404 783 280 000 | 51 709 668 | 7 828 |
| 2 | 40 060 000 | 404 783 280 000 | 51 709 668 | 7 828 |
| 3 | 1 590 000 | 404 783 280 000 | 51 709 668 | 7 828 |

На экране три строки, но окно прошло по всем 7 828 кредитам: 404 783 280 000 — это основной долг всей компании. `LIMIT` обрезал вывод уже после того, как окно было посчитано.

**Когда применять.**
- Общий итог или среднее по компании рядом с каждой строкой.
- Знаменатель доли (дальше в этом разделе).

> ⚠️ **Осторожно.** Окно видит только строки, прошедшие `WHERE`. Добавьте `WHERE customer_id = 3208` — и `company_total` станет 1 023 170 000: итогом двух кредитов этого клиента. `OVER ()` значит «все строки *этого* результата», а не «все строки таблицы».

### PARTITION BY — своё окно для каждой группы :id=partition-by-one-window-per-group

**Что это.** `PARTITION BY столбец` внутри скобок делит строки на группы — по окну на группу. Каждая строка получает агрегат **своей группы**. Строки остаются; меняется только окно.

**Что это.** `ORDER BY` внутри скобок упорядочивает строки каждого окна. Тогда агрегат берёт строки **от первой до текущей**. `SUM` превращается в **накопительный итог** (*running total*).

### Окно или GROUP BY — одна сумма, две формы :id=window-vs-group-by-the-same-sum-two-shapes

**Что это.** `GROUP BY` и окно считают один и тот же агрегат. Разница — в **форме результата**: `GROUP BY` возвращает одну строку на группу, окно возвращает каждую строку, а рядом — число её группы.

| `GROUP BY loan` → 2 строки | loan | SUM(amount) |
|---|---|---|
| | A | 600 |
| | B | 100 |

| `SUM(amount) OVER (PARTITION BY loan)` → 5 строк | loan | month | amount | loan_total |
|---|---|---|---|---|
| | A | 1 | 100 | 600 |
| | A | 2 | 200 | 600 |
| | A | 3 | 300 | 600 |
| | B | 1 | 50 | 100 |
| | B | 2 | 50 | 100 |

**Как пишется.** Две формы на `loans`:

```sql
SELECT product_id, COUNT(*) AS loans
FROM loans
GROUP BY product_id;                                                -- 5 строк
```

```sql
SELECT loan_id, product_id, COUNT(*) OVER (PARTITION BY product_id) AS loans_in_product
FROM loans;                                                         -- 7 828 строк
```

5 строк против 7 828 — одни и те же количества (2 669, 2 418, 1 569, 391, 781): один раз свёрнутые, другой раз записанные в каждый кредит.

**Когда применять.**

| Что нужно | Что использовать | Строк на выходе |
|---|---|---|
| одно число на группу | `GROUP BY` | по одной на группу |
| каждая строка, а рядом число её группы | окно с `PARTITION BY` | все строки |
| одна строка на группу **плюс** доля или накопительный итог по группам | `GROUP BY` и окно сверху | по одной на группу |

### SUM, AVG, COUNT, MIN, MAX как окна :id=sum-avg-count-min-max-as-windows

**Что это.** Любой обычный агрегат работает как окно: `SUM`, `AVG`, `COUNT(*)`, `COUNT(столбец)`, `MIN`, `MAX`. Поставьте после него `OVER (…)` — и он перестанет сворачивать строки.

**Как пишется.** Каждый кредит рядом с самым маленьким, самым большим и средним кредитом своего продукта:

```sql
SELECT l.loan_id, p.code, l.principal,
       MIN(l.principal)        OVER (PARTITION BY p.code) AS product_min,
       MAX(l.principal)        OVER (PARTITION BY p.code) AS product_max,
       ROUND(AVG(l.principal)  OVER (PARTITION BY p.code)) AS product_avg,
       ROUND(l.principal - AVG(l.principal) OVER (PARTITION BY p.code)) AS vs_avg   -- окно внутри арифметики
FROM loans l
JOIN products p ON p.product_id = l.product_id
ORDER BY l.loan_id
LIMIT 5;
```

Кредит 1 (Consumer, 31 150 000) лежит между 3 110 000 и 49 990 000 и на 4 223 085 выше среднего по Consumer. Кредит 3 (Micro, 1 590 000) на 1 115 586 ниже среднего по Micro. Окно — такое же число, как любое другое: его можно вычитать, делить и округлять.

**Когда применять.**
- «Насколько эта строка далека от своей группы?» — `x - AVG(x) OVER (…)`, `x / MAX(x) OVER (…)`.
- Размер группы рядом с каждой строкой — `COUNT(*) OVER (PARTITION BY …)`.

> ⚠️ **Осторожно.** `COUNT(DISTINCT …) OVER (…)` не разрешён — SQLite останавливается с *DISTINCT is not supported for window functions*, SQL Server тоже отказывает. Считайте различные значения через `GROUP BY` отдельным шагом, а потом соединяйте или стройте окно поверх него.

### Доля от итога — значение / SUM() OVER () :id=share-of-total-value-sum-over

**Что это.** **Доля от итога** (*share of total*) — значение строки, делённое на итог по всем строкам. Итог берётся из окна, поэтому он стоит в той же строке, что и значение, — второй запрос не нужен.

**Как пишется.** Две формы, по одной на каждую форму результата:

```sql
-- каждая строка: значение строки / итог окна
SELECT loan_id, principal,
       ROUND(100.0 * principal / SUM(principal) OVER (), 4) AS share_pct
FROM loans ORDER BY principal DESC LIMIT 3;                         -- кредит 2861: 0.148 % всего основного долга
```

```sql
-- одна строка на группу: сначала GROUP BY, затем окно по сгруппированным строкам
SELECT p.code,
       SUM(i.principal_due) AS outstanding,
       ROUND(100.0 * SUM(i.principal_due) / SUM(SUM(i.principal_due)) OVER (), 1) AS share_pct
FROM installments i
JOIN loans l    ON l.loan_id = i.loan_id
JOIN products p ON p.product_id = l.product_id
WHERE i.due_date > '2026-10-01'                                     -- остаток долга = основной долг платежей, срок которых ещё не наступил
GROUP BY p.code
ORDER BY outstanding DESC;
```

| code | outstanding | share_pct |
|---|---|---|
| SME | 125 892 942 411 | 60.3 |
| AUTO | 57 684 271 333 | 27.6 |
| CONS | 23 054 933 316 | 11.0 |
| BNPL | 1 135 251 000 | 0.5 |
| MICRO | 956 106 370 | 0.5 |

Пять строк; доли в сумме дают 100. SME держит 60.3 % из 208 723 504 430 остатка долга. Читайте `SUM(SUM(x)) OVER ()` изнутри наружу: внутренний `SUM` — агрегат `GROUP BY`, одно значение на продукт; внешний `SUM … OVER ()` складывает эти пять значений и пишет итог в каждую строку. Окно работает **после** `GROUP BY`, по сгруппированным строкам.

**Когда применять.**
- Доля в компании: `x / SUM(x) OVER ()`.
- Доля внутри группы: `x / SUM(x) OVER (PARTITION BY region)` — филиалы каждого региона в сумме дают 100.
- Доля по количеству: `COUNT(*) / SUM(COUNT(*)) OVER ()`.

> ⚠️ **Осторожно.** `principal / SUM(principal) OVER ()` делит одно целое число на другое, и целочисленное деление округляет каждую долю вниз до 0. Начинайте со `100.0 *`, чтобы арифметика была десятичной.

### Рамка — ROWS BETWEEN и умолчание, которое склеивает совпадения :id=the-frame-rows-between-and-the-default-that-lumps-ties

**Что это.** **Рамка** (*frame*) — та часть окна, которую агрегат действительно читает, отсчитанная от текущей строки. Её задают через `ROWS BETWEEN <начало> AND <конец>`.

```text
UNBOUNDED PRECEDING   первая строка окна
n PRECEDING           n строк до текущей
CURRENT ROW           текущая строка
n FOLLOWING           n строк после текущей
UNBOUNDED FOLLOWING   последняя строка окна
```

**Как пишется.** Накопительный итог с явно прописанной рамкой:

```sql
SUM(amount) OVER (PARTITION BY loan ORDER BY month
                  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)   -- от первой строки до этой
```

Если внутри `OVER` есть `ORDER BY`, а рамки нет, движок берёт рамку по умолчанию: `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`. **RANGE** включает каждую строку, у которой значение `ORDER BY` равно текущему. При совпадениях две рамки расходятся:

| day | x | по умолчанию (RANGE) | `ROWS UNBOUNDED PRECEDING` |
|---|---|---|---|
| 28 сен | 10 | **30** | 10 |
| 28 сен | 20 | 30 | 30 |
| 29 сен | 5 | 35 | 35 |

На настоящих данных — накопительный итог основного долга по дате выдачи за последнюю неделю сентября:

```sql
SELECT disbursed_at, loan_id, principal,
       SUM(principal) OVER (ORDER BY disbursed_at)                               AS range_run,  -- рамка по умолчанию
       SUM(principal) OVER (ORDER BY disbursed_at, loan_id ROWS UNBOUNDED PRECEDING) AS rows_run   -- строка за строкой
FROM loans
WHERE disbursed_at >= '2026-09-24' AND disbursed_at < '2026-10-01'
ORDER BY disbursed_at, loan_id;
```

77 кредитов за семь дней. `range_run` показывает одно и то же значение для всех кредитов одного дня — итог по эту дату. `rows_run` растёт от кредита к кредиту. Они совпадают только на последнем кредите каждого дня: 7 строк из 77.

**Когда применять.**
- `ROWS` — когда имеете в виду «по эту строку»; `RANGE` по умолчанию — когда «по это значение» (все кредиты дня).
- Рамка фиксированной длины для скользящих средних — следующий подраздел.

> ⚠️ **Осторожно.** Рамка по умолчанию появляется, как только вы пишете `ORDER BY` внутри `OVER`. Для столбца с повторами (даты, классы, круглые суммы) пишите `ROWS` и добавляйте второй ключ сортировки (`, loan_id`), иначе накопительный итог прыгает сразу на целый день.

**Ваша очередь.** Части внутри `OVER` всегда идут в одном порядке: секция, потом сортировка, потом рамка. Соберите окно.

### Где может стоять окно — в SELECT и ORDER BY, но не в WHERE :id=where-a-window-may-appear-select-and-order-by-not-where

**Что это.** Запрос выполняется в фиксированном порядке. Окна считаются поздно: после `WHERE`, `GROUP BY` и `HAVING`. Поэтому окно может стоять в `SELECT` и в `ORDER BY`, но не в `WHERE`, `GROUP BY` или `HAVING` — когда они выполняются, окна ещё не существует.

```text
FROM / JOIN → WHERE → GROUP BY → HAVING → окна → SELECT → ORDER BY → LIMIT
                ✗         ✗         ✗       ✓        ✓          ✓
```

**Как пишется.** Чтобы фильтровать по окну, посчитайте его внутри запроса в скобках — **производной таблицы** (*derived table*) — и фильтруйте снаружи:

```sql
SELECT COUNT(*) AS above_product_avg
FROM (SELECT l.loan_id, l.principal,
             AVG(l.principal) OVER (PARTITION BY l.product_id) AS product_avg   -- шаг 1: окно внутри
      FROM loans l) AS t
WHERE principal > product_avg;                                                  -- шаг 2: фильтр снаружи
```

3 919 кредитов больше среднего своего продукта — примерно половина каждого продукта. `WITH t AS (…) SELECT … FROM t WHERE …` делает то же самое; День 3 объясняет обе формы.

**Когда применять.**
- «Строки выше среднего своей группы», «топ-3 в каждой группе» (завтра), «месяцы, которые лучше предыдущего».
- Сортировать по окну можно напрямую: `ORDER BY SUM(x) OVER (…) DESC`.

> ⚠️ **Осторожно.** Этот же порядок объясняет эффект `WHERE` из `OVER ()`: `WHERE` решает, какие строки видит окно. Фильтруйте в `WHERE`, если нужно окно поменьше; фильтруйте снаружи, если нужно полное окно и меньше строк на экране.

### Собираем вместе :id=putting-it-together

Одна просьба, пять сегодняшних инструментов. *«Помесячная выдача 2026 года, с января по сентябрь: доля каждого месяца от девяти месяцев, накопленный итог с начала года, трёхмесячное скользящее среднее и месяц в % от лучшего месяца».*

```sql
WITH m AS (
  SELECT strftime('%Y-%m', disbursed_at) AS month, COUNT(*) AS loans, SUM(principal) AS disbursed
  FROM loans
  WHERE disbursed_at >= '2026-01-01' AND disbursed_at < '2026-10-01'              -- девять полных месяцев
  GROUP BY strftime('%Y-%m', disbursed_at))
SELECT month, loans, disbursed,
       ROUND(100.0 * disbursed / SUM(disbursed) OVER (), 1)                         AS share_pct,    -- доля от итога
       SUM(disbursed) OVER (ORDER BY month ROWS UNBOUNDED PRECEDING)                AS ytd,          -- накопительный итог
       ROUND(AVG(disbursed) OVER (ORDER BY month ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)) AS ma3, -- скользящее среднее
       ROUND(100.0 * disbursed / MAX(disbursed) OVER (), 1)                         AS pct_of_best   -- MAX как окно
FROM m
ORDER BY month;
```

## 2. Разобранный пример — таблица филиалов для Бекзода (15 мин) :id=_2-worked-example-bekzod39s-branch-table-15-min

**Просьба:** *«Остаток долга каждого филиала, его доля в компании, его доля в своём регионе и сколько портфеля держат крупнейшие филиалы вместе».* Каждый шаг — одно понятие из раздела 1, в том же порядке.

1. **Окно или GROUP BY — одна строка на филиал.** В ответе десять строк, поэтому основа — `GROUP BY` по филиалу. Одна строка до группировки — это платёж по графику, срок которого ещё не наступил (остаток долга, как в примере с долей от итога); `loans → branches` — «многие к одному» и добавляет только подпись.
2. **Доля от итога — `OVER ()`.** `SUM(SUM(x)) OVER ()` складывает десять итогов филиалов и ставит итог компании в каждую строку.
3. **PARTITION BY — доля внутри региона.** То же выражение с `OVER (PARTITION BY b.region)`: филиалы каждого региона в сумме дают 100.
4. **ORDER BY внутри OVER — накопленная доля.** `SUM(SUM(x)) OVER (ORDER BY SUM(x) DESC)` складывает филиалы от крупнейшего вниз; делённое на итог, оно читается как «топ-N держат …».
5. **Проверка.** Доли в сумме дают 100.0, остаток долга — 208 723 504 430 (итог пятницы), а накопленная доля заканчивается на 100.0.

```sql
SELECT b.branch_name, b.region,
       SUM(i.principal_due)                                                                             AS outstanding,
       ROUND(100.0 * SUM(i.principal_due) / SUM(SUM(i.principal_due)) OVER (), 1)                      AS share_pct,        -- шаг 2
       ROUND(100.0 * SUM(i.principal_due) / SUM(SUM(i.principal_due)) OVER (PARTITION BY b.region), 1) AS share_in_region,  -- шаг 3
       ROUND(100.0 * SUM(SUM(i.principal_due)) OVER (ORDER BY SUM(i.principal_due) DESC)
                   / SUM(SUM(i.principal_due)) OVER (), 1)                                              AS cum_share_pct     -- шаг 4
FROM installments i
JOIN loans l    ON l.loan_id = i.loan_id
JOIN branches b ON b.branch_id = l.branch_id
WHERE i.due_date > '2026-10-01'
GROUP BY b.branch_name, b.region                                                                         -- шаг 1
ORDER BY outstanding DESC;
```

## 6. Уголок компании <span class="badge company">Структура портфеля</span> :id=6-company-corner-portfolio-mix

**Структура портфеля** (*portfolio mix*) — первая страница любого обзора портфеля: *из чего состоит остаток долга?* Три разреза и проверка концентрации, всё по одному приёму — `GROUP BY` плюс `SUM(SUM()) OVER ()` — для 208 723 504 430 UZS остатка долга по 3 409 кредитам на 2026-10-01.

| разрез | строки | вывод |
|---|---|---|
| по **продукту** | SME **60.3 %** · Auto 27.6 · Consumer 11.0 · BNPL 0.5 · Micro 0.5 | 88 % денег лежит в двух продуктах, на которые приходится 28 % кредитов с остатком (SME 603 + Auto 368 из 3 409). По *количеству* портфель — это Consumer/Micro/BNPL; по *деньгам* — кредитор бизнеса и автомобилей. Скажите, что вы имеете в виду. |
| по **филиалу** | Tashkent Central 13.8 % · South 12.8 · North 12.5 · Fergana 11.9 · Samarkand 11.8 · Andijan 9.5 · Namangan 9.0 · Bukhara 7.2 · Nukus 6.4 · Termez 5.1 | Ровно: крупнейший филиал в 2.7 раза больше самого малого, ни один не выше 14 %. |
| по **классу** | B 44.7 % · C 27.0 · A 23.2 · D 5.1 | A+B = 68 % денег; D — 5 %: скоринг держит рискованный класс небольшим и по деньгам, и по количеству. |

**Концентрация** (*concentration*) задаёт другой вопрос: *насколько всё зависит от немногих?* Два стандартных числа:

- **Доля трёх крупнейших филиалов** — накопленная доля после трёх строк таблицы филиалов: `SUM(SUM(outstanding)) OVER (ORDER BY SUM(outstanding) DESC) / SUM(SUM(outstanding)) OVER ()` → 13.8 → 26.6 → **39.1 %**. Это три ташкентских филиала: 39 % портфеля в одном городе. Регулятор или совет директоров прочтёт это как *географическую концентрацию: один регион = 39 %*; Бекзод прочтёт так: *«столица — треть бизнеса, для узбекского кредитора ничего необычного, но один шок в Ташкенте ударит по 39 % портфеля».*
- **Доля крупнейшего клиента** — клиент 3208 (Улугбек Назаров, сегмент SME, два кредита SME на 568 200 000 и 454 970 000, оба выданы в августе 2026) должен 977 697 006 = **0.47 %** остатка долга. Топ-10 клиентов вместе держат 3.6 %, топ-25 — 7.8 %. Для розничного портфеля с SME это **низкая концентрация на одного заёмщика**: ни один заёмщик сам по себе ничего не решает. (Банк также сравнил бы крупнейшую позицию со своим капиталом — лимит «крупных рисков», обычно 25 % капитала; у нас здесь нет данных о капитале, поэтому мы сообщаем долю портфеля.)

**Как представить структуру.** Одна таблица, три разреза друг под другом, в каждом доля по количеству *и* доля по деньгам рядом (количество говорит об операциях, деньги — о риске); под ней две строки о концентрации. Предложение под таблицей: *«Портфель на 60 % состоит из SME по деньгам и на 41 % из Consumer по количеству кредитов с остатком; три ташкентских филиала держат 39 %; крупнейший заёмщик — 0.5 %, топ-25 — менее 8 %».*
