### Скалярный подзапрос — одно значение, используется как константа :id=scalar-subquery-one-value-used-like-a-constant

**Что это.** **Подзапрос** (*subquery*) — это запрос в скобках внутри другого запроса. **Скалярный подзапрос** возвращает ровно одну строку и один столбец — одно значение. Движок выполняет его и подставляет значение туда, где можно было бы написать число.

### IN с подзапросом — есть ли значение в этом списке? :id=in-with-a-subquery-is-the-value-in-that-list

**Что это.** `IN (подзапрос)` истинно, когда значение есть в **списке**, который возвращает подзапрос. Подзапрос возвращает один столбец и сколько угодно строк.

**Как пишется.**

```sql
SELECT COUNT(*)
FROM customers
WHERE customer_id IN (SELECT customer_id              -- один столбец,
                      FROM loans
                      WHERE status = 'written_off');   -- много строк: список
```

У 188 клиентов есть хотя бы один списанный кредит. Списанных кредитов 190: у двух клиентов по два. `JOIN` к `loans` вернул бы 190 строк; `IN` возвращает каждого клиента один раз, сколько бы раз он ни встречался в списке.

**Когда применять.**
- «X, которые есть в том множестве»: клиенты со списанием, кредиты канала app, филиалы из списка регионов.
- Принадлежность множеству без размножения строк.

> ⚠️ **Осторожно.** `NOT IN` ломается от одного NULL в списке. `x NOT IN (a, b, NULL)` означает `x <> a AND x <> b AND x <> NULL`, а `x <> NULL` неизвестно — поэтому ни одна строка не проходит, и молча:
>
> `WHERE disbursed_at NOT IN (SELECT closed_at FROM loans)` → **0** (в closed_at 3 601 NULL) · с `WHERE closed_at IS NOT NULL` внутри → **649**.
>
> Уберите NULL внутри или используйте `NOT EXISTS` (дальше).

### EXISTS и NOT EXISTS — есть ли хотя бы одна строка? :id=exists-and-not-exists-is-there-at-least-one-row

**Что это.** `EXISTS (подзапрос)` истинно, когда подзапрос возвращает **хотя бы одну строку**; `NOT EXISTS` — когда не возвращает ни одной. Что в строках, не важно, поэтому подзапрос обычно пишет `SELECT 1`. Подзапрос упоминает внешнюю строку (`a.customer_id = c.customer_id`), поэтому проверяется один раз на каждую внешнюю строку.

**Как пишется.** На двух маленьких таблицах из недели 2 — у Азиза (1) нет заявки:

```sql
WITH cust(id, name) AS (VALUES (1, 'Aziz'), (2, 'Bekzod'), (3, 'Dilnoza')),
     app(app_id, cust_id, amount) AS (VALUES (101, 2, 500), (102, 3, 900), (103, 4, 120))
SELECT c.id, c.name
FROM cust c
WHERE NOT EXISTS (SELECT 1 FROM app a WHERE a.cust_id = c.id);   -- 1 строка: Aziz
```

На реальных данных — сотрудники, которые ни разу не вели заявку:

```sql
SELECT s.role, COUNT(*) AS staff
FROM staff s
WHERE NOT EXISTS (SELECT 1 FROM applications a
                  WHERE a.officer_id = s.staff_id)     -- связь с внешней строкой
GROUP BY s.role;
```

Две строки: 10 управляющих филиалами и 30 коллекторов — 40 из 100 сотрудников. Каждый из 60 кредитных специалистов вёл хотя бы одну заявку — именно эту проверку вы и хотели.

**Когда применять.**

| | `NOT EXISTS` | `LEFT JOIN … WHERE right.key IS NULL` (неделя 2) |
|---|---|---|
| клиенты без кредита | 1 705 | 1 705 |
| NULL на другой стороне | никогда не совпадает — ловушки нет | нужен `IS NULL` по столбцу, который никогда не NULL |
| может размножить строки | никогда | не в анти-соединении, но да, если убрать фильтр `IS NULL` |
| может показать столбцы другой таблицы | нет | да |

Оба дают тех же 1 705 клиентов. Для «нет ни одного» обычно лучше читается `NOT EXISTS`; если нужны ещё и столбцы другой таблицы, берите соединение.

> ⚠️ **Осторожно.** Забудьте связь с внешней строкой (`WHERE l.customer_id = c.customer_id`) — и подзапрос спрашивает «существует ли **хоть какой-то** кредит?» — ответ всегда «да». Тогда `NOT EXISTS` вернёт 0 строк, а `EXISTS` — всех клиентов.

### Производная таблица — подзапрос во FROM :id=derived-table-a-subquery-in-from

**Что это.** **Производная таблица** (*derived table*) — это подзапрос во `FROM`: его результат используется как таблица. Ей нужен псевдоним, а каждому столбцу — имя.

**Как пишется.**

```sql
SELECT loans_per_customer, COUNT(*) AS customers
FROM (SELECT customer_id, COUNT(*) AS loans_per_customer     -- шаг 1: одна строка на клиента
      FROM loans
      GROUP BY customer_id) AS t                             -- псевдоним обязателен
GROUP BY loans_per_customer                                  -- шаг 2: одна строка на количество
ORDER BY loans_per_customer;
```

| loans_per_customer | customers |
|---|---|
| 1 | 2 089 |
| 2 | 1 378 |
| 3 | 593 |
| 4 | 194 |
| 5 | 62 |
| 6 | 15 |
| 7 | 4 |

Семь строк: у 2 089 заёмщиков один кредит, у 4 — семь. Всего 4 335 заёмщиков. Внутренний запрос **агрегирует один раз** (по клиенту), внешний — **агрегирует снова** (по количеству): два `GROUP BY` подряд, чего один запрос не умеет.

**Когда применять.**
- Агрегировать дважды: по клиенту, затем по количеству; по дню, затем средний день.
- Фильтр по окну (День 1): окно — внутри, `WHERE` — снаружи.

> ⚠️ **Осторожно.** Производная таблица без псевдонима работает в SQLite, но падает в SQL Server (*Incorrect syntax near ')'*). Всегда пишите `AS t`.

### Коррелированный подзапрос — внутренний запрос читает внешнюю строку :id=correlated-subquery-the-inner-query-reads-the-outer-row

**Что это.** **Коррелированный подзапрос** (*correlated subquery*) использует столбец **внешней** строки, поэтому для каждой внешней строки у него свой ответ. Проверки `EXISTS` выше были коррелированными. Скалярный подзапрос тоже может быть таким: «лимит продукта **этого кредита**».

**Как пишется.**

```sql
SELECT COUNT(*)
FROM loans l
WHERE l.principal >= 0.99 * (SELECT p.max_amount
                             FROM products p
                             WHERE p.product_id = l.product_id);   -- l = внешняя строка: её собственный продукт
```

85 кредитов лежат в пределах 1 % от максимальной суммы своего продукта. Читайте так: для каждого кредита `l` найдите лимит продукта `l`, затем сравните. Классическая форма сравнивает строку с её собственной группой — `l.principal > (SELECT AVG(x.principal) FROM loans x WHERE x.product_id = l.product_id)` даёт 3 919, P13 понедельника без окна, — но на наших таблицах, где пока нет индексов, она читает 7 828 × 7 828 строк и работает секунды (День 4).

**Когда применять.**
- Сравнить строку с её группой при **другом фильтре**: «крупнее среднего *закрытого* кредита своего продукта» — окно не умеет менять фильтр.
- Поиск одной строки: крупнейший кредит клиента, дата последнего платежа по этому кредиту.

| | коррелированный подзапрос | окно (День 1) |
|---|---|---|
| значение для сравнения видно в выводе | нет | да |
| другой фильтр для группы | да | нет |
| работа | концептуально раз на каждую внешнюю строку | один проход |

> ⚠️ **Осторожно.** Когда внутренний и внешний запрос читают одну и ту же таблицу, псевдонимы должны различаться (`l` и `x`). Напишите `WHERE product_id = product_id` — и обе стороны означают внутреннюю строку: условие всегда истинно, и подзапрос усредняет всю таблицу.

### CTE — WITH name AS (…), и почему так читается лучше :id=cte-with-name-as-and-why-it-reads-better

**Что это.** **CTE** (обобщённое табличное выражение, *common table expression*) — это производная таблица с **именем**, записанная **перед** запросом, который её использует: `WITH name AS (…) SELECT … FROM name`. Она существует только для этого одного оператора.

**Как пишется.** Производная таблица из примера выше, в виде CTE:

```sql
WITH per_customer AS (                                   -- имя, затем запрос в скобках
  SELECT customer_id, COUNT(*) AS loans_per_customer
  FROM loans
  GROUP BY customer_id)
SELECT loans_per_customer, COUNT(*) AS customers         -- основной запрос использует имя как таблицу
FROM per_customer
GROUP BY loans_per_customer
ORDER BY loans_per_customer;
```

Те же семь строк: 2 089, 1 378, 593 … 4. Работа та же; меняется порядок чтения. Производная таблица читается изнутри наружу (сначала скобки); CTE — сверху вниз, шаг 1, затем шаг 2, и у каждого шага имя, которое говорит, что такое одна строка.

**Когда применять.**
- Любой запрос с шагом, который читатель должен понять отдельно.
- Один и тот же результат нужен в запросе дважды (два среза из одной базы, итог и разбивка).

| | Производная таблица | CTE |
|---|---|---|
| где | внутри `FROM` | над запросом, с именем |
| как читается | изнутри наружу | сверху вниз |
| результат нужен дважды | написать дважды | назвать один раз, использовать дважды |
| сколько живёт | один запрос | один запрос |

> ⚠️ **Осторожно.** CTE живёт **только в одном операторе** — в `SELECT` сразу после `WITH`. Поставьте после него `;` — и следующий запрос это имя не увидит (*no such table*). Чтобы использовать результат в нескольких запросах, нужно представление или таблица — четверг.

### Цепочка CTE — одна зернистость на шаг :id=a-chain-of-ctes-one-grain-per-step

**Что это.** Один `WITH` может определить **несколько** CTE через запятую. Каждый может использовать все CTE выше себя. **Цепочка** превращает длинный анализ в именованные шаги, у каждого из которых одна **зернистость** — то, чем является одна строка.

```pic

На шаге 1 строка — кредит, на шаге 2 — клиент, на шаге 3 — число кредитов с долгом, посчитанное по всем заёмщикам. Каждый клиент попадает в строку своего числа.", "tables": [{"id": "pl", "name": "per_loan", "cols": ["loan_id", "outstanding"], "rows": [[3091, "3 315 222"], [5337, "3 266 500"], [1305, "2 720 000"], [1632, "13 363 875"], [4962, "9 794 087"], [7693, "6 195 970"]], "tone": ["b", "b", "a", "c", "c", "c"], "more": "… 3 409 кредитов"}, {"id": "pc", "name": "per_customer", "cols": ["customer_id", "owing_loans", "outstanding"], "rows": [[5, 1, "2 720 000"], [1, 2, "6 581 722"], [9, 3, "29 353 932"]], "tone": ["a", "b", "c"], "via": "GROUP BY l.customer_id"}, {"id": "fin", "name": "результат", "cols": ["owing_loans", "customers", "avg_outstanding"], "rows": [[1, "1 859", "63 340 783"], [2, "513", "115 862 999"], [3, "134", "181 709 079"], [4, "24", "227 685 135"], [5, "4", "254 977 446"], [6, "1", "701 901 165"]], "tone": ["a", "b", "c", null, null, null], "via": "GROUP BY owing_loans"}], "stack": true}
```

**Как пишется.** Остаток долга по кредиту → по клиенту → клиенты по числу кредитов с остатком:

```sql
WITH per_loan AS (                                        -- шаг 1, зернистость: кредит
  SELECT loan_id, SUM(principal_due) AS outstanding
  FROM installments
  WHERE due_date > '2026-10-01'
  GROUP BY loan_id),
per_customer AS (                                         -- шаг 2, зернистость: клиент — строится из шага 1
  SELECT l.customer_id, COUNT(*) AS owing_loans, SUM(pl.outstanding) AS outstanding
  FROM per_loan pl
  JOIN loans l ON l.loan_id = pl.loan_id
  GROUP BY l.customer_id)
SELECT owing_loans, COUNT(*) AS customers,                -- шаг 3, зернистость: число кредитов с остатком
       ROUND(AVG(outstanding)) AS avg_outstanding
FROM per_customer
GROUP BY owing_loans
ORDER BY owing_loans;
```

Шесть строк. 1 859 заёмщиков должны по одному кредиту (в среднем 63 340 783); один заёмщик должен по шести (701 901 165). Один `WITH`, два имени, запятая между ними. Шаг 2 соединяет `loans` с 3 409 строками кредитов, а не с 92 193 платежами — зернистость зафиксирована на шаге 1, поэтому ничего не размножается.

### Рекурсивный CTE — строки, которых нет ни в одной таблице :id=recursive-cte-rows-that-are-in-no-table

**Что это.** **Рекурсивный CTE** (*recursive CTE*) ссылается **сам на себя**. Он начинается с **якорной** строки и добавляет новые строки из последних, пока не перестанет выполняться условие остановки. Так порождаются строки, которых нет ни в одной таблице: календарь, числа от 1 до n.

**Как пишется.**

```sql
WITH RECURSIVE months(month_start) AS (                           -- SQL Server: без слова RECURSIVE
  SELECT '2025-01-01'                                             -- якорь: первая строка
  UNION ALL
  SELECT date(month_start, '+1 month')                            -- рекурсивный шаг: следующая строка из последней
  FROM months                                                     -- SQL Server: DATEADD(month, 1, month_start)
  WHERE month_start < '2026-09-01')                               -- условие остановки
SELECT COUNT(*), MIN(month_start), MAX(month_start) FROM months;  -- 21 · 2025-01-01 · 2026-09-01
```

21 строка: с января 2025 по сентябрь 2026. Каждый проход добавляет месяц, пока последний месяц раньше сентября 2026. Числа от 1 до 6 строятся так же: `WITH RECURSIVE k(n) AS (SELECT 1 UNION ALL SELECT n + 1 FROM k WHERE n < 6) SELECT n FROM k`.

**Когда применять.**
- Полный календарь, к которому делают `LEFT JOIN` количеств, чтобы месяц без кредитов показывал 0, а не исчезал. В 2026 году сетка филиал × продукт × месяц имеет 450 ячеек, и 16 из них пусты — обычный `GROUP BY` их не видит (P8).
- Последовательность чисел: месяцы жизни 1..6, корзины, тестовые случаи. (Когда есть таблица дат — наша `dim_date`, — проще `SELECT DISTINCT date(date_key, 'start of month') FROM dim_date …`.)

> ⚠️ **Осторожно.** Без условия остановки рекурсия не кончается. SQLite работает, пока не кончится память; SQL Server останавливается после 100 уровней (`OPTION (MAXRECURSION n)` это меняет). Пишите `WHERE` первым.

### Таблица поколений — шаг за шагом :id=the-vintage-table-built-step-by-step

**Что это.** **Поколение** (*vintage*, винтаж) или **когорта** (*cohort*) — это кредиты, выданные в одном месяце. **Таблица поколений** следит за каждой когортой по её возрасту в **месяцах жизни** (MOB, *months on book*) — здесь это номер платежа по графику — и показывает долю кредитов, которые к этому возрасту **хоть раз** просрочили 30+ дней. Когда каждая когорта читается в одном и том же возрасте, старые и новые когорты становятся сравнимы.

Вся хитрость — в «хоть раз»: однажды просрочив, кредит остаётся «хоть раз просрочившим». Это ровно то, что делает бегущий `MAX` флага 0/1 (бегущее окно Дня 1):

На MOB 3: 1 из 2 кредитов хоть раз просрочил = 50 %.

**Как пишется.** Четыре CTE, у каждого одна зернистость, затем доля по MOB для объединённых когорт 2025 года:

```sql
WITH inst AS (                                      -- зернистость: платёж по графику — сколько оплачено в течение 30 дней после срока?
  SELECT i.loan_id, i.installment_no, i.total_due,
         COALESCE(SUM(CASE WHEN p.paid_at <= date(i.due_date, '+30 days') THEN p.amount END), 0) AS paid_by_30   -- SQL Server: DATEADD(day, 30, i.due_date)
  FROM installments i
  LEFT JOIN payments p ON p.installment_id = i.installment_id
  WHERE i.installment_no <= 6
    AND date(i.due_date, '+30 days') <= '2026-10-01'   -- только платежи, у которых 30 дней уже прошли
  GROUP BY i.installment_id, i.loan_id, i.installment_no, i.total_due),
flag AS (                                           -- зернистость: платёж по графику — 1, если просрочка 30+
  SELECT loan_id, installment_no, CASE WHEN paid_by_30 < total_due THEN 1 ELSE 0 END AS late30
  FROM inst),
ever AS (                                           -- зернистость: платёж по графику — хоть раз к этому моменту (бегущий MAX)
  SELECT loan_id, installment_no,
         MAX(late30) OVER (PARTITION BY loan_id ORDER BY installment_no) AS ever30
  FROM flag),
base AS (                                           -- зернистость: кредит — когорты, которые мы читаем
  SELECT loan_id FROM loans
  WHERE term_months >= 6 AND disbursed_at >= '2025-01-01' AND disbursed_at < '2026-01-01')
SELECT e.installment_no AS mob, COUNT(*) AS observed, SUM(e.ever30) AS ever30,
       ROUND(100.0 * SUM(e.ever30) / COUNT(*), 2) AS rate_pct
FROM base b
JOIN ever e ON e.loan_id = b.loan_id
GROUP BY e.installment_no
ORDER BY mob;
```

### Собираем вместе :id=putting-it-together

Один запрос, несколько сегодняшних инструментов. *«Кредиты Auto крупнее среднего кредита SME, от клиентов, у которых никогда не списывали кредит, — по годам выдачи, в сравнении с числом кредитов Auto за тот год».*

```sql
WITH big_auto AS (                                                                          -- CTE: даём шагу имя
  SELECT l.loan_id, strftime('%Y', l.disbursed_at) AS yr
  FROM loans l
  WHERE l.product_id = 4
    AND l.principal > (SELECT AVG(principal) FROM loans WHERE product_id = 5)                 -- скалярный подзапрос со своим фильтром
    AND NOT EXISTS (SELECT 1 FROM loans w                                                     -- коррелированный NOT EXISTS
                    WHERE w.customer_id = l.customer_id AND w.status = 'written_off'))
SELECT yr, COUNT(*) AS big_auto_loans,
       (SELECT COUNT(*) FROM loans x                                                           -- коррелированный скалярный подзапрос в SELECT
        WHERE x.product_id = 4 AND strftime('%Y', x.disbursed_at) = b.yr) AS auto_loans
FROM big_auto b
GROUP BY yr
ORDER BY yr;
```

Три строки, по одной на год. Каждый инструмент делает одну работу: CTE называет множество, скалярный подзапрос приносит ориентир из другого продукта, `NOT EXISTS` исключает клиентов по их истории, а коррелированный подзапрос в `SELECT` добавляет знаменатель по году. Читаем результат: 17 из 82 кредитов Auto в 2024 году, 29 из 144 в 2025, 40 из 165 в 2026 — каждый год примерно каждый пятый кредит Auto крупнее среднего кредита SME.

## 2. Разобранный пример — снова кредит после списания (15 мин) :id=2-worked-example-lent-to-again-after-a-write-off-15-min

**Запрос (Нилуфар):** *«Клиенты, у которых списали кредит, а потом мы выдали им ещё один: сколько их, сколько они должны сегодня и больше это или меньше, чем у типичного заёмщика?»* Каждый шаг — одно понятие из раздела 1, в том же порядке.

**Шаг 1 — скалярный подзапрос: ориентир.** «Типичный заёмщик» = остаток долга на одного заёмщика с остатком, одно число:

```sql
SELECT (SELECT SUM(principal_due) FROM installments WHERE due_date > '2026-10-01')
     / (SELECT COUNT(DISTINCT l.customer_id)
        FROM installments i JOIN loans l ON l.loan_id = i.loan_id
        WHERE i.due_date > '2026-10-01') AS avg_per_borrower;
-- 208 723 504 430 / 2 535 = 82 336 688
```

**Шаг 2 — IN: у кого было списание.** `WHERE customer_id IN (SELECT customer_id FROM loans WHERE status = 'written_off')` → 188 клиентов. `IN` считает каждого один раз — даже двоих, у кого по два списания.

**Шаг 3 — производная таблица: дата первого списания, затем кредиты после неё.** Кредит считается *повторным*, если он выдан после первого списанного кредита клиента. Одна строка на клиента с этой датой, присоединённая обратно к `loans`:

```sql
SELECT COUNT(*) AS repeat_loans, COUNT(DISTINCT l.customer_id) AS customers
FROM loans l
JOIN (SELECT customer_id, MIN(disbursed_at) AS first_wo          -- одна строка на клиента со списанием
      FROM loans
      WHERE status = 'written_off'
      GROUP BY customer_id) AS f
  ON f.customer_id = l.customer_id
 AND l.disbursed_at > f.first_wo;                                 -- только кредиты, выданные позже
-- 145 повторных кредитов · 101 клиент
```

То же множество можно записать коррелированным `EXISTS (SELECT 1 FROM loans w WHERE w.customer_id = l.customer_id AND w.status = 'written_off' AND w.disbursed_at < l.disbursed_at)` — снова 145, но на наших таблицах без индексов он читает 7 828 × 7 828 строк. Производная таблица агрегирует один раз и соединяет один раз.

**Шаг 4 — цепочка CTE: сколько они должны в сравнении с ориентиром.** Одна зернистость на шаг: клиент → повторный кредит → клиент, который ещё должен → ответ.

```sql
WITH first_wo AS (                                                   -- зернистость: клиент со списанием
  SELECT customer_id, MIN(disbursed_at) AS first_wo
  FROM loans WHERE status = 'written_off' GROUP BY customer_id),
repeat_loans AS (                                                    -- зернистость: кредит, выданный после него
  SELECT l.loan_id, l.customer_id, l.status
  FROM loans l JOIN first_wo f ON f.customer_id = l.customer_id AND l.disbursed_at > f.first_wo),
owed AS (                                                            -- зернистость: клиент, который ещё должен по повторному кредиту
  SELECT r.customer_id, SUM(i.principal_due) AS outstanding
  FROM repeat_loans r
  JOIN installments i ON i.loan_id = r.loan_id
  WHERE i.due_date > '2026-10-01'
  GROUP BY r.customer_id)
SELECT COUNT(*) AS still_owing, SUM(outstanding) AS outstanding, ROUND(AVG(outstanding)) AS avg_outstanding
FROM owed;
-- 50 клиентов · 2 857 616 393 · 57 152 328 на клиента
```

**Читаем.** 101 клиенту снова выдали кредит после кредита, который был списан, — 145 повторных кредитов. 50 из них ещё должны 2 857 616 393, около 57.2 млн каждый: **69 %** от 82.3 млн типичного заёмщика. Из 145 повторных кредитов 81 закрыт, 61 действует и только 3 снова испортились (1 дефолт, 2 списания). Для Нилуфар: *повторное кредитование невелико, на человека меньше, чем в портфеле, и пока не повторило потерю — но это вопрос политики, а не случайность, и следить нужно за 61 действующим кредитом.*

> 💡 **Главное.** Каждый шаг отвечал на один маленький вопрос одним инструментом: число (скалярный подзапрос), множество (IN), агрегат как таблица (производная таблица), а имена склеили шаги (цепочка CTE). Так расплывчатая просьба превращается в запрос, который можно защитить.

## 5. Уголок компании <span class="badge company">Кривые поколений</span> :id=5-company-corner-vintage-curves

**Поколение** (*vintage*, винтаж) — это набор кредитов, выданных в одном месяце; **кривая поколения** прослеживает каждое поколение на протяжении его жизни, измеряемой в **месяцах жизни** (MOB, *months on book*), а не в календарном времени. Поскольку каждая когорта читается в одном и том же возрасте, когорты января и октября становятся сопоставимы, хотя одна на девять месяцев старше. Наши определения, записанные на слайде:

- **Когорта** = месяц `disbursed_at`; **MOB k** = платёж k (наши графики помесячные, поэтому номер платежа — это возраст).
- **«Хоть раз 30+ к MOB k»** = хотя бы один из платежей 1..k **не был полностью оплачен через 30 дней после срока**, на 2026-10-01.
- **База:** кредиты с `term_months >= 6` (чтобы у каждого кредита были все шесть платежей); ячейка показывается только когда у **всех** кредитов когорты на этом MOB истекли их 30 дней.

```sql
WITH inst AS ( … ), flag AS ( … ), ever AS ( … ),                        -- цепочка поколений из раздела 1
base AS (SELECT loan_id, strftime('%Y-%m', disbursed_at) AS cohort FROM loans
         WHERE term_months >= 6 AND disbursed_at >= '2025-01-01' AND disbursed_at < '2026-04-01'),
cells AS (SELECT b.cohort, e.installment_no AS mob, COUNT(*) AS observed, SUM(e.ever30) AS ever,
                 (SELECT COUNT(*) FROM base x WHERE x.cohort = b.cohort) AS cohort_size
          FROM base b JOIN ever e ON e.loan_id = b.loan_id GROUP BY b.cohort, e.installment_no)
SELECT cohort, MAX(cohort_size) AS loans,
       MAX(CASE WHEN mob = 1 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob1,
       MAX(CASE WHEN mob = 2 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob2,
       MAX(CASE WHEN mob = 3 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob3,
       MAX(CASE WHEN mob = 4 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob4,
       MAX(CASE WHEN mob = 5 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob5,
       MAX(CASE WHEN mob = 6 AND observed = cohort_size THEN ROUND(100.0 * ever / observed, 2) END) AS mob6
FROM cells GROUP BY cohort ORDER BY cohort;
-- SQL Server: то же самое, кроме DATEADD(day, 30, i.due_date) в inst и FORMAT(disbursed_at, 'yyyy-MM') в base
```
