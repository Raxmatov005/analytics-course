### S8. Накопленный итог — остаток долга нарастающим итогом :id=s8-cumulative-running-outstanding

<details><summary>Образец ответа</summary>

```sql

       SUM(outstanding_month_end) - LAG(SUM(outstanding_month_end)) OVER (ORDER BY month) AS net_growth
FROM v_portfolio_monthly WHERE month >= '2026-01-01' AND month < '2026-10-01' GROUP BY month ORDER BY month;
-- 2026-01 151 807 386 149 · 02 154 145 984 724 (+2.3 млрд) · 03 163 974 316 812
-- (+9.8) · 04 171 675 271 237 · 05 179 741 433 725 · 06 184 617 414 010
-- 07 193 664 170 150 (+9.0) · 08 203 830 205 928 (+10.2) · 09 208 243 879 623
-- (+4.4 млрд)
```

Без представления: рекурсивный календарь месяцев и, по каждому месяцу, `SUM(principal_due)` платежей с `due_date >= next_month` по кредитам с `disbursed_at < next_month` (День 4). Накопленная выдача по годам нарастающим итогом: 86.5 → 242.4 → 404.8 млрд (`SUM(SUM(principal)) OVER (ORDER BY year)`).

**Вывод.** Портфель вырос на 56 млрд (+37 %) за девять месяцев, с 151.8 до 208.2 млрд, при том что выдано 161.5 млрд: около двух третей новых выдач замещают погашения. Чистый рост неровный (+2.3 млрд в феврале, +10.2 млрд в августе) и следует за месяцами SME. Число кредитов с остатком выросло с 2 579 до 3 392.

</details>

<details><summary>Образцы ответов (открыть после сдачи)</summary>

1. `GROUP BY` схлопывает строки до одной на группу; окно считает агрегат *рядом с* каждой строкой по секции/рамке и сохраняет все строки. Обе — когда нужно и число по группе, **и** его доля или накопительный итог по группам: `SUM(SUM(outstanding)) OVER ()` — внутренний `SUM` относится к группе, внешнее окно складывает группы (SME 125.9 млрд = 60.3 % от 208.7 млрд).
2. Все три нумеруют строки по `ORDER BY`; различаются на равных значениях: `ROW_NUMBER` всегда 1, 2, 3; `RANK` 1, 1, 3; `DENSE_RANK` 1, 1, 2. Дедуплицируйте через `ROW_NUMBER() OVER (PARTITION BY столбцы-определяющие-одинаковость ORDER BY id)` и оставляйте `rn = 1` — он гарантирует ровно одну уцелевшую строку на группу, чего `RANK` не делает, когда равны и разрешающие признаки (25 дубликатов платежей, id 52851–52875, 58.4 млн посчитаны дважды).
3. Изменение к предыдущему месяцу и к прошлому году: `LAG(disbursed)` и `LAG(disbursed, 12)` по месяцам (февраль 2026: −31.8 % к предыдущему месяцу, +20.0 % к прошлому году). Ловушка: `WHERE month >= '2026-01'` в том же запросе убирает 2025 *до* того, как отработает окно, и все значения к прошлому году равны NULL — фильтруйте во внешнем запросе. То же для интервалов между платежами (58-дневный интервал кредита 1).
4. Цепочка CTE — когда результат используется дважды (два среза DPD), когда вложенность глубже двух уровней или когда у шагов разная зернистость (платёж → кредит → клиент) и читатель должен следить за ними сверху вниз. Подзапрос — когда это однострочный скаляр (`> (SELECT AVG(principal) FROM loans)`) или проверка `EXISTS`. Производительность на обоих движках одинакова; решают читаемость и дисциплина зернистости.
5. Чтобы порождать строки, которых нет ни в одной таблице: календарь месяцев (якорь `'2025-01-01'`, шаг `+1 month`, остановка на `'2026-09-01'` → 21 строка), чтобы месяцы с нулевой выдачей появлялись нулями — 16 пустых ячеек филиал × продукт × месяц в 2026 году, которые `GROUP BY` спрятал бы; а также последовательность 1..6 для месяцев жизни. `dim_date` — альтернатива без рекурсии, если она есть.
6. Представление хранит текст запроса — всегда свежее, каждый раз стоит как его запрос (12.8 с для `v_portfolio_monthly`); таблица хранит результат — мгновенно, заморожена на момент загрузки (0 с). Power BI читает **представления** (или ночные таблицы, построенные из них), чтобы одно определение DPD обслуживало каждый показатель; `v_loan_status` = одна строка на кредит с DPD, корзиной, остатком долга, днями жизни, 7 828 строк, сверяющихся с 208 723 504 430.
7. Цена: место на диске и более медленные вставки/обновления; выгода: фильтр или соединение по индексируемому столбцу становится поиском, а не сканированием (`SCAN payments` → `SEARCH … USING INDEX ix_payments_loan`). Не поможет, когда столбец обёрнут функцией — `strftime('%Y-%m', due_date) = '2026-09'`, `LOWER(method) = 'card'` — или при `LIKE '%x'`; перепишите в виде полуоткрытого диапазона или очистите данные в представлении.
