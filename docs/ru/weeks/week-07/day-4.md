### Мера или вычисляемый столбец — два контекста :id=measure-vs-calculated-column-two-contexts

**Что это.** **DAX** (*Data Analysis Expressions*) — язык формул Power BI. У него два дома. **Вычисляемый столбец** (*calculated column*) считается один раз на строку при обновлении, в **контексте строки** (*row context*): «эта строка». **Мера** (*measure*) считается для каждой ячейки каждого визуала, в **контексте фильтра** (*filter context*): «строки, которые оставили фильтры».

**Как пишется.** Home → **New column** для столбца, Home → **New measure** для меры; строка формул принимает `Имя = выражение`.

```dax
-- столбец: одно значение на кредит, читается в этой строке
is_90plus   = IF ( v_loan_status[dpd] > 90, "yes", "no" )
-- мера: одно значение на ячейку, по видимым строкам
Outstanding = SUM ( v_loan_status[outstanding] )
```

| | вычисляемый столбец | мера |
|---|---|---|
| считается | один раз на строку, при обновлении; хранится | при запросе, для каждой ячейки; ничего не хранит |
| контекст | контекст строки: эта строка | контекст фильтра: срезы, строка и столбец ячейки |
| для чего | значения, по которым режут или фильтруют (диапазон, флаг, ключ) | каждое число в визуале, каждое отношение |
| кредит 1 | `is_90plus` = "no" | — (у меры нет значения на строку) |

**Когда применять.** Спросите себя: «буду ли я по этому резать или покажу это числом?» Резать — столбец. Показывать — мера.

> ⚠️ **Осторожно.** В столбце `SUM ( v_loan_status[outstanding] )` не видит строку — у столбца нет контекста фильтра, поэтому он суммирует всю таблицу: 208 723 504 430 в каждой строке.

### Первые меры — SUM, COUNTROWS, DIVIDE :id=the-first-measures-sum-countrows-divide

**Что это.** Три функции составляют большинство мер. **SUM** складывает столбец по видимым строкам. **COUNTROWS** считает видимые строки таблицы. **DIVIDE** делит и возвращает пусто (или выбранное значение), когда знаменатель равен 0 или пуст.

**Как пишется.**

```dax
-- SUM ( таблица[столбец] )
Disbursed Amount = SUM ( v_loan_status[principal] )
-- COUNTROWS ( таблица )
Disbursed Count  = COUNTROWS ( v_loan_status )
-- DIVIDE ( числитель, знаменатель [, если ноль] )
Avg Ticket       = DIVIDE ( [Disbursed Amount], [Disbursed Count] )
```

| мера | без фильтра | SME | MICRO |
|---|---|---|---|
| Disbursed Amount | 404 783 280 000 | 241 117 150 000 | 7 221 210 000 |
| Disbursed Count | 7 828 | 781 | 2 669 |
| Avg Ticket | 51 709 668 | 308 728 745 | 2 705 586 |

Средний чек по всему портфелю: 404 783 280 000 ÷ 7 828 = 51 709 668 сумов. Мера может использовать другие меры (`[Disbursed Amount]`) — каждое определение пишется один раз.

**Когда применять.** Каждая карточка и каждое значение в таблице. Затем отформатируйте меру один раз (Measure tools → Format) — каждый визуал это унаследует.

> ⚠️ **Осторожно.** Пишите отношения через `DIVIDE`, никогда через `/`. `a / b` при b = 0 показывает на карточке «Infinity» и ломает итоги и графики.

### CALCULATE — изменить контекст фильтра :id=calculate-change-the-filter-context

**Что это.** **CALCULATE** вычисляет выражение в **изменённом** контексте фильтра. Это функция за каждым числом «из них»: остаток *с просрочкой больше 30 дней*, кредиты *в корзине 90+*.

**Как пишется.**

```dax
CALCULATE ( <выражение>, <фильтр 1>, <фильтр 2>, ... )
--          что посчитать   как изменить фильтры ячейки

-- 6 507 526 953
Outstanding DPD30+ = CALCULATE ( [Outstanding], v_loan_status[dpd] > 30 )
-- 3.12 %
PAR30 %            = DIVIDE ( [Outstanding DPD30+], [Outstanding] )
-- 2.55 %
NPL90 %            = DIVIDE ( CALCULATE ( [Outstanding], v_loan_status[dpd] > 90 ), [Outstanding] )
-- 234
Loans 90+          = CALCULATE ( COUNTROWS ( v_loan_status ), v_loan_status[bucket] = "90+" )
```

Всегда три шага: (1) взять контекст фильтра ячейки; (2) применить каждый аргумент-фильтр — он **заменяет** существующий фильтр на тот же столбец, а разные столбцы объединяются через И; (3) вычислить выражение там. В строке SME PAR30 использует оба фильтра — `product = SME` из строки и `dpd > 30` из CALCULATE: **2.55 %**; AUTO **4.44 %**, MICRO **0.72 %**. SQL недели 3 `SUM(CASE WHEN dpd > 30 THEN outstanding END) / SUM(outstanding)` — ровно это.

Когда условие использует меру или несколько столбцов, запишите фильтр таблицей через **FILTER**: `CALCULATE ( [Outstanding], FILTER ( v_loan_status, v_loan_status[dpd] > 30 && v_loan_status[product] <> "MICRO" ) )`. FILTER проходит таблицу построчно — мощно и медленнее; когда можно, фильтруйте столбец, а не весь факт.

**Когда применять.** Любая мера, которой нужно подмножество (корзина, статус, период) или другой набор строк, чем у ячейки (итог, прошлый год).

> ⚠️ **Осторожно.** Фильтр на столбец **заменяет** фильтр визуала на этот столбец. `CALCULATE ( [Outstanding], v_loan_status[bucket] = "90+" )` в матрице по корзинам показывает 5 319 475 527 в **каждой** строке. Оберните его в `KEEPFILTERS ( … )`, чтобы фильтры пересекались: у 90+ остаётся его число, остальные строки пустеют.

### Преобразование контекста — CALCULATE внутри строки :id=context-transition-calculate-inside-a-row

**Что это.** Внутри вычисляемого столбца (или итератора вроде `SUMX`) CALCULATE превращает **текущую строку** в фильтр. Это **преобразование контекста** (*context transition*): контекст строки становится контекстом фильтра.

**Как пишется.** Два столбца на `v_loan_status`, читаем для кредита 1:

```dax
-- SUM видит всю таблицу
share = v_loan_status[outstanding] / SUM ( v_loan_status[outstanding] )
-- CALCULATE делает «кредит 1» фильтром
own   = CALCULATE ( SUM ( v_loan_status[outstanding] ) )
```

| loan_id | outstanding | share | own |
|---|---|---|---|
| 1 | 9 593 064 | 0.0046 % | 9 593 064 |

`share`: 9 593 064 ÷ 208 723 504 430 — знаменатель весь портфель. `own`: сумма по строкам, совпадающим с кредитом 1, — только кредит 1.

**Когда применять.** Специально его пишут редко; вы встречаете его, когда мера вызывается внутри столбца или итератора (`[Outstanding]` в столбце означает `CALCULATE ( SUM ( … ) )`). Оно объясняет половину сюрпризов DAX.

> ⚠️ **Осторожно.** Мера в вычисляемом столбце считается построчно с преобразованием контекста — на большом факте это медленно. Держите построчную логику в столбцах с простыми значениями, а агрегации — в мерах.

### ALL и родственники — знаменатели :id=all-and-its-relatives-the-denominators

**Что это.** Доле нужен знаменатель с **меньшим** числом фильтров, чем у ячейки. **ALL** снимает фильтры внутри CALCULATE. Родственники снимают разное:

| функция | снимает | при срезе филиала Tashkent Central строка SME показывает |
|---|---|---|
| `ALL ( products )` = `REMOVEFILTERS ( products )` | только фильтры на `products` | **55.30 %** (доля SME в Tashkent Central) |
| `ALL ( v_loan_status )` | все фильтры, доходящие до факта, включая пришедшие от его измерений | **7.61 %** (SME Tashkent Central ÷ весь портфель) |
| `ALLEXCEPT ( v_loan_status, branches[branch_name] )` | всё, кроме филиала | 55.30 % |
| `ALLSELECTED ( products )` | фильтр продукта из строки; выбор пользователя в срезах остаётся | зависит от среза продукта |

**Как пишется.**

```dax
Outstanding Share of Total =
DIVIDE (
    -- собственный остаток ячейки
    [Outstanding],
    -- то же, со снятым фильтром продукта
    CALCULATE ( [Outstanding], ALL ( products ) )
)
-- без среза: SME 60.32 % · AUTO 27.64 % · CONS 11.05 % · BNPL 0.54 % · MICRO
-- 0.46 % · итого 100 %
```

### Логика операций со временем — TOTALYTD, SAMEPERIODLASTYEAR, DATEADD :id=time-intelligence-totalytd-sameperiodlastyear-dateadd

**Что это.** Функции **логики операций со временем** (*time intelligence*) возвращают **набор дат**, и CALCULATE использует этот набор как фильтр. Они работают только с отмеченной таблицей дат без пропусков, связанной с фактом (День 3).

**Как пишется.**

```dax
-- с 1 января до последней даты ячейки
YTD Disbursed        = TOTALYTD ( [Disbursed Amount], dim_date[date] )
-- те же даты год назад
Disbursed SPLY       = CALCULATE ( [Disbursed Amount], SAMEPERIODLASTYEAR ( dim_date[date] ) )
-- сдвиг на любое число дней / месяцев / лет
Disbursed Prev Month = CALCULATE ( [Disbursed Amount], DATEADD ( dim_date[date], -1, MONTH ) )
Disbursed YoY %      = DIVIDE ( [Disbursed Amount] - [Disbursed SPLY], [Disbursed SPLY] )
Disbursed MoM %      = DIVIDE ( [Disbursed Amount] - [Disbursed Prev Month], [Disbursed Prev Month] )
```

### Остатки во времени — полуаддитивные меры :id=balances-over-time-semi-additive-measures

**Что это.** **Поток** (выдано, собрано) складывается во времени. **Остаток** (остаток долга) — нет: портфель на конец года — это остаток последнего месяца, а не сумма двенадцати. ### Переменные — VAR … RETURN :id=variables-var-return

**Что это.** **Переменная** (*variable*) даёт имя промежуточному результату внутри меры. Она вычисляется **один раз** — в том контексте, где определена, — и дальше остаётся константой. `RETURN` отдаёт результат.

**Как пишется.** Кривая Парето по филиалам: остаток филиала плюс остатки всех более крупных.

```dax
Running Outstanding =
-- остаток этого филиала, посчитан один раз
VAR CurrentOutstanding = [Outstanding]
RETURN
    CALCULATE (
        [Outstanding],
        -- пройти все десять филиалов
        FILTER ( ALL ( branches[branch_name] ),
                 -- оставить не меньшие
                 [Outstanding] >= CurrentOutstanding )
    )
Running Outstanding % = DIVIDE ( [Running Outstanding], CALCULATE ( [Outstanding], ALL ( branches ) ) )
```

| филиал (по убыванию Outstanding) | Outstanding | Running Outstanding % |
|---|---|---|
| Tashkent Central | 28 716 674 373 | 13.76 % |
| Tashkent South | 26 787 392 136 | 26.59 % |
| Tashkent North | 26 175 671 562 | 39.13 % |
| Fergana Central | 24 797 334 197 | **51.01 %** |

Четыре филиала из десяти держат половину портфеля.

**Когда применять.** Всегда, когда значение нужно дважды или его нужно зафиксировать до смены контекста. И для читаемости длинных мер.

> ⚠️ **Осторожно.** Без переменной `[Outstanding]` внутри FILTER вычисляется для каждого перебираемого филиала — каждый филиал сравнивает себя с собой, и в каждой строке 100 %.

### RANKX — ранг внутри контекста фильтра :id=rankx-a-rank-inside-a-filter-context

**Что это.** **RANKX** проходит таблицу, вычисляет выражение для каждой её строки и возвращает место значения текущей ячейки среди них.

**Как пишется.**

```dax
Branch Rank =
IF (
    -- только в строках с одним филиалом (пусто в итоге)
    HASONEVALUE ( branches[branch_name] ),
    -- ранг среди всех десяти филиалов
    RANKX ( ALL ( branches[branch_name] ),
            -- по Outstanding, крупнейший первым
            [Outstanding], , DESC, DENSE )
)
```

Tashkent Central 1, Tashkent South 2, … Bukhara Central 8, Nukus Central 9, Termez Central 10. Срез продукта на SME меняет ранги: Tashkent South 1, Tashkent Central 2, Samarkand Central 3.

**Когда применять.** Списки Top-N, «где стоит этот филиал», рейтинги, которые следуют за срезами.

> ⚠️ **Осторожно.** Без `ALL` в таблице каждой строки только её собственный филиал, и каждый филиал получает ранг 1.

### Форматирование, которое уважает читателя :id=formatting-that-respects-the-reader

**Что это.** Форматирование — часть сообщения. Страницу читают **с левого верхнего угла**; цвет что-то значит, только если используется для одной вещи.

**Как пишется.**
1. **Расположение** — верхний ряд: карточки (KPI), самая важная слева вверху; середина: тренды; низ: подробные таблицы. Не больше **7 визуалов** на странице.
2. **Цвет** — один цвет для «плохо» (красный), серые и один акцент для всего остального. Красный никогда не цвет серии.
3. **Условное форматирование** мерой цвета: Format → Cell elements → Background colour → **fx** → Format style *Field value* → мера.

```dax
PAR30 Colour =
-- побеждает первое истинное условие, как CASE WHEN
SWITCH ( TRUE (),
    [PAR30 %] >= 0.05, "#C0392B",  -- 5 % и выше: красный
    [PAR30 %] >= 0.03, "#E67E22",  -- 3–5 %: янтарный
    "#7F8C8D" )                    -- иначе: серый
```

4. **Заголовки, которые говорят вывод** — «PAR30 сосредоточен в SME Нукуса и в Бухаре», а не «PAR30 по филиалам». **Динамический заголовок** говорит, что выбрано:

```dax
-- выбор или значение по умолчанию
Dynamic Title = "Outstanding - " & SELECTEDVALUE ( products[product_name], "all products" )
              & " · as of 1 Oct 2026: " & FORMAT ( [Outstanding] / 1e9, "#,0.0" ) & " bn soum"
-- без выбора: "Outstanding - all products · as of 1 Oct 2026: 208.7 bn soum"
```

Как подключить: Format → Title → **fx** → Field value → `Dynamic Title`.

5. **Дата «на» и определения** на каждой странице, одни и те же срезы на одном и том же месте.

**Когда применять.** До того как страницу увидит кто-то ещё, — и ещё раз перед экспортом в PDF.

> ⚠️ **Осторожно.** Скриншот отфильтрованной страницы без динамического заголовка или видимого среза лжёт: он выглядит как весь портфель.

### Публикация и обновление :id=publish-and-refresh

**Что это.** **Публикация** (*publish*) загружает `.pbix` в **Power BI Service**, где **обновление по расписанию** (*scheduled refresh*) перечитывает источники, а люди открывают отчёт в браузере.

**Как пишется.**
1. Home → **Publish** → рабочая область (нужен рабочий или учебный аккаунт Microsoft; личные Gmail / Mail.ru не принимаются).

4. Доступ: **рабочая область** для строителей, **приложение** для читателей, **дашборд** (закреплённые плитки) для руководителей.

### Безопасность на уровне строк :id=row-level-security

**Что это.** **Безопасность на уровне строк** (*row-level security*, RLS) даёт роли фильтр DAX. Пользователь в роли видит только строки, которые оставляет фильтр, — на каждой странице, в каждой мере.

**Как пишется.**
1. Modeling → **Manage roles** → новая роль *Branch manager — Bukhara*.
2. На таблице `branches` фильтр:

```dax
-- статическая роль: по одной на филиал
[branch_name] = "Bukhara Central"
-- динамическая, одна роль на всех управляющих, с таблицей соответствия e-mail →
-- филиал:
-- [branch_name] = LOOKUPVALUE ( map[branch_name], map[email], USERPRINCIPALNAME
-- () )
```

3. Modeling → **View as** → роль. Фильтр идёт по связям к каждому факту:

| карточка | как вы сами | View as *Branch manager — Bukhara* |
|---|---|---|
| Outstanding | 208 723 504 430 | 15 116 046 338 |
| PAR30 % | 3.12 % | 4.81 % |
| Branch Rank | — | 1 |

4. В Service: семантическая модель → Security → добавьте людей в роль. В Desktop роли можно только проверить.

**Когда применять.** Всегда, когда один отчёт обслуживает людей, которым можно видеть только часть данных, — управляющих филиалами у Севары.

> ⚠️ **Осторожно.** RLS удаляет строки до того, как выполнится любая мера: `ALL ( branches )` не может её обойти, поэтому ранг под RLS всегда 1. И RLS ограничивает строки, а не страницы — страница, которую управляющий видеть не должен, относится к отдельному отчёту.

### Типичные ошибки :id=mistakes-people-make

- `SUM` в вычисляемом столбце в ожидании группового итога строки; доля как столбец.
- Фильтр `CALCULATE`, молча заменяющий фильтр визуала по тому же столбцу (одно число в каждой строке).
- `a / b` вместо `DIVIDE`; проценты, усреднённые по строкам, вместо отношения сумм.
- Суммирование остатков по месяцам (Outstanding за год); помещение остатка «на дату» `Outstanding` на месячную линию тренда.
- Time intelligence без отмеченной таблицы дат без пропусков — или на собственном столбце дат факта.
- `RANKX` без `ALL`; ранг, показанный в итоговой строке.
- Десять визуалов, четыре цвета для категорий и красный для одной из них; заголовки, называющие диаграмму, а не вывод.
- Срез на одной странице, не синхронизированный с остальными; нет «на дату» на странице.
- Проверка RLS только от своего имени; ожидание, что `ALL` обойдёт её.
