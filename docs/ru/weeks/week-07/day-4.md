## 1. Теория — одна функция, которую нужно понять :id=1-learn-one-function-to-understand

### Меры, столбцы и два контекста :id=measures-columns-and-the-two-contexts

Вчера: **вычисляемый столбец** считается один раз на строку и хранится; **мера** считается для каждой ячейки каждого визуала. Они живут в двух разных мирах:

- **Контекст строки** (*row context*) — «текущая строка». Он существует в вычисляемом столбце (и внутри итераторов вроде `SUMX`, `FILTER`, `RANKX`). В столбце на `v_loan_status` выражение `v_loan_status[outstanding]` означает остаток долга *этого кредита*: кредит 1 → 9 593 064.
- **Контекст фильтра** (*filter context*) — «какие строки видимы». Его создаёт всё вокруг меры: срезы, строки и столбцы визуала, фильтры страницы и отчёта, связи, переносящие эти фильтры от измерений к фактам. В таблице по продуктам контекст фильтра строки SME — это `products[code] = "SME"` (плюс любой срез), и `SUM(v_loan_status[outstanding])` суммирует только кредиты SME: 125 892 942 411.

Знаменитая ловушка: в **столбце** `SUM(v_loan_status[outstanding])` игнорирует строку — у столбца нет контекста фильтра, так что сумма берётся по всей таблице. `share = v_loan_status[outstanding] / SUM(v_loan_status[outstanding])` даёт кредиту 1 **0.0046 %** портфеля: верно, но только потому, что нам нужна была «вся таблица». Оберните ту же сумму в `CALCULATE` внутри столбца — и она вернёт **собственное значение строки** (9 593 064 для кредита 1): `CALCULATE` превращает контекст строки в контекст фильтра — **преобразование контекста** (*context transition*). Эта одна фраза объясняет половину всех сюрпризов DAX.

### CALCULATE — вычислить выражение в изменённом контексте фильтра :id=calculate-evaluate-an-expression-in-a-modified-filter-context

```
CALCULATE ( <expression>, <filter 1>, <filter 2>, ... )
```

1. взять контекст фильтра ячейки; 2. применить аргументы-фильтры — каждый **заменяет** любой существующий фильтр по тому же столбцу, фильтры по разным столбцам объединяются через AND; 3. вычислить выражение там.

```
Outstanding DPD30+ = CALCULATE ( [Outstanding], v_loan_status[dpd] > 30 )          -- 6 507 526 953
PAR30 %            = DIVIDE ( [Outstanding DPD30+], [Outstanding] )                -- 3.12 %
NPL90 %            = DIVIDE ( CALCULATE ( [Outstanding], v_loan_status[dpd] > 90 ), [Outstanding] )   -- 2.55 %
Loans 90+          = CALCULATE ( COUNTROWS ( v_loan_status ), v_loan_status[bucket] = "90+" )        -- 234
```

В таблице по продуктам строка SME считает PAR30 с *обоими* фильтрами — `product = SME` от строки, `dpd > 30` от `CALCULATE` — над остатком долга SME: **2.55 %**; AUTO **4.44 %**, MICRO **0.72 %**. SQL недели 3 `SUM(CASE WHEN dpd > 30 THEN outstanding END) / SUM(outstanding)` — это в точности то же, записанное один раз.

**«Заменяет» на практике.** Матрица по `bucket` с `CALCULATE([Outstanding], v_loan_status[bucket] = "90+")` показывает **5 319 475 527 в каждой строке** — собственный фильтр меры по `bucket` перекрывает фильтр строки. Оберните фильтр в `KEEPFILTERS(...)`, и он вместо этого пересекается: 90+ показывает 5 319 475 527, остальные строки пусты. Когда мера на `CALCULATE` показывает везде одно и то же число, спросите себя: *какой столбец заменяет мой фильтр?*

### FILTER — когда условие не сводится к простой проверке столбца :id=filter-when-the-condition-is-not-a-simple-column-test

Булев фильтр (`v_loan_status[dpd] > 30`) — сокращение для `FILTER(ALL(v_loan_status[dpd]), v_loan_status[dpd] > 30)`. Используйте явный **`FILTER`**, когда условие включает меру или несколько столбцов: `CALCULATE([Outstanding], FILTER(v_loan_status, v_loan_status[dpd] > 30 && v_loan_status[product] <> "MICRO"))`. `FILTER` перебирает таблицу строка за строкой (контекст строки) и возвращает строки, прошедшие условие — мощно и медленнее; по возможности фильтруйте столбец, а не всю таблицу фактов.

### ALL, ALLEXCEPT, REMOVEFILTERS, ALLSELECTED — знаменатели :id=all-allexcept-removefilters-allselected-the-denominators

| Функция | Снимает | Типичное применение | При срезе по филиалу Tashkent Central строка SME показывает |
|---|---|---|---|
| `ALL ( products )` / `REMOVEFILTERS ( products )` | фильтры только по `products` | доля продукта внутри всего остального, что отфильтровано | **55.30 %** (доля SME в Tashkent Central) |
| `ALL ( v_loan_status )` | все фильтры, доходящие до факта, — включая приходящие от его измерений | доля во всём портфеле | **7.61 %** (SME Tashkent Central ÷ весь портфель) |
| `ALLEXCEPT ( v_loan_status, branches[branch_name] )` | всё, кроме филиала | «итог по филиалу» в матрице филиал × продукт | 55.30 % |
| `ALLSELECTED ( products )` | фильтр продукта строки, но сохраняет выбор в срезах | «доля от того, что выбрал пользователь» | зависит от среза по продукту |

```
Outstanding Share of Total = DIVIDE ( [Outstanding], CALCULATE ( [Outstanding], ALL ( products ) ) )
-- без среза: SME 60.32 % · AUTO 27.64 % · CONS 11.05 % · BNPL 0.54 % · MICRO 0.46 %
```

`REMOVEFILTERS` — читаемый синоним `ALL` внутри `CALCULATE`. А `CROSSFILTER(…, BOTH)` внутри одной меры — способ получить вчерашнюю двунаправленную фильтрацию для одного расчёта, не делая модель неоднозначной.

### DIVIDE и VAR … RETURN :id=divide-and-var-return

**`DIVIDE(a, b)`** возвращает пустое значение (или третий аргумент), когда b равно 0 или пусто — `a / b` возвращает Infinity (или NaN для 0 / 0), что на карточке выглядит как «Infinity» и портит итоги и диаграммы. Для долей всегда используйте `DIVIDE`.

**Переменные** (*variables*) называют промежуточный результат, вычисляют его **один раз** в текущем контексте и делают длинные меры читаемыми:

```
Running Outstanding =
VAR CurrentOutstanding = [Outstanding]                              -- вычисляется в контексте строки (этот филиал)
RETURN
    CALCULATE ( [Outstanding], FILTER ( ALL ( branches[branch_name] ), [Outstanding] >= CurrentOutstanding ) )
-- Парето по филиалам: Tashkent Central 28.72 bn (13.76 %), + Tashkent South 26.59 %, + Tashkent North 39.13 %, + Fergana 51.01 %
```

Без переменной `[Outstanding]` внутри `FILTER` вычислялся бы для каждого перебираемого филиала и сравнивал каждый филиал с самим собой. Переменная после определения — константа; в этом и смысл.

### Time intelligence — нужна отмеченная таблица дат :id=time-intelligence-needs-the-marked-date-table

```
YTD Disbursed        = TOTALYTD ( [Disbursed Amount], dim_date[date] )                         -- сент. 2026: 161 480 300 000
Disbursed SPLY       = CALCULATE ( [Disbursed Amount], SAMEPERIODLASTYEAR ( dim_date[date] ) ) -- сент. 2026: 14 644 540 000
Disbursed YoY %      = DIVIDE ( [Disbursed Amount] - [Disbursed SPLY], [Disbursed SPLY] )      -- сент. 2026: +16.19 %
Disbursed Prev Month = CALCULATE ( [Disbursed Amount], DATEADD ( dim_date[date], -1, MONTH ) ) -- сент. 2026: 22 290 210 000
Disbursed MoM %      = DIVIDE ( [Disbursed Amount] - [Disbursed Prev Month], [Disbursed Prev Month] )   -- сент. 2026: -23.66 %
```

Каждая функция **возвращает набор дат**, а `CALCULATE` использует его как фильтр: `SAMEPERIODLASTYEAR` сдвигает видимые даты на год назад, `DATEADD` — на любое число дней / месяцев / кварталов / лет, `TOTALYTD` расширяет их до 1 января того же года. Они работают, только если `dim_date` непрерывна (каждый день, без пропусков — наша идёт с 2024-01-01 по 2027-12-31) и **отмечена** как таблица дат, и только для фактов, связанных с ней. YTD по месяцам 2026: январь 17 452 370 000 · март 49 003 630 000 · июнь 101 480 730 000 · **сентябрь 161 480 300 000**; та же точка годом раньше 110 929 400 000: YTD **+45.6 %**.

**Срезы остатков — не потоки.** `Outstanding` — остаток; складывать остатки по месяцам нельзя. В `v_portfolio_monthly` есть остаток на конец месяца по каждому месяцу; простой `SUM` по 2026 даёт 1 808 092 257 935 — восемь сложенных остатков. **Полуаддитивная** мера берёт последний месяц периода:

```
Outstanding Month-End =
VAR LastMonth = CALCULATE ( MAX ( v_portfolio_monthly[month] ) )
RETURN CALCULATE ( SUM ( v_portfolio_monthly[outstanding_month_end] ), v_portfolio_monthly[month] = LastMonth )
-- янв. 2026 151 807 386 149 · авг. 203 830 205 928 · сент. 208 243 879 623 · год 2026: строка октября 196 392 195 577 (показывайте месяцы до сентября)
```

И помните вчерашнюю датировку: `v_loan_status` датирована **выдачей**. Срез по месяцу на карточке `Outstanding` показывает остаток долга по кредитам, выданным в этом месяце (сентябрь 2026: 16 965 990 458), а не портфель на конец сентября. Поместите меру Month-End на линию тренда, меру `Outstanding` «на дату» — на карточку, и подпишите обе.

### RANKX и SWITCH :id=rankx-and-switch

```
Branch Rank = IF ( HASONEVALUE ( branches[branch_name] ), RANKX ( ALL ( branches[branch_name] ), [Outstanding], , DESC, DENSE ) )
```

`RANKX` перебирает таблицу из первого аргумента (все десять филиалов — `ALL` снимает фильтр по собственному филиалу строки, иначе каждый филиал будет первым среди самого себя), вычисляет `[Outstanding]` для каждого и возвращает позицию текущего: Tashkent Central 1 … Bukhara Central 8 … Termez Central 10. `HASONEVALUE` делает итоговую строку пустой. Срез по продукту SME переранжирует: Tashkent South 1, Tashkent Central 2, Samarkand Central 3.

**`SWITCH(TRUE(), …)`** — это `CASE WHEN` в DAX: выигрывает первое истинное условие. Как вычисляемый столбец он перестраивает корзину (`measures.dax`, конец); как мера — выбирает текст или цвет:

```
PAR30 Colour = SWITCH ( TRUE (), [PAR30 %] >= 0.05, "#C0392B", [PAR30 %] >= 0.03, "#E67E22", "#7F8C8D" )
```

### Динамические заголовки :id=dynamic-titles

Заголовок, который говорит, что выбрано, не даёт скриншотам лгать:

```
Dynamic Title = "Outstanding - " & SELECTEDVALUE ( products[product_name], "all products" )
              & " · as of 1 Oct 2026: " & FORMAT ( [Outstanding] / 1e9, "#,0.0" ) & " bn soum"
```

Без выбора: *"Outstanding - all products · as of 1 Oct 2026: 208.7 bn soum"*; при выбранном SME: *"… Small business loan … 125.9 bn soum"*. Используйте его в заголовке любого визуала: Format → Title → **fx** → Field value → `Dynamic Title`.

**Правила компоновки** (верх-середина-низ из презентации 7.3): **левый верхний угол** содержит самое важное число (глаз начинает оттуда); **верхняя строка** = карточки (KPI), **середина** = тренды, **низ** = таблицы с деталями; **≤ 7 визуалов на странице**; **один цвет для «плохого»** (красный — только для того, что плохо, и никогда как цвет серии), остальное в серых тонах и одном акценте; у каждого визуала заголовок о том, что он **означает** («PAR30 выше всего в SME Нукуса»), а не о том, что это («PAR30 по филиалам»); одни и те же срезы на одном месте на каждой странице; дата актуальности видна.

### Публикация, обновление, доступ :id=publish-refresh-share

**Публикация**: Home → Publish → рабочая область в **Power BI Service** (нужен рабочий или учебный аккаунт Microsoft; личные аккаунты Gmail / Mail.ru не принимаются). В Service: семантическая модель (набор данных) → Settings → **Scheduled refresh** (Pro: до 8 раз в день). Модели, читающей файлы на вашем ПК или SQL Server внутри банка, нужен **шлюз данных on-premises (on-premises data gateway)**, установленный на машине, которая их видит; облачным источникам он не нужен. Затем доступ: **рабочая область** для разработчиков, **приложение** для читателей, **дашборды** (закреплённые плитки из нескольких отчётов) для руководителей. **Без рабочего аккаунта** (вариант курса по умолчанию): поделитесь `.pbix` (любой, у кого есть Desktop, откроет его и нажмёт Refresh) или **File → Export → Export to PDF** — каждая страница как PDF, формат пакета для правления. Оба варианта честны; скажите, каким воспользовались.

**Безопасность на уровне строк** (*row-level security*, RLS). В Desktop, Modeling → **Manage roles** → роль *Branch manager — Bukhara* с DAX-фильтром `branches[branch_name] = "Bukhara Central"` на таблице `branches`; фильтр идёт по связям на каждый факт. Проверьте через **View as** → роль: Outstanding **15 116 046 338**, PAR30 **4.81 %**, NPL90 4.48 %, FPD30 2.39 % (14 / 586), доля собранного за сентябрь 92.31 %. Одна роль на филиал не масштабируется; динамическая версия использует одну роль и таблицу соответствия e-mail → филиал: `branches[branch_name] = LOOKUPVALUE ( map[branch_name], map[email], USERPRINCIPALNAME () )`. Роли назначаются людям в Service (набор данных → Security); в Desktop их можно только проверить. Два следствия, которые стоит помнить: мера с `ALL(branches)` под RLS всё равно видит только разрешённый филиал (**Branch Rank показывает 1**), и RLS ограничивает **строки**, а не страницы — страница, которую управляющий видеть не должен, — это отдельный отчёт.

### Типичные ошибки :id=mistakes-people-make

- `SUM` в вычисляемом столбце в ожидании группового итога строки; доля как столбец.
- Фильтр `CALCULATE`, молча заменяющий фильтр визуала по тому же столбцу (одно число в каждой строке).
- `a / b` вместо `DIVIDE`; проценты, усреднённые по строкам, вместо отношения сумм.
- Суммирование остатков по месяцам (Outstanding за год); помещение остатка «на дату» `Outstanding` на месячную линию тренда.
- Time intelligence без отмеченной таблицы дат без пропусков — или на собственном столбце дат факта.
- `RANKX` без `ALL`; ранг, показанный в итоговой строке.
- Десять визуалов, четыре цвета для категорий и красный для одной из них; заголовки, называющие диаграмму, а не вывод.
- Срез на одной странице, не синхронизированный с остальными; нет «на дату» на странице.
- Проверка RLS только от своего имени; ожидание, что `ALL` обойдёт её.
