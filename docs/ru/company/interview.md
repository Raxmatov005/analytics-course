**B1.** **Доля одобрений по каналам за январь–сентябрь 2026, отменённые заявки исключены.**

```task
{"id": "interview-b1", "kind": "free", "min": 25, "model": "Группируем applications по channel при applied_at >= '2026-01-01' AND applied_at < '2026-10-01' (не BETWEEN: в applied_at есть время). Одобренные = status IN ('approved', 'approved_not_disbursed'); рассмотренные = status <> 'cancelled'; доля = ROUND(100.0 * одобренные / рассмотренные, 1). ```
```

<details><summary>Запрос и результат</summary>

```sql
SELECT channel,
       COUNT(*) AS applications,
       SUM(CASE WHEN status IN ('approved', 'approved_not_disbursed') THEN 1 ELSE 0 END) AS approved,
       SUM(CASE WHEN status <> 'cancelled' THEN 1 ELSE 0 END) AS decided,
       ROUND(100.0 * SUM(CASE WHEN status IN ('approved', 'approved_not_disbursed') THEN 1 ELSE 0 END)
             / SUM(CASE WHEN status <> 'cancelled' THEN 1 ELSE 0 END), 1) AS approval_rate_pct
FROM applications
-- не BETWEEN: в applied_at есть время
WHERE applied_at >= '2026-01-01' AND applied_at < '2026-10-01'
GROUP BY channel
ORDER BY approval_rate_pct DESC;
```

|---|---|---|---|---|
| branch | 2 396 | 1 527 | 2 113 | 72.3 |
| partner | 1 045 | 646 | 917 | 70.4 |
| app | 1 953 | 1 118 | 1 647 | 67.9 |

Назовите вслух два выбора: «в одобренные входят approved-not-disbursed; отменённые вынесены из знаменателя». `100.0 *` позволяет избежать целочисленного деления.

**B2.** **Топ-3 филиала по сумме выдач за январь–сентябрь 2026 с их долей в общей сумме.**

```task
{"id": "interview-b2", "kind": "free", "min": 25, "model": "Сумма principal по филиалам для кредитов, выданных с 2026-01-01 до (не включая) 2026-10-01, с соединением с branches; затем ROUND(100.0 * disbursed / SUM(disbursed) OVER (), 1) как доля и RANK() OVER (ORDER BY disbursed DESC); ORDER BY disbursed DESC LIMIT 3 (SQL Server: TOP 3). Что здесь проверяют: SUM(…) OVER () считает общий итог до того, как LIMIT отрежет строки, поэтому доля — от всех десяти филиалов, а не от трёх показанных.", "rubric": ["сумма principal по филиалам за январь–сентябрь 2026 с соединением с branches", "доля через SUM(…) OVER (), посчитанная до LIMIT, — доля от всех десяти филиалов", "тройка: Tashkent South (13.2 %), Fergana Central, Samarkand Central"]}
```

<details><summary>Запрос и результат</summary>

```sql
WITH b AS (
  SELECT br.branch_name, SUM(l.principal) AS disbursed
  FROM loans l JOIN branches br ON br.branch_id = l.branch_id
  WHERE l.disbursed_at >= '2026-01-01' AND l.disbursed_at < '2026-10-01'
  GROUP BY br.branch_name)
SELECT branch_name, disbursed,
       -- окно по всему результату
       ROUND(100.0 * disbursed / SUM(disbursed) OVER (), 1) AS share_pct,
       RANK() OVER (ORDER BY disbursed DESC) AS rnk
FROM b
ORDER BY disbursed DESC
LIMIT 3;
-- SQL Server: SELECT TOP 3
```

|---|---|---|---|
| Tashkent South | 21 380 780 000 | 13.2 | 1 |
| Fergana Central | 19 742 090 000 | 12.2 | 2 |
| Samarkand Central | 19 440 640 000 | 12.0 | 3 |

Что здесь проверяют: `SUM(…) OVER ()` считает общий итог до того, как `LIMIT` отрежет строки, поэтому доля считается от всех десяти филиалов, а не от трёх показанных.

```sql
  SELECT * FROM (
    SELECT p.*, ROW_NUMBER() OVER (PARTITION BY installment_id, paid_at, amount ORDER BY payment_id) AS rn
    FROM payments p) WHERE rn = 1),
first_inst AS (

         -- полуоткрытый интервал: включая 30-й день; DATEADD(day, 31,
         -- i.due_date)
```
