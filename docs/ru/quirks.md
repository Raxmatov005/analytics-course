# Подвохи — ловушки SQL, Excel и Python

> 🧭 **Зачем эта страница.** Все подвохи, которые разбирает курс, — по строке на каждый, со ссылкой на урок, где их можно увидеть своими глазами. Прочитайте перед экзаменом или собеседованием; возвращайтесь, когда число выглядит неправильным, а ничего не покраснело.

**Подвох** — правило, которое удивляет. Запрос выполняется, формула даёт число, код печатает результат — а результат не тот, что вы имели в виду. Большинство подвохов срабатывают **молча**: ни ошибки, ни предупреждения. Каждая строка ниже говорит, что происходит на самом деле; ссылка открывает урок, где можно попробовать это в блоке или в маленькой таблице.


## SQL (в курсе — SQLite)

- **Где сортируются NULL.** В SQLite и SQL Server первыми при `ASC`, в PostgreSQL и Oracle — последними; пишите `NULLS FIRST` / `NULLS LAST`. → [Неделя 1, день 2 · ORDER BY](weeks/week-01/day-2.md?id=order-by-sort-the-rows)
- **`LIMIT` без `ORDER BY`.** Возвращает *какие-то* N строк, а не самые большие или новые. → [Неделя 1, день 2 · LIMIT и TOP](weeks/week-01/day-2.md?id=limit-and-top-only-the-first-n-rows)
- **`= NULL` ничего не находит.** `NULL = NULL` — это NULL, а не истина; проверяйте через `IS NULL`. → [Неделя 1, день 2 · IS NULL](weeks/week-01/day-2.md?id=is-null-the-empty-cell)
- **`AND` раньше `OR`.** Без скобок запрос отвечает на другой вопрос — без ошибки. → [Неделя 1, день 2 · AND, OR, NOT](weeks/week-01/day-2.md?id=and-or-not-combining-conditions-with-brackets)
- **Двойные кавычки — это имя.** В SQLite опечатка в `"…"` становится текстом, а не ошибкой; значения пишут в одинарных кавычках. → [Неделя 1, день 2 · Текст, числа и даты в условиях](weeks/week-01/day-2.md?id=text-numbers-and-dates-in-conditions)
- **`BETWEEN` по дате со временем.** `BETWEEN '…-01' AND '…-30'` теряет всё после полуночи последнего дня; пишите `>=` и `<`. → [Неделя 1, день 2 · BETWEEN](weeks/week-01/day-2.md?id=between-a-range-with-both-ends-included)
- **`CREATE TABLE … AS SELECT`** копирует строки, но ни ключей, ни правил. → [Неделя 1, день 3 · CREATE TABLE](weeks/week-01/day-3.md?id=create-table-make-an-empty-table)
- **`UPDATE` / `DELETE` без `WHERE`** меняет все строки, без предупреждения. → [Неделя 1, день 3 · UPDATE … SET … WHERE](weeks/week-01/day-3.md?id=update-set-where-change-rows)
- **В SQLite нет `TRUNCATE`.** Синтаксическая ошибка; таблицу очищает `DELETE FROM t`. → [Неделя 1, день 3 · DELETE … WHERE](weeks/week-01/day-3.md?id=delete-where-remove-rows)
- **Каждая команда сохраняется сразу.** Отменить нельзя — если не открыть `BEGIN` и не закончить `ROLLBACK` или `COMMIT`. → [Неделя 1, день 3 · DELETE … WHERE](weeks/week-01/day-3.md?id=delete-where-remove-rows)
- **`WHERE` по правой таблице LEFT JOIN** выбрасывает строки без пары — снова INNER JOIN; фильтр пишите в `ON`. → [Неделя 2, день 1 · INNER vs LEFT](weeks/week-02/day-1.md?id=inner-vs-left-the-row-with-no-partner)
- **Запятая между таблицами — это соединение.** `FROM a, b` без условия в `WHERE` — перекрёстное соединение: каждая строка с каждой. → [Неделя 2, день 1 · CROSS JOIN](weeks/week-02/day-1.md?id=cross-join-every-row-with-every-row)
- **`COUNT(*)`, `COUNT(col)`, `COUNT(DISTINCT col)`** считают строки, заполненные значения и разные значения — три разных числа. → [Неделя 2, день 2 · COUNT](weeks/week-02/day-2.md?id=count-rows-values-and-different-values)
- **`COUNT(DISTINCT a, b)`** в SQLite — ошибка; считайте `a || '-' || b`. → [Неделя 2, день 2 · COUNT](weeks/week-02/day-2.md?id=count-rows-values-and-different-values)
- **`SUM` по нулю строк — NULL**, а не 0; `COUNT` даёт 0. → [Неделя 2, день 2 · SUM](weeks/week-02/day-2.md?id=sum-add-a-column-up)
- **Целое ÷ целое = целое.** `5 / 2` равно 2; начинайте с `1.0 *` или `100.0 *`. → [Неделя 2, день 2 · AVG](weeks/week-02/day-2.md?id=avg-the-average-and-the-whole-number-trap)
- **Среднее средних** — не среднее по всем строкам. → [Неделя 2, день 2 · AVG](weeks/week-02/day-2.md?id=avg-the-average-and-the-whole-number-trap)
- **`MAX` по тексту** идёт по символам: заглавные раньше строчных. → [Неделя 2, день 2 · MIN и MAX](weeks/week-02/day-2.md?id=min-and-max-the-smallest-and-the-largest)
- **Голый столбец рядом с `GROUP BY`.** SQLite выполняет запрос и берёт значение любой строки; SQL Server отказывается. → [Неделя 2, день 2 · GROUP BY по одному столбцу](weeks/week-02/day-2.md?id=group-by-one-column-one-row-per-group)
- **`WHERE` не видит агрегатов.** Условия на `COUNT` и `SUM` пишут в `HAVING`. → [Неделя 2, день 2 · WHERE vs HAVING](weeks/week-02/day-2.md?id=where-vs-having-filter-rows-or-filter-groups)
- **Соединение «один ко многим» умножает суммы.** Сначала сравните `COUNT(*)` и `COUNT(DISTINCT key)`. → [Неделя 2, день 2 · Агрегация после соединения](weeks/week-02/day-2.md?id=aggregating-over-a-join-decide-what-one-row-is)
- **`UNION` сопоставляет столбцы по позиции**, а не по имени. → [Неделя 2, день 2 · Операции над множествами](weeks/week-02/day-2.md?id=set-operators-stacking-results)
- **`||` с NULL даёт NULL**: одна пустая часть опустошает весь текст. `+` на тексте даёт 0. → [Неделя 2, день 3 · Конкатенация](weeks/week-02/day-3.md?id=concatenation-joining-texts-with)
- **`UPPER`, `LOWER` и `LIKE` в SQLite знают только латиницу**; кириллица не меняет регистр. → [Неделя 2, день 3 · UPPER и LOWER](weeks/week-02/day-3.md?id=upper-and-lower-one-case-for-every-value)
- **`LEN` и `LENGTH`.** `LEN` в SQL Server не видит пробелы в конце, `LENGTH` в SQLite их считает. → [Неделя 2, день 3 · LENGTH](weeks/week-02/day-3.md?id=length-how-many-characters)
- **`LIKE` не различает регистр, `=` различает** (SQLite, латиница). → [Неделя 2, день 3 · LIKE](weeks/week-02/day-3.md?id=like-patterns-with-and-_)
- **`ROUND(x, -3)` в SQLite ничего не делает**, а `ROUND(2.675, 2)` равно 2.67 (двоичная запись). → [Неделя 2, день 3 · ROUND](weeks/week-02/day-3.md?id=round-round-to-n-decimals)
- **`0.1 + 0.2 = 0.3` — ложь.** Не сравнивайте десятичные числа через `=`. → [Неделя 2, день 3 · ROUND](weeks/week-02/day-3.md?id=round-round-to-n-decimals)
- **CAST до деления, а не после.** `CAST(7917 / 14000 AS REAL)` уже 0. → [Неделя 2, день 3 · CAST](weeks/week-02/day-3.md?id=cast-change-the-type-of-a-value)
- **Плохой текст приводится молча.** `CAST('abc' AS INTEGER)` — 0, `'12abc'` — 12; числа-текст сортируются как текст. → [Неделя 2, день 3 · CAST](weeks/week-02/day-3.md?id=cast-change-the-type-of-a-value)
- **Даты — это текст.** Правильно сортируется и сравнивается только `'YYYY-MM-DD'`; `'2026-9-5'` — нет. → [Неделя 2, день 3 · Даты](weeks/week-02/day-3.md?id=dates-are-text-in-a-fixed-shape-and-today-is-2026-10-01)
- **`strftime` возвращает текст.** `strftime('%m', d) = 9` ничего не находит; `'09'` находит. → [Неделя 2, день 3 · strftime](weeks/week-02/day-3.md?id=strftime-the-parts-of-a-date)
- **`+1 month` перескакивает.** `date('2026-01-31', '+1 month')` — это 3 марта. → [Неделя 2, день 3 · Арифметика дат](weeks/week-02/day-3.md?id=date-arithmetic-days-between-two-dates-months-added-to-a-date)
- **`''` — не NULL.** `IS NULL` его не находит; `COUNT` его считает. → [Неделя 2, день 4 · NULL](weeks/week-02/day-4.md?id=null-the-value-that-is-not-there)
- **NULL собираются в одну группу.** `NULL = NULL` не истинно, но `GROUP BY`, `DISTINCT` и `UNION` делают одну группу NULL. → [Неделя 2, день 4 · Сравнение с NULL](weeks/week-02/day-4.md?id=comparing-with-null-is-null-never-null)
- **Что угодно + NULL = NULL.** Сначала превратите NULL в 0, если 0 — правильный смысл. → [Неделя 2, день 4 · NULL в арифметике](weeks/week-02/day-4.md?id=null-in-arithmetic-anything-combined-with-null-is-null)
