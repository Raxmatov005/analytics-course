# Quirks — the traps of SQL, Excel and Python

> 🧭 **What this page is for.** Every quirk the course teaches, one line each, with a link to the lesson where you can see it happen. Read it before an exam or an interview; come back whenever a number looks wrong and nothing turned red.

A **quirk** is a rule that surprises you. The query runs, the formula gives a number, the code prints a result — and the result is not what you meant. Most quirks fail **silently**: no error, no warning. Each line below says what really happens; the link opens the lesson, where a box or a small table lets you try it.


## SQL (SQLite in this course)

- **Where NULLs sort.** First with `ASC` in SQLite and SQL Server, last in PostgreSQL and Oracle; say `NULLS FIRST` / `NULLS LAST`. → [Week 1, Day 2 · ORDER BY](weeks/week-01/day-2.md?id=order-by-sort-the-rows)
- **`LIMIT` without `ORDER BY`.** Returns *some* N rows, not the biggest or the newest. → [Week 1, Day 2 · LIMIT and TOP](weeks/week-01/day-2.md?id=limit-and-top-only-the-first-n-rows)
- **`= NULL` finds nothing.** `NULL = NULL` is NULL, not true; test with `IS NULL`. → [Week 1, Day 2 · IS NULL](weeks/week-01/day-2.md?id=is-null-the-empty-cell)
- **`AND` before `OR`.** Without brackets the query answers another question, with no error. → [Week 1, Day 2 · AND, OR, NOT](weeks/week-01/day-2.md?id=and-or-not-combining-conditions-with-brackets)
- **Double quotes mean a name.** In SQLite a typo in `"…"` becomes text instead of an error; values go in single quotes. → [Week 1, Day 2 · Text, numbers and dates in conditions](weeks/week-01/day-2.md?id=text-numbers-and-dates-in-conditions)
- **`BETWEEN` on a date-time.** `BETWEEN '…-01' AND '…-30'` loses everything after midnight of the last day; use `>=` and `<`. → [Week 1, Day 2 · BETWEEN](weeks/week-01/day-2.md?id=between-a-range-with-both-ends-included)
- **`CREATE TABLE … AS SELECT`** copies the rows, but no key or rule. → [Week 1, Day 3 · CREATE TABLE](weeks/week-01/day-3.md?id=create-table-make-an-empty-table)
- **`UPDATE` / `DELETE` without `WHERE`** changes every row, with no warning. → [Week 1, Day 3 · UPDATE … SET … WHERE](weeks/week-01/day-3.md?id=update-set-where-change-rows)
- **No `TRUNCATE` in SQLite.** Syntax error; `DELETE FROM t` empties a table. → [Week 1, Day 3 · DELETE … WHERE](weeks/week-01/day-3.md?id=delete-where-remove-rows)
- **Every statement is saved at once.** No undo — unless you open `BEGIN` and end with `ROLLBACK` or `COMMIT`. → [Week 1, Day 3 · DELETE … WHERE](weeks/week-01/day-3.md?id=delete-where-remove-rows)
- **`WHERE` on the right table of a LEFT JOIN** drops the unmatched rows: it is an INNER JOIN again; put the filter in `ON`. → [Week 2, Day 1 · INNER vs LEFT](weeks/week-02/day-1.md?id=inner-vs-left-the-row-with-no-partner)
- **A comma between tables is a join.** `FROM a, b` without a `WHERE` condition is a cross join: every row with every row. → [Week 2, Day 1 · CROSS JOIN](weeks/week-02/day-1.md?id=cross-join-every-row-with-every-row)
- **`COUNT(*)`, `COUNT(col)`, `COUNT(DISTINCT col)`** count rows, filled values and different values — three different numbers. → [Week 2, Day 2 · COUNT](weeks/week-02/day-2.md?id=count-rows-values-and-different-values)
- **`COUNT(DISTINCT a, b)`** is an error in SQLite; count `a || '-' || b`. → [Week 2, Day 2 · COUNT](weeks/week-02/day-2.md?id=count-rows-values-and-different-values)
- **`SUM` over no rows is NULL**, not 0; `COUNT` is 0. → [Week 2, Day 2 · SUM](weeks/week-02/day-2.md?id=sum-add-a-column-up)
- **Whole ÷ whole = whole.** `5 / 2` is 2; start with `1.0 *` or `100.0 *`. → [Week 2, Day 2 · AVG](weeks/week-02/day-2.md?id=avg-the-average-and-the-whole-number-trap)
- **An average of averages** is not the average of all rows. → [Week 2, Day 2 · AVG](weeks/week-02/day-2.md?id=avg-the-average-and-the-whole-number-trap)
- **`MAX` on text** follows the characters: upper case comes before lower case. → [Week 2, Day 2 · MIN and MAX](weeks/week-02/day-2.md?id=min-and-max-the-smallest-and-the-largest)
- **A bare column next to `GROUP BY`.** SQLite runs it and picks any row's value; SQL Server refuses. → [Week 2, Day 2 · GROUP BY one column](weeks/week-02/day-2.md?id=group-by-one-column-one-row-per-group)
- **`WHERE` cannot see an aggregate.** Conditions on `COUNT` or `SUM` go in `HAVING`. → [Week 2, Day 2 · WHERE vs HAVING](weeks/week-02/day-2.md?id=where-vs-having-filter-rows-or-filter-groups)
- **A one-to-many join multiplies the sums.** Compare `COUNT(*)` with `COUNT(DISTINCT key)` first. → [Week 2, Day 2 · Aggregating over a join](weeks/week-02/day-2.md?id=aggregating-over-a-join-decide-what-one-row-is)
- **`UNION` matches columns by position**, not by name. → [Week 2, Day 2 · Set operators](weeks/week-02/day-2.md?id=set-operators-stacking-results)
- **`||` with NULL is NULL**: one empty part empties the whole text. `+` on text gives 0. → [Week 2, Day 3 · Concatenation](weeks/week-02/day-3.md?id=concatenation-joining-texts-with-)
- **`UPPER`, `LOWER` and `LIKE` know only Latin letters** in SQLite; Cyrillic keeps its case. → [Week 2, Day 3 · UPPER and LOWER](weeks/week-02/day-3.md?id=upper-and-lower-one-case-for-every-value)
- **`LEN` vs `LENGTH`.** SQL Server's `LEN` ignores trailing spaces, SQLite's `LENGTH` counts them. → [Week 2, Day 3 · LENGTH](weeks/week-02/day-3.md?id=length-how-many-characters)
- **`LIKE` ignores case, `=` does not** (SQLite, Latin letters). → [Week 2, Day 3 · LIKE](weeks/week-02/day-3.md?id=like-patterns-with-and-_)
- **`ROUND(x, -3)` does nothing in SQLite**, and `ROUND(2.675, 2)` is 2.67 (binary). → [Week 2, Day 3 · ROUND](weeks/week-02/day-3.md?id=round-round-to-n-decimals)
- **`0.1 + 0.2 = 0.3` is false.** Never compare decimals with `=`. → [Week 2, Day 3 · ROUND](weeks/week-02/day-3.md?id=round-round-to-n-decimals)
- **CAST the input, not the result.** `CAST(7917 / 14000 AS REAL)` is already 0. → [Week 2, Day 3 · CAST](weeks/week-02/day-3.md?id=cast-change-the-type-of-a-value)
- **Bad text casts quietly.** `CAST('abc' AS INTEGER)` is 0, `'12abc'` is 12; numbers stored as text sort as text. → [Week 2, Day 3 · CAST](weeks/week-02/day-3.md?id=cast-change-the-type-of-a-value)
- **Dates are text.** Only `'YYYY-MM-DD'` sorts and compares right; `'2026-9-5'` does not. → [Week 2, Day 3 · Dates are text in a fixed shape](weeks/week-02/day-3.md?id=dates-are-text-in-a-fixed-shape-and-quottodayquot-is-2026-10-01)
- **`strftime` returns text.** `strftime('%m', d) = 9` finds nothing; `'09'` does. → [Week 2, Day 3 · strftime](weeks/week-02/day-3.md?id=strftime-the-parts-of-a-date)
- **`+1 month` overflows.** `date('2026-01-31', '+1 month')` is 3 March. → [Week 2, Day 3 · Date arithmetic](weeks/week-02/day-3.md?id=date-arithmetic-days-between-two-dates-months-added-to-a-date)
- **`''` is not NULL.** `IS NULL` misses it; `COUNT` counts it. → [Week 2, Day 4 · NULL](weeks/week-02/day-4.md?id=null-the-value-that-is-not-there)
- **NULLs group together.** `NULL = NULL` is not true, yet `GROUP BY`, `DISTINCT` and `UNION` make one NULL group. → [Week 2, Day 4 · Comparing with NULL](weeks/week-02/day-4.md?id=comparing-with-null-is-null-never-null)
- **Anything + NULL is NULL.** Turn NULL into 0 first, when 0 is the right meaning. → [Week 2, Day 4 · NULL in arithmetic](weeks/week-02/day-4.md?id=null-in-arithmetic-anything-combined-with-null-is-null)
- **Division by zero.** SQLite returns NULL, SQL Server stops; `NULLIF` makes both safe. → [Week 2, Day 4 · NULLIF](weeks/week-02/day-4.md?id=nullif-safe-division)
- **NULL falls to `ELSE` in a `CASE`.** Test `IS NULL` first. → [Week 2, Day 4 · Searched CASE](weeks/week-02/day-4.md?id=searched-case-a-value-chosen-by-conditions)
- **`CASE col WHEN NULL`** never matches. → [Week 2, Day 4 · Simple CASE](weeks/week-02/day-4.md?id=simple-case-a-lookup-on-one-value)
- **`COUNT(CASE … ELSE 0 END)`** counts every row: 0 is a value. → [Week 2, Day 4 · CASE inside SUM and COUNT](weeks/week-02/day-4.md?id=case-inside-sum-and-count-counting-where)
- **A NULL key never matches** in a join — not even another NULL. → [Week 2, Day 4 · Joining on two columns](weeks/week-02/day-4.md?id=joining-on-two-columns)
- **`COUNT(DISTINCT …) OVER`** is not allowed. → [Week 3, Day 1 · SUM, AVG, COUNT, MIN, MAX as windows](weeks/week-03/day-1.md?id=sum-avg-count-min-max-as-windows)
- **`ORDER BY` inside `OVER` adds a frame** that lumps ties together; say `ROWS` and add a tiebreaker. → [Week 3, Day 1 · The frame](weeks/week-03/day-1.md?id=the-frame-rows-between-and-the-default-that-lumps-ties)
- **`ROW_NUMBER` on ties** numbers them in any order; end the window's `ORDER BY` with a unique column. → [Week 3, Day 2 · ROW_NUMBER](weeks/week-03/day-2.md?id=row_number-number-the-rows-1-2-3-)
- **`LAST_VALUE`** with `ORDER BY` and no frame returns the current row. → [Week 3, Day 2 · FIRST_VALUE and LAST_VALUE](weeks/week-03/day-2.md?id=first_value-and-last_value-the-edges-of-the-window-and-the-frame-trap)
- **A scalar subquery with two rows.** SQLite silently takes the first; SQL Server stops. → [Week 3, Day 3 · Scalar subquery](weeks/week-03/day-3.md?id=scalar-subquery-one-value-used-like-a-constant)
- **`NOT IN` with a NULL in the list** returns no rows; use `NOT EXISTS`. → [Week 3, Day 3 · IN with a subquery](weeks/week-03/day-3.md?id=in-with-a-subquery-is-the-value-in-that-list)
- **A CTE lives for one statement.** After the `;` its name is gone. → [Week 3, Day 3 · CTE](weeks/week-03/day-3.md?id=cte-with-name-as-and-why-it-reads-better)
- **A view is not faster** than its query: reading it runs the query. → [Week 3, Day 4 · What a view is](weeks/week-03/day-4.md?id=what-a-view-is-a-saved-query-with-a-name)
- **A `SELECT *` view** follows its table in SQLite and freezes its columns in SQL Server and PostgreSQL. → [Week 3, Day 4 · CREATE VIEW and DROP VIEW](weeks/week-03/day-4.md?id=create-view-and-drop-view)

## Excel and Google Sheets

- **A total row inside the data** is counted again by every `SUM` below it. → [Week 4, Day 1 · A proper table](weeks/week-04/day-1.md?id=a-proper-table-headers-one-row-per-thing-no-merged-cells)
- **Merged cells** break sorting, filtering and pivots; repeat the value on every row. → [Week 4, Day 1 · A proper table](weeks/week-04/day-1.md?id=a-proper-table-headers-one-row-per-thing-no-merged-cells)
- **`SUM` of a filtered table** still adds the hidden rows; the status bar shows only the visible ones. → [Week 4, Day 1 · Excel Tables (Ctrl+T) and structured references](weeks/week-04/day-1.md?id=excel-tables-ctrlt-and-structured-references)
- **A missing `$`** still returns numbers — wrong ones. → [Week 4, Day 1 · Relative and absolute references](weeks/week-04/day-1.md?id=relative-and-absolute-references-the-)
- **`AVERAGE` skips blanks, not zeros.** Filling blanks with 0 changes the average. → [Week 4, Day 1 · SUM, AVERAGE, COUNT, COUNTA](weeks/week-04/day-1.md?id=sum-average-count-counta-the-basic-aggregates)
- **A formula's `""`** is counted by `COUNTA` and by `COUNTBLANK`. → [Week 4, Day 1 · SUM, AVERAGE, COUNT, COUNTA](weeks/week-04/day-1.md?id=sum-average-count-counta-the-basic-aggregates)
- **Criteria and `=` ignore case** in Excel; only `EXACT` does not. → [Week 4, Day 1 · COUNTIFS, SUMIFS, AVERAGEIFS](weeks/week-04/day-1.md?id=countifs-sumifs-averageifs-an-aggregate-with-a-condition)
- **Wildcards** work in `COUNTIFS`/`SUMIFS` criteria, not with `=`. → [Week 4, Day 1 · Wildcards in criteria](weeks/week-04/day-1.md?id=wildcards-in-criteria-and-)
- **A date stored as text** is skipped by every date criterion; `ISNUMBER` must say TRUE. → [Week 4, Day 1 · Dates in criteria](weeks/week-04/day-1.md?id=dates-in-criteria-date-and-amp)
- **A date with a time** is a number with a fraction: `<=` the last day loses that day's afternoon. → [Week 4, Day 1 · Dates in criteria](weeks/week-04/day-1.md?id=dates-in-criteria-date-and-amp)
- **Whole-column references** are fine in `SUMIFS`, slow in `SUMPRODUCT` and array formulas. → [Week 4, Day 1 · SUMPRODUCT](weeks/week-04/day-1.md?id=sumproduct-when-the-condition-is-not-a-simple-comparison)
- **An empty cell is 0 in a test**: a blank score fails `>=600` like a low one. → [Week 4, Day 1 · IF](weeks/week-04/day-1.md?id=if-two-branches)
- **`&` drops the number format**; wrap the number in `TEXT`. → [Week 4, Day 1 · Joining text](weeks/week-04/day-1.md?id=joining-text-amp-and-textjoin)
- **`LEFT` of a real date** cuts its day number, not the year. → [Week 4, Day 1 · LEFT, RIGHT, MID, SEARCH](weeks/week-04/day-1.md?id=left-right-mid-search-cutting-text)
- **`=100*A1/A2` formatted as %** is multiplied by 100 twice. → [Week 4, Day 1 · Number formats vs values](weeks/week-04/day-1.md?id=number-formats-vs-values-the-display-changes-the-value-does-not)
- **A format hides decimals**, it does not remove them: shown and stored values differ. → [Week 4, Day 1 · Number formats vs values](weeks/week-04/day-1.md?id=number-formats-vs-values-the-display-changes-the-value-does-not)
- **Day 60 is 29 February 1900**, a day that never was; outside Excel, count from 30 December 1899; the 1904 system is 1 462 days off. → [Week 4, Day 1 · Number formats vs values](weeks/week-04/day-1.md?id=number-formats-vs-values-the-display-changes-the-value-does-not)
- **Excel does binary maths**: `=1*(0.5-0.4-0.1)` is -2.78E-17; `ROUND` before you compare. → [Week 4, Day 1 · Number formats vs values](weeks/week-04/day-1.md?id=number-formats-vs-values-the-display-changes-the-value-does-not)
- **A lookup returns the first match only**; a repeated key gives one arbitrary row. → [Week 4, Day 2 · The lookup problem](weeks/week-04/day-2.md?id=the-lookup-problem-a-left-join-that-brings-one-column)
- **`VLOOKUP` without `FALSE`** is an approximate match: a neighbour's value, no `#N/A`. → [Week 4, Day 2 · VLOOKUP and its four traps](weeks/week-04/day-2.md?id=vlookup-and-its-four-traps)
- **`MATCH` without its third argument** is approximate too; write the `0`. → [Week 4, Day 2 · INDEX / MATCH](weeks/week-04/day-2.md?id=index-match-find-the-position-then-take-the-value)
- **`IFERROR(…, 0)`** turns every miss into a zero, and the total looks complete. → [Week 4, Day 2 · IFERROR](weeks/week-04/day-2.md?id=iferror-a-replacement-for-an-expected-error)
- **A number stored as text** is skipped by `SUM`; changing the format does not convert it. → [Week 4, Day 3 · What dirty data looks like](weeks/week-04/day-3.md?id=what-dirty-data-looks-like-a-checklist)
- **A CSV opened by double-click** follows your Windows settings: one column, or `1,5` read wrongly. → [Week 4, Day 3 · Power Query](weeks/week-04/day-3.md?id=power-query-load-steps-load-back)
- **Excel changes values on open**: `00123` → 123, a 20-digit account keeps 15 digits, `1-2` → a date. → [Week 4, Day 3 · Power Query](weeks/week-04/day-3.md?id=power-query-load-steps-load-back)
- **Power Query's *Changed Type*** is a guess from the first 200 rows. → [Week 4, Day 3 · Change Type](weeks/week-04/day-3.md?id=change-type-the-first-step-after-the-headers)
- **A pivot shows Count instead of Sum** when the column holds one text cell or blank. → [Week 4, Day 4 · Rows and Values](weeks/week-04/day-4.md?id=rows-and-values-the-group-and-the-aggregate)
- **A pivot's calculated field** sees sums only — even of ids. → [Week 4, Day 4 · A calculated field](weeks/week-04/day-4.md?id=a-calculated-field-a-ratio-of-sums)

## Python and pandas

- **Text times 2 repeats the text**: `"31150000" * 2` is `"3115000031150000"`. → [Week 5, Day 1 · Values and types](weeks/week-05/day-1.md?id=values-and-types-int-float-str-bool-none)
- **A string never changes in place**: keep the result of `strip()`. → [Week 5, Day 1 · Strings and f-strings](weeks/week-05/day-1.md?id=strings-and-f-strings-text-and-numbers-inside-text)
- **Floats are binary**: `0.1 + 0.2 == 0.3` is False; compare with `math.isclose`. `int()` cuts, it does not round. → [Week 5, Day 1 · Numbers and arithmetic](weeks/week-05/day-1.md?id=numbers-and-arithmetic-operators-and-rounding)
- **`round(2.5)` is 2**: a half goes to the even neighbour; Excel and SQLite give 3. → [Week 5, Day 1 · Numbers and arithmetic](weeks/week-05/day-1.md?id=numbers-and-arithmetic-operators-and-rounding)
- **`round(2.675, 2)` is 2.67**: the float holds 2.67499…; use `Decimal` for half-up. → [Week 5, Day 1 · Numbers and arithmetic](weeks/week-05/day-1.md?id=numbers-and-arithmetic-operators-and-rounding)
- **Division differs from SQL**: `7 / 2` is 3.5 (SQL: 3); `-7 // 2` is -4 (SQLite: -3). → [Week 5, Day 1 · Numbers and arithmetic](weeks/week-05/day-1.md?id=numbers-and-arithmetic-operators-and-rounding)
- **Positions start at 0**, and a slice `x[a:b]` stops before `b`. → [Week 5, Day 1 · Lists](weeks/week-05/day-1.md?id=lists-an-ordered-column-of-values)
- **A missing dict key raises `KeyError`**; `d.get(key, 0)` does not. → [Week 5, Day 1 · Dicts](weeks/week-05/day-1.md?id=dicts-a-lookup-table-key-→-value)
- **A function without `return` gives `None`**; `print` is not a result. → [Week 5, Day 1 · Functions](weeks/week-05/day-1.md?id=functions-def-parameters-return)

- **`import datetime` ≠ `from datetime import datetime`**: one name, two meanings. → [Week 5, Day 1 · Importing modules](weeks/week-05/day-1.md?id=importing-modules-someone-else39s-functions)
- **A bare `except:`** hides every mistake, typos included. → [Week 5, Day 1 · Errors](weeks/week-05/day-1.md?id=errors-how-to-read-a-traceback-and-tryexcept)
- **One blank turns whole numbers into `float64`**; `dtype="Int64"` keeps them whole. → [Week 5, Day 2 · read_csv](weeks/week-05/day-2.md?id=read_csv-a-file-into-a-dataframe-parse_dates-dtype)
- **`read_csv` drops leading zeros and `+`** unless `dtype=str`, and leaves dates as text unless `parse_dates`. → [Week 5, Day 2 · read_csv](weeks/week-05/day-2.md?id=read_csv-a-file-into-a-dataframe-parse_dates-dtype)
- **A text column sums by gluing**: `"1" + "2" + "30"` is `"1230"`; `pd.to_numeric` first. → [Week 5, Day 2 · read_csv](weeks/week-05/day-2.md?id=read_csv-a-file-into-a-dataframe-parse_dates-dtype)
- **`and`/`or` on a Series** raise an error; write `&`, `|` with brackets round each condition. → [Week 5, Day 2 · Selecting rows](weeks/week-05/day-2.md?id=selecting-rows-the-boolean-mask-amp-isin-between-strcontains)
- **`loc[1:3]` includes 3, `iloc[1:3]` does not.** → [Week 5, Day 2 · loc and iloc](weeks/week-05/day-2.md?id=loc-and-iloc-rows-by-label-rows-by-position)
